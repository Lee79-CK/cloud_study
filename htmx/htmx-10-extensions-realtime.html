04

hx-sse

htmx 4의 SSE 확장은 2.x와 구조가 완전히 다릅니다. 브라우저의 EventSource 대신 htmx의 일반 요청(fetch)으로 연결하고, 응답의 Content-Type이 text/event-stream이면 이벤트가 올 때마다 처리합니다. 그래서 공식 문서 표현대로 hx-sse:connect는 "미리 설정된 hx-get"에 가깝습니다.

메시지처리 (공식 문서·소스)
data: <html> (이름 없음)일반 응답처럼 스왑. hx-target·hx-swap 적용, OOB·<hx-partial>도 동작. 연결 요소에서는 swapEmpty:false가 기본이라 partial만 있으면 연결 요소는 그대로
event: 이름스왑하지 않고 그 이름의 DOM 이벤트를 요청 요소에서 발생 (event.detail.data, id)
id: …재접속 때 Last-Event-ID 헤더로 보냄. 무엇을 다시 보낼지는 서버가 결정
retry: 밀리초재접속 대기 시간 변경
hx-sse:connect 기본값값

"연결 끊기"를 누르면 모의 서버가 스트림을 닫고, 확장이 백오프 후 다시 연결합니다. 기록에서 재접속 요청에 Last-Event-ID가 붙고, 모의 서버가 그 뒤의 이벤트만 다시 보내는 것을 확인할 수 있습니다. 랩 서버도 같은 방식으로 최근 200건을 보관합니다. 확장 소스를 보면 재접속은 htmx 요청 과정을 다시 거치지 않고, 처음 연결 때 만든 요청 정보(헤더 포함)를 그대로 써서 fetch를 직접 호출합니다. 그래서 처음 연결 때 htmx:config:request에서 붙인 헤더(랩의 요청 ID·탭 ID)는 재접속에도 같은 값으로 따라갑니다.

  

    
2.x에서 넘어오는 분께

    
2.x의 sse-connect·sse-swap="이름" 방식에서는 이름 있는 이벤트를 골라 스왑했지만, 4.x는 반대로 이름 없는 이벤트만 스왑하고 이름 있는 이벤트는 DOM 이벤트가 됩니다. hx-trigger="sse:progress"는 hx-trigger="progress from:body"로 바뀝니다. 이벤트 이름도 htmx:sse:before:message처럼 바뀌었습니다(공식 마이그레이션 표).

apps/server/src/app.js (발췌)


function sseMessage(entries, user) {
  return als.run({ user }, () => {                          // 접속한 사용자의 권한으로 렌더링
    const names = [...new Set(entries.flatMap(e => e.names))];
    let html = `<hx-partial hx-target="#summary" hx-swap="innerHTML">${part('./partials/summary', { sum: store.summary() })}</hx-partial>`;
    for (const name of names) {
      const vm = store.find(name);
      html += vm
        ? `<hx-partial hx-target="#row-${name}" hx-swap="outerHTML">${part('./partials/vm-row', { vm })}</hx-partial>`
        : `<hx-partial hx-target="#row-${name}" hx-swap="delete"></hx-partial>`;   // 삭제된 VM
    }
    return html;
  });
}

  
한 변경을 <hx-partial> 묶음 하나로 보냅니다. 5편에서 확인했듯 partial은 표 행도 안전하게 실어 나릅니다. 대상 행이 그 사용자 화면에 없을 때(검색으로 걸러졌거나 아직 스크롤하지 않은 페이지)는 별도 실험에서 오류 없이 그 partial만 건너뛰고 나머지는 정상 적용됐습니다. 행 템플릿에는 id="row-이름"을 붙였고, 4편의 "전환 중 행이 1.5초 뒤 스스로 다시 묻기"와 요약 카드의 5초 폴링은 지웠습니다.

자기 변경의 반향 문제

  
SSE를 붙이고 5편 회귀 테스트를 돌리자, 재시작 후 떠야 할 토스트와 View Transition이 사라졌습니다. 원인은 경쟁 상태(race condition)였습니다.

  

    
1운영자가 web-02 재시작 클릭 → POST /vms/web-02/restart (대상: closest tr)

    
2서버가 상태를 바꾸는 순간 변경 알림 → SSE가 같은 탭에 web-02 행을 먼저 밀어 넣음 (행 요소 교체)

    
3POST 응답 도착. 그런데 원래 대상이던 행 요소는 이미 문서에서 떨어져 있음

    
4htmx 4.0.1은 대상이 문서에 없으면 스왑과 그 부수 효과를 모두 건너뜀 (소스: "prevent swap and side effects if target just got removed") → 응답에 담긴 OOB 토스트도 버려짐

  

  
해결은 "변경을 일으킨 탭에는 그 변경을 되돌려 보내지 않는 것"입니다. 그 탭은 자기 요청의 응답으로 이미 화면을 바꾸고 있기 때문입니다. 탭을 구분하려고 직접 만든 확장(9절)이 탭마다 무작위 X-Client-ID를 모든 요청과 SSE 연결에 붙이고, 서버는 요청 문맥에 그 값을 담아 둔 채 변경 알림에 "origin"으로 기록합니다. SSE는 접속한 탭의 ID와 같은 origin의 변경을 빼고 보냅니다. 단 전환 완료(타이머가 만든 변경)는 origin이 없으므로 그 탭에도 갑니다. 고친 뒤 같은 테스트에서 토스트와 View Transition이 돌아왔고, 다른 사용자 화면은 여전히 즉시 갱신됐습니다.

hx-ptag

  
hx-ptag 확장은 소스가 30줄 남짓입니다. 응답의 HX-PTag 헤더 값을 요청 요소에 저장했다가, 다음 요청 때 같은 이름의 요청 헤더로 보냅니다. 서버가 "바뀐 게 없다"고 판단하면 304를 주고, 304는 1편부터 본 noSwap 기본값이라 스왑이 일어나지 않습니다. HTTP의 ETag와 비슷하지만 URL이 아니라 요소 단위입니다.

app.get('/vms/:name/activity/live', loadVm, (req, res) => {
  const version = store.activityVersion(req.vm);           // 가장 최근 기록의 일련번호
  res.set('HX-PTag', version);

hx-preload

  
마우스를 올리거나 누르기 시작하는 순간 GET 요청을 미리 보내 두고, 실제 클릭이 오면 그 응답을 씁니다. 소스 기준 규칙은 이렇습니다.

  

    
규칙 (4.0.1 확장 소스)내용

    
      
대상hx-preload 속성이 있는 요소, 또는 (속성이 없어도) 부스트된 링크

      
시점속성값의 트리거(mouseenter, focus 등). 부스트 링크 기본은 mousedown·touchstart

      
유효 시간기본 5초, 트리거에 timeout: 수식어로 변경. 지나면 버리고 다시 요청

랩에서 요청 헤더를 기록하니, 미리 보낸 요청에는 8편부터 붙여 온 X-Request-ID가 없었습니다. 같은 링크를 마우스 이동 없이 클릭(이벤트 직접 발생)하면 붙어 있었습니다. 확장 소스를 보면 preload는 요청 문맥만 만든 뒤 fetch()를 바로 부르고, 실제 클릭 때는 이미 끝난 응답을 끼워 넣습니다. 그래서 htmx:config:request에서 붙이는 헤더(요청 ID, 인증 토큰, CSRF 토큰)와 hx-headers가 모두 빠집니다. preload는 부작용 없는 GET, 그리고 쿠키만으로 인증되는 요청에만 쓰세요. 또 5절의 X-Client-ID도 빠지므로, 조회 요청이라 문제는 없지만 서버 로그의 요청 ID는 서버가 새로 만든 값이 됩니다. 8편 테스트의 "보낸 ID와 로그 ID 비교" 항목은 이 때문에 preload가 걸린 링크에서는 비교 대상이 없어졌습니다.

hx-ws

  
WebSocket 확장은 연결 요소(hx-ws:connect)와 보내는 요소(hx-ws:send)로 나뉩니다. 공식 문서 페이지마다 메시지 형식과 이벤트 이름 설명이 조금씩 달라, 이 절은 4.0.1 배포본 소스를 기준으로 정리했습니다.

  

    
항목4.0.1 소스 기준

    
      
보내는 형식텍스트 프레임에 JSON 하나: { ...폼 값과 hx-vals, headers: {...} }. 폼 값은 최상위 키, 같은 이름이 여러 개면 배열. headers는 일반 요청과 같은 핵심 헤더(HX-Request, HX-Source, HX-Current-URL 등)에서 Accept만 뺀 것

      
받는 형식JSON이 아니면 문자열 전체를 HTML로 스왑. JSON이고 content가 있으면 그것을 HTML로, target·swap·select로 위치 지정. content가 없는 JSON은 스왑 없이 이벤트로만

      
스왑 기본연결 요소의 hx-target·hx-swap, 없으면 연결 요소 자신. swapEmpty:false가 자동으로 붙어 partial만 있는 메시지는 연결 요소를 비우지 않음

      
이벤트htmx:ws:before:connection·after:connection, htmx:ws:before:message:outgoing·after:message:outgoing, htmx:ws:before:message:incoming·after:message:incoming, htmx:ws:close, htmx:ws:error

    
  

  

    
문서와 소스가 다를 때

    
검색되는 공식 문서 페이지 중에는 보내는 메시지를 {"headers": …, "body": …}로, 이벤트를 htmx:before:ws:send나 htmx:before:ws:request로 설명하는 곳이 있습니다. 4.0.1 배포본 소스는 폼 값을 최상위에 펼치고 이벤트 이름도 위 표와 같습니다. 랩 서버 로그에도 {message, headers} 형태로 받은 값이 찍혔습니다. 확장은 코어보다 빠르게 바뀌니, 버전을 올릴 때는 문서보다 소스와 실제 프레임을 확인하세요.
