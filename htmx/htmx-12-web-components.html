웹 컴포넌트 다섯 가지 콜백

사용자 정의 요소(Custom Elements)는 HTMLElement를 상속한 클래스를 customElements.define('태그-이름', 클래스)로 등록한 것입니다. 이름에는 반드시 하이픈이 들어갑니다. 브라우저는 그 태그가 문서에 들어오고 나가고 바뀔 때 아래 콜백을 부릅니다.

콜백언제htmx와의 접점이번 편에서 하는 일
connectedCallback요소가 문서에 연결될 때 (이미 있던 태그는 정의 시점에 "업그레이드"되며 호출)스왑으로 새 HTML이 들어올 때React 루트 생성·렌더
disconnectedCallback문서에서 떨어질 때교체로 사라질 때한 틱 뒤에도 떨어져 있으면 언마운트
attributeChangedCallbackstatic observedAttributes에 적은 속성이 바뀔 때모핑이 속성만 바꿀 때 (5편)새 속성으로 다시 렌더
connectedMoveCallbackElement.moveBefore()로 옮겨질 때. 정의돼 있으면 연결·분리 콜백 대신 이것만 호출hx-preserve가 지원 브라우저에서 moveBefore 사용 (5편)아무것도 안 함 (상태 유지)
adoptedCallback다른 문서로 옮겨질 때거의 없음사용 안 함
Chrome 153 측정: 같은 이동, 콜백 차이
<with-move>  (connectedMoveCallback 있음)    <no-move>  (없음)
--- parent.moveBefore(el, null)
W:connectedMove                               N:disconnected → N:connected
--- parent.insertBefore(el, null)
W:disconnected → W:connected                  N:disconnected → N:connected

moveBefore를 지원하지 않는 브라우저, 또는 htmx가 아닌 다른 코드가 insertBefore로 요소를 옮기면 "분리 → 연결"이 연달아 옵니다. 분리 콜백에서 바로 언마운트하면 React 상태가 날아가므로, 이번 편 도우미는 한 마이크로태스크 뒤에 아직도 문서 밖인지 확인하고서야 정리합니다. Vue의 defineCustomElement도 Vue 소스를 보면 disconnectedCallback에서 nextTick 뒤에 연결 여부를 확인하고 언마운트하는 같은 전략을 씁니다.

섀도 DOM의 득과 실

  

    
섀도 DOM (이번 편 기본)라이트 DOM (shadow: false)

    
      
htmx·OOB·partial이 안쪽을 겨냥불가 (측정: 대상 없음 경고)가능 (11편의 침범 위험 그대로)

      
모핑호스트의 속성·라이트 자식만 맞춤. 섀도 안은 그대로 (측정)React가 그린 자식을 서버 HTML로 맞춰 버림 (11편 측정) → hx-morph-skip-children 필요

      
페이지 CSS들어오지 않음 (측정: 페이지에 figcaption{color:red !important}를 넣어도 섀도 안은 원래 색). 호스트 요소 자체에는 적용 (측정: .island 외곽선 적용)들어옴. 디자인 시스템 공유는 쉽지만 충돌도 쉬움

      
CSS 변수(--color)상속되어 들어옴 → 테마 토큰은 변수로 전달 (15편)들어옴

      
이벤트composed 이벤트는 경계를 넘되 대상이 호스트로 바뀜 (측정: 섀도 안 클릭이 document에서는 metric-chart로 보임)그대로

      
폼·접근성안쪽 입력은 바깥 <form>에 포함되지 않음, aria-labelledby 같은 id 참조가 경계를 못 넘음제약 없음

    
  

  
정리하면, 읽기 전용 위젯(차트, 지도, 상태 표시)은 섀도 DOM이 htmx와의 경계를 거의 공짜로 지켜 줍니다. 반대로 폼 입력을 받는 아일랜드가 바깥 폼과 함께 제출되어야 하거나, 페이지 디자인 시스템 CSS를 그대로 써야 한다면 라이트 DOM이 낫고, 그때는 11편의 경계 규칙(안쪽을 대상으로 삼지 않기)과 hx-morph-skip-children을 함께 씁니다. 폼 연동이 꼭 필요한 섀도 DOM 요소는 ElementInternals(form-associated custom elements)라는 표준 방법이 있습니다. 이벤트가 호스트로 바뀌어 보이는 성질은 13편 이벤트 브리지의 출발점입니다.

  1. 사용자 정의 요소는 마운트(connected)·정리(disconnected)·속성 변화(attributeChanged)·이동(connectedMove) 시점을 요소마다 정확히 알려 준다. 11편 등록부의 짐작이 필요 없다.
    2. 
    
  2. 정리는 한 틱 뒤 연결 여부를 확인하고서. Vue의 defineCustomElement도 같은 전략이다.
    3. 
    
  3. 섀도 DOM은 htmx 대상 지정·모핑·페이지 CSS로부터 안쪽을 지킨다(측정). 대신 폼·id 참조·이벤트 대상에 제약이 있다.
    4. 
    
  4. 모핑은 이제 아일랜드의 친구다. 속성만 바꾸면 같은 요소가 새 값으로 다시 그린다.

  5. hx-preserve는 상태를 지키지만, 응답 쪽 자리표시 요소가 잠깐 마운트되는 비용이 있다(측정).
