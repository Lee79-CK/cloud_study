CLAUDE.md프로젝트의 기억

지금까지 “표준 라이브러리만”, “127.0.0.1만”, “테스트는 고치지 마”를 세션마다 다시 말했습니다. 이번 편에서는 그 말을 프로젝트에 심어, 새 세션의 Claude도 처음부터 알고 시작하게 만듭니다.

CLAUDE.md와 자동 메모리의 차이, 그리고 둘 다 “강제”가 아니라는 점을 설명한다
관리형·사용자·프로젝트·로컬 범위와 로딩 순서를 안다
넣을 것과 뺄 것을 구분해 200줄 이하의 구체적인 CLAUDE.md를 쓴다
경로별 규칙, @ 가져오기, AGENTS.md, /memory를 상황에 맞게 쓴다

층을 누르면 설명이 나옵니다. 위에서 아래로 넓은 범위 → 좁은 범위 순서로 대략 배치했습니다.

매 세션은 백지에서 시작한다

2편에서 봤듯 모든 세션은 새 컨텍스트 창으로 시작하고, 모델은 지난 대화를 기억하지 않습니다. 세션을 넘어 지식을 나르는 장치는 둘입니다.

CLAUDE.md자동 메모리
누가 쓰나사람Claude
무엇을 담나지시와 규칙배운 것과 패턴
범위조직, 사용자, 프로젝트저장소 단위 (worktree끼리 공유)
로드매 세션매 세션 (MEMORY.md 앞 200줄 또는 25KB)
쓰임코딩 규칙, 작업 흐름, 구조 결정내 선호, 내가 준 교정, 코드로 알 수 없는 맥락
핵심: 둘 다 “맥락”이지 “강제”가 아닙니다 CLAUDE.md는 시스템 프롬프트가 아니라 그 뒤에 사용자 메시지로 전달됩니다. Claude는 읽고 따르려 하지만 엄격한 준수를 보장하지는 않습니다. 특히 모호하거나 서로 충돌하는 지시는 더 그렇습니다. 무슨 일이 있어도 막아야 하는 행동은 9편의 deny 규칙이나 11편의 Hook으로 만듭니다. CLAUDE.md는 “이렇게 해 줘”, 설정과 Hook은 “이건 못 해”입니다.

무엇을 적고 무엇을 뺄까

공식 문서는 CLAUDE.md를 “다시 설명하게 될 것을 적어 두는 곳”으로 보라고 합니다. 이럴 때 추가하세요.

  • Claude가 같은 실수를 두 번째 할 때
  • 코드 리뷰에서 “이 코드베이스라면 알았어야 할 것”이 걸렸을 때
  • 지난 세션에 입력한 교정을 또 입력하고 있을 때
  • 새 팀원도 똑같은 설명이 필요할 때

모든 세션에 필요한 사실만 둡니다: 빌드·테스트 명령, 관례, 구조, “항상 X” 규칙. 여러 단계로 된 절차나 코드베이스 일부에만 해당하는 내용은 Skill(10편)이나 경로별 규칙(7장)으로 옮깁니다. 각 줄마다 이렇게 물으세요: “이 줄을 지우면 Claude가 실수할까?” 아니라면 지웁니다.

프로젝트./CLAUDE.md 또는 ./.claude/CLAUDE.md팀 (Git으로 공유)테스트 명령, 구조, 팀 규칙
로컬./CLAUDE.local.md (.gitignore에 추가)나 (이 프로젝트만)내 샌드박스 주소, 개인 테스트 데이터

로딩 규칙: 실행한 폴더와 그 위쪽 모든 폴더의 CLAUDE.md·CLAUDE.local.md는 시작할 때 읽힙니다. 서로 덮어쓰지 않고 이어 붙으며, 파일 시스템 루트에서 실행 폴더 쪽으로 내려오는 순서라 실행 위치에 가까운 지시가 나중에 읽힙니다. 같은 폴더에서는 CLAUDE.local.md가 CLAUDE.md 뒤에 붙습니다. 아래쪽 하위 폴더의 CLAUDE.md는 시작할 때가 아니라, Claude가 그 폴더의 파일을 읽을 때 함께 로드됩니다.

로딩 시뮬레이터: 무엇이 언제 읽히나

관리형 CLAUDE.md vs 관리형 설정 조직 차원에서도 같은 원칙입니다. 코드 스타일, 데이터 취급 주의 같은 행동 안내는 관리형 CLAUDE.md에, 특정 도구·명령·경로 차단이나 샌드박스 강제 같은 기술적 강제는 관리형 설정(permissions.deny 등)에 둡니다. MSP 조직 도입은 24편에서 다룹니다.

어떻게 쓰나: 구체적으로, 짧게

📏 크기

파일 하나당 200줄 이하가 목표. 길수록 컨텍스트를 먹고 준수율이 떨어집니다. 4MiB를 넘는 파일은 아예 건너뜁니다.

🧱 구조

마크다운 제목과 글머리표로 묶습니다. Claude도 사람처럼 구조를 훑어봅니다.

🎯 구체성

확인할 수 있을 만큼 구체적으로. “코드 잘 정리” 대신 “API 핸들러는 src/api/handlers/에”.

⚖️ 일관성

두 규칙이 충돌하면 Claude가 아무거나 고를 수 있습니다. 중첩 CLAUDE.md와 rules까지 주기적으로 정리.

❗ 강조는 아껴서

계속 무시되는 한 줄에만 IMPORTANT를 붙입니다. 여러 줄을 강조하면 아무것도 두드러지지 않습니다.

💬 사람용 메모

블록 단위 HTML 주석(<!-- 메모 -->)은 Claude에게 전달되기 전에 제거되어 토큰을 쓰지 않습니다. 관리자용 설명을 남길 때.

/init으로 시작하기

/init은 코드베이스를 분석해 빌드 명령, 테스트 방법, 발견한 관례로 CLAUDE.md 초안을 만듭니다. 이미 CLAUDE.md가 있으면 덮어쓰지 않고 개선안을 제안합니다. 프로젝트에 Cursor 규칙(.cursor/rules/, .cursorrules)이나 Copilot 규칙(.github/copilot-instructions.md)이 있으면 관련 부분을 반영합니다.

환경 변수 CLAUDE_CODE_NEW_INIT=1을 설정하면 대화형 다단계 흐름이 됩니다. CLAUDE.md·Skills·Hooks 중 무엇을 만들지 묻고, 서브에이전트로 코드베이스를 탐색하고, 빈 곳은 질문으로 채운 뒤, 파일을 쓰기 전에 검토할 제안을 보여 줍니다. 이 모드에서는 AGENTS.md와 다른 도구의 규칙 파일도 읽습니다.

/init 결과는 초안일 뿐 /init은 코드에서 찾을 수 있는 것을 적습니다. 그런데 CLAUDE.md의 진짜 가치는 코드에서 찾을 수 없는 것(왜 표준 라이브러리만 쓰는지, 무엇을 절대 하면 안 되는지)에 있습니다. 초안을 받은 뒤 디렉토리 구조 설명처럼 코드를 읽으면 아는 내용은 지우고, 함정과 이유를 더하세요. 체크인한 CLAUDE.md는 /doctor가 코드에서 유도할 수 있는 내용을 덜어 내자는 제안도 해 줍니다.

@ 가져오기와 CLAUDE.local.md

# CLAUDE.md 프로젝트 개요는 @README.md, 서버 목록 형식은 @docs/servers-format.md 참고. # 추가 지침 - Git 작업 흐름 @docs/git-workflow.md
경로 해석

상대 경로는 실행 폴더가 아니라 가져오는 파일 기준. 절대 경로도 됩니다. 최대 4단계까지 연쇄 가져오기.

가져오지 않고 언급만

백틱으로 감싸면 글자 그대로 남습니다. `@README`는 언급, @README는 가져오기. 코드 블록 안도 무시됩니다.

컨텍스트는 줄지 않는다

가져온 파일도 시작할 때 모두 로드됩니다. 정리에는 좋지만 크기 문제의 해결책은 아닙니다. 그건 경로별 규칙(7장)이나 Skill.

외부 가져오기 승인

프로젝트 파일이 작업 폴더 밖을 가져오면 처음 한 번 승인 창이 뜹니다. 남이 커밋한 파일이 내 홈의 파일을 끌어오지 못하게 막는 장치입니다. 거절하면 계속 꺼진 채로 유지됩니다.

CLAUDE.local.md

커밋하면 안 되는 이 프로젝트만의 개인 지침은 루트의 CLAUDE.local.md에 두고 .gitignore에 넣습니다. 단, gitignore된 파일이라 그 파일을 만든 worktree에만 있습니다(7편). 여러 worktree에서 같은 개인 지침을 쓰려면 홈의 파일을 가져오세요.

# CLAUDE.local.md 대신, 모든 worktree에서 쓰려면 CLAUDE.md 안에 - @~/.claude/vibe-lab-personal.md

.claude/rules: 경로별 규칙

프로젝트가 커지면 지침을 주제별 파일로 나눕니다. .claude/rules/ 안의 모든 .md가 하위 폴더까지 발견됩니다. 그리고 맨 위에 paths를 적으면 그 경로의 파일을 Claude가 읽을 때만 로드되어 컨텍스트를 아낍니다.

vibe-lab/ ├── CLAUDE.md └── .claude/ └── rules/ ├── security.md # paths 없음 → 매 세션 로드 └── shell-scripts.md # paths: scripts/**/*.sh → 셸 스크립트를 읽을 때만
--- paths: - "scripts/**/*.sh" --- # 셸 스크립트 규칙 - 첫 줄 다음에 set -euo pipefail - 변수는 항상 큰따옴표로 감싸기: "$ip" - 서버에 쓰는 명령(rm, mv, 재시작)은 넣지 않는다. 점검 스크립트는 읽기 전용
패턴맞는 파일
**/*.tf모든 폴더의 테라폼 파일
k8s/**/*.{yaml,yml}k8s 아래 YAML (중괄호 확장)
scripts/*.shscripts 바로 아래 셸 스크립트
*.md프로젝트 루트의 마크다운

개인 규칙은 ~/.claude/rules/에 두면 모든 프로젝트에 적용되고, 프로젝트 규칙보다 먼저 읽힙니다. 둘이 충돌하면 어느 쪽이 따를지 보장되지 않으니 일관되게 유지하세요. frontmatter가 YAML로 해석되지 않으면 paths 없이 항상 로드되는 규칙으로 취급됩니다.

AGENTS.md와 다른 도구

다른 코딩 에이전트용으로 AGENTS.md를 쓰는 저장소도 Claude Code가 읽을 수 있습니다(v2.1.277 이상).

저장소에 있는 것Claude가 읽는 것 (기본값)
AGENTS.md만 (실행 폴더와 위쪽에 CLAUDE.md·CLAUDE.local.md 없음)AGENTS.md
AGENTS.md와 CLAUDE.md(또는 CLAUDE.local.md)CLAUDE.md 쪽만
CLAUDE.md 안에 @AGENTS.mdCLAUDE.md, 가져온 AGENTS.md 포함
함정: CLAUDE.local.md 하나가 AGENTS.md를 끕니다 AGENTS.md로 운영하는 저장소에 개인용 CLAUDE.local.md를 추가하면, 그것도 “CLAUDE.md 쪽 파일”로 쳐서 AGENTS.md를 읽지 않게 됩니다. 둘 다 읽게 하려면 /config의 Project instructions를 claude-md-and-agents-md로 바꾸거나, CLAUDE.md에 @AGENTS.md를 넣으세요. 가장 확실한 공용 방법은 가져오기입니다.
# CLAUDE.md @AGENTS.md ## Claude Code 전용 - scripts/ 변경은 Plan 모드로 계획부터

심볼릭 링크(ln -s AGENTS.md CLAUDE.md)도 되지만, Windows에서는 관리자 권한이나 개발자 모드가 필요하고 Git이 링크를 일반 텍스트 파일로 꺼낼 수 있어서 팀에 Windows 사용자가 있다면 가져오기를 권합니다. 다른 에이전트의 설정을 한 번에 옮기려면 /import도 있습니다.

자동 메모리

자동 메모리는 여러분이 아무것도 쓰지 않아도 Claude가 세션을 넘어 지식을 쌓게 합니다. 기본으로 켜져 있고, Claude는 네 종류의 메모를 남깁니다.

👤 user

나의 역할, 전문성, 작업 선호

🧭 feedback

내가 준 교정, 내가 좋다고 확인한 방식

📌 project

진행 중인 일, 마감, 코드나 Git 기록으로 알 수 없는 결정

🔗 reference

프로젝트 밖의 정보 위치: 이슈 트래커, 대시보드

코드로 알 수 있는 것(구조, 파일 경로, 디버깅 수정)과 CLAUDE.md에 이미 있는 것은 저장하지 않습니다. 매 세션 저장하는 것도 아니고, 미래 대화에 쓸모 있을지로 판단합니다. 화면에 “Saved 2 memories”, “Recalled 2 memories” 같은 문구가 보이면 메모리를 쓰거나 읽은 것입니다.

~/.claude/projects/<프로젝트>/memory/ ├── MEMORY.md # 색인. 한 줄에 메모 하나. 앞 200줄 또는 25KB가 매 세션 로드 ├── user_role.md # 주제 파일: 시작할 때 로드되지 않고 필요할 때 읽음 └── feedback_testing.md
하고 싶은 일방법
무엇이 저장됐나 보기·고치기/memory → 자동 메모리 폴더 열기. 전부 평범한 마크다운
켜기·끄기/memory의 토글, 또는 settings의 autoMemoryEnabled, 환경 변수 CLAUDE_CODE_DISABLE_AUTO_MEMORY=1

    안 지켜질 때와 압축 후

    1
    로드됐나?

    /context의 Memory files 목록에 그 파일이 있는지. 없으면 Claude는 볼 수 없습니다. 위치(3장)를 확인하고 /memory로 열어 고칩니다.

    2
    구체적인가?

    “포맷 잘해” 대신 “2칸 들여쓰기”. 확인할 수 있는 문장으로.

    3
    충돌하지 않나?

    사용자·프로젝트·하위 폴더 CLAUDE.md와 rules에 다른 말이 없는지.

    4
    너무 길지 않나?

    권장 길이를 넘으면 시작할 때와 /status에서 경고가 나옵니다. 계속 무시되는 규칙이 있다면 파일이 길어서 묻힌 것일 가능성이 큽니다.

    5
    반드시 지켜야 하나?

    매 커밋 전, 매 편집 후처럼 정해진 시점에 꼭 실행돼야 한다면 Hook(11편). 차단이 필요하면 deny 규칙(9편).

    /compact 뒤에 사라진 지시

    프로젝트 루트의 CLAUDE.md는 압축 후 디스크에서 다시 읽혀 들어옵니다. 하위 폴더의 CLAUDE.md와 paths 규칙은 해당 파일을 다시 읽을 때 다시 로드됩니다. 압축 후 사라진 지시는 대개 대화로만 말한 것입니다. 오래 지켜야 할 것이면 CLAUDE.md로 옮기세요. 압축 시 무엇을 남길지도 적어 둘 수 있습니다.
