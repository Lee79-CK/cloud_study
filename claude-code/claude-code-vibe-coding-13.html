서브에이전트란

서브에이전트는 특정 종류의 일을 맡는 전문 AI 조수입니다. 각자 자기 컨텍스트 창, 자기 시스템 프롬프트, 자기 도구 권한을 가지고 독립적으로 일한 뒤 결과를 돌려줍니다. 공식 문서의 기준은 명확합니다: 다시 볼 일 없는 검색 결과·로그·파일 내용이 메인 대화를 채울 곁가지 일이면 서브에이전트에게 맡기고 요약만 받으세요. 같은 종류의 일꾼을 같은 지시로 반복해서 부르게 되면 커스텀 서브에이전트로 정의합니다.

🧹 컨텍스트 보존

탐색과 실행 출력을 메인 대화 밖에 둡니다. 2편의 “컨텍스트가 가장 귀한 자원”을 지키는 가장 강력한 도구.

🚧 제약 강제

서브에이전트마다 쓸 수 있는 도구를 좁힙니다. 리뷰어는 편집 불가, 조사관은 조회 도구만.

💸 비용 조절

단순한 일은 Haiku 같은 빠르고 저렴한 모델로 보냅니다.

⚠️ 공짜는 아님

서브에이전트도 자기 요청을 보내므로 같은 사용량 한도에 잡힙니다. 결과를 길게 돌려주는 서브에이전트를 여럿 돌리면 오히려 메인 컨텍스트가 찹니다.

정의 파일과 범위

서브에이전트는 YAML frontmatter가 붙은 마크다운 파일입니다. frontmatter는 설정, 본문은 그 서브에이전트의 시스템 프롬프트입니다. 서브에이전트는 Claude Code의 시스템 프롬프트가 아니라 이 본문과 작업 폴더 같은 기본 환경 정보만 받습니다. 필수 필드는 name과 description뿐입니다.

--- name: code-reviewer description: 코드 변경을 리뷰한다. 코드를 쓰거나 고친 직후 적극적으로 사용. 읽기 전용. tools: Read, Grep, Glob, Bash model: inherit --- 너는 MSP 운영 도구를 리뷰하는 시니어 엔지니어다. 코드는 절대 고치지 않는다. …
우선순위위치범위
1 (최상)관리형 설정 폴더의 .claude/agents/조직 전체
2--agents '{…}' CLI 플래그그 세션만 (디스크에 저장 안 됨)
3.claude/agents/이 프로젝트 (커밋해서 팀 공유)
4~/.claude/agents/내 모든 프로젝트
5플러그인 agents/플러그인이 켜진 곳 (15편)
만들기

공식 문서의 권장은 Claude에게 “~/.claude/agents/에 이런 서브에이전트를 만들어줘”라고 시키고 파일을 검토하는 것. 최신 버전의 /agents는 이 방법을 안내하는 메시지를 보여 줍니다.

바로 반영

agents 폴더 변경은 몇 초 안에 반영됩니다. 단 세션 시작 때 없던 agents 폴더를 새로 만들었다면 재시작.

이름 규칙

폴더 깊이는 상관없고 name이 정체성. :는 쓸 수 없습니다(플러그인 전용). 같은 이름이 둘이면 하나만 로드되니 고유하게.

조용히 건너뛰는 파일

name이나 description이 없거나 YAML이 깨지면 경고 없이 건너뜁니다. claude --debug 로그나 claude plugin validate .claude/agents로 확인.

도구 제한

허용 목록 tools

tools: Read, Grep, Glob, Bash

이것만 씀. 편집·쓰기·MCP 불가.

거부 목록 disallowedTools

disallowedTools: Write, Edit

나머지는 물려받음. Bash·MCP는 남음.

목표필드예
한 MCP 서버의 모든 도구만 주기toolsmcp__k8s-ro__*
한 서버의 도구 빼기disallowedToolsmcp__github
모든 MCP 도구 빼기disallowedToolsmcp__*
disallowedTools의 지정자는 도구 전체를 뺌

disallowedTools: Bash(git push *)는 git push만이 아니라 Bash 전체를 뺍니다. 특정 명령만 막으려면 9편의 permissions.deny 규칙(메인과 서브에이전트 모두 적용)을 쓰세요.

백그라운드에서는 도구가 줄어듦

백그라운드 서브에이전트(기본)는 MCP 도구는 모두 유지하지만 내장 도구는 Read·Grep·Glob·Bash·Edit·Write·WebFetch·Skill 등 정해진 목록만 씁니다. 같은 정의라도 실행 방식에 따라 도구가 달라질 수 있습니다.

모든 서브에이전트에서 빠지는 것

AskUserQuestion, EnterPlanMode 등은 항상 제외. 그래서 서브에이전트는 여러분에게 질문하지 못합니다. 필요한 정보는 위임 메시지에.

목록이 비면 실행 실패

tools의 이름이 전부 오타면 “도구 0개로 실행될 것”이라는 오류로 아예 시작하지 않습니다.

모델과 권한 모드

모델이 정해지는 순서

1
Claude가 호출 때 넘긴 model

“이건 haiku로 돌려”라고 하면 그 호출에만.

2
정의 파일의 model

inherit면 메인 대화 모델.

3
CLAUDE_CODE_SUBAGENT_MODEL

기본값 역할. 모든 서브에이전트에 강제하려면 CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1도.

4
메인 대화 모델

위에 아무것도 없으면.

effort 는 어떻게 정해지나 (v2.1.316~317 변경) 정의 파일의 effort가 있으면 그것을 씁니다. 없을 때의 동작이 최근 바뀌었습니다. v2.1.317부터 메인 대화와 다른 모델로 도는 서브에이전트·팀원은 세션의 effort를 물려받지 않고 그 모델에 저장된 effort(없으면 그 모델의 기본값)를 씁니다. 모든 서브에이전트의 기본 effort를 정하려면 v2.1.316에 추가된 CLAUDE_CODE_SUBAGENT_EFFORT 환경 변수를 씁니다. 예를 들어 메인이 Opus에서 max여도 haiku 서브에이전트는 haiku의 기본값으로 돕니다.

실행 중인 서브에이전트의 모델은 /tasks에서 확인합니다. 조직의 허용 모델 목록에 없는 값은 다른 모델로 대체되고 경고가 뜹니다. 서브에이전트는 메인 대화의 확장 사고 설정을 물려받습니다.

권한 모드 상속

메인 대화가서브에이전트는
bypassPermissions · acceptEdits · auto정의의 permissionMode를 무시하고 메인과 같은 모드. auto면 분류기가 서브에이전트의 작업과 최종 보고까지 검토
plan무엇을 설정했든 plan 모드 유지
default(Manual) · dontAsk정의의 permissionMode를 따름. 단 bypassPermissions는 메인이 그 모드일 때만
백그라운드 서브에이전트의 승인은 세션 전체에 적용 백그라운드 서브에이전트가 권한을 요청하면 메인 세션에 어느 서브에이전트가 묻는지 표시됩니다. 여기서 “이 세션 동안 허용”처럼 오래가는 답을 고르면 메인 대화를 포함한 세션 전체에 적용됩니다. Esc로 그 호출 하나만 거부할 수 있습니다.

전용 MCP·Skill·메모리·Hook

🔌 mcpServers

인라인 정의는 서브에이전트가 시작할 때 연결되고 끝나면 끊깁니다. 메인 대화에는 그 도구가 아예 없어 설명이 컨텍스트를 먹지도 않습니다. 이름 문자열로 쓰면 이미 설정된 서버의 연결을 공유합니다.

📚 skills

나열한 Skill의 전체 내용을 시작할 때 주입합니다(최대 32개). disable-model-invocation: true인 Skill은 미리 넣을 수 없습니다.

🧠 memory

user(~/.claude/agent-memory/이름/), project(.claude/agent-memory/이름/, 커밋 가능, 권장), local(.claude/agent-memory-local/이름/). MEMORY.md 앞 200줄·25KB가 시스템 프롬프트에 들어갑니다.

🪝 hooks

그 서브에이전트가 도는 동안만. frontmatter의 Stop은 SubagentStop으로 바뀝니다. 세션 설정의 Hook(11편)도 서브에이전트 도구 호출에 똑같이 걸립니다.

함정: memory를 켜면 Write·Edit가 자동으로 생깁니다 공식 문서대로 memory가 켜지면 메모리 파일 관리를 위해 Read·Write·Edit 도구가 자동으로 활성화됩니다. tools: Read, Grep로 “읽기 전용”을 만들었더라도 memory를 켜면 파일을 쓸 수 있게 됩니다. 정말 코드를 건드리면 안 되는 리뷰어라면 memory를 끄거나, 프롬프트 지시에 더해 11편처럼 Edit|Write를 감시하는 Hook을 두세요. 자동 메모리를 꺼 두면(8편) memory 필드는 효과가 없습니다.
인라인 MCP는 폴더 신뢰가 필요합니다 프로젝트 .claude/agents/ 파일의 인라인 MCP 서버는 그 폴더를 신뢰한다고 승인한 뒤에만 연결됩니다. 상위 폴더의 신뢰나 -p 세션은 인정되지 않습니다. 프로젝트 서브에이전트의 frontmatter Hook도 같은 규칙입니다. 플러그인 서브에이전트는 보안상 hooks, mcpServers, permissionMode를 아예 쓸 수 없습니다.

무엇을 들고 시작하나

서브에이전트는 새 컨텍스트로 시작합니다. 여러분과 나눈 대화, 이미 부른 Skill, Claude가 읽은 파일을 보지 못합니다. Claude가 쓴 위임 메시지가 유일한 업무 지시입니다. 무엇이 전달되는지 비교해 보세요.

그래서: 중요한 규칙은 위임할 때 다시 말하세요 “vendor/ 폴더는 무시해”, “고객사 이름은 결과에 쓰지 마”처럼 서브에이전트가 반드시 지켜야 할 규칙은, CLAUDE.md에 있더라도 Explore·Plan이나 omitClaudeMd 서브에이전트에게는 전달되지 않습니다. 요청할 때 함께 적거나 서브에이전트 본문에 넣으세요. 서브에이전트는 질문을 할 수 없으니(5장) 필요한 정보는 처음에 다 줘야 합니다.
