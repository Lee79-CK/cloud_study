Terraform & Ansible 강의 · Level 5 통합·MSP 실전 · 26편 / 26편 (마지막 편) · 시리즈 목차

AI가 쓰고, 기계가 검사하고, 사람이 승인한다 AI 시대의 IaC와 커리어 로드맵 — Terraform MCP 서버·AI 코딩 어시스턴트로 모듈 작성·리뷰, 환각 방지 가드레일, 정책·테스트 자동 검증 루프, Ansible Lightspeed, 자격증 로드맵, 다음 학습 경로

AI 코딩 어시스턴트는 Terraform 모듈과 Ansible 플레이북을 몇 초 만에 써 냅니다. 문제는 그럴듯하다는 것입니다 — 존재하지 않는 리소스, 없는 속성, 오래된 문법, 안전하지 않은 기본값이 자신 있게 섞여 나옵니다. 이번 편은 그 출력을 믿지 않고도 빠르게 쓰는 방법을 다룹니다. 핵심은 이 시리즈 내내 만든 결정적 도구들(validate·tflint·trivy·OPA·terraform test·ansible-lint·Molecule)을 AI의 피드백 루프에 연결하는 것입니다. 흔한 환각을 일부러 넣은 초안을 관문에 통과시키며, 어느 관문이 무엇을 잡고 무엇은 끝까지 못 잡는지 실측합니다. 그리고 1~26편을 마친 엔지니어의 자격증·커리어 로드맵으로 시리즈를 마무리합니다.

1AI가 잘하는 것, 위험한 것

IaC는 “틀리면 바로 비용·장애·보안 사고”인 코드다

맡기기 좋은 일조건
초안 작성 (모듈 골격, 변수·출력, validation, README)저장소 규칙(AGENTS.md)과 기존 모듈을 문맥으로 주고, 관문 통과를 완료 조건으로
리팩터링 (count → for_each, moved 블록, 중복 제거)plan이 “No changes”(또는 기대한 변경만)여야 한다 — 9편 기준
테스트·정책 작성 (terraform test, rego, Molecule verify)테스트가 실패하는 경우도 만들어 보게 한다 — 24편처럼 테스트 자체가 틀릴 수 있다
리뷰 보조 (plan 요약, 위험한 변경 찾기, 비용 영향 설명)판단은 사람. plan JSON을 근거로 말하게 한다
오류 해석 (긴 오류 메시지·로그 정리)원문 오류를 함께 남긴다
위험한 일이유장치
apply·destroy·state 조작을 AI가 직접되돌리기 어려운 변경 (5·11·25편)권한 거부(8장), 적용은 CI·AWX만
보안 설정·정책 예외를 AI가 결정“일단 열어 두는” 초안이 흔하다(5장 실측: SSH 0.0.0.0/0)trivy·OPA 관문, 예외는 사람만
비밀을 문맥에 넣기대화·로그·학습 데이터로 새어 나갈 수 있다비밀은 저장소 밖(19편), 예시 값만
최신 기능·버전에 대한 답학습 시점 이후 정보가 없다 — 그럴듯하게 지어낸다MCP로 최신 문서, 스키마로 확인(2·6장)

2Terraform MCP 서버

AI에게 “기억”이 아니라 “지금의 레지스트리 문서”를 보게 한다

MCP(Model Context Protocol)는 AI 어시스턴트가 외부 도구·데이터를 호출하는 표준 방식입니다. HashiCorp의 Terraform MCP 서버는 Terraform 레지스트리(프로바이더 문서·모듈·정책)와 HCP Terraform/Enterprise API를 도구로 제공합니다. 어시스턴트가 “aws_s3_bucket의 암호화 설정은?”을 기억에 의존하지 않고 해당 버전의 문서를 가져와 쓰게 하는 것이 목적입니다.

도구 묶음 (toolset)주요 도구필요한 것
registry (공개 레지스트리)search_providers(1.3.1부터 search_provider_docs), get_provider_details, get_latest_provider_version, get_provider_capabilities, search_modules, get_module_details, get_latest_module_version, search_policies, get_policy_details없음 (공개 문서)
terraform (HCP Terraform·Enterprise, 비공개 레지스트리 포함)비공개 모듈·프로바이더, 워크스페이스·런(run)·변수·state 버전·팀(1.3.0의 whoami·list_teams 등)TFE_TOKEN, 조직 허용 목록
파괴적·변경 도구run 생성·적용, 팀 삭제 등ENABLE_TF_OPERATIONS=true일 때만 (기본 false)
.mcp.json — Claude Code 등에서 공개 레지스트리 도구만 (문서 기준, JSON 문법 검증)
{
  "mcpServers": {
    "terraform": {
      "command": "docker",
      "args": [
        "run", "-i", "--rm",
        "-e", "ENABLE_TF_OPERATIONS=false",
        "hashicorp/terraform-mcp-server:1.3.0",
        "--toolsets=registry"
      ]
    }
  }
}
안전 설정이유
--toolsets=registry필요한 도구만 노출 — 문서 조회만 필요하면 HCP 쪽 도구는 열지 않는다
ENABLE_TF_OPERATIONS=false (기본값 유지)AI가 run을 만들거나 적용하는 길을 막는다
이미지 태그 고정 (:1.3.0)도구 이름이 바뀐다 — 1.3.1(main)의 CHANGELOG에 search_providers → search_provider_docs 이름 변경이 “BREAKING”으로 적혀 있다. 20편 EE와 같은 원칙
토큰은 최소 권한·읽기 전용 팀 토큰1.2.0부터 조직 허용 목록(MCP_ORGANIZATION_ALLOWLIST)으로 다른 조직 호출을 막을 수 있다 — 25편 계정 가드와 같은 생각
MCP가 해 주지 않는 것

MCP는 정확한 문서를 가져다줄 뿐, AI가 그 문서대로 썼는지는 보장하지 않습니다. 문서를 읽고도 다른 버전의 속성을 섞거나, 요구사항과 다른 설계를 할 수 있습니다. 그래서 최종 판정은 다음 장들의 결정적 관문이 합니다.

3AI로 모듈 작성·리뷰

좋은 결과는 좋은 문맥과 분명한 완료 조건에서 나온다

AGENTS.md — 저장소에 두는 AI 규칙 (도구마다 CLAUDE.md·.github/copilot-instructions.md 등 이름만 다르다)
# AGENTS.md — 이 저장소에서 AI 코딩 어시스턴트가 지킬 규칙

## 반드시
- Terraform 리소스·속성·함수는 **추측하지 않는다**. 모르면 Terraform MCP 서버(get_provider_details)나
  `tools/schema_lookup.py <dir> <resource>.<attr>` 로 확인한 뒤 쓴다.
- 코드를 바꾼 뒤에는 `tools/ai_guard.sh <dir>` 를 실행하고, feedback.json 의 문제를 0건으로 만든 뒤에 끝낸다.
- Ansible 은 FQCN 만 쓴다. 바꾼 플레이북·역할은 `ansible-lint`(args 규칙 켬)와 `tools/arg_check.py` 를 통과해야 한다.
- 공통 모듈은 `git::…//modules/<이름>?ref=vX.Y.Z` 로만 참조한다(25편). 고객 저장소 안에서 모듈을 복사·수정하지 않는다.
- 프로바이더·컬렉션 버전은 저장소에 이미 고정된 범위를 따른다. 새 버전이 필요하면 이유를 PR 설명에 쓴다.

## 하지 않는다
- 비밀(키·비밀번호·토큰)을 코드·tfvars·출력·로그에 쓰지 않는다(19편). 예시 값은 `CHANGE_ME` 로.
- `provisioner "local-exec"`·`ansible_playbook` 리소스로 서버를 구성하지 않는다(23편).
- `terraform apply`·`destroy`·`state` 명령, `ansible-playbook`(check 없이)을 직접 실행하지 않는다. 적용은 CI·AWX 가 한다.
- 정책 예외(`policy-data/exceptions.yaml`, `.trivyignore.yaml`)를 추가하지 않는다. 필요하면 사람에게 요청한다.

4환각의 종류와 잡는 관문

환각을 누르면 어느 관문이 어떤 메시지로 잡았는지 실측 결과가 나옵니다

환각을 선택하세요

관문은 싸고 빠른 것부터: init(버전) → validate(스키마) → tflint(값) → trivy·OPA(보안·정책) → plan·test(실행) → 사람(의미). 앞 관문이 실패하면 뒤 관문은 돌지 않으므로, 루프를 여러 번 돌아야 한다(5장).

관문잡는 것못 잡는 것
init존재하지 않는 프로바이더·버전 제약버전은 있지만 그 버전에 없는 기능
validate (프로바이더 스키마)없는 리소스 타입·속성·함수, 타입 오류, 지원 중단 경고값의 유효성(인스턴스 타입 이름), 의미
tflint + 프로바이더 규칙잘못된 값(인스턴스 타입·엔진 버전 등), 사용하지 않는 선언보안 판단
trivy·checkov안전하지 않은 설정(공개 S3, 0.0.0.0/0 SSH, 암호화 없음)조직별 규칙
OPA(plan JSON)태그·환경별 규칙·삭제 금지(12편)규칙으로 쓰지 않은 것
plan·terraform test·apply(시험 계정)조건부 필수 인자, 리전·계정 의존 값, API 제약비즈니스 요구 위반
사람요구사항·설계·비용·운영 영향—

#   사용: ai_guard.sh <디렉터리>   → 사람이 읽는 요약(stdout) + feedback.json
#   종료 코드 0 = 모든 관문 통과
dir=${1:-.}; cd "$dir" || exit 2
fb=(); add(){ fb+=("$(jq -cn --arg g "$1" --arg l "$2" --arg m "$3" '{gate:$g,where:$l,msg:$m}')"); }
fmt_out=$(tofu fmt -check -list=true . 2>&1) || add fmt "$fmt_out" "terraform fmt 필요"

  add init "versions.tf" "$(echo "$init_out" | grep -A3 -m1 'Error:' | tr '\n' ' ' | sed 's/  */ /g')"
else
  tofu validate -json -no-color > .v.json 2>/dev/null
  jq -c '.diagnostics[] | select(.severity=="error")' .v.json > .vd
  while read -r d; do
    [ -z "$d" ] && continue
    add validate "$(echo "$d" | jq -r '"\(.range.filename // "?"):\(.range.start.line // "?")"')" "$(echo "$d" | jq -r '.summary + " — " + (.detail // "" | .[0:160])')"
  done < .vd
  # 지원 중단 경고도 피드백에 (AI 는 오래된 예제를 학습해 지원 중단 문법을 자주 쓴다)
  while read -r d; do
    [ -z "$d" ] && continue
    add deprecated "$(echo "$d" | jq -r '"\(.range.filename // "?"):\(.range.start.line // "?")"')" "$(echo "$d" | jq -r '.summary + " — " + (.detail // "" | .[0:160])')"
  done < <(jq -c '.diagnostics[] | select(.severity=="warning")' .v.json)
  if [ ! -s .vd ]; then
    tflint --format json > .tl.json 2>/dev/null
    while read -r d; do
      [ -z "$d" ] && continue
      add tflint "$(echo "$d" | jq -r '"\(.range.filename):\(.range.start.line)"')" "$(echo "$d" | jq -r '.rule.name + ": " + .message')"
    done < <(jq -c '.issues[]?' .tl.json)
    trivy config --skip-check-update --quiet --severity HIGH,CRITICAL --format json . > .tv.json 2>/dev/null
    while read -r d; do
      [ -z "$d" ] && continue
      add trivy "$(echo "$d" | jq -r '"\(.CauseMetadata.Resource // "?")"')" "$(echo "$d" | jq -r '.ID + " (" + .Severity + "): " + .Title')"
    done < <(jq -c '.Results[]?.Misconfigurations[]? | select(.Status=="FAIL")' .tv.json)
  fi
fi
printf '%s\n' "${fb[@]}" | jq -s '.' > feedback.json

6스키마를 기준으로

“이 속성이 있나?”의 정답은 AI의 기억도 블로그도 아니라 설치된 프로바이더의 스키마

tools/schema_lookup.py
#!/usr/bin/env python3
"""프로바이더 스키마로 '이 리소스에 이 속성이 있나'를 확인 — AI 가 의심스러운 속성을 쓸 때의 기준 자료
   사용: schema_lookup.py <terraform 디렉터리> aws_db_instance.multi_az_enabled"""
import json, subprocess, sys, difflib
d, q = sys.argv[1], sys.argv[2]
rtype, attr = q.split(".", 1)
s = json.loads(subprocess.run(["tofu", "providers", "schema", "-json"], cwd=d, capture_output=True, text=True).stdout)
for p in s["provider_schemas"].values():
    rs = p.get("resource_schemas", {})
    if rtype not in rs:
        near = difflib.get_close_matches(rtype, rs.keys(), n=3, cutoff=0.6)
        print(f"리소스 {rtype} 없음 — 비슷한 이름: {near}"); continue
    blk = rs[rtype]["block"]
    attrs = {**blk.get("attributes", {}), **{k: {"block": True} for k in blk.get("block_types", {})}}
    if attr in attrs:
        a = attrs[attr]
        flag = "블록" if a.get("block") else ("필수" if a.get("required") else "선택") + (" · 지원 중단" if a.get("deprecated") else "")
        print(f"{rtype}.{attr} 있음 ({flag}) — {(a.get('description') or '')[:100]}")
    else:
        print(f"{rtype}.{attr} 없음 — 비슷한 이름: {difflib.get_close_matches(attr, attrs.keys(), n=3, cutoff=0.5)}")
# 실측 (AWS 프로바이더 6.70)
aws_db_instance.multi_az_enabled 없음 — 비슷한 이름: ['multi_az', 'customer_owned_ip_enabled', 'publicly_accessible']
리소스 aws_s3_bucket_encryption 없음 — 비슷한 이름: ['aws_s3_bucket_notification', 'aws_s3_bucket_versioning', 'aws_s3_bucket_metric']
aws_instance.subnet_cidrs 없음 — 비슷한 이름: ['subnet_id', 'host_id']
aws_s3_bucket.versioning 있음 (블록)                         ← 있지만 지원 중단 (validate 경고, 5장)
aws_db_instance.manage_master_user_password 있음 (선택)

스키마는 “존재”에 대해서는 확실한 답을 주지만, 비슷한 이름 추천은 글자 유사도일 뿐입니다 — aws_s3_bucket_encryption의 실제 대체 리소스인 aws_s3_bucket_server_side_encryption_configuration은 추천에 나오지 않았습니다. 대체 방법은 문서(MCP의 get_provider_details, 프로바이더 업그레이드 가이드)로 확인합니다. 스키마 JSON(terraform providers schema -json)은 프로바이더 버전을 올릴 때 “어떤 속성이 사라지나”를 비교하는 데도 씁니다.

tools/arg_check.py — 인자·선택지·지원 중단을 모듈 문서와 대조 (21·22편 방식 확장)
#!/usr/bin/env python3
"""플레이북의 모듈 인자·선택지를 설치된 모듈 문서와 대조 (lint 가 놓치는 값까지)"""
import json, subprocess, sys, yaml
def doc(mod):
    r = subprocess.run(["ansible-doc", "-j", mod], capture_output=True, text=True)
    try:
        d = json.loads(r.stdout); return d[next(iter(d))]
    except Exception:
        return None
problems = []
for play in yaml.safe_load(open(sys.argv[1])):
    for t in play.get("tasks", []) + play.get("handlers", []):
        for k, v in t.items():
            if "." not in k or not isinstance(v, dict): continue
            d = doc(k)
            if d is None:
                problems.append(f"{t.get('name')}: 모듈 {k} 을(를) 찾을 수 없음"); continue
            if d.get("doc", {}).get("deprecated"):
                dep = d["doc"]["deprecated"]
                problems.append(f"{t.get('name')}: {k} 지원 중단 — {dep.get('why','')} → {dep.get('alternative','')}")
            opts = d["doc"].get("options", {})
            names = {a: n for n, o in opts.items() for a in [n] + (o.get("aliases") or [])}
            for arg, val in v.items():
                if arg not in names:
                    problems.append(f"{t.get('name')}: {k} 에 없는 인자 '{arg}'"); continue
                ch = opts[names[arg]].get("choices")
                if ch and isinstance(val, str) and "{{" not in val and val not in ch:
                    problems.append(f"{t.get('name')}: {k}.{arg} = '{val}' 은 허용값이 아님 {ch}")
print(f"문제 {len(problems)}건"); [print("  -", p) for p in problems]
sys.exit(1 if problems else 0)
ansible-lint 통과 ≠ 인자가 맞음 (실측)

ansible-lint의 args 규칙은 “실험(experimental)” 태그라 이 강의 프로젝트 설정(16편: warn_list: [experimental])에서는 보고조차 되지 않았고, 켜도 첫 번째 잘못된 인자만 보고하고 선택지 오류는 잡지 않았습니다. AI가 만든 Ansible 코드에는 ① args 규칙 켜기 ② 모듈 문서 대조 ③ 시험 서버 check 모드(24편 Molecule)까지 세 겹을 둡니다.
