스왑의 모든 것: 무엇을 지우고 무엇을 지킬까

스왑은 HTMX의 마지막 한 걸음이지만, 통합 포털에서는 가장 위험한 한 걸음이기도 합니다. 사용자가 입력 중이던 글자, React가 그려 둔 차트, 스크롤 위치, 포커스. 교체 한 번에 이것들이 사라질 수 있습니다. 이번 편은 hx-swap 수식어, OOB와 <hx-partial>, hx-select, 내장 모핑, hx-preserve, 전환 효과까지, "바꿀 것은 바꾸고 지킬 것은 지키는" 도구를 모두 다룹니다.

02

스왑의 생애

응답을 받은 뒤 화면이 바뀌기까지 htmx 4.0.1이 거치는 단계입니다. 소스의 swap()과 #insertContent()를 순서대로 따라 정리했습니다. 이 순서를 알면 이벤트를 어디에 걸지, CSS를 어느 클래스에 걸지가 분명해집니다.

1. 조각 만들기응답을 파싱. <hx-*> 태그를 <template hx type="*">로 바꾸고 <title> 추출
2. 작업 나누기OOB 요소, hx-partial, 본 스왑(main)을 각각 작업으로 분리
htmx:before:swap작업 목록 전달. preventDefault로 스왑 전체 취소 가능
3. 히스토리 갱신push/replace URL (7편)
htmx-swapping대상에 클래스 부착 → swap: 지연만큼 대기
4. 교체 실행hx-preserve 요소를 빼 두고 → 교체 → 다시 끼움. 포커스 복원
htmx:before:settle새 요소에 htmx-added 부착
htmx-settling같은 id 요소의 class·style 전환이 있을 때만 settle: 대기
htmx:after:settlehtmx-added 제거, 새 요소 htmx 처리, autofocus
5. 스크롤scroll: / show: 적용
htmx:after:swap모든 작업 완료 후. 그다음 문서 제목 갱신
htmx:finally:swap성공·실패와 무관하게 마지막

OOB·partial·본 스왑 작업은 동시에 진행됩니다(Promise.all). 단, 전환 효과(transition:true)가 걸린 작업은 View Transition 하나로 묶여 차례로 실행됩니다. 이벤트 이름은 4편에서 본 htmx:단계:동작 규칙을 따르며, 2.x의 htmx:beforeSwap·htmx:afterSettle는 각각 htmx:before:swap·htmx:after:settle입니다.

03

hx-swap 수식어 총정리

스왑 방식 뒤에 공백으로 수식어를 붙입니다. 4편의 트리거처럼 HCON으로 파싱되므로 키:값 형식이고, 공백이 든 값은 따옴표로 감쌉니다. 아래는 공식 레퍼런스(four.htmx.org)의 hx-swap 문서와 4.0.1 소스를 대조한 목록입니다.

수식어뜻기본값예
swap:응답 후 교체까지 지연0msinnerHTML swap:300ms (사라지는 애니메이션과 맞추기)
settle:교체 후 정착 단계까지 지연1ms (2.x는 20ms)settle:600ms
transition:View Transitions API 사용htmx.config.transitions (기본 false)outerHTML transition:true
scroll: + scrollTarget:교체 후 대상(또는 지정 요소)을 맨 위/아래로 스크롤-beforeend scroll:bottom, scroll:top scrollTarget:window
show: + showTarget:교체 후 대상(또는 지정 요소)이 보이게 scrollIntoViewboost 요청은 topshow:top showTarget:'closest .card', show:none
focusScroll:포커스 복원 시 그 요소로 스크롤할지htmx.config.defaultFocusScroll (false)focusScroll:true
target:hx-target 대신 여기서 대상 지정-innerHTML target:#results
strip:응답 최상위 요소의 껍데기를 벗기고 내용만 넣을지본 스왑: false / OOB 비outer 방식: truestrip:true
swapEmpty:OOB·partial을 뺀 뒤 본문이 비었을 때도 본 스왑을 할지부가 조각이 있으면 건너뜀outerHTML swapEmpty (9절 행 삭제)
ignoreTitle:응답의 <title>로 문서 제목을 바꾸지 않음false (바꿈)innerHTML ignoreTitle:true (5절 레거시)
2.x와 다른 표기

2.x의 show:#other:top, scroll:window:bottom처럼 콜론으로 대상과 위치를 이어 붙이던 표기는 4.x 문서에서 show:top showTarget:#other, scroll:bottom scrollTarget:window처럼 별도 수식어로 바뀌었습니다. focus-scroll:true는 focusScroll:true, 전역 설정 globalViewTransitions는 htmx.config.transitions입니다. 4.0.1 소스의 #handleScroll은 scrollTarget·showTarget만 읽습니다.

스왑 방식도 3편에서 다룬 것 외에 두 가지가 더 있습니다. outerSync는 대상의 속성만 모핑하고 자식은 교체해 대상 요소 자체는 남기는 방식이고(body에 outerHTML을 쓰면 자동으로 이 방식이 됨), upsert는 id가 같은 요소는 갱신하고 새 요소는 추가하는 방식으로 hx-upsert 확장이 필요합니다.

여러 곳 바꾸기: OOB와 hx-partial

응답 하나로 여러 곳을 바꾸는 방법은 두 가지입니다. 2.x부터 있던 hx-swap-oob 속성, 그리고 htmx 4에서 새로 생긴 <hx-partial> 태그. 아래 실험의 결과가 둘을 언제 쓸지 알려 줍니다.

OOB · hx-partial 실험실 (htmx 4.0.1 실동작)

원래 내용
#toast2 (OOB 대상)
#tb2 (표 본문)
기존 행
document.title
마지막 응답 원문

      

    

  


  
실험이 보여 주는 규칙

  

    
실험결과 (htmx 4.0.1)이유 (소스)

    
      
①토스트는 뜨고 #m2는 그대로OOB나 partial이 있으면 남은 본문이 비었을 때 본 스왑을 건너뜀 (allowEmptySwapAfterOOB 기본 false)

      
②토스트 + #m2가 비워짐swapEmpty가 위 판단을 덮어씀

      
③표에 행이 안 들어가고 #m2에 "OOB 행" 글자만 섞임응답 첫 요소가 <p>라 HTML 파서가 그 뒤의 <tr>·<td> 태그를 버림. 속성이 사라져 OOB로 인식 불가

      
④표에 행이 정상 추가<hx-partial>은 <template>으로 바뀌어 파싱되므로 안에 무엇이든 담을 수 있음

      
⑤ ⑥⑤는 문서 제목 변경, ⑥은 유지응답의 <title>은 스왑 후 document.title에 적용됨

    
  


  
OOB 값의 형식

  

    
값대상방식

    
      
hx-swap-oob="true"같은 id의 요소outerHTML

      
hx-swap-oob="innerHTML"같은 id의 요소innerHTML (껍데기 벗김)

      
hx-swap-oob="beforeend:#toasts"#toastsbeforeend (껍데기 벗김)

      
hx-swap-oob="innerHTML target:#x"#xHCON 형식, 수식어 추가 가능

    
  

  
outer 계열이 아니면 기본으로 OOB 요소의 껍데기를 벗기고 내용만 넣습니다(strip). 그래서 9절 토스트는 <div hx-swap-oob="beforeend:#toasts">로 감싼 안쪽의 <div class="toast">만 들어갑니다.

  

    
언제 무엇을 쓰나

    
<hx-partial hx-target hx-swap>은 "이 조각을 어디에 어떻게 넣는다"를 속성 두 개로 명확히 표현하고, 표 행처럼 아무 위치에나 오지 못하는 요소도 안전하게 실어 나릅니다. 새 코드에는 partial을 권합니다. OOB는 "응답 HTML의 요소 하나가 그대로 페이지의 같은 id 요소를 대체한다"는 표현이 자연스러울 때(예: 카운터 배지 하나를 통째로 교체), 그리고 2.x 서버 코드와 호환이 필요할 때 씁니다. 랩은 활동 기록에 partial을, 토스트에 OOB를 써서 둘 다 보여 줍니다.

  







  05
  
hx-select로 일부만 쓰기

  
응답이 전체 페이지인데 그중 일부만 필요할 때 hx-select로 고릅니다. 통합 포털에서 이 기능은 특별한 의미가 있습니다. htmx를 전혀 모르는 옛 시스템의 페이지를 고치지 않고도 포털에 붙일 수 있기 때문입니다.

  
views/pages/lab.eta (발췌)


<!-- 레거시 페이지의 <title>이 포털 제목을 바꾸지 않도록 ignoreTitle:true -->
<button hx-get="/legacy/notice" hx-select="#notice-body" hx-target="#legacy-slot"
        hx-swap="innerHTML ignoreTitle:true">공지 가져오기</button>

  
랩의 /legacy/notice는 2014년풍 레이아웃(메뉴, 표 레이아웃, 저작권 표시)을 가진 독립 페이지입니다. 포털은 그중 #notice-body만 가져옵니다. 2편 7절에서 본 대로 hx-select를 쓰는 요청은 HX-Request-Type: full을 보내므로, 서버 로그에도 GET /legacy/notice → 200 [htmx:full]로 찍힙니다.

  

    
랩에서 실제로 밟은 함정: 제목이 바뀐다

    
처음에는 ignoreTitle 없이 만들었는데, 테스트에서 공지를 가져오자 포털 탭 제목이 "랩 점검 · HTMX 포털 랩"에서 레거시 페이지의 "구 공지 시스템"으로 바뀌었습니다. htmx는 응답에 <title>이 있으면 hx-select와 무관하게 문서 제목을 갱신합니다. 전체 페이지를 응답하는 서버의 일부를 가져올 때는 ignoreTitle:true를 기본으로 붙이세요.

  

  
응답에서 여러 부분을 골라 각각 다른 곳에 넣는 hx-select-oob="#a, #b:afterbegin"도 있습니다. 쉼표로 구분한 선택자 각각을 OOB처럼 처리합니다. 15편에서 여러 팀의 기존 페이지를 하나의 포털 셸로 조합할 때 이 두 속성을 본격적으로 씁니다.







  06
  
모핑: 상태를 지키는 교체

  
innerHTML·outerHTML은 기존 요소를 버리고 새로 만듭니다. 모핑(innerMorph/outerMorph)은 기존 DOM과 새 HTML을 비교해 바뀐 부분만 고칩니다. 요소가 그대로 남으므로 그 요소에 붙어 있던 상태도 남습니다. 아래 비교기로 차이를 직접 확인하세요.


  

    
모핑 비교기 (htmx 4.0.1 실동작)
입력할 때마다 서버(0.45초 지연)가 폼 전체를 다시 그려 보냄

    

      
outerHTML
hx-trigger="input" hx-swap="outerHTML"
        

        

      

      
outerMorph
hx-trigger="input" hx-swap="outerMorph"
        

        

      

    

    
직접 빠르게 타이핑해 봐도 됩니다

  

  
자동 입력은 한 칸씩 차례로 포커스를 주고 0.1초 간격으로 열 글자를 입력합니다. 서버 응답(0.45초)이 타이핑보다 느리기 때문에 응답이 도착할 때마다 폼이 다시 그려집니다. outerHTML 쪽은 입력 요소가 새로 만들어지면서 요청을 보낸 시점의 값으로 되돌아가고, 그사이 친 글자가 사라집니다. 게다가 4편에서 본 기본 대기열(queue first)이 중간 요청을 버리므로 마지막 상태도 보장되지 않습니다. outerMorph 쪽은 포커스가 있는 입력의 값을 건드리지 않으므로 친 글자가 모두 남고, 오류 문구·렌더링 번호 같은 나머지 부분만 서버 내용으로 바뀝니다.


  
모핑은 무엇을 어떻게 맞추나 (4.0.1 소스)

  

    
규칙내용

    
      
짝 맞추기기존·새 트리의 id로 먼저 짝을 찾고(id가 중복되면 제외), 없으면 같은 태그끼리 순서대로 맞춤. 짝이 된 요소는 버리지 않고 속성과 자식만 고침

      
포커스된 입력<input>의 value 속성이 바뀌어도 그 입력이 현재 포커스 중이면 화면의 값(.value)은 덮어쓰지 않음. textarea도 포커스 중이면 유지

      
건너뛰기hx-morph-skip: 이 요소의 속성·자식 모두 건드리지 않음 / hx-morph-skip-children: 속성만 고치고 자식은 그대로 (전역 설정 morphSkip, morphSkipChildren)

      
무시할 속성htmx.config.morphIgnore(기본 ["data-htmx-powered"])에 적은 접두사의 속성은 비교하지 않음

      
hx 속성 변경모핑으로 hx-* 속성이 바뀐 요소는 htmx가 다시 초기화

    
  


  

    
통합 관점에서 모핑이 중요한 이유

    
모핑은 짝이 맞은 요소를 같은 DOM 노드로 유지합니다. React·Vue가 마운트된 컨테이너, 서드파티 위젯, 재생 중인 동영상처럼 "노드가 바뀌면 상태를 잃는 것"이 영역 안에 있을 때, 그 컨테이너에 id를 주고 hx-morph-skip을 달면 서버가 주변을 다시 그려도 그 안쪽은 손대지 않습니다. 다음 절의 hx-preserve와 함께 12편 아일랜드 생명주기의 기초가 됩니다. 2.x에서는 idiomorph 확장을 따로 설치해야 했지만 4.x는 내장입니다.

  

  
그렇다고 모든 스왑을 모핑으로 바꿀 필요는 없습니다. 비교 비용이 들고, 리스트 항목을 대량으로 바꾸는 경우엔 id 없이 순서로 맞추다 엉뚱한 요소를 재사용할 수 있습니다. 랩의 기준은 이렇습니다. 사용자가 입력 중일 수 있는 폼, 그리고 상태를 가진 요소가 섞인 영역은 모핑. 그 밖에는 innerHTML/outerHTML.







  07
  
hx-preserve: 요소 통째로 지키기

  
모핑이 "비교해서 고치기"라면 hx-preserve는 "아예 손대지 않기"입니다. id와 hx-preserve가 있는 요소는 스왑 직전에 따로 빼 두었다가, 새 HTML에서 같은 id 자리를 찾아 원래 노드를 그대로 다시 끼워 넣습니다. 응답에 담긴 그 요소의 새 내용은 버려집니다.

내부 동작: moveBefore

    
4.0.1은 보존 요소를 옮길 때 브라우저가 지원하면 Element.moveBefore()를, 아니면 insertBefore()를 씁니다. moveBefore는 노드를 옮기면서 iframe 로딩·포커스·애니메이션 같은 상태를 초기화하지 않는 비교적 새로운 DOM API입니다. 지원하지 않는 브라우저에서도 노드 자체는 같으므로 React·Vue의 JS 상태는 유지되지만, iframe은 다시 로드될 수 있습니다.

settle: 같은 id의 CSS 전환

  
htmx의 오래된 기법입니다. 새 HTML에 기존과 같은 id를 가진 요소가 있으면, 교체 직후 그 요소에 옛 class·style·width·height를 잠시 입혀 두었다가 settle 지연 뒤 새 값으로 돌려놓습니다. 그 사이 CSS transition이 동작해 값이 부드럽게 바뀝니다.

  

    
settle 전환 실험
응답: <div id="gbar" style="width:NN%">

    

    

  

  
같은 id 버튼은 막대가 미끄러지듯 늘고, id가 없는 버튼은 순간 이동합니다. 실측으로 확인한 내부 동작은 이렇습니다. 교체 직후 막대의 class·width가 옛 값(w1, 10px)이었다가 settle 뒤 새 값(w2, 200px)으로 바뀌었습니다.

  

    
htmx-added만으로는 페이드인이 안 된다 (실측)

    
.htmx-added { opacity: 0 } + transition: opacity로 새 요소를 페이드인하려는 예제를 흔히 봅니다. 4.0.1 소스는 settle 대기를 같은 id 요소의 전환 작업이 있을 때만 하므로, 그런 요소가 없으면 htmx-added가 붙자마자 같은 순간에 떨어집니다. 실제로 측정하니 30ms 시점에 불투명도가 이미 1이었습니다. 새로 들어온 요소를 부드럽게 보이게 하려면 CSS @keyframes 애니메이션을 쓰세요. 애니메이션은 요소가 문서에 들어가는 순간 시작되므로 htmx 타이밍과 무관하게 동작합니다. 랩의 #vm-body tr { animation: rowIn .35s }가 이 방식입니다.

  


  
View Transitions

  
transition:true를 붙이면 htmx가 스왑을 document.startViewTransition()으로 감싸 브라우저가 이전·이후 화면 사이를 애니메이션합니다. 지원하지 않는 브라우저에서는 그냥 교체합니다. 전후로 htmx:before:viewTransition·htmx:after:viewTransition 이벤트가 발생하며, 여러 전환 요청은 대기열로 하나씩 처리됩니다.

C. 행 삭제에 swapEmpty가 필요해진 이유

  
삭제 응답은 원래 빈 200이었습니다. 여기에 토스트(OOB)를 붙이자 본문은 여전히 비어 있지만 "부가 조각이 있으니 빈 본 스왑은 건너뛴다"는 규칙에 걸려 행이 지워지지 않았습니다. 테스트에서 swapEmpty를 뺀 버튼으로 삭제하니 실제로 행이 남았습니다. 그래서 삭제 버튼을 hx-swap="outerHTML swapEmpty"로 바꿨습니다. hx-swap="delete"도 같은 결과를 내지만, 서버가 409처럼 "삭제하지 않았다"는 응답을 줄 때도 행을 지워 버린다는 차이가 있습니다.

  
views/partials/vm-row.eta (발췌)


<button hx-post="/vms/<%= vm.name %>/restart" hx-target="closest tr" hx-swap="outerHTML transition:true"
        hx-disable="this">재시작</button>
...
<button hx-delete="/vms/<%= vm.name %>" hx-target="closest tr" hx-swap="outerHTML swapEmpty"
