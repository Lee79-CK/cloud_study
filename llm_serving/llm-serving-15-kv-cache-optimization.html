KV 캐시 최적화
프리픽스 캐싱·오프로딩·압축

14편에서 KV 공간이 동시성의 천장이라는 것을 확인했습니다. 그런데 KV는 공간 문제만이 아닙니다. 한 번 계산한 KV를 버리면 같은 앞부분을 다시 계산하느라 GPU와 TTFT를 씁니다. 이번 편은 KV를 다루는 세 가지 지렛대 — 재사용(프리픽스 캐시), 확장(CPU·SSD·원격으로 오프로딩), 축소(정밀도·구조로 압축) — 를 다루고, 멀티턴 대화와 에이전트처럼 문맥이 계속 자라는 워크로드에서 효과를 측정합니다.

01시작하기 전에

가장 싼 Prefill은 하지 않는 Prefill입니다.

학습 목표

  1. KV 캐시의 세 지렛대(재사용·확장·축소)가 각각 무엇을 아끼는지 설명할 수 있다.
  2. 프리픽스 캐시 적중률을 높이는 프롬프트 구성 규칙을 앱 팀에 제시할 수 있다.
  3. vLLM 프리픽스 캐시의 동작(블록 해시·축출·솔트)과 라우팅과의 관계를 설명할 수 있다.
  4. 네이티브 CPU 오프로딩·LMCache·스토리지 계층의 구조와 “불러오기가 재계산보다 빠른 조건”을 계산할 수 있다.
  5. FP8 KV와 구조적 압축(GQA·MLA·슬라이딩 윈도우)의 효과와 품질 위험을 설명할 수 있다.
  6. 멀티턴·에이전트 워크로드에서 캐시·오프로딩 효과를 턴별 TTFT와 적중률로 측정할 수 있다.
이 편의 비유: 도서관의 책 보관

KV 캐시는 이미 읽고 정리한 메모입니다. 책상(GPU 메모리)은 좁고 빠르고, 서고(CPU 메모리)는 넓고 조금 느리고, 지하 창고(SSD)는 더 넓고 더 느립니다. 메모를 버리면 책을 처음부터 다시 읽어야(재계산) 합니다. 좋은 사서는 자주 찾는 메모를 책상에, 가끔 찾는 메모를 서고에 두고(오프로딩), 메모를 압축해 적고(FP8), 같은 내용의 메모는 여러 사람이 함께 씁니다(프리픽스 공유). 그리고 무엇보다, 메모를 찾기 쉽게 책의 첫 장부터 같은 순서로 정리합니다(프롬프트 설계).

05KV 오프로딩: CPU·SSD·원격

GPU에서 밀려나는 KV를 버리지 않고 더 넓은 계층에 보관했다가, 그 세션·문서가 다시 오면 불러옵니다.

방식구조설정 (vLLM v0.31 기준)특징
vLLM 네이티브 CPU 오프로딩OffloadingConnector가 완성된 GPU KV 블록을 고정(pinned) CPU 메모리로 복사, 나중에 적중하면 다시 올림--kv-offloading-backend native --kv-offloading-size <GiB> (TP가 여러 장이면 전체 합계)외부 구성 요소 불필요. GPU→CPU 복사는 비동기라 캐시 미스의 TTFT에 거의 영향 없음
LMCache별도 캐시 엔진이 KV 커넥터로 붙어 CPU·로컬 디스크·원격 저장소 계층과 공유를 관리--kv-offloading-backend lmcache 또는 KV 전송 설정 + LMCache 설정여러 인스턴스 간 공유, 다양한 저장소. 별도 운영 대상

언제 오프로딩이 이기나

세션이 돌아왔을 때 그 KV를 불러오는 시간이 처음부터 다시 계산하는 시간보다 짧아야 합니다. 8B 모델·H100에서 토큰당 KV 144KiB, 연산 약 1,000TF(BF16 실효) 기준으로 대략 계산하면:

8,000토큰 재계산 ≈ 2 × 8.2e9 × 8,000 ÷ (1e15 × 0.5) ≈ 0.26초 8,000토큰 CPU에서 ≈ 8,000 × 144KiB ÷ 약 50GB/s ≈ 0.02초 8,000토큰 SSD에서 ≈ 8,000 × 144KiB ÷ 약 5GB/s ≈ 0.24초

CPU 계층은 거의 언제나 이기고, SSD 계층은 모델이 클수록(재계산이 비쌀수록)·문맥이 길수록 이깁니다. 이 숫자는 장비와 모델에 따라 크게 달라지므로 실측해야 합니다(실습 15-4).

GB10에서의 CPU 오프로딩

GB10은 CPU와 GPU가 같은 메모리를 씁니다. “CPU로 오프로딩”해도 같은 128GB 안의 다른 영역으로 옮길 뿐이라, 데이터센터 GPU처럼 “GPU 메모리 밖의 넓은 공간”을 얻는 효과는 없습니다. 메모리 예산(8편) 안에서라면 오프로딩 버퍼를 따로 두는 것보다 KV 공간 자체를 키우는 것이 대체로 단순하고 빠릅니다. GB10에서 의미 있는 확장 계층은 SSD(또는 원격)입니다. 실습 15-4는 이 차이를 확인하는 것을 목표로 합니다.

  • 모델 구조 제약: 오프로딩·일부 계층은 표준 어텐션(MHA·GQA) 모델에서 가장 잘 동작하고, MLA·슬라이딩 윈도우·하이브리드 모델은 지원이 제한되거나 추가 옵션이 필요할 수 있습니다. 모델별로 문서를 확인합니다.
  • 라우팅과의 연결: 엔진이 CPU 계층의 블록도 KV 이벤트로 알리면, 캐시 인지 라우터(10·11편, Dynamo)가 “CPU에 있는 프리픽스”도 적중으로 계산할 수 있습니다. 이 연결이 없으면 라우터는 오프로딩된 프리픽스를 미스로 봅니다.

07멀티턴·에이전트 워크로드

문맥이 턴마다 자라는 워크로드는 KV 재사용의 효과가 가장 크고, 잘못 다루면 비용이 가장 빨리 커지는 곳입니다.

패턴KV 관점의 특징대응
긴 대화 (상담·코딩)턴 n의 입력 = 턴 n−1까지 전체 + 새 질문. 캐시가 맞으면 새 부분만 Prefill세션 친화 라우팅(11편), 앞부분을 바꾸지 않는 대화 관리
에이전트 루프툴 호출 결과가 계속 덧붙고, 같은 시스템·도구 정의가 매 호출 반복도구 정의 고정 순서, 툴 결과는 덧붙이기만
사용자의 휴지 시간사용자가 몇 분 뒤 돌아오면 그사이 다른 세션이 GPU KV를 밀어냄CPU·SSD 오프로딩으로 “돌아온 세션” 재계산 방지

09보안과 격리

재사용은 공유이고, 공유는 격리 문제를 낳습니다.

  • 타이밍 부채널: 공용 엔진에서 응답 속도 차이로 “다른 사용자가 같은 앞부분을 보냈는지” 추정할 여지가 있습니다. 테넌트별 cache_salt를 게이트웨이가 강제 주입합니다(4·12편). 같은 테넌트 안에서는 공유 이득을 그대로 얻습니다.
  • 해시 충돌: 다른 내용이 같은 해시를 가지면 엉뚱한 KV를 재사용할 수 있습니다. 멀티테넌트에서는 강한 해시 알고리즘을 선택합니다.
  • 오프로딩된 KV는 데이터다: CPU·SSD·원격 저장소에 내려간 KV는 프롬프트 내용을 복원할 단서가 될 수 있는 사용자 데이터입니다. 디스크 계층은 암호화·접근 통제·삭제 정책(보존 기간)을 적용하고, 공유 저장소라면 테넌트별 분리를 확인합니다.
  • 데이터 정책과의 충돌: 고객 데이터의 저장 금지 계약이 있다면, 디스크·원격 KV 계층 사용이 “저장”에 해당하는지 검토합니다.

10MSP 관점

캐시는 원가를 낮추고, 그 절감을 가격에 반영할 수 있게 해 줍니다.

  • 캐시된 입력 토큰 가격: 외부 공급자들이 프롬프트 캐시 적중 토큰을 할인하듯, 셀프호스팅 서비스도 “캐시 적중 입력”의 내부 단가를 낮게 잡아 원가 배분과 가격에 반영할 수 있습니다(12편 과금).
  • 앱 팀 가이드: 3장의 프롬프트 설계 규칙을 고객 개발 가이드에 넣으면, 같은 GPU로 더 많은 요청을 받을 수 있습니다. 적중률 리포트를 고객에게 정기 제공하면 개선 효과가 보입니다.
  • 용량 계획: 오프로딩 계층은 GPU를 늘리지 않고 “돌아오는 세션”을 더 많이 수용하는 수단입니다. 단, GB10 같은 통합 메모리 장비에서는 효과가 다르므로 장비별로 측정합니다.

실습 15-1 · 프리픽스 캐시 지표 읽기

python · cache_stats.py (50-tools/scripts에 추가)
"""엔진 /metrics에서 프리픽스 캐시 조회·적중 카운터를 읽는다. 다른 스크립트에서 import해 전후 차이를 계산."""
import re, urllib.request
def read(base="http://llm-engine:8000"):
    txt = urllib.request.urlopen(base + "/metrics", timeout=10).read().decode()
    q = h = 0.0
    for line in txt.splitlines():
        if line.startswith("#") or "prefix_cache" not in line: continue
        name, val = line.split("{")[0].split(" ")[0], float(line.rsplit(" ", 1)[1])
        if re.search(r"prefix_cache_queries", name): q += val
        elif re.search(r"prefix_cache_hits", name): h += val
    return q, h
if __name__ == "__main__":
    q, h = read(); print(f"조회 {q:.0f} 토큰, 적중 {h:.0f} 토큰, 적중률 {h / q * 100 if q else 0:.1f}%")

실습 15-2 · 프롬프트 배치 실험

python · prefix_layout.py
"""같은 내용을 두 배치로 보낸다. A: 맨 앞에 초 단위 시각 / B: 고정 내용 먼저, 시각은 마지막.
사용: python prefix_layout.py A|B [요청 수]"""
import sys, time, random, statistics, datetime
sys.path.insert(0, "/scripts")
import cache_stats
from openai import OpenAI
mode, n = sys.argv[1], int(sys.argv[2]) if len(sys.argv) > 2 else 30
cli = OpenAI(base_url="http://llm-engine:8000/v1", api_key="EMPTY")
W = "노드 파드 쿼터 지연 처리량 메모리 대역폭 캐시 배치 스케줄러 게이트웨이 장애 알림 예산".split()
r = random.Random(1)
SYSTEM = "너는 사내 인프라 상담봇이다. 운영 규정: " + " ".join(r.choice(W) for _ in range(1200))
q0, h0 = cache_stats.read(); ttfts = []
for i in range(n):
    now = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S.%f")
    user = f"사용자{i}"
    q = f"{user}의 질문 {i}: 장애 알림 정책을 한 줄로."
    if mode == "A":
        msgs = [{"role": "system", "content": f"현재 시각: {now}\n" + SYSTEM}, {"role": "user", "content": q}]
    else:
        msgs = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": f"(요청 시각 {now}) {q}"}]
    t0 = time.perf_counter()
    s = cli.chat.completions.create(model="qwen3-8b", messages=msgs, max_tokens=8, stream=True,
                                    extra_body={"chat_template_kwargs": {"enable_thinking": False}})
    for ev in s:
        if ev.choices and ev.choices[0].delta.content:
            ttfts.append((time.perf_counter() - t0) * 1000); break
    for _ in s: pass
q1, h1 = cache_stats.read()
print(f"배치 {mode}: TTFT 중앙값 {statistics.median(ttfts):.0f} ms, 이번 실험 적중률 {(h1 - h0) / max(q1 - q0, 1) * 100:.1f}%")

실습 15-3 · 멀티턴 세션 벤치마크

python · session_bench.py
"""여러 세션이 번갈아 대화를 이어 가며 턴별 TTFT를 잰다. 사용자의 휴지 시간(think)을 두면 그사이 다른 세션이 KV를 밀어낸다.
사용: python session_bench.py --label X [--sessions 20 --turns 6 --think 5 --sys-words 800]"""
import argparse, asyncio, json, random, statistics, time, sys
sys.path.insert(0, "/scripts")
import cache_stats
from openai import AsyncOpenAI
ap = argparse.ArgumentParser()
ap.add_argument("--label", required=True); ap.add_argument("--sessions", type=int, default=20)
ap.add_argument("--turns", type=int, default=6); ap.add_argument("--think", type=float, default=5)
ap.add_argument("--sys-words", type=int, default=800); ap.add_argument("--q-words", type=int, default=150)
a = ap.parse_args()
cli = AsyncOpenAI(base_url="http://llm-engine:8000/v1", api_key="EMPTY", timeout=600)
W = "노드 파드 쿼터 지연 처리량 메모리 대역폭 캐시 배치 스케줄러 게이트웨이 장애 알림 예산 토큰".split()
by_turn = {t: [] for t in range(a.turns)}

async def session(sid):
    r = random.Random(sid)
    hist = [{"role": "system", "content": f"[세션 {sid} 전용 자료] " + " ".join(r.choice(W) for _ in range(a.sys_words))}]
    await asyncio.sleep(r.random() * 2)
    for t in range(a.turns):
        hist.append({"role": "user", "content": f"턴 {t}: " + " ".join(r.choice(W) for _ in range(a.q_words)) + " 요약해 줘."})
        t0 = time.perf_counter(); first = None; out = []
        s = await cli.chat.completions.create(model="qwen3-8b", messages=hist, max_tokens=64, stream=True,
                                              extra_body={"chat_template_kwargs": {"enable_thinking": False}})
        async for ev in s:
            if ev.choices and ev.choices[0].delta.content:
                first = first or time.perf_counter(); out.append(ev.choices[0].delta.content)
        by_turn[t].append((first - t0) * 1000)
        hist.append({"role": "assistant", "content": "".join(out)})   # 대화는 덧붙이기만
        await asyncio.sleep(r.expovariate(1 / a.think) if a.think else 0)

async def main():
    q0, h0 = cache_stats.read()
    await asyncio.gather(*[session(i) for i in range(a.sessions)])
    q1, h1 = cache_stats.read()
    row = {"label": a.label, "hit_rate": (h1 - h0) / max(q1 - q0, 1),
           "ttft_median_by_turn": [round(statistics.median(v)) for v in by_turn.values()]}
    print(json.dumps(row, ensure_ascii=False))
    open("/results/session.jsonl", "a").write(json.dumps(row, ensure_ascii=False) + "\n")
asyncio.run(main())

실습 15-4 · KV를 모자라게 만들고 오프로딩 비교

KV 공간을 일부러 작게 고정해 세션들이 서로의 KV를 밀어내게 만든 뒤, 세 구성을 비교합니다. kv-cache-memory-bytes로 KV 크기를 직접 지정합니다.

9문제.

15정리와 체크리스트

핵심 여섯 문장.

  1. KV의 세 지렛대: 재사용·확장·축소. 가장 싼 Prefill은 하지 않는 Prefill이다.
  2. 프리픽스 캐시는 앞에서부터 똑같은 부분만 재사용한다. 고정된 것을 앞에, 바뀌는 것을 뒤에, 순서는 결정적으로.
  3. 캐시는 레플리카마다 따로라 캐시 인지 라우팅과 함께여야 효과가 난다. 테넌트 격리는 cache_salt로.
  4. 오프로딩은 “불러오기가 재계산보다 빠를 때” 이긴다. CPU 계층은 대개 이기고, SSD는 큰 모델·긴 문맥에서 이긴다. GB10은 통합 메모리라 CPU 계층의 의미가 다르다.
  5. 압축의 우선순위는 FP8 KV이며 품질 회귀로 확인한다. 구조적 압축은 모델 선택의 문제다.
  6. 효과는 적중률과 턴별 TTFT로 증명하고, 오프로딩된 KV는 사용자 데이터로 취급한다.
