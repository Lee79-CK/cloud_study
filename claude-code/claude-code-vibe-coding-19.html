claude -p 기초

-p(--print)를 붙이면 대화 화면 없이 한 번 실행하고 결과를 출력한 뒤 끝납니다. 공식 문서는 이것을 CLI로 쓰는 Agent SDK라고 부릅니다(23편에서 Python·TypeScript SDK).

알아둘 것내용
종료 코드성공 0, 실패는 0이 아님. 잘못된 플래그는 실행 전 stderr로. 인증 실패처럼 실행 중 실패는 stdout의 결과로 나옴
파이프 입력cat build-error.txt | claude -p '원인을 짧게'. stdin은 10MB 상한, 넘으면 파일 경로를 주세요
--output-formattext(기본) · json(result, session_id, 메타데이터) · stream-json(한 줄에 이벤트 하나)
비용json 출력에 total_cost_usd와 모델별 내역. 클라이언트 추정치라 실제 청구와 다를 수 있음
--json-schema스키마에 맞춘 결과가 structured_output에. Claude가 거절하는 등 실패하면 필드가 없으므로 쓰기 전에 확인
이어서--continue(최근 대화), --resume <session_id>. 이어 하면 비용은 대화 전체 누적
Skill프롬프트에 /skill-이름을 넣으면 실행됨. /login처럼 화면 전용 명령은 안 됨
# 결과 텍스트만 claude -p "이 프로젝트를 요약해" --output-format json | jq -r '.result' # 스키마로 받은 값만 (없으면 null 이 나오니 꼭 검사) claude -p "auth.py 의 함수 이름" --output-format json \ --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}' \ | jq '.structured_output'

--bare: 같은 결과를 어디서나

--bare는 Hook, Skill, 사용자 명령, 서브에이전트, 플러그인, MCP 서버, 자동 메모리, CLAUDE.md의 자동 탐색을 모두 건너뜁니다. 공식 문서는 스크립트·SDK 호출에 이것을 권장하며, 앞으로 -p의 기본값이 될 예정이라고 밝힙니다.

--bare 없이

  • 작업 폴더와 ~/.claude의 설정을 대화 세션처럼 모두 읽음
  • 신뢰하지 않은 폴더라도 프로젝트 .claude/settings.json의 Hook이 돌고 .mcp.json 서버가 연결됨. 신뢰 창도 서버 승인 창도 없음(9·11·12편)
  • 팀원 PC마다 결과가 달라질 수 있음

--bare로

  • Bash·파일 읽기·편집 도구만
  • 필요한 것만 플래그로 넣음: --append-system-prompt-file, --settings, --mcp-config, --agents, --plugin-dir
  • 백그라운드 명령·서브에이전트를 못 씀, 시스템 리마인더 없음
  • 구독 로그인을 쓰지 않음: ANTHROPIC_API_KEY 또는 --settings의 apiKeyHelper 필요(Bedrock 등은 각자의 자격 증명)
--bare 에서 CLAUDE.md 를 쓰고 싶다면 자동으로 읽지 않으니 --append-system-prompt-file CLAUDE.md로 직접 넘깁니다. 실습의 daily_report.sh가 이 방식이고, CLAUDE.md가 없을 때는 플래그를 빼도록 짰습니다(둘 다 시험함).

무인 실행의 권한

승인 버튼을 누를 사람이 없습니다. 최신 버전의 -p는 아무것도 정하지 않으면 Manual 모드로 시작하고, 승인이 필요한 호출은 거부됩니다. 무엇을 미리 허용할지가 곧 설계입니다.

설정효과무인 실행에서
--allowedTools "Read,Grep,Bash(git log *)"나열한 것은 묻지 않고 실행. 9편 규칙 문법(* 앞의 공백 주의: Bash(git diff*)는 git diff-index도 허용)필수. 좁게
--permission-mode dontAsk물어야 할 호출은 모두 거부. 읽기 전용 명령·허용 규칙은 실행. 잠근 CI용권장
--permission-mode acceptEdits파일 쓰기와 mkdir·mv 등은 자동. 그 밖의 명령은 허용 필요수정 작업에만
--permission-mode auto분류기가 대부분의 행동을 검토(3편 차단 목록)범위가 넓은 작업에. 이때 맨 Bash 허용은 무시되고 명령마다 평가
--permission-prompts none물어볼 곳이 있어도 기다리지 않고 거부, 재시도하지 말라고 알림SDK 앱·승인 도구가 있는 무인 실행
--dangerously-skip-permissions모든 확인을 건너뜀쓰지 마세요. 격리된 일회용 컨테이너가 아니면 금지
허용 목록은 “최소 + 읽기 위주”로 보고서는 읽기만 하면 됩니다. 실습의 허용 목록은 Read,Grep,Glob,Bash(git log *),Bash(python3 -m unittest *)뿐이고, Edit·Write는 없습니다. 이 사실을 테스트(test_safety_flags)로 고정해, 누군가 나중에 넓히면 테스트가 실패하게 했습니다. 9편 deny 규칙과 11편 guard Hook은 --bare에서는 자동으로 안 읽히니, 필요하면 --settings로 넘깁니다.
5 / 15

상한 걸기

--max-turns 15

에이전틱 턴 수 상한. 도달하면 오류로 끝납니다. 기본은 무제한.

--max-budget-usd 1.00

비용 상한. 도달하면 남은 백그라운드 작업도 멈춥니다. 추정치 기준이니 여유 있게.

timeout 900 claude …

시계 시간 상한은 바깥에서. 실습에서 가짜 claude가 멈추면 timeout이 124로 끊고 스크립트가 1로 끝나는 것을 확인했습니다.

멈출 때의 신호

SIGTERM이면 종료 코드 143, 진행 중이던 턴은 결과 없이 끝납니다. 턴을 정리하고 끝내려면 SIGINT를 먼저.

백그라운드 작업 대기

Claude가 띄운 백그라운드 작업이 있으면 -p는 끝나기 전에 기다립니다. 한가한 대기는 기본 10분 상한(CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS). --bare에선 백그라운드 작업 자체가 없습니다.

사용량 추적

json의 total_cost_usd를 매번 기록하면 이상 징후가 보입니다. 실습 보고서 끝에 추정 비용을 적습니다(20편에서 비용 관리).

실패를 실패로 알리기

무인 실행의 가장 큰 위험은 조용한 실패입니다(16편 백업이 그랬습니다). daily_report.sh는 상황마다 다른 종료 코드를 내고, cron·CI는 0이 아니면 알림을 보냅니다. 아래 결과는 가짜 claude로 실제로 돌린 것입니다.

📄 scripts/daily_report.sh
#!/bin/bash # 매일 아침 acme-ops-legacy 상태 보고서를 만든다. 사람이 지켜보지 않는 실행이다. # 종료 코드: 0 정상(ok/warn) · 1 claude 실행 실패 · 2 구조화 출력 없음 · 3 상태 fail set -euo pipefail cd "$(dirname "$0")/.." OUT_DIR=${REPORT_DIR:-reports} mkdir -p "$OUT_DIR" DAY=$(date +%F) RAW="$OUT_DIR/$DAY.json" SCHEMA='{"type":"object","properties":{"status":{"type":"string","enum":["ok","warn","fail"]},"summary":{"type":"string"},"findings":{"type":"array","items":{"type":"object","properties":{"file":{"type":"string"},"issue":{"type":"string"},"severity":{"type":"string","enum":["high","medium","low"]}},"required":["file","issue","severity"]}}},"required":["status","summary","findings"]}' PROMPT='오늘의 acme-ops-legacy 상태를 점검해. 1) python3 -m unittest discover -s tests -t tests 결과 2) 최근 24시간 git log 3) docs/RISKS.md 의 남은 과제 파일은 고치지 말고, 확인하지 못한 것은 summary 에 “미확인”으로 적어.' # --bare 는 CLAUDE.md 를 읽지 않으므로, 있으면 직접 넘긴다 EXTRA=() [ -f CLAUDE.md ] && EXTRA+=(--append-system-prompt-file CLAUDE.md) set +e timeout "${CLAUDE_TIMEOUT:-900}" claude --bare -p "$PROMPT" "${EXTRA[@]}" \ --allowedTools "Read,Grep,Glob,Bash(git log *),Bash(python3 -m unittest *)" \ --permission-mode dontAsk \ --max-turns 15 \ --max-budget-usd "${CLAUDE_BUDGET_USD:-1.00}" \ --output-format json \ --json-schema "$SCHEMA" > "$RAW" rc=$? set -e if [ "$rc" -ne 0 ]; then echo "claude 실행 실패 (종료 코드 $rc). 원본: $RAW" >&2 exit 1 fi python3 - "$RAW" "$OUT_DIR/$DAY.md" << 'PY' import json, sys raw, md = sys.argv[1], sys.argv[2] d = json.load(open(raw, encoding="utf-8")) s = d.get("structured_output") if not s: print("구조화 출력이 없습니다: " + str(d.get("result", ""))[:200], file=sys.stderr) sys.exit(2) icon = {"ok": "🟢", "warn": "🟡", "fail": "🔴"}[s["status"]] lines = [f"# {icon} acme-ops-legacy 일일 점검", "", s["summary"], ""] for f in s["findings"]: lines.append(f"- [{f['severity']}] {f['file']}: {f['issue']}") cost = d.get("total_cost_usd") if cost is not None: lines += ["", f"_추정 비용: ${cost:.4f} (클라이언트 추정치)_"] open(md, "w", encoding="utf-8").write("\n".join(lines) + "\n") print(f"{s['status']} {md}") sys.exit(3 if s["status"] == "fail" else 0) PY
📄 tests/test_daily_report.py (가짜 claude로 6가지 경우 시험)
"""daily_report.sh 를 가짜 claude 로 시험한다. 진짜 claude 는 부르지 않는다.""" import json, os, subprocess, tempfile, unittest from pathlib import Path ROOT = Path(__file__).resolve().parent.parent FAKE = r'''#!/bin/bash echo "$@" > "$FAKE_ARGS" case "$FAKE_MODE" in ok) echo '{"result":"done","total_cost_usd":0.01,"structured_output":{"status":"warn","summary":"요약","findings":[{"file":"docs/RISKS.md","issue":"남은 과제","severity":"high"}]}}' ;; fail) echo '{"result":"x","structured_output":{"status":"fail","summary":"테스트 실패","findings":[]}}' ;; nostruct) echo '{"result":"거절"}' ;; crash) echo "Error: authentication failed"; exit 1 ;; hang) sleep 5 ;; esac ''' class DailyReportTest(unittest.TestCase): def run_mode(self, mode, **extra): tmp = tempfile.TemporaryDirectory(); self.addCleanup(tmp.cleanup) d = Path(tmp.name); (d / "bin").mkdir() fake = d / "bin" / "claude"; fake.write_text(FAKE); fake.chmod(0o755) env = dict(os.environ, PATH=f"{d/'bin'}:{os.environ['PATH']}", FAKE_MODE=mode, FAKE_ARGS=str(d / "args.txt"), REPORT_DIR=str(d / "reports"), **extra) r = subprocess.run(["bash", str(ROOT / "scripts/daily_report.sh")], env=env, capture_output=True, text=True, cwd=ROOT) args = (d / "args.txt").read_text() if (d / "args.txt").exists() else "" return r, args, d / "reports" def test_ok_writes_report(self): r, _, rep = self.run_mode("ok") self.assertEqual(r.returncode, 0, r.stderr) self.assertIn("[high] docs/RISKS.md", next(rep.glob("*.md")).read_text()) def test_status_fail_exits_3(self): self.assertEqual(self.run_mode("fail")[0].returncode, 3) def test_missing_structured_output_exits_2(self): self.assertEqual(self.run_mode("nostruct")[0].returncode, 2) def test_claude_error_exits_1(self): self.assertEqual(self.run_mode("crash")[0].returncode, 1) def test_timeout_exits_1(self): self.assertEqual(self.run_mode("hang", CLAUDE_TIMEOUT="1")[0].returncode, 1) def test_safety_flags(self): _, args, _ = self.run_mode("ok") for flag in ["--bare", "--permission-mode dontAsk", "--max-turns", "--max-budget-usd", "--json-schema"]: self.assertIn(flag, args) self.assertNotIn("dangerously", args) self.assertNotIn("Edit", args.split("--allowedTools")[1].split("--")[0]) if __name__ == "__main__": unittest.main()

세션 안에서만

Claude Code가 켜져 있고 한가할 때만 실행됩니다. 터미널을 닫으면 멈춥니다. /bg로 백그라운드 세션에 넘기면 터미널 없이 이어집니다(14편).

7일 만료

반복 작업은 만든 지 7일 뒤 마지막으로 한 번 실행하고 스스로 지워집니다. 잊힌 루프가 영원히 도는 것을 막습니다.

지연(jitter)과 시간대

정각에 몰리지 않게 반복 작업은 최대 30분(한 시간보다 잦으면 간격의 절반까지) 늦게 실행될 수 있습니다. 시간은 여러분의 로컬 시간대입니다. GitHub Actions cron은 UTC라는 점과 다릅니다.

스킬도 돌릴 수 있지만

/loop 20m /review-pr 1234처럼. 단 Claude가 스스로 부를 수 있는 Skill만 실행됩니다. 번들 /verify처럼 disable-model-invocation인 것은 글자로만 전달됩니다.

멈추기·관리

스스로 간격을 고르는 루프는 대기 중 Esc. 그 밖엔 “예약된 작업 보여줘”, “배포 확인 작업 취소해”. 한 세션에 최대 50개.

모두 끄기

CLAUDE_CODE_DISABLE_CRON=1이면 스케줄러와 /loop가 사라집니다.

# .claude/loop.md — 이 저장소에서 /loop 만 쳤을 때의 기본 프롬프트 현재 브랜치의 PR 을 확인해. CI 가 실패했으면 실패 로그를 요약하고 원인 파일을 짚어(고치지는 마). 새 리뷰 코멘트가 있으면 반영/질문/반대로 분류해서 알려줘. 모두 초록이고 조용하면 한 줄로 그렇다고 말해.

클라우드 Routines

Routines는 Anthropic이 관리하는 클라우드에서 도는 Claude Code 세션입니다. 노트북을 닫아도 돌아갑니다. 리서치 프리뷰라 동작과 한도가 바뀔 수 있습니다. Pro·Max·Team·Enterprise에서 Claude Code on the web이 켜져 있어야 하고, claude.ai/code/routines나 데스크톱 앱, CLI의 /schedule에서 만듭니다.

트리거 세 가지

일정(매시·매일·평일·매주·한 번), API(전용 URL에 토큰으로 POST), GitHub 이벤트(PR 열림, 머지 등). 함께 걸 수 있습니다. CLI의 /schedule은 일정만 만들고, API·GitHub 트리거는 웹에서.

관리

/schedule list, /schedule update, /schedule run(지금 실행).

승인 창이 없습니다

Routines는 권한 모드 선택도 승인 프롬프트도 없이 자율적으로 돕니다. 할 수 있는 일은 고른 저장소와 브랜치 push 설정, 환경의 네트워크·변수, 포함한 커넥터가 정합니다. 여기서 권한을 좁히세요.

MSP: 무엇이 클라우드로 가나

저장소를 새로 클론해 클라우드에서 실행합니다. 고객사 코드·자격 증명을 외부 클라우드에서 다뤄도 되는지 계약과 회사 정책을 먼저 확인하세요. 운영 자격 증명은 넣지 않는 것이 기본입니다.

Team·Enterprise 관리자는 관리 설정에서 Routines를 조직 전체에 끌 수 있고, 끄면 기존 Routines도 멈춥니다(24편).
