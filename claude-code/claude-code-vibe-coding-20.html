무엇에 사용량이 드나

Claude Code는 토큰으로 계산됩니다. 그리고 공식 문서의 한 문장이 거의 모든 것을 설명합니다: 토큰 비용은 컨텍스트 크기를 따라간다. Claude Code는 요청마다 대화 전체를 보내고, Claude가 도구를 쓸 때마다 그 결과를 실은 요청을 또 보냅니다. 하루 종일 열어 둔 세션에서 한 줄 질문을 해도 대화 전체만큼의 사용량이 듭니다(캐시 덕분에 싼 값으로).

공식 문서의 기준선

기업 배포 평균은 활동일 기준 개발자당 약 $13, 월 $150~250, 사용자의 90%는 활동일당 $30 미만. 팀마다 크게 다르니 작은 시범 그룹으로 기준선을 먼저 재라고 권합니다.

생각도 출력이다

확장 사고(thinking) 토큰은 출력 토큰으로 계산됩니다. 기본 예산이 요청당 수만 토큰일 수 있습니다.

서브에이전트도 요청을 보낸다

13편에서 본 것처럼 요약만 돌아오지만, 서브에이전트 자신의 요청은 사용량에 잡힙니다.

가만히 있어도 조금

이어 열기용 대화 요약 같은 백그라운드 작업이 세션당 보통 $0.04 미만을 씁니다. 다음 프롬프트 제안도 짧은 요청을 보냅니다(캐시 재사용).

줄이는 레버

① 작업 사이에 /clear

관계없는 일로 넘어갈 때. 남은 맥락은 이후 모든 메시지에서 낭비됩니다. 나중에 찾으려면 먼저 /rename, 돌아갈 땐 /resume(6편). /clear는 비용이 0, /compact는 큰 대화를 읽으므로 그 자체가 큰 요청입니다.

② 압축할 때 지시하기

/compact 테스트 결과와 코드 변경 위주로. CLAUDE.md에 “# Compact instructions” 절을 둘 수도 있습니다.

③ 모델 맞추기

대부분의 코딩은 Sonnet, 복잡한 설계·여러 단계 추론은 Opus. 세션 모델을 Opus로 바꾸면 상속받는 서브에이전트도 Opus가 됩니다. 단순한 서브에이전트는 model: haiku(13편).

④ effort 낮추기

단순한 일엔 /effort를 낮춥니다. Opus 5.5·Sonnet 5.5·Haiku 5.5·Fable은 생각을 끌 수 없어 effort가 레버입니다. 고정 예산 모델은 MAX_THINKING_TOKENS도.

⑤ CLAUDE.md는 200줄 이하

매 세션 통째로 들어갑니다. PR 리뷰 절차 같은 특정 작업 지시는 Skill로 옮기면 필요할 때만 로드됩니다(8·10편).

⑥ MCP 줄이기

도구 정의는 기본 지연 로드지만, 쓸 수 있는 CLI(gh, aws, gcloud)가 더 효율적입니다. 안 쓰는 서버는 /mcp에서 끕니다(12편).

⑦ 긴 출력은 서브에이전트·Hook으로

테스트 실행, 로그 처리는 서브에이전트에(13편). 공식 예처럼 PreToolUse Hook이 테스트 명령을 고쳐 실패 줄만 남기면 수만 토큰이 수백 토큰이 됩니다(11편).

⑧ 구체적으로 묻기

“코드베이스를 개선해”는 넓은 탐색을 부릅니다. “auth.ts의 login 함수에 입력 검증 추가”는 최소한만 읽습니다(4편).

⑨ 잘못된 길을 일찍 끊기

복잡한 일은 Plan 모드로 먼저, 엇나가면 바로 Esc, /rewind. 검증 기준을 주면 고치라는 요청이 줄어듭니다(4·6·17편).

⑩ 코드 인텔리전스 플러그인

타입 있는 언어에서 “정의로 이동” 한 번이 grep과 여러 파일 읽기를 대신합니다(16편).

/usage가 직접 추천해 줍니다 Pro·Max·Team·Enterprise에서 /usage는 최근 사용량의 10% 이상을 차지하는 행동마다 추천 줄을 보여 줍니다(예: 25% Trim ~/code/api/CLAUDE.md · 49k tokens per request). 줄 앞 비율은 “절약량”이 아니라 “그 줄이 해당하는 사용량의 몫”입니다. 하단에 f to fix가 보이면 f로 Claude Code가 적용할 수 있는 것을 적용합니다. /effort 줄은 바로 실행되고, 나머지는 Claude가 변경을 보여 주고 나서 진행합니다.

프롬프트 캐시 지키기

2편에서 본 프롬프트 캐싱은 같은 앞부분(시스템 프롬프트, 도구 정의, 이전 대화)을 다시 보낼 때 싼 값으로 읽게 해 줍니다. Claude Code가 알아서 하지만, 캐시를 깨는 습관은 여러분 몫입니다.

쉬었다 돌아오기

캐시 수명(5분 또는 1시간)이 지난 뒤 첫 메시지는 대화 전체를 다시 처리합니다. 오래 자리를 비울 거라면 정리하고 /clear, 돌아와서 이어 갈 거라면 요약을 남기세요. 최신 버전에는 유휴 압축(idle compaction)이 있어, 20만 토큰이 넘는 대화를 오래 두면 미리 요약해 두었다가 캐시가 식은 뒤 다음 메시지에 그 요약을 씁니다(v2.1.314에서 VS Code·데스크톱 앱까지 넓어짐).

도구 목록 바꾸기

세션 중간에 MCP 서버를 켜고 끄면 도구 정의가 바뀌어 캐시가 깨질 수 있습니다(tools_changed). 필요한 서버는 시작할 때 정해 둡니다.

시스템 프롬프트 바뀜

system_prompt_changed. 세션 중 설정을 자주 바꾸지 마세요.

압축은 “예상된 재구축”

압축하거나 오래된 도구 결과를 지우면 캐시를 새로 만듭니다. /usage는 이것을 실패가 아니라 expected rebuild로 따로 셉니다.

Prompt cache (main): 14 requests · 91% of input tokens from cache · 2 misses (last 6m 10s ago, 310.2k tokens re-cached) · 1 expected rebuild (compaction or tool-result clearing) · warm (1h TTL, last activity 40s ago)

공식 문서의 예시 줄입니다. 91%가 캐시에서 읽혔고, 실패 2번에 31만 토큰을 다시 캐시에 썼습니다. 최신 버전은 마지막 실패의 원인 추정(예: likely cause: tool definitions changed)도 붙입니다. 메인 대화만 세고 서브에이전트는 포함하지 않습니다.

Console의 “Claude Code” 워크스페이스

계약 단가로 보이게

Claude Code의 금액은 정가 기준 추정입니다. 관리형 설정의 modelPricing으로 계약 단가를 넣으면 /usage·상태줄·OpenTelemetry의 금액이 그 단가로 계산됩니다. 청구액을 바꾸지는 않습니다.

MSP: 고객사별로 나누기

고객 프로젝트별 비용을 청구·보고해야 한다면, API 키·워크스페이스를 고객별로 나누거나 OpenTelemetry 속성으로 구분하는 방식을 24편에서 설계합니다.

상태줄 만들기

상태줄은 화면 아래에 늘 보이는 계기판입니다. Claude Code가 세션 정보를 JSON으로 스크립트의 stdin에 넣고, 스크립트가 찍은 것을 보여 줍니다. 로컬에서 돌아 토큰을 쓰지 않습니다. 가장 쉬운 길은 /statusline 모델 이름과 컨텍스트 %를 막대로 보여줘처럼 말로 시키는 것이고, 아래는 jq 없이 Python으로 만든 버전입니다. 공식 문서의 예시 JSON, 세션 시작 직후(null 값), 빈 객체, 깨진 입력으로 시험했습니다.

#!/usr/bin/env python3 """Claude Code 상태줄: 모델·폴더·effort·캐시 / 컨텍스트 막대·세션 비용·요금제 한도. jq 없이 Python 표준 라이브러리만 쓴다. 값이 없거나 null 이어도 깨지지 않는다.""" import json, os, sys try: d = json.load(sys.stdin) except Exception: print("[status] 입력 없음") sys.exit(0) def g(*path, default=None): cur = d for p in path: if not isinstance(cur, dict) or cur.get(p) is None: return default cur = cur[p] return cur GREEN, YELLOW, RED, CYAN, DIM, RESET = "\033[32m", "\033[33m", "\033[31m", "\033[36m", "\033[2m", "\033[0m" model = g("model", "display_name", default="?") folder = os.path.basename(g("workspace", "current_dir", default=g("cwd", default="")) or "") effort = g("effort", "level") hit = g("prompt_cache", "hit_ratio") warm = g("prompt_cache", "warm") top = f"{CYAN}[{model}]{RESET} 📁 {folder}" if effort: top += f" · effort {effort}" if hit is not None: top += f" · 캐시 {hit * 100:.0f}%" + ("" if warm else f" {DIM}(식음){RESET}") pct = int(g("context_window", "used_percentage", default=0) or 0) color = RED if pct >= 90 else YELLOW if pct >= 70 else GREEN bar = "█" * (pct // 10) + "░" * (10 - pct // 10) cost = g("cost", "total_cost_usd", default=0) or 0 bottom = f"{color}{bar}{RESET} {pct}% · ${cost:.2f}" limits = [] for key, label in (("five_hour", "5h"), ("seven_day", "7d")): v = g("rate_limits", key, "used_percentage") if v is not None: c = RED if v >= 90 else YELLOW if v >= 70 else "" limits.append(f"{c}{label} {v:.0f}%{RESET if c else ''}") if limits: bottom += " · " + " ".join(limits) print(top) print(bottom)
