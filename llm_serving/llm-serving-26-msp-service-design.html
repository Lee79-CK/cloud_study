Level 5 · 운영·MSP 전략 — 26편 (시리즈 마지막)

MSP 서비스 설계
상품·과금·SLA·운영 조직

25편까지 우리는 GPU 위에 엔진을 세우고, 라우팅·게이트웨이로 묶고, 튜닝하고, 관측하고, 안전하게 바꾸는 방법을 만들었습니다. 마지막 편은 이 기술을 고객이 살 수 있는 서비스로 바꿉니다. 어떤 상품을 몇 가지 등급으로 팔지, 원가는 얼마이고 가격은 어떻게 매길지, SLA에 무엇을 약속하고 무엇을 빼야 하는지, 고객을 어떻게 받아들이고(온보딩) 매달 무엇을 보고할지, 그리고 이 모든 것을 운영할 조직과 당직 체계까지. 마지막에는 시리즈 전체를 한 장의 로드맵으로 정리합니다.

01시작하기 전에

기술이 좋아도 상품·가격·약속·조직이 맞지 않으면 서비스는 지속되지 않습니다.

학습 목표

  1. 격리 수준(24편)과 운영 범위를 기준으로 LLM 서빙 상품 포트폴리오를 설계할 수 있다.
  2. GPU·간접비·사용률로 토큰당 원가를 계산하고, 가격과 손익분기를 정할 수 있다.
  3. 토큰 종량·전용 월정액·약정+초과 과금의 장단점과 계량 요구를 설명할 수 있다.
  4. 측정 가능한 SLI 기반의 SLA 문구·제외 조건·보상 표를 작성할 수 있다.
  5. 온보딩 절차와 월간 보고서를 이 시리즈의 산출물로 구성할 수 있다.
  6. 운영 조직·당직·책임 분담과 사업 지표를 설계하고, 주요 사업 위험에 대비할 수 있다.
이 편의 비유: 렌터카 회사

렌터카 회사는 차(GPU)를 사서 여러 상품으로 팝니다. 시간 단위 공유차(토큰 종량), 월 단위 전용 장기 렌트(전용 레플리카), 기업 차량 관리 대행(고객 클러스터 운영), 고객 차고지 상주 관리(온프레미스). 차 한 대의 원가는 구입비·보험·정비·주차비이고, 실제로 빌려 나간 시간 비율(사용률)이 낮으면 대당 원가가 올라갑니다. 고장 시 대차 약속(SLA)과 보상, 계약 시 면허·사용 목적 확인(온보딩), 월말 운행 내역 보고(월간 보고서), 24시간 긴급 출동 팀(당직)이 있어야 사업이 됩니다.

02상품 포트폴리오

격리 수준(24편)과 MSP가 맡는 운영 범위로 상품을 나눕니다.

상품대상 고객격리 (24편)과금 기준SLAMSP 운영 범위
A. 공유 추론 APIPoC·중소 규모·사내 다부서L1~L2토큰 종량 (입력·출력·캐시 적중 차등)표준 (가용성·TTFT)전부
B. 전용 모델 서빙지연 SLA·전용 모델·맞춤 어댑터L3~L4전용 GPU 월정액 + 초과 토큰 또는 약정강화 (지연·용량 보장)전부
C. 고객 클러스터 매니지드자체 클라우드 계정·클러스터 보유 기업L5운영 관리비 (노드·GPU 수 기준) + 인프라는 고객 부담운영 대응 시간 중심엔진·관측·변경·장애 대응
D. 온프레미스 구축·운영금융·공공·망분리 기관L6구축 프로젝트 + 연간 유지보수계약별구축·원격(또는 상주) 운영
E. 하이브리드 AI 게이트웨이여러 외부 API와 셀프호스팅 혼용 기업게이트웨이 테넌트관리비 + 외부 API 원가 대행 수수료게이트웨이 가용성키·한도·비용·폴백·감사 (12편)
F. 부가 서비스모든 고객—프로젝트·건별—벤치마크·용량 계획(19), 튜닝(14~16), 품질 평가(22), 보안 점검(24), 어댑터 서빙(16)

처음부터 모든 상품을 열 필요는 없습니다. A(공유 API) + F(벤치마크·용량 계획)로 시작해 고객의 실제 워크로드 카드(19편)를 확보하고, 지연·규제 요구가 확인되는 고객부터 B·C·D로 확장하는 순서가 위험이 작습니다.

03원가 모델

토큰당 원가를 결정하는 가장 큰 변수는 GPU 가격이 아니라 사용률입니다.

소프트웨어상용 지원 계약·라이선스(해당 시), 외부 SaaS 도구노드·사용자

토큰당 원가 = (GPU 월 원가 × GPU 수 × (1 + 간접비 비율)) ÷ (레플리카 SLO 용량 × 레플리카 수 × 월 초 × 실제 사용률) 판매가 = 토큰당 원가 × (1 + 마진) 손익분기 사용률 = 외부 API 단가와 우리 원가가 같아지는 사용률

히어로 설계기에서 사용률을 바꿔 보면, 사용률이 절반이 되면 원가가 두 배가 되는 것을 볼 수 있습니다. 그래서 공유 상품(A)은 여러 고객의 부하를 모아 사용률을 높이고, 전용 상품(B)은 낮은 사용률의 위험을 고객이 부담하는 월정액으로 설계합니다. 용량은 반드시 측정값(14·19편)을 쓰고, 캐시 적중(15편)·추측 디코딩(16편) 같은 최적화는 원가를 낮추는 지렛대로 따로 계산합니다.

07월간 보고서

고객이 매달 받는 보고서가 곧 서비스의 얼굴입니다. 숫자는 모두 재현 가능해야 합니다.

markdown · 월간 서비스 보고서 양식
# <고객> LLM 서비스 월간 보고 (<YYYY-MM>)
## 1. 요약           — 이번 달 핵심 3줄 (SLA 달성 여부, 주요 사건, 권고)
## 2. 사용량         — 모델·팀별 요청·입력·출력·캐시 적중 토큰, 전월 대비 (12·20편)
## 3. 비용           — 과금 내역, 외부 API 대행분, 토큰당 실효 단가
## 4. SLA·SLO        — 가용성·TTFT 달성률, 오류 예산 사용, 제외 시간과 사유 (21편)
## 5. 품질·안전       — 형식 준수·잘림·안전 판정률 추세, 평가 결과 (22편)
## 6. 사건           — 장애 목록·영향·사후 검토 요약·조치 진행 (23편)
## 7. 변경           — 모델·엔진·설정 변경과 결과 (25편)
## 8. 용량·예측       — 피크 사용률, 다음 분기 예측과 증설 필요 여부 (19편)
## 9. 권고           — 비용 절감(캐시 친화 프롬프트, 양자화), 품질 개선, 보안 점검 결과

숫자의 출처는 기록 규칙의 장기 보관값(20편), 게이트웨이 사용량(12편), 경보·장애 기록(23편), Git 이력(25편)입니다. 실습 26-2가 이 양식의 2·4·6·7장을 자동으로 채웁니다.

실습 26-1 · 원가·단가 모델

python · pricing_model.py
"""상품별 토큰당 원가·판매가·손익분기 사용률을 계산한다. 가정은 ASSUMPTIONS를 고쳐서 쓴다(모두 예시 값)."""
SECONDS = 30 * 24 * 3600
ASSUMPTIONS = {
    "gpu_month_cost": 2200,          # GPU 1장 월 원가 ($): 감가상각·전력·상면 포함
    "overhead": 0.40,                # 운영·관측·인력 간접비 비율
    "margin": 0.25,                  # 목표 마진
    "external_out_price": 10.0,      # 비교용 외부 API 출력 단가 ($/1M)
    "tiers": {
        # 이름: (레플리카당 GPU, 레플리카 수, 레플리카당 SLO 용량 출력 tok/s [14·19편 측정], 예상 사용률)
        "A 공유 API":      (2, 3, 1800, 0.45),
        "B 전용 (고객 X)": (2, 1, 1800, 0.20),
    },
}
a = ASSUMPTIONS
print(f"{'상품':<16}{'월 원가($)':>12}{'처리 토큰(M/월)':>16}{'원가($/1M)':>12}{'판매가($/1M)':>14}{'손익분기 사용률':>16}")
for name, (gpr, reps, cap, util) in a["tiers"].items():
    month = a["gpu_month_cost"] * gpr * reps * (1 + a["overhead"])
    tokens_m = cap * reps * SECONDS * util / 1e6
    cost = month / tokens_m
    price = cost * (1 + a["margin"])
    be = month / (cap * reps * SECONDS / 1e6) / a["external_out_price"]     # 외부 단가와 원가가 같아지는 사용률
    print(f"{name:<16}{month:>12,.0f}{tokens_m:>16,.0f}{cost:>12.2f}{price:>14.2f}{be:>15.0%}")
print("\n전용 상품은 사용률 위험을 고객이 지도록 월정액으로: 고객 X 월 청구 =",
      f"${a['gpu_month_cost'] * 2 * (1 + a['overhead']) * (1 + a['margin']):,.0f} (레플리카 1개 기준)")

레플리카당 용량은 14편 tune_report.py의 SLO 용량(req/s) × 평균 출력 토큰으로 환산해 넣습니다. GB10 랩 숫자는 데이터센터 GPU와 크게 다르므로, 고객 견적에는 고객 하드웨어에서의 측정값을 씁니다.

"""관측 데이터·Git 이력·사후 검토 파일로 월간 보고서(마크다운) 초안을 만든다.

import glob, json, os, subprocess, sys, urllib.parse, urllib.request
from datetime import date
win = sys.argv[1] if len(sys.argv) > 1 else "30d"
prom = sys.argv[2] if len(sys.argv) > 2 else "http://localhost:9090"
repo = sys.argv[3] if len(sys.argv) > 3 else "."
PRICE = {"input": 0.5, "output": 2.0}      # $/1M 토큰 (예시 단가표)
def q(expr):
    try: return json.load(urllib.request.urlopen(f"{prom}/api/v1/query?query={urllib.parse.quote(expr)}", timeout=20))["data"]["result"]
    except Exception as e: return []
def val(r): return float(r["value"][1])
L = [f"# LLM 서비스 월간 보고 ({date.today():%Y-%m}, 창 {win})", "", "## 2. 사용량", "", "| 모델 | 입력 토큰(M) | 출력 토큰(M) | 요청 수 | 예상 청구($) |", "|---|---:|---:|---:|---:|"]
ins = {r["metric"].get("model_name"): val(r) for r in q(f"sum by (model_name) (increase(vllm:prompt_tokens_total[{win}]))")}
outs = {r["metric"].get("model_name"): val(r) for r in q(f"sum by (model_name) (increase(vllm:generation_tokens_total[{win}]))")}
reqs = {r["metric"].get("model_name"): val(r) for r in q(f"sum by (model_name) (increase(vllm:request_success_total[{win}]))")}
for m in sorted(set(ins) | set(outs)):
    i, o = ins.get(m, 0) / 1e6, outs.get(m, 0) / 1e6
    L.append(f"| {m} | {i:,.2f} | {o:,.2f} | {reqs.get(m, 0):,.0f} | {i*PRICE['input'] + o*PRICE['output']:,.2f} |")
L += ["", "## 4. SLA·SLO", ""]
for r in q(f"avg_over_time(llm:ttft_slo_ratio[{win}])"):
    L.append(f"- TTFT 기준 달성률 ({r['metric'].get('model_name')}): {val(r)*100:.2f}%  (20·21편 기록 규칙)")
for r in q(f'avg_over_time((sum(up{{job="monitoring/vllm-engines"}}) > bool 0)[{win}:5m])'):
    L.append(f"- 엔진 가용 시간 비율(근사): {val(r)*100:.2f}%  — 계약 SLA는 게이트웨이 기준으로 산정")
L += ["", "## 6. 사건 (경보)", "", "| 경보 | 등급 | 울린 표본 수 |", "|---|---|---:|"]
for r in sorted(q(f'sum by (alertname, severity) (count_over_time(ALERTS{{alertstate="firing"}}[{win}]))'), key=val, reverse=True)[:10]:
    L.append(f"| {r['metric'].get('alertname')} | {r['metric'].get('severity','')} | {val(r):,.0f} |")
pms = sorted(glob.glob(os.path.join(repo, "postmortems", "*.md")))
L += ["", "사후 검토: " + (", ".join(os.path.basename(p) for p in pms) if pms else "없음")]
L += ["", "## 7. 변경", ""]
try:
    log = subprocess.run(["git", "-C", repo, "log", f"--since={win.rstrip('d')}.days", "--pretty=- %ad %s", "--date=short"],
                         capture_output=True, text=True).stdout.strip()
    L.append(log or "- 변경 없음")
except Exception: L.append("- Git 이력을 읽지 못함")
L += ["", "## 1·3·5·8·9장은 담당자가 작성 (요약·비용 상세·품질·용량 예측·권고)"]
out = f"report-{date.today():%Y-%m}.md"; open(out, "w").write("\n".join(L) + "\n"); print(open(out).read())
