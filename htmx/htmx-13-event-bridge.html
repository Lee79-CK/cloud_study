네 방향의 신호

아일랜드 → htmx이벤트. 아일랜드는 "무슨 일이 있었다"만 알리고, 무엇을 할지는 htmx 영역(결국 서버)이 정한다.
서버 → 아일랜드 (값)속성. 서버가 HTML로 말하는 방식 그대로. 모핑이 속성만 바꾸면 attributeChangedCallback이 받는다(12편).
서버 → 아일랜드 (사건)이벤트. HX-Trigger로 "이 VM이 바뀌었다"를 알리면 관심 있는 아일랜드가 반응한다.
아일랜드 ↔ 아일랜드이벤트. 서로를 import하지 않는다. 프레임워크가 달라도 DOM 이벤트는 공용어.

공통 원칙은 하나입니다. 서로의 내부(함수, 상태 저장소, DOM)를 직접 만지지 않는다. 11편에서 DOM 소유권을 나눈 것과 같은 이유입니다. 공개 계약은 "태그 이름 + 속성 + 내보내는 이벤트(이름과 detail 모양)"뿐이고, 이것을 문서로 적어 두면 React 팀과 Vue 팀과 서버 팀이 따로 일할 수 있습니다.

요소속성 (입력)내보내는 이벤트 (출력)듣는 이벤트
<metric-chart> (React)vm, thresholdmetric:select — {vm, t, cpu}, bubblesvmChanged — {name} (document)
<metric-summary> (Vue)vm없음metric:select (document)

섀도 경계를 넘는 이벤트

12편에서 섀도 안의 클릭이 document에서는 호스트로 보인다는 것을 확인했습니다. 사용자 정의 이벤트는 옵션에 따라 아예 경계를 못 넘기도 합니다. Chrome 153에서 측정한 결과입니다(document에 리스너 하나).

어디서 발생bubblescomposeddocument에서 받았나event.targetcomposedPath()[0]
섀도 안 버튼truefalse못 받음--
섀도 안 버튼truetrue받음호스트안쪽 버튼
섀도 안 버튼falsetrue못 받음--
호스트 요소truefalse받음호스트호스트

그래서 이번 편은 이벤트를 호스트 요소에서 발생시킵니다. 호스트는 라이트 DOM에 있으므로 composed와 무관하게 평범하게 버블링되고, 받는 쪽에서 대상이 늘 그 사용자 정의 요소라 "누가 보냈는지"가 명확합니다. React 컴포넌트가 호스트를 알 수 있도록 12편 도우미의 렌더 함수에서 요소(el)를 prop으로 넘겼습니다. 섀도 안쪽에서 발생시켜야 한다면 bubbles: true, composed: true 둘 다 필요하고, 안쪽의 실제 대상은 composedPath()로 봅니다.

apps/react-islands/src/main.jsx (발췌)
function pick(i) {
  const p = pts[i];
  setSelected(p.t);

  host.dispatchEvent(new CustomEvent('metric:select', { bubbles: true, composed: true, detail: { vm, t: p.t, cpu: p.cpu } }));
}

회귀 테스트가 잡아낸 함정: VM별 id는 모핑의 짝을 깬다

    
처음에는 partial 대상을 지정하려고 차트에 id="chart-web-01"처럼 VM별 id를 주었습니다. 그러자 12편의 "상세 패널을 다른 VM의 HTML로 모핑하면 같은 요소가 유지된다" 테스트가 실패했습니다(같은 요소 false, 마운트 +1). 5편에서 본 대로 모핑은 id로 먼저 짝을 찾기 때문에, chart-web-02와 chart-web-03은 다른 요소로 판정되어 옛 요소를 버리고 새로 만든 것입니다. 상세 패널에는 차트가 하나뿐이므로 id를 detail-chart로 고정하자 두 테스트가 모두 통과했습니다. 모핑 대상에 id를 줄 때는 "이 id가 같은 대상을 가리키는 동안 유지되는가"를 확인하세요.

  

  
사건은 이벤트로: HX-Trigger

  
6편부터 재시작·시작 응답은 HX-Trigger: {"vmChanged": {"name": "web-01"}}를 보내고 있습니다. htmx는 이를 문서 이벤트로 발생시키므로(요청 요소가 사라졌으면 document에서, 4편) React 차트는 document.addEventListener('vmChanged', …)만 하면 됩니다. 측정: 재시작 버튼을 누르자 0.6초 안에 서버 로그에 POST /vms/web-01/restart 다음 줄로 GET /api/vms/web-01/metrics가 찍혔습니다(5초 주기를 기다리지 않음). 리스너는 useEffect의 정리 함수에서 반드시 제거합니다. 그렇지 않으면 12편에서 막은 누수가 이벤트 리스너 형태로 돌아옵니다.
