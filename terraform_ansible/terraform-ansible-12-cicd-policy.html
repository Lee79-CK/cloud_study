Terraform & Ansible 강의 · Level 2 Terraform 심화·운영 · 12편 / 26편 (Level 2 마지막) · 시리즈 목차

사람은 승인하고, 기계가 적용한다 CI/CD와 정책 — GitHub Actions + OIDC, PR plan 게시, 승인 기반 apply, 드리프트 스케줄, OPA·conftest·Sentinel, 플랫폼 비교

지금까지 모든 apply는 여러분의 노트북에서, 여러분의 자격증명으로 실행되었습니다. 혼자 실습할 때는 괜찮지만 고객사 운영에서는 곤란합니다. 누가 언제 무엇을 적용했는지 기록이 흩어지고, 사람마다 Terraform 버전이 다르고, 장기 액세스 키가 노트북에 남습니다. 이번 편은 Level 2를 마무리하며 8~11편에서 만든 모든 관문(환경 분리, 테스트, 스캔, 드리프트 점검)을 하나의 파이프라인으로 묶고, “운영계는 Multi-AZ” 같은 조직 규칙을 정책 코드로 plan 단계에서 강제합니다.

키 없음

OIDC로 실행할 때마다 짧은 임시 자격증명. 저장소에 비밀 없음.

리뷰한 것을 적용

PR에 plan 게시 → 승인 → 그 plan 파일 그대로 apply.

규칙은 코드로

OPA 정책이 plan JSON을 읽고 위반을 막는다. 정책도 테스트한다.

1왜 파이프라인인가

노트북에서의 apply가 운영에서 만드는 다섯 가지 문제

문제노트북 apply파이프라인 apply
자격증명운영 계정의 쓰기 권한이 사람 노트북에 (장기 키, 분실·유출 위험)실행할 때만 발급되는 임시 자격증명. 사람은 운영 쓰기 권한이 없어도 됨
기록누가 언제 무엇을 적용했는지 개인 터미널에만PR·리뷰·plan·실행 로그가 한곳에 남음 (감사 증적)
환경 차이사람마다 Terraform·프로바이더 버전·로컬 파일이 다름같은 버전·같은 깨끗한 환경에서 매번 실행
리뷰한 것 = 적용한 것?리뷰 후 다시 plan하면 그 사이 바뀐 것이 섞일 수 있음리뷰한 plan 파일 그대로 적용, 다르면 실패
동시 실행두 사람이 동시에 (잠금이 막아 주지만 순서는 우연)환경별 동시 실행 그룹으로 줄 세움
GitOps 원칙으로 정리하면

① 원하는 상태는 Git에 선언된다(1편). ② 변경은 PR로만 들어온다. ③ 승인된 변경만 자동으로 적용된다. ④ 실제 상태와 선언의 차이(드리프트)는 지속적으로 감지된다(9편). 이번 편의 파이프라인이 이 네 가지를 각각 구현합니다. 사람이 하는 일은 “리뷰하고 승인하는 것”으로 줄어듭니다.

3OIDC: 키 없는 인증

GitHub가 “이 실행은 이 저장소의 이 브랜치에서 왔다”고 서명한 토큰을 AWS가 믿게 한다

상황토큰의 sub신뢰 정책 조건 예

sub 조건을 넓게 쓰면 끝

repo:my-org/*나 *처럼 넓게 쓰면 조직의 다른 저장소, 심하면 남의 저장소 워크플로도 이 역할을 맡을 수 있습니다. 반드시 저장소 이름까지, 쓰기 역할은 environment:까지 고정합니다. 그리고 GitHub 환경(prd)에 “필수 검토자”와 “배포 가능 브랜치: main”을 설정해, 그 환경 이름을 단 job이 승인 없이 돌 수 없게 합니다.

terraform {
  required_version = "~> 1.16.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }

  backend "s3" {}
}

provider "aws" {
  region = "ap-northeast-2"
}

variable "github_repo" {
  description = "OWNER/REPO 형식 (예: my-org/iac-lab)"
  type        = string

  validation {
    condition     = can(regex("^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$", var.github_repo))
    error_message = "github_repo는 OWNER/REPO 형식이어야 합니다."
  }
}

variable "state_bucket" {
  description = "5편에서 만든 state 버킷 이름"
  type        = string
}

# ---------- GitHub Actions OIDC 공급자 (계정에 하나) ----------
resource "aws_iam_openid_connect_provider" "github" {
  url            = "https://token.actions.githubusercontent.com"
  client_id_list = ["sts.amazonaws.com"]
}

# ---------- plan 역할: PR과 main에서, 읽기 + state 잠금만 ----------
data "aws_iam_policy_document" "plan_trust" {
  statement {
    actions = ["sts:AssumeRoleWithWebIdentity"]

    principals {
      type        = "Federated"
      identifiers = [aws_iam_openid_connect_provider.github.arn]
    }

    condition {
      test     = "StringEquals"
      variable = "token.actions.githubusercontent.com:aud"
      values   = ["sts.amazonaws.com"]
    }

    # 이 저장소의 PR과 main 브랜치에서만 (포크·다른 저장소는 불가)
    condition {
      test     = "StringLike"
      variable = "token.actions.githubusercontent.com:sub"
      values = [
        "repo:${var.github_repo}:pull_request",
        "repo:${var.github_repo}:ref:refs/heads/main",
      ]
    }
  }
}

resource "aws_iam_role" "plan" {
  name                 = "gha-terraform-plan"
  assume_role_policy   = data.aws_iam_policy_document.plan_trust.json
  max_session_duration = 3600
}

resource "aws_iam_role_policy_attachment" "plan_readonly" {
  role       = aws_iam_role.plan.name
  policy_arn = "arn:aws:iam::aws:policy/ReadOnlyAccess"
}

# plan도 state 잠금 파일을 만들고 지운다 (5편 6장)
data "aws_iam_policy_document" "plan_state_lock" {
  statement {
    actions   = ["s3:PutObject", "s3:DeleteObject"]
    resources = ["arn:aws:s3:::${var.state_bucket}/*.tflock"]
  }
}

resource "aws_iam_role_policy" "plan_state_lock" {
  name   = "state-lock"
  role   = aws_iam_role.plan.id
  policy = data.aws_iam_policy_document.plan_state_lock.json
}

# ---------- apply 역할: GitHub 환경(dev)에서만 ----------
data "aws_iam_policy_document" "apply_trust" {
  statement {
    actions = ["sts:AssumeRoleWithWebIdentity"]

    principals {
      type        = "Federated"
      identifiers = [aws_iam_openid_connect_provider.github.arn]
    }

    condition {
      test     = "StringEquals"
      variable = "token.actions.githubusercontent.com:aud"
      values   = ["sts.amazonaws.com"]
    }

    # environment: dev 인 job만 이 역할을 맡을 수 있다 (prd는 prd 계정에 따로)

      test     = "StringEquals"

}

resource "aws_iam_role" "apply" {
  name                 = "gha-terraform-apply-dev"
  assume_role_policy   = data.aws_iam_policy_document.apply_trust.json

IAM OIDC 공급자의 인증서 지문(thumbprint)은 AWS가 GitHub의 OIDC를 신뢰된 인증 기관으로 검증하므로 더 이상 지정하지 않아도 됩니다(프로바이더 6.x에서 선택 인자). 오프라인 plan 실측: OIDC 공급자 1, 역할 2, 정책 연결 2, 인라인 정책 1로 “Plan: 6 to add”.

4PR 워크플로

빠른 검사 → 모듈 테스트 → 환경별 plan과 정책 → PR 댓글

.github/workflows/terraform-pr.yml
# PR마다: 정적 검사 → 모듈 테스트 → 환경별 plan + 정책 검사 → plan을 PR에 게시
name: terraform-pr

on:
  pull_request:
    paths:
      - "terraform/**"
      - "modules/**"
      - "policy/**"
      - ".github/workflows/terraform-*.yml"

permissions:
  contents: read
  pull-requests: write # plan 댓글
  id-token: write      # AWS OIDC

concurrency:
  group: tf-pr-${{ github.event.pull_request.number }}
  cancel-in-progress: true

env:
  TF_IN_AUTOMATION: "true"
  TF_INPUT: "false"
  TF_VERSION: "1.16.5"

jobs:
  static:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: hashicorp/setup-terraform@v4
        with:
          terraform_version: ${{ env.TF_VERSION }}
          terraform_wrapper: false
      - name: fmt
        run: terraform fmt -check -recursive -diff
      - uses: terraform-linters/setup-tflint@v6
        with:
          tflint_version: v0.64.0
      - name: tflint
        run: |
          tflint --init --config="$GITHUB_WORKSPACE/.tflint.hcl"
          tflint --recursive --config="$GITHUB_WORKSPACE/.tflint.hcl"
        env:
          GITHUB_TOKEN: ${{ github.token }}
      - name: trivy (HIGH, CRITICAL)
        uses: aquasecurity/trivy-action@v0.36.0
        with:
          scan-type: config
          scan-ref: .
          severity: HIGH,CRITICAL
          exit-code: "1"
      - name: 정책 자체의 단위 테스트
        run: |
          curl -fsSL https://github.com/open-policy-agent/conftest/releases/download/v0.71.1/conftest_0.71.1_Linux_x86_64.tar.gz \
            | tar xz -C /usr/local/bin conftest
          conftest verify --policy policy

  module-tests:
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        module: [vpc, label, rds-postgres]
    defaults:
      run:
        working-directory: modules/${{ matrix.module }}
    steps:
      - uses: actions/checkout@v7
      - uses: hashicorp/setup-terraform@v4
        with:
          terraform_version: ${{ env.TF_VERSION }}
          terraform_wrapper: false
      - run: terraform init -backend=false
      - name: mock 단위 테스트 (클라우드 자격증명 불필요)
        run: terraform test -filter=tests/unit.tftest.hcl

  plan:
    needs: [static, module-tests]
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        include:
          - stack: terraform/06-network
            env: dev
          - stack: terraform/07-app
            env: dev
    defaults:
      run:
        working-directory: ${{ matrix.stack }}
    steps:
      - uses: actions/checkout@v7
      - uses: hashicorp/setup-terraform@v4
        with:
          terraform_version: ${{ env.TF_VERSION }}
          terraform_wrapper: false
      - uses: aws-actions/configure-aws-credentials@v6
        with:
          role-to-assume: ${{ vars.TF_PLAN_ROLE_ARN }}
          aws-region: ap-northeast-2
          role-session-name: gha-plan-${{ github.run_id }}
      - name: init
        run: terraform init -backend-config=backend/${{ matrix.env }}.s3.tfbackend
      - name: plan
        id: plan
        run: |
          set -o pipefail
          terraform plan -out=tfplan -no-color -lock-timeout=5m \
            -var-file=envs/${{ matrix.env }}.tfvars 2>&1 | tee plan.txt
          terraform show -json tfplan > plan.json
      - name: 정책 검사 (conftest)
        run: |
          curl -fsSL https://github.com/open-policy-agent/conftest/releases/download/v0.71.1/conftest_0.71.1_Linux_x86_64.tar.gz \
            | tar xz -C /usr/local/bin conftest
          conftest test plan.json --policy "$GITHUB_WORKSPACE/policy" --data "$GITHUB_WORKSPACE/policy-data" --no-color | tee policy.txt
      - name: plan을 PR 댓글로
        if: always()
        uses: actions/github-script@v9
        env:
          STACK: ${{ matrix.stack }}
          ENV_NAME: ${{ matrix.env }}
          WORKDIR: ${{ matrix.stack }}
        with:
          script: |
            const fs = require('fs');
            const read = (f) => fs.existsSync(`${process.env.WORKDIR}/${f}`) ? fs.readFileSync(`${process.env.WORKDIR}/${f}`, 'utf8') : '(없음)';
            const plan = read('plan.txt');
            const summary = (plan.match(/^(Plan:.*|No changes\..*)$/m) || ['(요약 없음)'])[0];
            const body = [
              `### ${process.env.STACK} (${process.env.ENV_NAME})`,
              `**${summary}**`,

package mainconftest가 기본으로 찾는 패키지
deny contains msg if { … }본문의 모든 조건이 참이면 msg를 deny 집합에 넣는다 → 실패. warn은 경고만
some rc in input.resource_changes목록의 각 항목에 대해 (반복)
not 조건조건이 거짓이거나 정의되지 않으면 참. 값이 null이면 “정의됨, 거짓 아님”이라 not이 거짓이 된다 (아래 실측)
object.get(obj, key, 기본값)키가 없을 때 기본값. null·누락을 안전하게 다루는 기본 도구
sprintf메시지 만들기. 규칙 ID([DB-001])를 넣어 두면 예외·보고가 쉽다
data.exceptionsconftest --data로 넘긴 외부 데이터. 승인된 예외 목록을 코드와 분리 (12장)

승인자 = 변경 관리 절차

prd 환경의 필수 검토자에 고객 측 승인자를 넣거나, 고객 변경 요청 번호를 PR 템플릿의 필수 항목으로 둡니다. GitHub의 승인 기록이 그대로 ITSM 변경 관리의 증적이 됩니다.

정책 = 계약과 보안 기준의 코드화

고객 보안 기준서의 항목에 정책 ID(DB-001 등)를 매핑해 두면, 보안 감사 때 “이 기준은 어떤 정책이 어떻게 강제하는가”를 바로 보여 줄 수 있습니다. 예외 파일은 그대로 “승인된 예외 대장”입니다.

과제 1. 정책 규칙 추가

다음 규칙을 추가하고 각각 정책 테스트(통과·실패 각 1개)를 쓰세요: ① 운영 S3 버킷은 버전닝 리소스가 함께 있어야 한다, ② aws_instance는 IMDSv2 필수(metadata_options[0].http_tokens == "required"), ③ 허용 리전 외 리소스 금지(provider 설정이 plan JSON의 configuration에 있음).

과제 5. 승인 없는 prd 적용을 막는 이중 장치

“누군가 워크플로 파일을 고쳐 prd apply job에서 environment를 지운다”는 공격을 가정하고, 이것이 실패하는 이유를 3장·10장의 설정으로 설명하세요. 실패하지 않는 설정 실수가 있다면 무엇인가요?

해설

environment를 지우면 OIDC 토큰의 sub가 …:environment:prd가 아니라 …:ref:refs/heads/…가 되어 prd apply 역할의 신뢰 정책(StringEquals environment:prd)에 맞지 않아 거부됩니다. 또 워크플로 파일 변경은 CODEOWNERS 리뷰와 브랜치 보호로 main에 들어가기 어렵습니다. 실패하지 않는 실수: 신뢰 정책 sub를 repo:org/repo:*로 넓게 쓴 경우, prd 역할을 PR에서도 맡을 수 있게 한 경우, 브랜치 보호에 관리자 예외를 둔 경우.
