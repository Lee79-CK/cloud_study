세션·체크포인트되돌리기

대담하게 시도하려면 확실하게 돌아올 수 있어야 합니다. 대화를 저장하고, 이름 붙이고, 갈라내고, 원하는 지점으로 되감는 법을 익힙니다. 그리고 무엇이 되돌려지지 않는지도 정확히 압니다.

모든 파일영구
공식 문서의 경고 한 줄 체크포인트는 Claude의 파일 편집 도구로 바뀐 것만 추적합니다. Bash 명령이나 외부 프로세스로 바뀐 것은 잡지 못하므로 Git을 대신하지 못합니다. 체크포인트는 세션 안의 “실행 취소”, Git은 “영구 버전 관리”라고 생각하세요.

세션은 어디에 남나

세션은 프로젝트 폴더에 묶인 저장된 대화입니다. Claude Code는 작업하는 동안 계속 로컬 파일에 저장하므로, 종료하거나 /clear를 해도 다시 돌아올 수 있습니다.

~/.claude/projects/<프로젝트>/<세션-ID>.jsonl # <프로젝트> = 작업 폴더 경로에서 영문·숫자 외의 문자를 - 로 바꾼 이름 # 예) /home/me/vibe-lab → -home-me-vibe-lab
하고 싶은 일방법
보관 기간 바꾸기기본 30일 후 자동 삭제. settings.json의 cleanupPeriodDays
지금 지우기claude purge — 프로젝트의 기록과 관련 상태 삭제
저장 위치 옮기기환경 변수 CLAUDE_CONFIG_DIR (3편의 계정 분리와 같은 변수)
사람이 읽을 기록으로 저장/export — 클립보드 복사 또는 텍스트 파일. 파일 이름을 주면 바로 저장
스크립트에서 세션에 질문claude -p --resume <세션-ID> --output-format json "무엇을 바꿨는지 요약해"
JSONL 파일을 직접 파싱하지 마세요 각 줄의 형식은 내부용이라 버전마다 바뀝니다. 공식 문서는 기록을 활용하려면 /export나 claude -p의 JSON 출력, Hook이 받는 transcript_path를 쓰라고 권합니다.
MSP 관점: 세션 기록도 고객 데이터다 2편에서 봤듯 기록은 평문이고, Claude가 읽은 로그·설정·명령 출력이 그대로 들어갑니다. 고객사 작업을 했다면 보관 기간(cleanupPeriodDays)을 회사 정책에 맞추고, 끝난 작업은 claude purge를 고려하세요. 3편의 CLAUDE_CONFIG_DIR 분리를 쓰면 업무 기록이 개인 기록과 섞이지 않습니다.

세션에 이름 붙이기

공식 문서는 세션을 브랜치처럼 다루라고 권합니다. 작업 줄기마다 이름 붙은 세션 하나. 여러 작업을 병렬로 할 때 특히 중요합니다.

언제방법
시작할 때claude -n dashboard-json
세션 중/rename dashboard-json (프롬프트 줄에도 표시)
세션 선택기에서항목을 고르고 Ctrl+R
계획 승인 시이름이 없으면 계획 내용으로 제목이 자동 생성

🏷️ 이름을 안 붙여도 생기는 것

  • 기본 표시 이름: 폴더 이름 + 두 글자 (예: vibe-lab-3f). 실행 중 목록 식별용이며 이어가기 이름으로는 못 씁니다.
  • 생성된 제목: 첫 프롬프트를 작은 모델이 요약한 제목. 이건 이어가기에 쓸 수 있습니다.

📛 MSP 이름 규칙 예시

  • 고객사-작업-날짜: acme-cert-rotation-1101
  • 티켓번호-요약: INC2041-db-latency
  • 실습: lab-dashboard-json

나중에 세션 선택기에서 검색어로 쓰기 좋게 짧고 일관되게.

명령하는 일

claude --resume세션 선택기 열기
claude --resume <이름>이름이 정확히 맞으면 바로 열고, 여러 개면 그 이름으로 검색한 선택기
claude --from-pr <번호>그 PR과 연결된 세션만 보여 주는 선택기 (7편)

세션 선택기 연습

아래 상자를 클릭해 포커스를 준 뒤 실제 단축키(↑↓, Space, →, Ctrl+B, Ctrl+A, Enter)를 눌러 보세요. 휴대폰에서는 아래 버튼을 쓰세요.

이어 연 세션에서 복원되는 것과 아닌 것

✅ 복원됨

  • 도구 호출과 결과를 포함한 전체 대화
  • 사용하던 모델
  • 권한 모드 (터미널에서 --continue나 이름·ID로 이어갈 때. bypassPermissions는 예외)
  • 진행 중이던 /goal, 만료되지 않은 예약 작업

❌ 다시 지정해야 함

  • --mcp-config, --settings, --add-dir 같은 시작 플래그
  • 세션 중 /add-dir로 추가한 폴더
  • 백그라운드 Bash와 Monitor 작업 (끝나지 않았다는 메모로 남음)
  • 도중에 끊긴 도구 호출은 다시 실행되지 않고, Claude가 실제로 적용됐는지 먼저 확인합니다
선택기에 안 보이는 세션 claude -p와 Agent SDK로 만든 세션, 첫 프롬프트가 /loop였던 세션은 선택기와 --continue에서 빠집니다. 세션 ID를 알면 claude --resume <세션-ID>로 열 수 있습니다(19편).

갈라내기: /branch

갈라내기는 지금까지의 대화를 복사해 그쪽으로 옮겨 가고, 원래 세션은 그대로 둡니다. 지금 가던 길을 잃지 않고 다른 접근을 시험할 때 씁니다.

/branch try-dark-mode # 세션 안에서 (이름은 생략 가능) claude --continue --fork-session # 명령줄에서
상태/branch 후
대화 기록실행한 시점까지 새 갈래로 복사
“이 세션에서 허용” 권한같은 프로세스라 그대로 유지. --fork-session으로 새 프로세스를 띄우면 다시 승인
백그라운드 서브에이전트·Bash계속 실행되고, 출력은 새 갈래에 나타남
원래 세션디스크에 그대로. 확인 메시지에 두 세션 ID가 모두 표시됨. /resume <원래-이름>으로 복귀
대화는 갈라져도 파일은 하나입니다 /branch는 대화를 복사할 뿐, 작업 폴더의 파일은 공유합니다. 갈래에서 고친 파일은 원래 세션으로 돌아가도 고쳐진 상태입니다. 파일까지 따로 실험하려면 Git 브랜치나 worktree를 함께 씁니다(7편). 또 같은 세션을 갈라내지 않고 두 터미널에서 이어 열면 두 쪽의 메시지가 한 기록에 뒤섞입니다.

체크포인트와 /rewind

턴을 시작하는 프롬프트를 보낼 때마다 체크포인트가 생기고, Claude가 파일을 고치기 직전 상태가 저장됩니다. 체크포인트는 대화와 함께 저장되므로 터미널을 닫았다가 세션을 이어 열어도 되감을 수 있고, 세션과 함께 30일(설정 가능) 뒤 정리됩니다.

/rewind를 실행하거나, 입력창이 비어 있을 때 Esc를 두 번 누르면 되감기 메뉴가 열립니다. 입력창에 글자가 있으면 Esc 두 번은 글자를 지웁니다. 보낸 프롬프트 목록에서 지점을 고르고 동작을 선택합니다.

동작코드대화언제
Restore code and conversation⏪ 되돌림⏪ 되돌림그 지점으로 완전히 돌아가 다른 방법으로
Restore conversation유지⏪ 되돌림코드는 마음에 드는데 대화 방향이 틀어졌을 때
Restore code⏪ 되돌림유지지금까지 논의는 살리고 코드만 이전으로
Summarize from here유지그 지점부터 요약곁가지 토론을 압축해 공간 확보, 앞부분은 원문 그대로
Summarize up to here유지그 지점 이전을 요약오래된 앞부분만 압축, 최근 대화는 원문 그대로

코드 복원 두 가지는 고른 지점 이후에 추적된 파일 변경이 있을 때만 메뉴에 나옵니다. 대화를 되돌리거나 Summarize from here를 고르면 그 지점의 원래 프롬프트가 입력창에 다시 들어와, 고쳐서 다시 보낼 수 있습니다. Never mind는 아무것도 하지 않고 닫습니다.

되감기 시뮬레이터

대시보드 프로젝트에서 여섯 번 프롬프트를 보낸 상태입니다. 지점(왼쪽)을 고르고 동작(가운데)을 눌러 결과(오른쪽)를 보세요.

① 되감을 지점
② 동작
③ 결과
대화
/clear 이전으로도 되감을 수 있습니다 같은 Claude Code 프로세스에서 앞서 /clear를 했다면, 되감기 메뉴 맨 위에 /resume <세션-ID> (previous session) 항목이 추가로 보입니다. 비운 대화로 돌아가는 통로입니다.
되감기는 대담함의 보험 공식 문서는 모든 수를 신중히 계획하는 대신 위험한 시도를 맡겨 보고, 안 되면 되감아 다른 방법을 시도하라고 권합니다. 단, 7장의 한계를 알고 있을 때만입니다.

체크포인트가 못 잡는 것

Bash로 바꾼 파일

rm, mv, cp, sed -i, 스크립트가 만든 파일. 되감아도 그대로입니다.

내가 직접 고친 것

에디터에서 손으로 고친 파일, 다른 동시 세션의 편집은 보통 잡히지 않습니다(같은 파일을 Claude도 고친 경우 제외).

컴퓨터 밖의 변화

DB 변경, API 호출, 배포, 원격 서버 명령, git push. 2편부터 반복한 경고입니다.

일부 서브에이전트 편집

백그라운드로 도는 서브에이전트나 스킬 등이 한 편집은 되감기로 복원되지 않을 수 있습니다. Git으로 되돌리세요.

심볼릭·하드 링크

링크 파일은 건너뛰고 “Restored the code, but skipped N files” 경고를 보여 줍니다.

잡는 것

현재 세션에서 Claude의 Edit·Write 같은 파일 편집 도구로 바뀐 파일.

그래서 규칙은 하나: 위험한 시도 전에 커밋 5편에서 장애 주입 전에 커밋했던 이유입니다. 커밋이 있으면 Bash가 무엇을 했든 git status로 보고 git restore나 git checkout으로 돌아갈 수 있습니다. Git 사용법은 바로 다음 7편에서 다룹니다.

컨텍스트 정리 도구 고르기

도구무엇이 남나언제
/clear빈 컨텍스트로 새 세션. 이전 세션은 저장되어 /resume으로 돌아갈 수 있음관련 없는 작업으로 넘어갈 때, 두 번 교정해도 안 될 때(4편)
/clear 이름떠나는 세션에 그 이름을 붙이고 새 세션은 이름 없이 시작지금 작업을 나중에 이름으로 찾고 싶을 때
/compact [지시]전체 대화를 요약으로 대체. 지시로 초점 지정같은 작업을 이어가는데 공간이 필요할 때, 작업 사이 쉼표에서(2편 캐시)
Summarize from here고른 지점 앞은 원문, 그 뒤만 요약방금의 곁가지 토론·시행착오만 압축
Summarize up to here고른 지점 앞만 요약, 뒤는 원문초반 탐색은 압축하고 최근 작업은 그대로
/btw 질문답이 기록에 남지 않음잠깐 확인할 곁가지 질문
압축 후에도 살아남게 하려면 CLAUDE.md에 “압축할 때는 수정한 파일 목록과 테스트 명령을 반드시 남겨” 같은 지시를 적어 둘 수 있습니다(8편). 이름을 지정한 세션은 /clear 후에도 그 이름을 유지하지만, 자동 생성된 제목은 유지되지 않습니다.
