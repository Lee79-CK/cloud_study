MCP란 무엇인가

MCP(Model Context Protocol)는 AI가 외부 도구·데이터와 연결되는 공개 표준입니다. 1편 용어 사전의 비유대로, USB-C처럼 한 번 규격을 맞추면 어떤 서비스든 같은 방식으로 꽂을 수 있습니다. Claude Code는 클라이언트, 연결되는 쪽은 MCP 서버입니다. 공식 문서가 꼽는 쓰임: 이슈 트래커의 이슈로 기능 구현, 모니터링 데이터 분석, 데이터베이스 조회, 디자인 파일 연동, 업무 흐름 자동화.

🛠️ 도구 (tools)

Claude가 호출하는 기능. 이름은 mcp__서버__도구 모양으로 보입니다. 이번 편의 중심.

📄 리소스 (resources)

서버가 제공하는 읽을거리. 프롬프트에서 @로 가리켜 맥락에 넣을 수 있습니다.

💬 프롬프트 (prompts)

서버가 제공하는 미리 만든 지시. 슬래시 명령으로 나타납니다.

MCP냐 CLI냐

공식 모범 사례 문서는 CLI 도구가 외부 서비스와 일하는 가장 컨텍스트 효율적인 방법이라고 합니다. gh, aws, gcloud, kubectl이 이미 있다면 Claude는 Bash로 그대로 씁니다. MCP가 빛나는 곳은 따로 있습니다.

⌨️ CLI가 나을 때

  • 좋은 CLI가 이미 있고 Claude가 잘 안다
  • 출력을 grep·jq로 줄여 볼 수 있다
  • 권한 규칙·샌드박스(9편)로 통제하고 싶다

🔌 MCP가 나을 때

  • CLI가 없거나 불편한 SaaS (Notion, Figma, Sentry 등)
  • OAuth 로그인이 필요한 원격 서비스
  • 할 수 있는 일을 도구 단위로 좁히고 싶다: “조회 3개만” 같은 서버

서버 추가하기

터미널에서 claude mcp add로 추가합니다. stdio는 -- 뒤에 서버를 띄울 명령을 씁니다. 아래 생성기로 명령과 저장되는 설정을 비교해 보세요.

공식 문서의 예

claude mcp add --transport http notion https://mcp.notion.com/mcp
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp

JSON으로 바로

공급자 문서의 JSON 설정을 그대로 붙여 넣으려면 claude mcp add-json 이름 '{…}'.

Claude에게 맡기기

“이 문서를 보고 Sentry MCP를 프로젝트 범위로 추가해줘”처럼 시켜도 됩니다. 단 명령을 실행하기 전에 범위와 헤더를 확인하세요.

범위와 .mcp.json

범위플래그저장 위치누구에게어울리는 것
로컬 (기본)--scope local~/.claude.json의 이 프로젝트 항목나, 이 프로젝트개인 실험, 민감한 자격 증명
프로젝트--scope project저장소 루트의 .mcp.json저장소를 받는 모두팀 공용 도구 (커밋)
사용자--scope user~/.claude.json 최상위나, 모든 프로젝트어디서나 쓰는 개인 도구

.mcp.json의 환경 변수 확장

.mcp.json은 커밋되므로 비밀을 적으면 안 됩니다. 대신 ${VAR}와 ${VAR:-기본값}을 command, args, env, url, headers에 쓸 수 있어, 값은 각자의 환경 변수에서 채웁니다.

{ "mcpServers": { "api-server": { "type": "http", "url": "${API_BASE_URL:-https://api.example.com}/mcp", "headers": { "Authorization": "Bearer ${API_KEY}" } } } }
저장소의 .mcp.json은 스스로를 승인하지 못합니다 남이 커밋한 .mcp.json의 서버는 대화형 세션에서 연결 전에 여러분의 승인을 받습니다. 저장소 설정 안의 “미리 승인” 항목은 인정되지 않습니다. 단 9편에서 봤듯 claude -p와 SDK는 신뢰 창이 없어 승인 여부와 상관없이 연결하므로, 모르는 저장소의 무인 실행 전에는 --setting-sources user나 disabledMcpjsonServers를 고려하세요.

인증과 비밀

🔐 OAuth (원격 http 서버)

서버를 추가한 뒤 세션에서 /mcp를 열고 해당 서버를 인증합니다. 브라우저 로그인이 끝나면 토큰은 Claude Code가 관리합니다. 고정 콜백 포트가 필요한 서비스는 --callback-port.

🔑 고정 토큰 (헤더)

--header "Authorization: Bearer …". 이 값은 ~/.claude.json에 저장되므로 로컬이나 사용자 범위에만 쓰세요. 프로젝트 범위라면 ${API_KEY} 확장으로.

🌱 stdio 서버의 비밀

--env KEY=값 또는 .mcp.json의 env에 ${KEY}. 서버 프로세스의 환경 변수로 들어갑니다.

최소 권한 토큰

MCP 서버는 받은 토큰이 허락하는 모든 일을 할 수 있습니다. 읽기만 필요하면 읽기 전용 토큰·계정을 발급하세요. 이것이 도구 이름보다 확실한 울타리입니다.

컨텍스트·리소스·프롬프트

도구 정의는 지연 로드

2편에서 봤듯 기본으로 MCP 도구 정의는 처음부터 전부 싣지 않고 이름과 서버 설명만 두었다가 필요할 때 불러옵니다(도구 검색). 서버를 여럿 붙여도 컨텍스트 부담이 적고, 연결·해제해도 캐시가 덜 깨집니다.

큰 출력 주의

MCP 도구가 아주 큰 결과를 돌려주면 경고가 뜨고 일정 크기에서 잘립니다. 한도는 환경 변수 MAX_MCP_OUTPUT_TOKENS로 조정합니다. 서버 쪽에서 결과를 요약·필터하는 도구를 만드는 편이 근본 해결입니다.

@ 리소스

리소스를 제공하는 서버라면 프롬프트에서 @서버:로 시작하는 멘션을 자동 완성해 그 내용을 맥락에 넣을 수 있습니다.

프롬프트 = 명령

서버가 제공하는 프롬프트는 /mcp__서버__프롬프트 모양의 슬래시 명령으로 나타납니다.

보안: 남의 서버를 들이기 전에

MCP 서버는 여러분 컴퓨터에서 도는 남의 코드이거나(stdio), 여러분 자격 증명을 쥐고 도는 원격 서비스입니다(http). 그리고 서버가 돌려주는 내용은 1편 리스크 지도의 프롬프트 인젝션 통로가 될 수 있습니다. 들이기 전에 점검해 보세요.

연결한 뒤의 울타리

장치MCP에 쓰는 법
권한 규칙 (9편)deny mcp__*(MCP 전체 차단), deny mcp__github__delete_*(특정 도구군 차단), allow mcp__k8s-ro__*(서버 이름이 고정된 allow만 인정). 괄호가 붙은 mcp__ 규칙은 설정 파일에서 무시됨
Hook (11편)matcher mcp__k8s-ro__.*로 호출 기록·검사. mcp__서버만 쓰면 아무것도 안 맞으니 .*까지
샌드박스 (9편)MCP 서버를 자동으로 가두지 않습니다. stdio 서버가 무엇을 하는지는 서버 코드가 정합니다
관리형 설정 (24편)조직이 허용·거부 목록으로 쓸 수 있는 서버를 정함. 거부가 항상 우선
MSP: 고객 클러스터에 “만능” MCP를 붙이지 마세요 kubectl의 모든 기능을 여는 범용 서버보다, 오늘 만들 것처럼 조회 몇 개만 제공하는 서버 + 읽기 전용 서비스 계정 + 컨텍스트 고정이 훨씬 안전합니다. 도구가 없으면 Claude는 그 일을 할 방법 자체가 없습니다.

직접 만든 k8s-ro 서버

Python 표준 라이브러리만 쓴 stdio MCP 서버입니다. 이 강의를 만들며 공식 MCP Python SDK(v2.3.0)의 클라이언트로 접속해 초기화, 도구 목록, 도구 호출, 잘못된 네임스페이스 거부(x; rm -rf /), 없는 도구 거부, kubectl 없음 처리를 확인했습니다. 학습용 최소 구현이며, 운영에서는 공식 SDK로 만드는 것을 권합니다.

도구 3개뿐

get_pods · get_events · get_nodes. 삭제·적용 도구는 존재하지 않음.

셸 없음

kubectl을 고정 인자 리스트로 실행. 5편의 명령 주입 위험 차단.

입력 검증

네임스페이스는 쿠버네티스 이름 규칙 정규식으로만 허용.

컨텍스트 고정·데모 모드

KUBE_CONTEXT로 대상 클러스터 고정, MCP_K8S_DEMO=1이면 클러스터 없이 가짜 출력.

📄 tools/k8s_readonly_mcp.py
#!/usr/bin/env python3 """k8s-ro: 읽기 전용 Kubernetes 조회 MCP 서버 (Python 표준 라이브러리만 사용). MCP는 stdio 위의 JSON-RPC 2.0 입니다. 이 서버는 세 가지 도구만 제공합니다: get_pods(namespace), get_events(namespace), get_nodes() kubectl 을 고정된 인자로만 실행하고(셸 사용 안 함), 변경 명령은 만들 수 없습니다. 환경 변수 KUBE_CONTEXT : 이 컨텍스트로 고정 (--context). 비우면 현재 컨텍스트 MCP_K8S_DEMO=1 : 클러스터 없이 실습용 가짜 출력 """ import json, os, re, subprocess, sys NS_RE = re.compile(r"^[a-z0-9]([-a-z0-9]{0,61}[a-z0-9])?$") DEMO = os.environ.get("MCP_K8S_DEMO") == "1" CONTEXT = os.environ.get("KUBE_CONTEXT", "") TOOLS = [ {"name": "get_pods", "description": "네임스페이스의 파드 목록과 상태(재시작 횟수 포함)를 조회한다. 읽기 전용.", "inputSchema": {"type": "object", "properties": {"namespace": {"type": "string", "description": "예: default"}}, "required": ["namespace"]}}, {"name": "get_events", "description": "네임스페이스의 최근 이벤트를 시간순으로 조회한다. 장애 원인 조사용. 읽기 전용.", "inputSchema": {"type": "object", "properties": {"namespace": {"type": "string"}}, "required": ["namespace"]}}, {"name": "get_nodes", "description": "노드 목록과 상태를 조회한다. 읽기 전용.", "inputSchema": {"type": "object", "properties": {}}}, ] DEMO_OUT = { "get_pods": "NAME READY STATUS RESTARTS AGE\napi-7f9c6d-x2k4p 1/1 Running 0 3d\npayment-5d8b7-qq91z 0/1 CrashLoopBackOff 14 2h\nworker-6c4f9-mm2l8 1/1 Running 2 1d", "get_events": "LAST SEEN TYPE REASON OBJECT MESSAGE\n2m Warning BackOff pod/payment-5d8b7-qq91z Back-off restarting failed container\n5m Warning Unhealthy pod/payment-5d8b7-qq91z Readiness probe failed: connection refused", "get_nodes": "NAME STATUS ROLES AGE VERSION\nnode-a Ready control-plane 40d v1.31.2\nnode-b Ready <none> 40d v1.31.2", } def kubectl(args): if DEMO: return None cmd = ["kubectl"] + (["--context", CONTEXT] if CONTEXT else []) + args try: r = subprocess.run(cmd, capture_output=True, text=True, timeout=20) except FileNotFoundError: raise RuntimeError("kubectl을 찾을 수 없습니다.
