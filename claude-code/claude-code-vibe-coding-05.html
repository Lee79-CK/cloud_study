출발 점검과 명세

예시 명세 (SPEC.md)

4편의 인터뷰로 만든 명세가 있으면 그것을 쓰세요. 아래는 비교와 대체용입니다. “범위 밖”과 “끝에서 끝까지 검증”이 들어 있는지가 핵심입니다.

# 서버 상태 대시보드 명세 ## 목적 servers.txt의 서버들이 응답하는지 한 화면에서 본다. 운영자 한 명이 자기 PC에서 쓴다. ## 기능 - servers.txt(이름 IP 포트, 공백 구분, # 주석)를 읽는다 - 서버마다 지정 포트로 TCP 연결을 시도한다 (타임아웃 1초, 병렬) - GET /api/status 가 JSON으로 결과를 돌려준다: 이름, IP, 포트, up, 응답시간(ms) - 웹 화면: 서버별 카드, 응답 없음은 빨간색, 마지막 확인 시각과 요약, 30초마다 갱신 ## 제약 - Python 3 표준 라이브러리만. 외부 패키지·CDN 금지 - 127.0.0.1:8080 에만 바인딩 - 셸 명령(ping 등) 실행 금지 - 서버에 아무것도 설치하거나 쓰지 않는다 (읽기 전용 확인) ## 범위 밖 - 로그인·사용자 구분, 알림, 디스크·메모리 지표, 이력 저장 ## 끝에서 끝까지 검증 1. 가짜 서버(127.0.0.1:8001)를 띄우고 백엔드를 실행한다 2. curl /api/status 에서 lab-a만 up, 나머지 down, 응답 2초 이내 3. 브라우저에서 카드 색과 요약이 맞는지 확인 4. 가짜 서버를 끄면 30초 안에 lab-a 카드가 빨간색으로 바뀐다

설계 결정 네 가지

바이브 코딩에서도 결정은 사람이 합니다. Claude는 계획 단계에서 여러 선택지를 제안할 것이고, 여러분은 이유를 알고 고르면 됩니다. 이 강의가 고른 답과 이유입니다.

상태는 어떻게 확인하나?

선택: 포트로 TCP 연결 시도

지정한 포트에 연결이 1초 안에 맺어지면 “응답함”.

다른 선택지와 비교

ICMP ping: 많은 클라우드·방화벽이 막고, 컨테이너·WSL에서는 권한 문제가 납니다. 게다가 “서비스가 살아 있는지”가 아니라 “호스트가 살아 있는지”만 봅니다.
HTTP 요청: 웹 서버에는 더 정확하지만 SSH·DB 같은 포트에는 안 맞습니다. 확장 과제로 남깁니다.

백엔드는 무엇으로?

선택: Python 표준 라이브러리만

http.server와 socket으로 충분합니다. 설치할 것이 없습니다.

다른 선택지와 비교

Flask·FastAPI: 더 편하지만 패키지 설치와 가상환경이 필요합니다. 고객사 작업 VM처럼 설치가 제한된 환경을 연습하는 의미도 있습니다. 1편 리스크 지도의 “환각 패키지” 위험도 피합니다.

여러 서버를 어떻게 확인하나?

선택: 스레드로 병렬 확인

응답 없는 서버가 3대면 순서대로는 3초, 병렬이면 약 1초.

다른 선택지와 비교

순차 확인: 코드가 단순하지만 서버 수만큼 느려집니다. 30초 갱신 주기를 넘기는 순간 화면이 밀립니다. 7장 실험 3번에서 직접 확인합니다.
asyncio: 대량에는 좋지만 이 규모에는 과합니다.

화면은 무엇으로?

선택: HTML 한 장 + 순수 JavaScript

빌드 도구 없이 백엔드가 그대로 내려줍니다.

다른 선택지와 비교

React·Vue: 화면이 커지면 좋지만, Node.js와 빌드 단계가 추가됩니다. 지금 단계에서는 이해하고 고칠 수 있는 코드가 더 중요합니다(1편의 이해 부채).

보안 결정 하나는 처음부터 고정합니다 백엔드는 127.0.0.1(내 컴퓨터에서만 접속)로 띄웁니다. 0.0.0.0으로 띄우면 같은 네트워크의 누구나 고객사 서버 목록과 상태를 볼 수 있습니다. 이 결정은 프롬프트의 제약에 명시합니다.

실습용 가짜 서버 준비

servers.txt의 10.0.x.x 주소는 가짜라서 전부 “응답 없음”으로 나올 것입니다. 초록색 카드도 봐야 검증이 되니, 내 컴퓨터에 살아 있는 서버 하나와 꺼진 서버 하나를 목록에 추가합니다.

cd ~/vibe-lab cat >> servers.txt <<'LAB' # 실습용 로컬 서버 lab-a 127.0.0.1 8001 lab-b 127.0.0.1 8002 LAB git commit -am "실습용 로컬 서버 추가" # 다른 터미널 창에서 lab-a 역할을 할 가짜 서버를 띄웁니다 (lab-b는 일부러 안 띄움) python3 -m http.server 8001

이 터미널은 열어 둔 채로 진행합니다. 7장 실험에서 이 창을 Ctrl+C로 끄면 lab-a가 빨간색으로 바뀌어야 합니다. 이 준비 작업도 Claude에게 시킬 수 있지만, 계속 떠 있어야 하는 프로세스는 직접 띄우는 편이 흐름을 이해하기 쉽습니다.

사이클 2: 화면

백엔드가 커밋되었으니 깨끗한 기준점이 있습니다. 화면은 계획이 간단하므로 Plan 모드를 건너뛰어도 되지만, 첫 실습이니 짧게라도 계획을 받아 보세요. 주제가 바뀌었으므로 /clear로 새로 시작하는 것도 좋습니다. 필요한 맥락은 SPEC.md와 커밋에 있습니다.

@SPEC.md 와 @dashboard/server.py 를 보고 화면을 만들어줘. - dashboard/static/index.html 한 파일. server.py가 / 에서 이 파일을 내려주게 연결 - 서버마다 카드 하나: 이름, ip:port, 응답 시간. 응답 없음은 빨간색 - 위쪽에 마지막 확인 시각과 “N대 중 M대 응답 없음” 요약 - 30초마다 /api/status 를 다시 가져오기. 실패하면 화면 위에 오류 배너, 마지막 카드는 유지 - 외부 CDN·라이브러리 금지. 서버 이름은 textContent로 넣어 HTML로 해석되지 않게 검증: 서버를 띄운 뒤 curl로 / 가 200인지 확인하고, 화면에서 확인할 항목을 체크리스트로 줘.

핵심 diff만 읽기

1편의 3단계 기어, 가이드 바이브 코딩은 모든 줄을 읽지 않되 위험이 숨는 줄은 골라 읽습니다. 이런 앱에서 볼 곳은 정해져 있습니다.

🌐 바인딩 주소

0.0.0.0이면 외부에 열립니다. 127.0.0.1인지 확인.

🐚 셸 실행

subprocess, os.system, shell=True. 파일 내용이 명령에 섞이면 명령 주입.

📂 파일 경로

요청 주소로 파일을 여는 코드. ../로 다른 파일을 읽을 수 있는지.

🔑 비밀

코드에 박힌 키·비밀번호. 커밋 전에 반드시.

🖼️ HTML 삽입

innerHTML에 외부 데이터. 서버 이름에 스크립트가 들어오면 실행됩니다.

⏳ 시간 제한

타임아웃이 없거나 순차 처리라면 서버 하나가 전체를 멈춥니다.

게임: 이 코드에서 위험한 줄을 찾아보세요

어느 날 다른 세션에서 Claude가 이런 코드를 내놓았다고 합시다. 문제라고 생각하는 줄을 누른 뒤 “채점”하세요.

diff를 직접 다 읽기 어려울 때 “방금 변경에서 위 여섯 가지 관점으로 위험한 줄이 있는지 줄 번호와 함께 알려줘”라고 Claude에게 물어도 됩니다. 단, 같은 세션의 Claude는 자기가 쓴 코드에 관대할 수 있으니, 중요한 코드는 /clear 후 새 세션이나 리뷰 서브에이전트에게 묻습니다(4편 검증 사다리 4단, 18편).

테스트와 README

다음에 이 코드를 고칠 때 망가뜨리지 않으려면 테스트가 안전망입니다. 네트워크에 의존하지 않는 부분, 즉 servers.txt 파싱부터 테스트하게 합니다. 실험 2에서 발견한 경우들이 그대로 테스트 케이스가 됩니다.

dashboard/server.py 의 servers.txt 파싱 부분에 대한 단위 테스트를 dashboard/test_server.py 로 써줘. unittest만 쓰고 네트워크에 접속하지 마. 주석, 빈 줄, 칸 수 오류, 포트가 숫자가 아닌 줄, 줄 끝 주석을 다뤄. 테스트를 실행해서 출력을 보여주고, 실패하면 테스트가 아니라 코드를 고쳐. 그다음 README.md에 대시보드 실행 방법(가짜 서버 띄우기 포함)과 테스트 실행 방법을 짧게 추가하고 커밋해줘.

“실패하면 테스트가 아니라 코드를 고쳐”는 4편의 “증상을 숨기지 말라”를 테스트에 적용한 문장입니다.

#!/usr/bin/env python3 """vibe-lab 서버 상태 대시보드 (참고 구현, 표준 라이브러리만 사용)""" import json import socket import time from concurrent.futures import ThreadPoolExecutor from http.server import SimpleHTTPRequestHandler, ThreadingHTTPServer from pathlib import Path BASE = Path(__file__).resolve().parent SERVERS_FILE = BASE.parent / "servers.txt" HOST, PORT, TIMEOUT = "127.0.0.1", 8080, 1.0 def load_servers(path=SERVERS_FILE): """servers.txt를 읽어 [{name, ip, port}] 목록으로. 주석·빈 줄·형식 오류 줄은 건너뜀.""" servers = [] for line in path.read_text(encoding="utf-8").splitlines(): line = line.split("#", 1)[0].strip() if not line: continue parts = line.split() if len(parts) != 3 or not parts[2].isdigit(): continue servers.append({"name": parts[0], "ip": parts[1], "port": int(parts[2])}) return servers def check(server): """TCP 연결이 TIMEOUT 안에 맺어지면 up. 응답 시간(ms)도 잰다.""" start = time.monotonic() try: with socket.create_connection((server["ip"], server["port"]), timeout=TIMEOUT): up = True except OSError: up = False ms = round((time.monotonic() - start) * 1000) return {**server, "up": up, "ms": ms if up else None} class Handler(SimpleHTTPRequestHandler): def __init__(self, *args, **kwargs): super().__init__(*args, directory=str(BASE / "static"), **kwargs) def do_GET(self): if self.path.split("?", 1)[0] == "/api/status": try: servers = load_servers() except FileNotFoundError: return self.send_json({"error": "servers.txt를 찾을 수 없습니다"}, 500) with ThreadPoolExecutor(max_workers=min(32, len(servers) or 1)) as pool: results = list(pool.map(check, servers)) return self.send_json({"checked_at": time.strftime("%Y-%m-%d %H:%M:%S"), "servers": results}) return super().do_GET() def send_json(self, data, code=200): body = json.dumps(data, ensure_ascii=False).encode("utf-8") self.send_response(code) self.send_header("Content-Type", "application/json; charset=utf-8") self.send_header("Cache-Control", "no-store") self.send_header("Content-Length", str(len(body))) self.end_headers() self.wfile.write(body) if __name__ == "__main__": print(f"대시보드: http://{HOST}:{PORT}") ThreadingHTTPServer((HOST, PORT), Handler).serve_forever()
