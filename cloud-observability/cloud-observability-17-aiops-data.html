Cloud 모니터링·로깅 실전 강의 17편 (Level 6. AIOps와 종합, 첫 편)

AIOps를 위한 관측 데이터 설계

LLM에게 "결제가 왜 느려졌지?"라고 물으면 대답의 품질은 모델보다 먼저 데이터가 정합니다. 신호마다 고객사와 서비스를 같은 이름으로 부르는지, 알림이 도착할 때 근거가 함께 오는지, 모델이 무엇을 읽을 수 있고 무엇은 절대 못 하는지. 이 편은 AIOps 챗봇의 이벤트 수신 어댑터와 MCP 도구에 바로 가져다 쓸 수 있는 형태로 만듭니다.

대상: 1~2년차 클라우드 엔지니어 형식: 개념 + 실습 5개 예상 소요: 4~5시간 기준: MCP Python SDK 2.3, mcp-grafana 2.0.2
실제로 만들어진 사건 묶음Alertmanager가 보낸 알림 하나를 이 편의 보강기가 받아, 메트릭, 로그, 트레이스를 모아 만든 결과 그대로입니다. 오류율 10% 장애를 넣은 결제 서비스에서 작성 중 생성했습니다.

0시작하기 전에

Level 6의 첫 편입니다. 1~16편에서 만든 관측 플랫폼을 사람 대신(또는 사람과 함께) 읽을 AI에게 여는 방법을 다룹니다.

학습 목표

  1. AIOps가 실패하는 데이터 쪽 원인(식별자 불일치, 문맥 부족, 과도한 원문)을 설명할 수 있다.
  2. 고객사, 서비스, 트레이스 식별자를 모든 신호에서 같은 열쇠로 쓰도록 점검하고 고칠 수 있다.
  3. 알림에 관련 메트릭, 로그, 트레이스를 붙이는 보강기를 만들고 결과를 사건 묶음으로 넘길 수 있다.
  4. 관측 API를 LLM이 쓸 수 있는 MCP 도구로 만들되, 테넌트 고정, 의도 기반 입력, 상한, 입력 검사로 안전하게 설계할 수 있다.
  5. Grafana MCP 서버를 읽기 전용으로 배치할 수 있다.
  6. 도구, 입구, 저장소의 세 겹으로 읽기 전용 권한을 강제하고 감사 기록을 남길 수 있다.

1왜 데이터 설계가 먼저인가

AIOps가 틀리는 이유예데이터 쪽 해결
같은 대상을 다른 이름으로 부름메트릭은 service="payment", 로그는 service_name="payment", 알림은 서비스 라벨 없음식별자 표준과 점검 (2장)
근거 없이 추측알림 제목만 보고 "DB 문제 같습니다"알림이 도착할 때 근거를 같이 붙임 (3장)
원문이 너무 많음로그 수천 줄을 그대로 넣어 문맥 창이 넘치거나 비용 폭증비슷한 줄을 묶고 숫자는 요약 (3장, 실측 128줄 → 1패턴)
모델이 쿼리를 잘못 씀존재하지 않는 라벨, 무거운 범위, 다른 고객사 데이터 조회원문 쿼리 대신 의도를 받는 도구 (4장)
모델이 위험한 일을 함규칙 삭제, 로그 삭제 요청, 대량 질의로 저장소 마비세 겹의 읽기 전용 (6장)

그래서 이 편의 순서는 "데이터 표준 → 근거 묶음 → 도구 → 권한"입니다. 모델을 바꾸는 것보다 이 네 가지를 고치는 것이 답의 품질에 더 큰 영향을 줍니다.

실측으로 찾은 불일치 1: OTLP 로그의 customer

9편에서 만든 Loki Ruler 알림 LogsSilent(absent_over_time({customer="cust-a", service_name="payment"}[5m]))가 이 편의 실험 중에 critical로 울렸습니다. 결제 로그는 멀쩡히 들어오고 있었습니다. 원인은 12편부터 결제 로그가 Alloy가 아니라 OTLP로 들어오면서 customer가 색인 라벨이 아니라 Structured Metadata가 되었기 때문입니다(Loki는 OTLP 리소스 속성 중 정해진 것만 라벨로 올림, 11편). 셀렉터 {customer="cust-a"}가 OTLP 로그와 맞지 않으니 "로그가 없다"는 잘못된 판단이 나온 것입니다. Loki 테넌트 한도의 otlp_config로 customer를 색인 라벨로 승격하자 같은 셀렉터로 OTLP 로그가 다시 잡혔습니다(Lab 1). 자동화가 사람보다 먼저 이런 불일치에 걸린다는 좋은 예입니다.

실측으로 찾은 불일치 2: service와 service_name

4~6편의 lab-app 지표와 알림 규칙은 service 라벨을 썼고, 8편 이후의 로그와 11편 이후의 OTel 계열은 service_name을 씁니다. 6편 규칙에서 나온 알림을 보강기가 받으면 service_name이 없어 근거를 못 모읍니다. 보강기에 "service_name이 없으면 service"라는 대체 규칙을 넣고 어느 라벨을 썼는지 묶음에 기록했으며(실측에서 service_label_used: service로 정상 처리), 근본적으로는 알림 규칙에서 service_name 라벨을 함께 붙이도록 고칩니다(Lab 1).

세 번째 불일치는 12편에서 이미 봤습니다. Tempo 검색 결과는 앞자리 0을 뗀 31자 trace ID를 돌려줄 수 있어, 로그의 32자 trace_id와 비교하려면 맞춰야 합니다. 이 편의 보강기와 MCP 서버는 모두 32자로 맞춘 뒤 비교합니다.

3알림 보강

알림은 "무엇이 이상하다"만 말합니다. 보강(Enrichment)은 알림이 도착하는 순간 "그 근거"를 함께 모아, 사람이든 LLM이든 첫 질문부터 근거 위에서 시작하게 합니다.

묶음 항목모으는 방법설계 이유
알림 자체웹훅 본문: 이름, 심각도, 시작 시각, 지문, 요약, 런북 URL지문은 같은 사건을 한 스레드로 묶는 열쇠
식별자라벨의 customer, service_name(없으면 service)없으면 보강하지 않고 "식별자 누락"을 기록 (실측)

로그오류 수준 로그를 숫자와 ID를 지운 문장 틀로 묶어 상위 5개, 예시 한 줄씩, trace_id실측 128줄이 한 패턴으로. 비밀번호, 카드 번호는 가림

오류출처별 조회 실패한 출처의 실패가 묶음 전체를 막지 않게 (실측: Loki 재시작 중에도 메트릭, 트레이스는 채워짐)

묶음은 약 4KB였습니다(히어로). 모든 조회에 시간 상한(5초), 줄 수 상한(200), 결과 크기 상한(64KB)을 두었습니다. 보강기는 MSP 내부 구성 요소라 저장소에 직접 질의하고 알림의 customer를 테넌트로 씁니다. 알림 라벨은 우리가 만든 규칙에서만 오기 때문입니다. 반대로 LLM이 직접 부르는 도구(4장)는 테넌트를 입력으로 받지 않습니다.

4관측 API를 LLM 도구로

MCP(Model Context Protocol)는 LLM 애플리케이션이 외부 도구를 같은 방식으로 부르게 하는 표준입니다. 관측 API를 MCP 도구로 내주면 챗봇이 대화 중에 "지난 15분 결제 오류율"을 직접 확인합니다.

도구 설계의 네 원칙

원칙이 편의 구현막는 것

5Grafana MCP 서버

Grafana Labs는 공식 MCP 서버(mcp-grafana)를 제공합니다. 작성 시점 최신은 v2.0.2이며, 대시보드 검색, 데이터소스, Prometheus와 Loki 질의, 알림 규칙, Tempo, Pyroscope 등 기본으로 활성화된 도구 묶음이 스무 개가 넘습니다.

관점Grafana MCP 서버이 편의 관측 MCP 서버
질의 방식모델이 PromQL, LogQL을 직접 작성해 Grafana 데이터소스로의도를 받아 서버가 질의 작성
테넌트 경계서비스 계정이 속한 Grafana 조직의 데이터소스 (16편의 조직 분리에 기댐)서버당 테넌트 고정 + 입구에서 강제
강점대시보드, 알림 규칙, 주석까지 Grafana 전체를 탐색질의 비용과 결과 크기를 예측할 수 있음
쓰기 통제--disable-write, --disable-admin, --enabled-tools, Viewer 권한 서비스 계정쓰기 도구가 애초에 없음

v2.0.2의 옵션을 실제로 확인한 결과, --disable-write는 "생성, 수정 작업 도구를 끔"이고, SQL류 원문 질의 도구는 따로 허용하지 않으면 함께 꺼집니다. HTTP로 띄울 때는 --allowed-hosts(Host 헤더 허용 목록)와 --allowed-origins가 기본으로 엄격하게 잡혀 있어, 클러스터 안 서비스 이름으로 접근하려면 그 이름을 허용 목록에 넣어야 합니다. 두 서버는 경쟁 관계가 아닙니다. 사건 대응 중 정해진 근거 수집은 이 편의 서버로, "이 고객사 대시보드 중 결제 관련 것을 찾아 줘" 같은 탐색은 Grafana MCP 서버로 나누는 것을 권합니다. 서비스 계정은 반드시 Viewer 역할, 고객사별 Grafana 조직 안에 만듭니다.

6읽기 전용 권한 설계

Mimir, Loki, Tempo에는 사용자별 읽기, 쓰기 권한이 없습니다. 테넌트 헤더만 맞으면 쓰기도 지우기도 됩니다. 그래서 읽기 전용은 앞단에서 만들어야 합니다.

1겹

#!/usr/bin/env python3
"""aiops-enricher: Alertmanager 웹훅을 받아 관련 메트릭, 로그, 트레이스를 모아 '사건 묶음'을 만드는 수신기 (17편)

표준 라이브러리만 사용합니다. 알림 라벨의 customer, service_name을 열쇠로 써서
  - 메트릭(Mimir): 서비스의 요청률, 오류율, p99 추이
  - 로그(Loki): 오류 로그를 비슷한 문장끼리 묶은 상위 목록과 trace_id
  - 트레이스(Tempo): 오류 트레이스 목록과 가장 오래 걸린 span
을 조회하고, JSON 묶음과 사람이 읽을 요약을 OUT_DIR에 저장합니다. FORWARD_URL이 있으면 그곳(예: AIOps 챗봇의
이벤트 수신 어댑터)으로 POST 합니다. 모든 조회는 읽기 전용이며 시간, 줄 수, 크기 상한을 둡니다.
"""
import json, os, re, time, urllib.parse, urllib.request
from collections import Counter
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

METRICS_URL = os.environ.get("METRICS_URL", "http://mimir.metrics.svc:8080/prometheus")
LOKI_URL = os.environ.get("LOKI_URL", "http://loki-gateway.logging.svc")
TEMPO_URL = os.environ.get("TEMPO_URL", "http://tempo.tracing.svc:3200")
GRAFANA_URL = os.environ.get("GRAFANA_URL", "http://localhost:30300")
FORWARD_URL = os.environ.get("FORWARD_URL", "")
OUT_DIR = os.environ.get("OUT_DIR", "/tmp/incidents")
PORT = int(os.environ.get("PORT", "5002"))
LOOKBACK_MIN = 15          # 알림 시작 전 몇 분부터 볼지
MAX_LOG_LINES = 200        # 로그 조회 상한
MAX_TRACES = 5             # 트레이스 조회 상한
TIMEOUT = 5                # 조회당 시간 상한(초)
REDACT = [(re.compile(r"(password=)\S+", re.I), r"\1[REDACTED]"),
          (re.compile(r"\b(\d{4})-\d{4}-\d{4}-(\d{4})\b"), r"\1-****-****-\2")]


def get(url, tenant, params):
    req = urllib.request.Request(url + "?" + urllib.parse.urlencode(params, doseq=True),
                                 headers={"X-Scope-OrgID": tenant})
    with urllib.request.urlopen(req, timeout=TIMEOUT) as r:
        return json.load(r)


def redact(s):
    for pat, rep in REDACT:
        s = pat.sub(rep, s)
    return s


def promql(tenant, q, start, end):
    d = get(METRICS_URL + "/api/v1/query_range", tenant, {"query": q, "start": start, "end": end, "step": 60})
    res = d["data"]["result"]
    if not res:
        return None
    vals = [float(v[1]) for v in res[0]["values"] if v[1] not in ("NaN", "+Inf")]
    return {"first": round(vals[0], 4), "last": round(vals[-1], 4), "max": round(max(vals), 4), "points": len(vals)} if vals else None


def metrics(tenant, svc, start, end):
    sel = f'service_name="{svc}", span_kind="SPAN_KIND_SERVER"'
    qs = {
        "request_rate_per_s": f'sum(rate(traces_span_metrics_calls_total{{{sel}}}[5m]))',
        "error_ratio": f'sum(rate(traces_span_metrics_calls_total{{{sel}, status_code="STATUS_CODE_ERROR"}}[5m])) / sum(rate(traces_span_metrics_calls_total{{{sel}}}[5m]))',
        "p99_ms": f'histogram_quantile(0.99, sum by (le) (rate(traces_span_metrics_duration_milliseconds_bucket{{{sel}}}[5m])))',
    }
    return {name: {"query": q, "result": promql(tenant, q, start, end)} for name, q in qs.items()}


def normalize(line):
    line = re.sub(r"\b[0-9a-f]{16,32}\b", "<id>", line)
    line = re.sub(r"\b[a-z]-\d+\b", "<id>", line)
    return re.sub(r"\d+", "<n>", line)


def logs(tenant, svc, start, end):
    q = f'{{service_name="{svc}"}} | detected_level=~"(?i)error|fatal"'
    d = get(LOKI_URL + "/loki/api/v1/query_range", tenant,
            {"query": q, "start": int(start * 1e9), "end": int(end * 1e9), "limit": MAX_LOG_LINES})
    groups, examples, trace_ids = Counter(), {}, []
    for stream in d["data"]["result"]:
        tid = stream["stream"].get("trace_id")
        for _, line in stream["values"]:
            key = normalize(line)
            groups[key] += 1
            examples.setdefault(key, redact(line))
            if tid:
                trace_ids.append(tid)
    top = [{"count": c, "example": examples[k]} for k, c in groups.most_common(5)]
    return {"query": q, "total_lines": sum(groups.values()), "top_patterns": top, "trace_ids": list(dict.fromkeys(trace_ids))[:10]}


def traces(tenant, svc, start, end):
    q = f'{{ resource.service.name = "{svc}" && status = error }}'
    d = get(TEMPO_URL + "/api/search", tenant, {"q": q, "start": int(start), "end": int(end), "limit": MAX_TRACES})
    found = [{"trace_id": t["traceID"].rjust(32, "0"), "root": t.get("rootTraceName"), "duration_ms": t.get("durationMs")}
             for t in d.get("traces", [])]
    slowest = []
    if found:
        full = get(TEMPO_URL + "/api/v2/traces/" + found[0]["trace_id"], tenant, {})
        for rs in full.get("trace", full).get("resourceSpans", []):
            name = next((a["value"].get("stringValue") for a in rs["resource"]["attributes"] if a["key"] == "service.name"), "?")
            for ss in rs.get("scopeSpans", []):
                for sp in ss.get("spans", []):
                    ms = (int(sp["endTimeUnixNano"]) - int(sp["startTimeUnixNano"])) / 1e6
                    slowest.append({"service": name, "span": sp["name"], "ms": round(ms, 1),
                                    "error": sp.get("status", {}).get("code") == "STATUS_CODE_ERROR"})
        slowest.sort(key=lambda x: -x["ms"])
    return {"query": q, "error_traces": found, "first_trace_spans": slowest[:6]}


def enrich(alert):
    lb, ann = alert.get("labels", {}), alert.get("annotations", {})
    tenant = lb.get("customer")
    svc = lb.get("service_name") or lb.get("service")          # 4~6편 규칙은 service, OTel 계열은 service_name
    id_key = "service_name" if lb.get("service_name") else ("service" if lb.get("service") else None)
    bundle = {"alert": {"name": lb.get("alertname"), "status": alert.get("status"), "severity": lb.get("severity"),
                        "starts_at": alert.get("startsAt"), "fingerprint": alert.get("fingerprint"),
                        "summary": ann.get("summary"), "runbook_url": ann.get("runbook_url")},
              "identity": {"customer": tenant, "service_name": svc, "service_label_used": id_key}, "evidence": {}, "errors": []}
    if not tenant or not svc:
        bundle["errors"].append("식별자 누락: 알림 라벨에 customer와 service_name이 모두 있어야 보강할 수 있음")
        return bundle
    end = time.time()
    start = end - LOOKBACK_MIN * 60
    for name, fn in (("metrics", metrics), ("logs", logs), ("traces", traces)):
        try:
            bundle["evidence"][name] = fn(tenant, svc, start, end)
        except Exception as e:                      # 한 출처의 실패가 묶음 전체를 막지 않게
            bundle["errors"].append(f"{name}: {type(e).__name__}: {e}")
    lt = set(bundle["evidence"].get("logs", {}).get("trace_ids", []))
    tt = {t["trace_id"] for t in bundle["evidence"].get("traces", {}).get("error_traces", [])}
    bundle["correlation"] = {"trace_ids_in_both_logs_and_traces": sorted(lt & tt)}
    bundle["links"] = {"explore_logs": f"{GRAFANA_URL}/explore", "runbook": ann.get("runbook_url")}
    return bundle


def summary(b):
    m = b["evidence"].get("metrics", {})
    def mv(k):
        r = (m.get(k) or {}).get("result")
        return f'{r["first"]} → {r["last"]}' if r else "데이터 없음"
    lines = [f'# {b["alert"]["name"]} ({b["alert"]["severity"]}) {b["identity"]["customer"]}/{b["identity"]["service_name"]}',
             f'- 요청률(초당): {mv("request_rate_per_s")}', f'- 오류율: {mv("error_ratio")}', f'- p99(ms): {mv("p99_ms")}']
    lg = b["evidence"].get("logs")
    if lg:
        lines.append(f'- 오류 로그 {lg["total_lines"]}줄, 상위 패턴:')
        lines += [f'  - {p["count"]}회: {p["example"][:160]}' for p in lg["top_patterns"][:3]]
    tr = b["evidence"].get("traces")
    if tr and tr["first_trace_spans"]:
        lines.append(f'- 오류 트레이스 {len(tr["error_traces"])}개, 첫 트레이스의 가장 긴 span:')
        lines += [f'  - {s["service"]} / {s["span"]}: {s["ms"]}ms{" (오류)" if s["error"] else ""}' for s in tr["first_trace_spans"][:3]]
    if b.get("correlation", {}).get("trace_ids_in_both_logs_and_traces"):
        lines.append(f'- 로그와 트레이스에 함께 나온 trace_id: {", ".join(b["correlation"]["trace_ids_in_both_logs_and_traces"][:3])}')
    if b["errors"]:
        lines.append(f'- 수집 오류: {"; ".join(b["errors"])}')
    return "\n".join(lines)


class Handler(BaseHTTPRequestHandler):
    def do_POST(self):
        payload = json.loads(self.rfile.read(int(self.headers.get("Content-Length", 0))) or b"{}")
        self.send_response(200); self.end_headers(); self.wfile.write(b"ok\n")
        os.makedirs(OUT_DIR, exist_ok=True)
        for alert in payload.get("alerts", []):
            if alert.get("status") != "firing":
                continue
            b = enrich(alert)
            b["summary_text"] = summary(b)
            body = json.dumps(b, ensure_ascii=False, indent=1)[:65536]       # 크기 상한
            fname = os.path.join(OUT_DIR, f'{b["alert"]["fingerprint"] or int(time.time())}.json')
            open(fname, "w").write(body)
            print(b["summary_text"], flush=True)
            if FORWARD_URL:
                try:
                    urllib.request.urlopen(urllib.request.Request(FORWARD_URL, data=body.encode(),
                                           headers={"Content-Type": "application/json"}), timeout=TIMEOUT)
                except Exception as e:
                    print("forward failed:", e, flush=True)

    def log_message(self, *a):
        pass


if __name__ == "__main__":
    print(f"aiops-enricher :{PORT} → {OUT_DIR}", flush=True)
    ThreadingHTTPServer(("0.0.0.0", PORT), Handler).serve_forever()

#!/usr/bin/env python3
"""obs-mcp-server: 관측 데이터를 LLM 에이전트에 '읽기 전용 도구'로 내주는 MCP 서버 (17편)

설계 원칙
  1. 테넌트(고객사)는 서버를 띄울 때 환경 변수로 고정. 도구 인자로 받지 않으므로 LLM이 바꿀 수 없음
  2. 원문 PromQL/LogQL/TraceQL을 받지 않음. 의도(서비스, 기간, 찾을 문자열)를 받아 서버가 질의를 만듦
  3. 기간, 개수, 크기에 상한. 입력은 형식 검사 후 사용 (질의 주입 방지)
  4. 모든 도구에 readOnlyHint. 쓰기, 삭제 도구는 만들지 않음
MCP Python SDK 2.x (MCPServer) 기준.
"""
import json, os, re, time, urllib.parse, urllib.request
from mcp.server.mcpserver import MCPServer
from mcp.server.mcpserver.exceptions import ToolError    # 2.x: 이 예외의 메시지만 모델에게 전달됨
from mcp.types import ToolAnnotations

TENANT = os.environ["MCP_TENANT"]                       # 예: cust-a (필수)
METRICS_URL = os.environ.get("METRICS_URL", "http://ai-query-gateway.aiops.svc:8080/prometheus")
LOKI_URL = os.environ.get("LOKI_URL", "http://ai-query-gateway.aiops.svc:8080")
TEMPO_URL = os.environ.get("TEMPO_URL", "http://ai-query-gateway.aiops.svc:8080/tempo")
AUTH = os.environ.get("QUERY_AUTH", "")                 # 읽기 전용 입구의 기본 인증 "user:password"
MAX_MINUTES, MAX_LINES, MAX_TRACES, TIMEOUT = 360, 200, 20, 10
NAME = re.compile(r"^[a-z0-9][a-z0-9_.-]{0,62}$")
TRACE_ID = re.compile(r"^[0-9a-f]{16,32}$")
RO = ToolAnnotations(readOnlyHint=True, destructiveHint=False, openWorldHint=False)

mcp = MCPServer("obs-readonly", instructions=f"고객사 {TENANT}의 관측 데이터를 읽기 전용으로 조회합니다. 숫자는 근거로 인용하세요.")


def _get(url, params):
    headers = {"X-Scope-OrgID": TENANT}
    if AUTH:
        import base64
        headers["Authorization"] = "Basic " + base64.b64encode(AUTH.encode()).decode()
    req = urllib.request.Request(url + "?" + urllib.parse.urlencode(params, doseq=True), headers=headers)
    with urllib.request.urlopen(req, timeout=TIMEOUT) as r:
        return json.load(r)


def _check_name(service):
    if not NAME.match(service):
        raise ToolError("service는 소문자, 숫자, - _ . 로 된 서비스 이름이어야 합니다")


def _window(minutes):
    minutes = max(1, min(int(minutes), MAX_MINUTES))
    end = time.time()
    return end - minutes * 60, end, minutes


def _range(q, start, end):
    d = _get(METRICS_URL + "/api/v1/query_range", {"query": q, "start": start, "end": end, "step": 60})
    r = d["data"]["result"]
    vals = [float(v[1]) for v in r[0]["values"] if v[1] not in ("NaN", "+Inf")] if r else []
    return {"first": round(vals[0], 4), "last": round(vals[-1], 4), "max": round(max(vals), 4)} if vals else None


@mcp.tool(annotations=RO)
def list_services(minutes: int = 60) -> dict:
    """최근 기간에 트레이스 기반 메트릭이 있는 서비스 이름 목록."""
    start, end, minutes = _window(minutes)
    d = _get(METRICS_URL + "/api/v1/query", {"query": f"group by (service_name) (last_over_time(traces_span_metrics_calls_total[{minutes}m]))", "time": end})
    return {"tenant": TENANT, "services": sorted(x["metric"].get("service_name", "") for x in d["data"]["result"])}


@mcp.tool(annotations=RO)
def service_health(service: str, minutes: int = 30) -> dict:
    """서비스의 요청률(초당), 오류율, p99(ms)를 기간의 처음, 마지막, 최대값으로 요약."""
    _check_name(service)
    start, end, minutes = _window(minutes)
    sel = f'service_name="{service}", span_kind="SPAN_KIND_SERVER"'
    return {"tenant": TENANT, "service": service, "minutes": minutes,
            "request_rate_per_s": _range(f"sum(rate(traces_span_metrics_calls_total{{{sel}}}[5m]))", start, end),
            "error_ratio": _range(f'sum(rate(traces_span_metrics_calls_total{{{sel}, status_code="STATUS_CODE_ERROR"}}[5m])) / sum(rate(traces_span_metrics_calls_total{{{sel}}}[5m]))', start, end),
            "p99_ms": _range(f"histogram_quantile(0.99, sum by (le) (rate(traces_span_metrics_duration_milliseconds_bucket{{{sel}}}[5m])))", start, end)}


@mcp.tool(annotations=RO)
def search_error_logs(service: str, minutes: int = 15, contains: str = "", limit: int = 50) -> dict:
    """서비스의 오류 수준 로그를 찾음. contains가 있으면 그 문자열을 포함한 줄만. 비슷한 줄은 묶어서 돌려줌."""
    _check_name(service)
    start, end, minutes = _window(minutes)
    limit = max(1, min(int(limit), MAX_LINES))
    q = f'{{customer="{TENANT}", service_name="{service}"}} | detected_level=~"(?i)error|fatal"'
    if contains:
        safe = re.sub(r'[`"\\{}|]', "", contains)[:100]          # 질의 문법 문자 제거 (주입 방지)
        q += f' |= "{safe}"'
    d = _get(LOKI_URL + "/loki/api/v1/query_range", {"query": q, "start": int(start * 1e9), "end": int(end * 1e9), "limit": limit})
    groups = {}
    for s in d["data"]["result"]:
        for _, line in s["values"]:
            key = re.sub(r"\d+", "<n>", re.sub(r"\b[0-9a-f]{16,32}\b", "<id>", line))
            g = groups.setdefault(key, {"count": 0, "example": re.sub(r"(password=)\S+", r"\1[REDACTED]", line), "trace_ids": []})
            g["count"] += 1
            if s["stream"].get("trace_id") and len(g["trace_ids"]) < 3:
                g["trace_ids"].append(s["stream"]["trace_id"])
    return {"tenant": TENANT, "query": q, "patterns": sorted(groups.values(), key=lambda g: -g["count"])[:10]}


@mcp.tool(annotations=RO)
def find_error_traces(service: str, minutes: int = 15, limit: int = 5) -> dict:
    """서비스에서 오류가 난 트레이스 목록 (trace_id, 루트 이름, 소요 시간)."""
    _check_name(service)
    start, end, _ = _window(minutes)
    q = f'{{ resource.service.name = "{service}" && status = error }}'
    d = _get(TEMPO_URL + "/api/search", {"q": q, "start": int(start), "end": int(end), "limit": max(1, min(int(limit), MAX_TRACES))})
    return {"tenant": TENANT, "query": q, "traces": [{"trace_id": t["traceID"].rjust(32, "0"), "root": t.get("rootTraceName"),
                                                     "duration_ms": t.get("durationMs")} for t in d.get("traces", [])]}


@mcp.tool(annotations=RO)
def get_trace(trace_id: str) -> dict:
    """트레이스 하나의 span을 오래 걸린 순서로 (서비스, 이름, ms, 오류 여부). 최대 20개."""
    trace_id = trace_id.lower().strip()
    if not TRACE_ID.match(trace_id):
        raise ToolError("trace_id는 16~32자리 16진수여야 합니다")
    d = _get(TEMPO_URL + "/api/v2/traces/" + trace_id.rjust(32, "0"), {})
    spans = []
    for rs in d.get("trace", d).get("resourceSpans", []):
        svc = next((a["value"].get("stringValue") for a in rs["resource"]["attributes"] if a["key"] == "service.name"), "?")
        for ss in rs.get("scopeSpans", []):
            for sp in ss.get("spans", []):
                spans.append({"service": svc, "span": sp["name"],
                              "ms": round((int(sp["endTimeUnixNano"]) - int(sp["startTimeUnixNano"])) / 1e6, 1),
                              "error": sp.get("status", {}).get("code") == "STATUS_CODE_ERROR"})
    if not spans:
        return {"tenant": TENANT, "trace_id": trace_id, "found": False}     # Tempo는 없는 트레이스도 200을 줌 (12편)
    return {"tenant": TENANT, "trace_id": trace_id, "found": True, "spans": sorted(spans, key=lambda s: -s["ms"])[:20]}


if __name__ == "__main__":
    if os.environ.get("MCP_TRANSPORT") == "http":           # 클러스터 안의 챗봇, 에이전트가 HTTP로 붙을 때

13트러블슈팅

증상을 눌러 원인과 해결 방법을 확인하세요.

ModuleNotFoundError: No module named 'mcp.server.fastmcp'Lab 4

MCP Python SDK 2.x입니다. from mcp.server.mcpserver import MCPServer로 바꾸거나 1.x 코드를 유지하려면 mcp<2로 고정합니다(실측 오류 메시지가 직접 안내).

도구 오류가 "Error executing tool ..."만 나오고 이유가 없음Lab 4

도구 안에서 일반 예외를 던진 경우입니다. ToolError로 던져야 메시지가 클라이언트로 갑니다(실측).

보강 묶음에 "식별자 누락"Lab 3

알림에 customer 또는 서비스 라벨이 없습니다. 노드, 디스크처럼 서비스와 무관한 알림이면 정상이고, 서비스 알림이면 규칙에 라벨을 더합니다(Lab 1 수정 2).

보강 묶음의 로그가 비어 있음Lab 3

{customer=..., service_name=...} 셀렉터가 로그와 맞지 않는 경우가 대부분입니다. OTLP 로그라면 Lab 1 수정 1(customer 승격)을 확인합니다. 로그 레벨 감지가 안 된 로그는 detected_level이 없어 오류 필터에 걸리지 않습니다.

Alertmanager가 보강기로 보내지 않음Lab 3

보강기 경로가 routes의 맨 앞에 있고 continue: true인지, 매처가 알림의 심각도와 맞는지 확인합니다. amtool config routes test(6편)로 확인합니다.

MCP HTTP 접속이 Host, Origin 관련으로 거부됨Lab 4, 5

MCP 서버들은 DNS 재바인딩 공격을 막으려고 Host와 Origin 헤더를 검사합니다. mcp-grafana는 --allowed-hosts에 클러스터 서비스 이름을, Python SDK는 transport_security 설정에 허용 호스트를 넣습니다.

도구 결과가 늘 빈 값Lab 4

입구 자격 증명의 테넌트와 MCP_TENANT가 다르면, 입구가 덮어쓴 테넌트로 조회되어 엉뚱한(빈) 결과가 나옵니다. 둘을 같은 고객사로 맞춥니다.

입구에서 정상 조회가 403Lab 2

허용 경로 정규식에 없는 API입니다(예: Loki의 detected_fields, Tempo의 태그 검색). 필요한 조회 경로만 하나씩 더합니다. 쓰기 경로는 더하지 않습니다.
