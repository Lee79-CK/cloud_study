Claude Code해부

“말하면 코드가 생긴다”의 내부를 열어 봅니다. 누가 생각하고, 누가 손을 움직이고, 무엇이 기억되고 잊히는지, 그리고 그 모든 것이 비용과 속도로 어떻게 이어지는지 알면 Claude Code를 훨씬 정확하게 다룰 수 있습니다.

에이전트 = 모델 + 하네스 + 도구

모델+ 하네스+ 도구= 에이전트

공식 문서는 Claude Code를 모델을 감싸는 층이라고 설명합니다. 생각은 모델(Claude)이 하고, 행동은 도구가 하며, 그 둘을 이어 주면서 모델이 무엇을 보게 할지 관리하는 바깥 층을 에이전틱 하네스(agentic harness)라고 부릅니다. Claude Code 자체가 바로 이 하네스입니다.

  • 모델은 텍스트만 만들 수 있습니다. 도구가 없으면 “이 파일을 이렇게 고치세요”라고 말할 수는 있어도 직접 고칠 수는 없습니다. 1편에서 본 채팅형 보조의 한계가 바로 이것입니다.
  • 도구가 손발입니다. 모델이 “Read 도구로 servers.txt를 읽어 달라”는 요청을 출력하면, 하네스가 실제로 내 컴퓨터에서 파일을 읽고 그 결과를 모델에게 돌려줍니다.
  • 하네스가 작업대입니다. 도구 호출을 실행하고, 권한을 검사하고, 대화와 파일 결과를 모아 매번 모델에게 보낼 내용을 꾸리고, 세션을 디스크에 저장합니다.
가장 중요한 사실 하나: 모델은 원격, 도구는 로컬 로컬 터미널에서 실행할 때, Claude 모델은 Anthropic(또는 Bedrock 같은 클라우드 제공자)의 서버에서 돌고, 도구는 여러분의 컴퓨터에서 여러분의 권한으로 실행됩니다. 그래서 Claude Code는 여러분이 터미널에서 할 수 있는 거의 모든 일을 할 수 있고, 반대로 여러분의 계정이 접근할 수 있는 운영 서버·클라우드 자격 증명에도 닿을 수 있습니다. 권한 설정이 중요한 이유입니다.

Claude Code가 실행되면 무엇에 접근하나

📁 프로젝트

실행한 폴더와 하위 폴더의 파일. 그 밖의 경로는 허락을 받고 접근합니다.

⌨️ 터미널

빌드 도구, git, 패키지 관리자, kubectl 등 여러분이 실행할 수 있는 모든 명령.

🌿 Git 상태

현재 브랜치, 커밋하지 않은 변경, 최근 커밋 기록.

📝 CLAUDE.md

매 세션 읽는 프로젝트 지시 파일. 다른 에이전트용 AGENTS.md도 읽을 수 있습니다.

🧠 자동 메모리

작업하며 Claude가 스스로 저장한 학습 내용. MEMORY.md의 앞부분(200줄 또는 25KB 중 먼저 닿는 쪽)이 세션 시작 시 로드됩니다.

🔌 확장 기능

설정한 MCP 서버, Skills, 서브에이전트, Chrome 연동 등.

어디서 쓰든 같은 엔진

터미널, 데스크톱 앱, IDE 확장, 웹(claude.ai/code), Slack, CI/CD 파이프라인까지 화면은 달라도 에이전틱 루프와 도구는 동일합니다. 달라지는 것은 코드가 어디서 실행되느냐입니다.

💻 로컬

기본값. 내 컴퓨터에서 실행되며 내 파일·도구·환경에 모두 접근합니다.

☁️ 클라우드

Anthropic이 관리하는 VM(또는 조직의 셀프 호스팅 환경)에서 실행. 로컬에 없는 레포 작업이나 작업 위임에 씁니다.

📱 Remote Control

실행과 파일은 내 컴퓨터에 그대로 두고, 브라우저나 휴대폰에서 그 세션을 조작하는 방식입니다.

에이전틱 루프의 세 단계

작업을 받으면 Claude는 컨텍스트 수집 → 행동 → 결과 검증의 세 단계를 거칩니다. 공식 문서는 이 단계들이 칼같이 나뉘지 않고 서로 섞인다고 강조합니다. 코드베이스에 대한 질문은 수집만으로 끝날 수 있고, 버그 수정은 세 단계를 여러 번 돌며, 리팩터링은 검증에 많은 시간을 씁니다. 앞 단계에서 알게 된 것에 따라 다음 단계가 정해지므로, 수십 개의 행동을 이어 가며 도중에 방향을 고치기도 합니다.

커리큘럼에서 쓴 “읽기 → 계획 → 편집 → 실행 → 검증”은 이 세 단계를 더 잘게 쪼갠 표현입니다. 읽기·계획은 컨텍스트 수집, 편집·실행은 행동, 검증은 결과 검증에 해당합니다.

공식 문서의 예시 “실패하는 테스트 고쳐줘”를 한 단계씩 진행해 보세요. 도구 결과가 쌓일수록 컨텍스트가 늘어납니다.

🔍 컨텍스트 수집검색하고, 읽고, 파악한다
🛠️ 행동편집하고, 실행한다
✅ 결과 검증테스트·출력으로 확인한다
컨텍스트: 시스템 프롬프트 + CLAUDE.md + 내 요청

턴(turn)과 루프의 끝

Agent SDK 문서는 루프 안의 한 번의 왕복을 턴이라고 부릅니다. Claude가 도구 호출이 담긴 출력을 내면 하네스가 도구를 실행하고, 그 결과가 자동으로 다시 Claude에게 들어갑니다. 이 과정은 여러분에게 제어권을 돌려주지 않고 계속됩니다. Claude가 더 이상 도구를 부르지 않고 최종 답변을 내면 그 작업이 끝납니다.

여러분도 루프의 일부입니다 언제든 끼어들 수 있습니다. Esc를 누르면 실행 중인 도구 호출이 취소되고 Claude가 다음 지시를 기다립니다. 멈추지 않고 그냥 수정 지시를 입력하고 Enter를 누르면 그 메시지가 대기열에 올라가, 진행 중인 도구 호출이 끝나는 대로 Claude가 읽고 다음 단계에 반영합니다. 처음부터 완벽한 프롬프트일 필요가 없는 이유입니다.

내장 도구 카탈로그

도구가 Claude Code를 에이전트로 만듭니다. 공식 문서는 기본 도구를 다섯 범주로 나눕니다: 파일 작업, 검색, 실행, 웹, 코드 인텔리전스. 여기에 서브에이전트 생성, 질문하기 같은 오케스트레이션 도구가 더해집니다. 평소에는 도구 이름을 몰라도 되지만, 권한 규칙·Hooks·서브에이전트 설정(9·11·13편)에서는 이 이름을 그대로 씁니다.

도구하는 일권한 필요*알아 둘 점

* Manual 모드에서 작업 폴더 안의 경로 기준. Read·Grep·Glob도 작업 폴더 밖이면 묻습니다. Bash는 “필요”지만 내장된 읽기 전용 명령 목록은 묻지 않고 실행합니다. Auto 모드에서는 분류기가 대부분의 결정을 대신합니다.

macOS·Linux·WSL에서 검색은 Bash로 최신 버전에서는 macOS·Linux·WSL에서 Glob·Grep 도구가 기본 도구 목록에서 빠지고, Claude가 Bash로 find·grep을 실행해 검색합니다(내부적으로 내장된 bfs·ugrep이 실행됨). 그래서 세션 로그에 Grep(...) 대신 Bash(grep ...)가 보여도 정상입니다. 권한 규칙과 Hooks에서도 이 검색은 Bash 호출로 취급됩니다. (2.1.317 재확인: Linux CLI의 -p 초기화 목록에 Glob·Grep 없음. 반면 Agent SDK 세션에서는 Glob·Grep이 목록에 보였고, --tools에 명시하면 전용 검색 도구가 생깁니다.)

도구 맞히기 게임

도구를 다룰 때 자주 만나는 동작

Edit는 정확한 문자열 교체

정규식이나 대충 비슷한 매칭이 아닙니다. 공백 한 칸만 달라도 실패하고, 같은 문자열이 두 번 나오면 주변 문맥을 더 붙여 하나로 좁힙니다.

Bash 명령은 매번 새 프로세스

프로젝트 안에서의 cd는 이어지지만, export한 환경 변수는 다음 명령에 남지 않습니다. 가상환경은 Claude Code를 켜기 전에 활성화하세요.

Bash 타임아웃

기본 2분, Claude가 요청하면 최대 10분. 시간이 다 된 명령은 멈추지 않고 백그라운드로 옮겨집니다. 개발 서버 같은 장기 실행은 처음부터 백그라운드로 띄웁니다.

긴 출력은 파일로

성공한 명령의 출력은 기본 약 3만 자까지 바로 전달되고, 그 이상은 파일로 저장된 뒤 Claude가 필요한 부분만 읽거나 검색합니다.

WebFetch는 요약해서 전달

페이지를 마크다운으로 바꾼 뒤 별도 모델 호출로 필요한 내용만 뽑아 Claude에게 줍니다. “그 페이지에 없다”는 답은 추출 질문이 그걸 묻지 않았다는 뜻일 수도 있습니다.

지금 쓸 수 있는 도구 확인

세션에서 “What tools do you have access to?”라고 물으면 요약해 줍니다. MCP 도구의 정확한 이름은 /mcp로 봅니다.

안전장치: 권한 모드와 체크포인트

Claude Code에는 두 가지 안전장치가 있습니다. 권한은 Claude가 묻지 않고 할 수 있는 일을 정하고, 체크포인트는 파일 변경을 되돌리게 해 줍니다. 터미널에서는 Shift+Tab으로 모드를 순환합니다. 자세한 설정은 3편과 9편에서 다룹니다.

Auto최신 버전의 기본 시작 모드

분류기가 대부분의 행동을 백그라운드에서 검토해, 위험한 것만 막고 나머지는 묻지 않고 진행합니다.

Manual가장 보수적

파일 편집과 셸 명령 전에 매번 묻습니다. 운영 환경과 가까운 작업에 적합합니다.

Accept edits편집은 자동

파일 편집과 mkdir·mv 같은 흔한 파일 명령은 묻지 않고, 그 밖의 명령은 묻습니다.

Plan읽기와 계획만

소스 파일을 고치지 않고 조사한 뒤 계획을 제안합니다. 큰 작업의 첫 단계로 씁니다.

⏪ 체크포인트가 지켜 주는 것

Claude가 파일을 고치기 전에 현재 내용을 스냅샷으로 남깁니다. Esc를 두 번 누르거나 되돌려 달라고 하면 이전 상태로 돌아갑니다. Git과 별개이며, 세션을 다시 열어도 남아 있습니다.

🚫 체크포인트가 지켜 주지 못하는 것

데이터베이스 변경, API 호출, 배포, 원격 서버 명령처럼 내 컴퓨터 밖에 영향을 주는 행동은 되돌릴 수 없습니다. 이런 일은 권한 모드와 권한 규칙으로 미리 막아야 합니다.

MSP 엔지니어를 위한 경고 kubectl delete, terraform apply, 고객사 서버로의 ssh는 모두 체크포인트 밖입니다. 운영 자격 증명이 로드된 터미널에서 Claude Code를 실행할 때는 Manual 모드와 deny 규칙을 기본으로 생각하세요.

컨텍스트 창: Claude의 작업 기억

컨텍스트 창은 모델이 한 번에 볼 수 있는 모든 것입니다. 여기에는 시스템 지시, 도구 정의, CLAUDE.md, 자동 메모리, 로드된 Skills, 대화 기록, 읽은 파일 내용, 명령 출력이 모두 들어갑니다. 일할수록 차오르고, 한계에 다가가면 Claude Code가 자동으로 정리합니다.

현재 주력 모델들(Fable 5.1·5, Sonnet 5 이후, Haiku 5.5, Opus 4.7 이후)은 기본으로 100만(1M) 토큰 컨텍스트 창을 쓰며, 기본 설정에서는 약 96.7만 토큰쯤에서 자동 압축(컴팩션)을 시작합니다. 넉넉해 보이지만, 큰 로그 파일 몇 개와 긴 테스트 출력이면 생각보다 빨리 찹니다.

컨텍스트 창 시뮬레이터
시스템·도구 정의 CLAUDE.md·메모리 대화 도구 출력·파일 압축 요약
빨간 선 = 자동 압축 지점
버튼을 눌러 세션을 진행해 보세요. 수치는 이해를 돕기 위한 대략적인 예시입니다.

가득 차면 무슨 일이 생기나

  • 오래된 도구 출력부터 비웁니다. 그래도 부족하면 대화를 요약합니다. 여러분의 요청과 핵심 코드 조각은 보존되지만, 대화 초반의 세세한 지시는 사라질 수 있습니다.
  • 그래서 영구 규칙은 CLAUDE.md에. “테스트는 반드시 make test로” 같은 규칙을 대화로만 말했다면 압축 후 잊힐 수 있습니다.
  • 압축 방향을 지정할 수 있습니다. /compact focus on the API changes처럼 무엇을 남길지 알려 주거나, CLAUDE.md에 “Compact Instructions” 섹션을 둡니다.
  • 무한 압축 방지. 파일 하나나 출력 하나가 너무 커서 요약 직후 다시 가득 차면, 몇 번 시도 후 에러를 보여 주고 멈춥니다.
  • /context로 무엇이 공간을 쓰는지 봅니다. MCP 도구 정의는 기본적으로 지연 로드되어, 실제로 쓰기 전까지는 이름과 서버 설명만 공간을 차지합니다.

세션 시작 시에는 스킬 설명만 보이고, 전체 내용은 실제로 쓸 때 로드됩니다.

세션: 대화는 어디에 남는가

Claude Code는 작업하는 동안 모든 메시지, 도구 호출, 결과를 ~/.claude/projects/ 아래의 평문 JSONL 파일에 저장합니다. 이 기록 덕분에 되돌리기, 이어가기, 갈라내기가 가능합니다.

🆕 세션은 서로 독립

새 세션은 빈 컨텍스트 창으로 시작합니다. 지난 세션의 대화는 기억하지 않습니다. 세션을 넘어 남기고 싶은 것은 CLAUDE.md나 자동 메모리에 둡니다.

↩️ 이어가기

claude --continue 또는 --resume은 같은 세션 ID로 다시 열고 기존 대화 뒤에 이어 씁니다.

🌱 갈라내기(fork)

--fork-session이나 /branch는 기록을 새 세션 ID로 복사합니다. 원래 세션은 그대로입니다.

📂 세션은 폴더에 묶임

세션은 실행한 디렉토리에 연결됩니다. 브랜치를 바꾸면 Claude는 새 브랜치의 파일을 보지만 대화 기록은 유지됩니다. 병렬 작업은 git worktree로 폴더를 나눕니다.

보안 메모 세션 기록은 평문입니다. Claude가 읽은 설정 파일이나 명령 출력에 비밀번호가 있었다면 그 내용도 기록에 남습니다. 보존 기간과 삭제 방법은 공식 문서의 ~/.claude 애플리케이션 데이터 항목에서 확인할 수 있고, 6편에서 세션 관리를 자세히 다룹니다.

프롬프트 캐싱의 원리

놀랍게 들리겠지만 모델은 요청과 요청 사이에 아무것도 기억하지 않습니다. 그래서 Claude Code는 메시지를 보낼 때마다 시스템 프롬프트, 프로젝트 컨텍스트, 지금까지의 모든 메시지와 도구 결과, 그리고 새 메시지까지 전부 다시 보냅니다. 새 내용은 끝에 붙기 때문에, 매 요청의 대부분은 직전 요청과 똑같습니다.

프롬프트 캐싱은 바뀌지 않은 앞부분(접두부, prefix)을 다시 처리하지 않고 재사용하는 기술입니다. 재사용된 부분은 더 낮은 캐시 요금으로 청구되고, 응답도 빨라집니다. 핵심 규칙은 하나입니다: 접두부는 정확히 일치해야 하며, 어딘가 하나라도 바뀌면 그 뒤는 전부 다시 계산됩니다. 파일 단위나 구간 단위 캐시는 없습니다.

① 시스템 프롬프트핵심 지시, 도구 정의로드된 도구 정의 집합이 바뀔 때
② 프로젝트 컨텍스트CLAUDE.md, 자동 메모리, 범위 없는 규칙세션 시작, /clear·/compact 후
③ 대화내 메시지, Claude 응답, 도구 결과매 턴

잘 바뀌지 않는 것이 앞에 오도록 배치됩니다. ③이 바뀌면 ①②는 캐시에 남지만, ①이 바뀌면 전부 무효가 됩니다. 모델과 effort 수준도 캐시 키의 일부입니다.

캐시 시뮬레이터

행동을 골라 턴을 쌓아 보세요. ■ 캐시에서 읽음 ■ 다시 처리 ■ 새로 추가된 내용

캐시를 깨는 행동, 지키는 행동

공식 문서의 팁 모델과 effort 수준은 세션을 시작할 때 정하고, /compact는 작업과 작업 사이의 자연스러운 쉼표에 쓰세요. 작업 도중에 바꾸는 것이 적을수록 캐시 적중률이 올라갑니다. 버리고 싶은 시도가 있다면 /compact보다 /rewind가 낫습니다. 이미 캐시된 지점으로 잘라 내기 때문입니다.

캐시 수명(TTL)

캐시는 일정 시간 아무 요청이 없으면 만료됩니다. API에는 5분과 1시간 두 가지 수명이 있고, 1시간은 쓰기 요금이 더 비싼 대신 긴 휴식 뒤에도 살아남습니다. 기본값은 결제 방식에 따라 다릅니다.

Claude 구독 (요금제 포함 사용량 안)

메인 대화는 1시간. 서브에이전트·압축 등 나머지는 대부분 5분. 사용량 한도를 넘겨 사용량 크레딧으로 넘어가면 메인 대화도 5분으로 내려갑니다.

API 키 · 클라우드 제공자

모두 5분이 기본입니다. promptCacheTtl 설정으로 메인 대화를 1시간으로 바꿀 수 있습니다.

휴식 후 첫 응답이 유독 느리다면 캐시가 만료된 것입니다. /usage의 “Prompt cache (main)” 줄에서 세션의 적중률과 마지막 실패 원인을 볼 수 있습니다. 비용 관리는 20편에서 깊게 다룹니다.

effort와 사고

effort는 모델이 각 단계에서 얼마나 깊이 생각할지 정하는 다이얼입니다. 최신 모델은 적응형 추론을 써서, 단계마다 생각할지 말지와 얼마나 생각할지를 작업 난이도에 맞춰 스스로 정합니다. effort가 낮으면 빠르고 저렴하고, 높으면 더 깊이 따져 보고 더 많이 검증하는 대신 토큰을 더 씁니다.

low브레인스토밍, 이름 바꾸기 같은 작은 수정
medium5.5 모델의 기본값. 범위가 분명한 일상 기능 구현
high엣지 케이스가 많은 버그 수정. 다른 대부분 모델의 기본값
xhigh더 깊은 추론, 더 많은 토큰
max혼자 오래 붙잡게 할 어려운 문제. 과하게 생각하는 경향
  • 설정 방법: /effort(슬라이더), /effort high(바로 지정), /model 선택기에서 좌우 화살표, 시작 시 --effort, 환경 변수 CLAUDE_CODE_EFFORT_LEVEL. max는 기본적으로 현재 세션에만 적용됩니다.
  • 한 번만 깊게: 프롬프트 어딘가에 ultrathink를 넣으면 그 턴만 더 깊이 생각하라는 지시가 추가됩니다. “think hard” 같은 다른 표현은 특별한 키워드로 인식되지 않고 평범한 문장으로 전달됩니다.
  • 모델마다 눈금이 다릅니다. 같은 “high”라도 모델이 다르면 실제 깊이가 다릅니다. Opus 5에서 Opus 5.5로 옮겼다면 high를 그대로 가져가지 말고 medium부터 시작하라는 것이 공식 권고입니다.
  • 사고는 끌 수 없는 모델도 있습니다. Opus·Sonnet·Haiku 5.5와 Fable 모델에서는 사고를 끌 수 없고, effort로 깊이만 조절합니다. 사고 내용은 기본으로 접혀 있으며 Ctrl+O로 펼쳐 볼 수 있습니다. 접혀 있어도 사고 토큰은 모두 과금됩니다.
  • Ultracode: /effort 슬라이더의 토글로, 켜면 큰 작업마다 여러 서브에이전트를 조율하는 동적 워크플로우를 계획합니다. effort 수준과는 별개의 설정이며 14편에서 다룹니다.
effort를 바꾸면 캐시는? 대부분의 모델에서는 세션 중 effort를 바꾸면 캐시가 깨집니다. 다만 Opus·Sonnet·Haiku 5.5와 Fable 5.1을 API 키나 Claude 구독으로 쓸 때는 캐시가 유지됩니다(Bedrock·Google Cloud 등에서는 해당되지 않음).
