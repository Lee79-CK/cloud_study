06

시리즈가 남긴 원칙

1. 서버가 원천이면 서버가 그린다상태의 원천이 서버라면 HTML도 서버가. 판단 순서는 HTML → CSS → htmx → hx-on·hx-live → 아일랜드 (9편, 21편).
2. 같은 URL, 두 응답전체 요청엔 페이지, 부분 요청엔 조각. Vary로 캐시에 알리고, htmx 응답은 no-store (2·18편).
3. 한 요소의 주인은 하나htmx와 React(11편), 요청 응답과 스트림(10·21편), htmx history와 SPA 라우터(14편). 주인이 둘이면 조용히 어긋나다가 터진다.
4. 경계는 표준으로웹 컴포넌트(생명주기), 섀도 DOM(격리), DOM 이벤트(대화), CSS 변수(모양), import map(런타임) (12·13·15편).
5. 서버가 최종 판단권한·검증·CSRF는 서버에서. 버튼 숨기기는 편의일 뿐 (6·17편).
6. 되돌릴 수 있게 옮긴다게이트웨이 + 기능 플래그 + 그림자 비교 + 지표로 화면 하나씩 (16·20편).
7. 문서보다 소스, 짐작보다 측정52가지 발견의 대부분은 문서만 읽었다면 놓쳤을 것 (5절).
8. 두 구현은 서로의 테스트Express·FastAPI를 맞대어 비교하자 반올림·라벨·회귀가 드러났다 (19·21편).

이 시리즈는 "htmx냐 React·Vue냐"를 고르는 이야기가 아니었습니다. 서버가 잘하는 일은 서버가 HTML로, 브라우저에서만 할 수 있는 일은 React·Vue가 맡고, 둘의 경계를 표준(웹 컴포넌트, DOM 이벤트, CSS 변수, import map)으로 긋는 방법이었습니다. 그리고 그 경계에서 생기는 문제 대부분은 문서가 아니라 측정에서 드러났습니다.

  
통합 저장소의 README로 시작해, 궁금한 동작은 해당 편의 실험 상자로 돌아가 재 보시기 바랍니다. 새 기능을 붙일 때는 21편의 출시 점검표와 npm test가 출발점입니다.
