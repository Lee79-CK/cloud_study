1장

호환의 전제: Redwood 모드

이 편의 모든 내용은 Oracle 호환 모드(Redwood 모드)로 만든 클러스터를 전제로 합니다(3편). --no-redwood-compat으로 만든 PostgreSQL 모드 클러스터에서는 일부 호환 기능만 쓸 수 있으며, EDB는 모든 기능을 쓰려면 Redwood 모드를 권장합니다.

영역대표 기능장
데이터 타입VARCHAR2, NUMBER, Oracle식 DATE, CLOB, BLOB3장
SQL 문법DUAL, ROWNUM, CONNECT BY, NVL, DECODE, 시퀀스.NEXTVAL, 시너님, (+) 외부 조인4~6장
절차 언어SPL: 익명 블록, 프로시저, 함수, 트리거, 패키지, 예외7~9장
내장 패키지DBMS_OUTPUT, DBMS_SCHEDULER, UTL_FILE 등10장
도구·딕셔너리EDB*Plus(4편), EDB*Loader(9편), ALL_/DBA_/USER_ 뷰(6편)—
"호환"은 "동일"이 아니다

EDB 문서도 여러 내장 패키지를 Oracle 대비 부분 구현이라고 밝힙니다. 지원되는 함수·프로시저 목록이 정해져 있고, 세부 동작이 다를 수 있습니다. 이관 프로젝트에서는 9편의 Migration Portal 평가와 함께, 핵심 프로그램을 실제로 돌려 보는 테스트가 반드시 필요합니다.

2장

호환 파라미터가 바꾸는 동작

5편에서 이름만 봤던 파라미터들이 실제로 무엇을 바꾸는지 확인합니다. 각 줄에서 켜고 꺼 보세요. 세션에서 SET으로 바꿀 수 있는 파라미터들입니다.

시험 포인트

edb_redwood_date를 켜면 DDL의 DATE가 시각까지 담는 TIMESTAMP 계열로 만들어집니다(Oracle DATE와 같은 동작). edb_redwood_strings를 켜면 NULL과의 문자열 연결이 NULL이 되지 않고 빈 문자열처럼 처리됩니다. edb_stmt_level_tx는 오류 문장만 롤백합니다(4편의 aborted 트랜잭션과 대비). 날짜의 표시 형식은 세션의 날짜 형식 설정에 따라 달라집니다.

Oracle 호환 데이터 타입

Oracle 타입EPAS에서PostgreSQL 대응주의
VARCHAR2(n)지원varchar(n)Oracle의 BYTE/CHAR 길이 의미 차이는 이관 시 확인
NVARCHAR2(n)지원varchar(n)EPAS는 UTF-8 DB에서 모두 유니코드
NUMBER, NUMBER(p,s)지원numeric(p,s)정수만 담는 키는 bigint로 바꾸면 더 빠름
DATE시각 포함 (edb_redwood_date)timestamp(0)PostgreSQL date는 날짜만 담음
CLOB / BLOB지원text / byteaLOB 조작은 DBMS_LOB 패키지
RAW(n)지원byteaUTL_RAW 패키지
BINARY_FLOAT / BINARY_DOUBLE지원real / double precision

EPAS에서는 Oracle 타입 이름과 PostgreSQL 타입 이름을 섞어 쓸 수 있습니다(1편 "양쪽 다 된다"). 새로 만드는 테이블이라면 팀 표준을 정해 한쪽으로 통일하는 편이 유지보수에 좋습니다.

4장

Oracle 호환 SQL

-- 테이블 없이 계산
SELECT SYSDATE, SYSTIMESTAMP, USER FROM DUAL;

-- NULL 처리와 조건 함수
SELECT ename, NVL(comm, 0), NVL2(comm, 'Y', 'N'),
       DECODE(deptno, 10, 'ACCT', 20, 'RSCH', 'OTHER') AS dept_code
FROM emp;

-- 시퀀스 Oracle 문법
CREATE SEQUENCE emp_seq START WITH 8000;
SELECT emp_seq.NEXTVAL FROM DUAL;
SELECT emp_seq.CURRVAL FROM DUAL;

-- 시너님: 스키마 이름을 숨기는 별칭
CREATE PUBLIC SYNONYM emp FOR hr.emp;      -- 모든 사용자에게
CREATE SYNONYM my_emp FOR hr.emp;          -- 현재 스키마에

-- Oracle식 외부 조인 표기 (+)
SELECT e.ename, d.dname
FROM   emp e, dept d
WHERE  e.deptno = d.deptno(+);             -- = LEFT JOIN dept d ON ...

-- 집합 연산 MINUS (= EXCEPT)
SELECT deptno FROM dept MINUS SELECT deptno FROM emp;

-- 날짜 함수
SELECT ADD_MONTHS(SYSDATE, 3), LAST_DAY(SYSDATE),
       MONTHS_BETWEEN(SYSDATE, hiredate), TRUNC(SYSDATE),
       TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS')
FROM emp WHERE ROWNUM = 1;
시험 포인트

이 문장들은 EPAS(Oracle 호환 모드)에서 그대로 실행되지만 커뮤니티 PostgreSQL에서는 대부분 오류입니다. 동시에 EPAS는 COALESCE, CASE, LIMIT, LEFT JOIN, EXCEPT, nextval('emp_seq') 같은 PostgreSQL 문법도 모두 받아들입니다. "EPAS에서는 둘 중 하나만 된다"는 선택지는 함정입니다.

ROWNUM 함정

ROWNUM은 결과 행에 1부터 붙는 가상 컬럼인데, ORDER BY보다 먼저 매겨집니다. 그래서 "급여 상위 3명"을 구하는 흔한 실수가 생깁니다. EPAS도 Oracle과 같은 의미로 동작합니다.

7장

  
SPL 기초

  
SPL(Stored Procedure Language)은 Oracle PL/SQL과 호환되는 EPAS의 절차 언어입니다. 블록 구조는 다음과 같습니다.


DECLARE                                  -- 선언부 (선택)
  v_ename  emp.ename%TYPE;               -- 컬럼과 같은 타입
  v_emp    emp%ROWTYPE;                  -- 행 전체와 같은 구조
  v_total  NUMBER := 0;
BEGIN                                    -- 실행부 (필수)
  SELECT * INTO v_emp FROM emp WHERE empno = 7369;
  IF v_emp.sal > 1000 THEN
    v_total := v_emp.sal * 12;
  ELSIF v_emp.sal > 500 THEN
    v_total := v_emp.sal * 13;
  ELSE
    v_total := 0;
  END IF;
  FOR r IN (SELECT ename FROM emp WHERE deptno = 20) LOOP   -- 커서 FOR 루프
    DBMS_OUTPUT.PUT_LINE(r.ename);
  END LOOP;
EXCEPTION                                -- 예외부 (선택, 8장)
  WHEN NO_DATA_FOUND THEN
    DBMS_OUTPUT.PUT_LINE('없음');
END;
/

  
프로시저와 함수


CREATE OR REPLACE PROCEDURE raise_sal (p_empno IN NUMBER, p_pct IN NUMBER, p_new OUT NUMBER) IS
BEGIN
  UPDATE emp SET sal = sal * (1 + p_pct/100) WHERE empno = p_empno
  RETURNING sal INTO p_new;
END;
/
CREATE OR REPLACE FUNCTION annual_sal (p_empno NUMBER) RETURN NUMBER IS
  v_sal emp.sal%TYPE;
BEGIN
  SELECT sal INTO v_sal FROM emp WHERE empno = p_empno;
  RETURN v_sal * 12;
END;
/
SELECT ename, annual_sal(empno) FROM emp;     -- 함수는 SQL 안에서 호출
EXEC raise_sal(7369, 10, :v);                 -- EDB*Plus: EXEC (psql은 CALL)

  

    
기능설명

    
      
IN / OUT / IN OUT매개변수 방향. IN이 기본

      
명시적 커서CURSOR c IS SELECT ...; OPEN c; FETCH c INTO ...; CLOSE c;, 속성 c%FOUND, c%NOTFOUND, c%ROWCOUNT

      
BULK COLLECT / FORALL여러 행을 한 번에 컬렉션으로 받기 / 컬렉션을 한 번에 DML로 보내기

      
PRAGMA AUTONOMOUS_TRANSACTION호출한 트랜잭션과 별개로 커밋되는 블록 (오류 로그 기록 등)

      
트리거CREATE OR REPLACE TRIGGER ... BEFORE INSERT ON emp FOR EACH ROW BEGIN :NEW.ename := UPPER(:NEW.ename); END;

    

  

    시험 포인트
    
SPL 블록은 DECLARE(선택) – BEGIN(필수) – EXCEPTION(선택) – END 구조입니다. %TYPE은 컬럼 타입, %ROWTYPE은 행 구조를 그대로 가져옵니다. EDB*Plus에서는 블록 끝에 /를 입력해 실행합니다(4편). EPAS는 같은 DB 안에서 SPL과 PL/pgSQL을 함께 쓸 수 있습니다.

    트랜잭션과 예외
    
예외를 예외부에서 잡으면 블록 안에서 그 예외를 낸 변경이 되돌려지고, 트랜잭션은 계속 진행할 수 있습니다. 잡지 않으면 호출자에게 전파되어 4편의 규칙대로 트랜잭션이 중단됩니다. 문장 단위 롤백 동작이 필요하면 2장의 edb_stmt_level_tx를 검토합니다.

  







  
9장

  
패키지

  
패키지는 관련된 프로시저·함수·변수·타입을 하나로 묶는 Oracle의 모듈 단위입니다. 바깥에 보여 줄 부분(명세, specification)과 실제 구현(본문, body)을 나눠 만듭니다.


-- 명세: 공개 인터페이스
CREATE OR REPLACE PACKAGE emp_admin IS
  g_hire_count NUMBER := 0;                              -- 패키지 변수 (세션마다 따로 유지)
  FUNCTION  get_dept_name (p_deptno NUMBER) RETURN VARCHAR2;
  PROCEDURE hire_emp (p_ename VARCHAR2, p_deptno NUMBER, p_sal NUMBER DEFAULT 1000);
END emp_admin;
/
-- 본문: 구현 (히어로의 코드). 명세에 없는 프로시저는 패키지 안에서만 쓰는 비공개 요소
CREATE OR REPLACE PACKAGE BODY emp_admin IS ... END emp_admin;
/
-- 사용
SELECT emp_admin.get_dept_name(10) FROM DUAL;
EXEC emp_admin.hire_emp('KIM', 20, 3000);
GRANT EXECUTE ON PACKAGE emp_admin TO app_user;

  

    시험 포인트
    
패키지는 명세(PACKAGE)와 본문(PACKAGE BODY)으로 나뉘며, 명세에 선언한 것만 밖에서 패키지명.요소명으로 부를 수 있습니다. 패키지 변수는 세션 단위로 값을 유지합니다. 11편의 transaction 풀 모드에서는 세션이 바뀔 수 있으므로 패키지 변수에 기대는 코드에 주의하세요. 권한은 GRANT EXECUTE ON PACKAGE로 줍니다.

  







  
10장

  
내장 패키지

  
EPAS는 Oracle의 내장 패키지와 호환되는 패키지를 함께 제공합니다. 모두 특수 사용자 sys가 소유하며, 일부 패키지는 슈퍼유저가 아닌 사용자에게 EXECUTE 권한을 명시적으로 줘야 합니다.


GRANT EXECUTE ON PACKAGE SYS.UTL_FILE TO app_user;

  
  
  

  
자주 쓰는 셋


-- DBMS_OUTPUT: 메시지 출력 (EDB*Plus는 SET SERVEROUTPUT ON 필요)
BEGIN DBMS_OUTPUT.PUT_LINE('Hello'); END;
/

-- UTL_FILE: 서버 파일 읽기·쓰기. 경로는 디렉터리 객체로 지정
CREATE DIRECTORY rpt_dir AS '/var/lib/edb/reports';   -- 서버 경로 (9편 COPY처럼 서버 기준)
DECLARE
  f UTL_FILE.FILE_TYPE;
BEGIN
  f := UTL_FILE.FOPEN('rpt_dir', 'daily.txt', 'w');
  UTL_FILE.PUT_LINE(f, 'report line');
  UTL_FILE.FCLOSE(f);
END;
/

-- DBMS_SCHEDULER: Oracle식 작업 예약 (EPAS 18은 edb_job_scheduler 확장이 실행 담당)
CREATE EXTENSION IF NOT EXISTS dbms_scheduler;
EXEC DBMS_SCHEDULER.CREATE_JOB(job_name => 'nightly_cleanup', job_type => 'STORED_PROCEDURE',
     job_action => 'purge_old_logs', repeat_interval => 'FREQ=DAILY;BYHOUR=2', enabled => TRUE);

  

    시험 포인트
    
내장 패키지는 sys 소유이므로 권한을 줄 때 SYS.패키지명으로 지정합니다. DBMS_SCHEDULER는 CREATE EXTENSION dbms_scheduler가 필요하고, EPAS 18에서는 edb_job_scheduler 확장이 작업을 백그라운드에서 실행합니다(9편 Clone Schema 준비 단계에서도 등장). DBMS_SCHEDULER와 UTL_FILE은 Oracle 대비 부분 구현이라 지원 목록에 있는 함수만 쓸 수 있습니다.
