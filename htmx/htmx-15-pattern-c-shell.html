게이트웨이로 조각 조합하기

① 브라우저 → 포털GET /billing/invoices (+ HX-Request, 쿠키)

④ 청구 서비스 → 포털HTML 조각 (+ HX-Trigger 등)
⑤ 포털 → 브라우저부분 요청: 조각 그대로 / 전체 요청: 포털 레이아웃 + 조각
apps/server/src/app.js (게이트웨이)
app.all('/billing/{*rest}', async (req, res) => {
  const up = UPSTREAMS.billing;
  const path = req.originalUrl.slice('/billing'.length) || '/';
  const headers = {
    'X-Gateway-Token': GATEWAY_TOKEN,                 // 업스트림은 이 값이 있을 때만 응답 (직접 호출 차단)
    'X-Portal-User': req.user.id, 'X-Portal-Role': req.user.role,
    'X-Forwarded-Prefix': '/billing',                // 업스트림이 링크를 공개 경로로 만들 수 있게
    'X-Request-ID': req.id, Accept: 'text/html',
  };
  for (const h of PASS_REQ) if (req.get(h)) headers[h] = req.get(h);
  ...
  try {
    upRes = await fetch(up.url + path, { method: req.method, headers, body, signal: AbortSignal.timeout(5000) });
    html = await upRes.text();
  } catch (e) {
    // 업스트림 장애는 포털 전체 장애가 되지 않게: 해당 영역만 오류 조각으로
    ...
  }
  for (const [k, v] of upRes.headers) if (k.toLowerCase().startsWith('hx-')) res.set(k, v);   // HX-Trigger 등은 그대로
  if (wantsFragment(req)) return send(res, html, upRes.status);
  render(res, './pages/composed', { title: up.title, fragment: html }, upRes.status);
});

핵심은 2편부터 쓴 wantsFragment()입니다. 같은 /billing/invoices라도 htmx 부분 요청이면 조각만, 주소창·새로고침·부스트(전체 요청)면 포털 레이아웃에 끼운 완전한 페이지를 돌려줍니다. 청구 서비스는 레이아웃을 전혀 모르고, 포털은 청구 업무를 전혀 모릅니다. 업스트림의 HX-Trigger 같은 응답 헤더는 그대로 통과시켜, 납부 처리 후 청구 서비스가 보낸 invoicePaid 이벤트가 브라우저에서 그대로 발생했습니다(측정).

  04
  
업스트림과의 계약

  

    
헤더방향의미지키지 않으면

    
      
X-Gateway-Token포털 → 업스트림"이 요청은 게이트웨이를 거쳤다"는 공유 비밀누구나 업스트림에 직접 X-Portal-User: admin을 보내 사칭 가능. 랩: 토큰 없는 직접 호출은 403

      
X-Portal-User, X-Portal-Role포털 → 업스트림인증 결과 (업스트림은 다시 인증하지 않음)업스트림마다 로그인 구현 중복

      
X-Forwarded-Prefix포털 → 업스트림공개 경로(/billing). 조각 안 링크·hx-get을 이 접두사로 생성조각의 hx-get="/invoices/…"가 포털의 엉뚱한 경로로 감

      
X-Request-ID포털 → 업스트림8편 요청 ID. 장애 추적사용자 오류 화면과 업스트림 로그를 잇지 못함

      
HX-* 요청 헤더포털 → 업스트림업스트림도 htmx 요청인지 알 수 있게 (선택)-

      
HX-* 응답 헤더업스트림 → 포털 → 브라우저HX-Trigger 등 통과업스트림의 이벤트·리다이렉트가 사라짐

    
  

  
측정: 포털 로그의 POST /billing/invoices/INV-2026-0101/pay … rid=6436fefd와 청구 서비스 로그의 BILLING POST /invoices/INV-2026-0101/pay user=kim rid=6436fefd hx=true가 같은 요청 ID로 이어졌습니다. 실제 운영에서는 공유 비밀 대신 서비스 간 mTLS나 서명된 토큰(JWT)을 씁니다(17편). 랩의 고정 문자열은 개념을 보이기 위한 것입니다.

  

    
권한은 셸에서 한 번

    
조회 전용 사용자 화면에도 청구 서비스는 "납부 처리" 버튼을 그렸지만(역할 헤더를 받으면서도 숨기지 않았음), 누르자 포털의 6편 역할 미들웨어가 403 + HX-Retarget으로 경고 토스트를 띄웠고, 청구 서비스 로그에는 그 요청이 아예 없었습니다. 업스트림이 버튼을 숨기는 것(화면)과 셸이 막는 것(정책)은 6편과 같은 이중 구조입니다.

셸 사이의 이동: 부스트할 것과 말 것

  

    
메뉴대상부스트측정

    
      
VM 관리같은 셸(포털 레이아웃)예7편

      
청구같은 셸 (게이트웨이가 포털 레이아웃으로 조합)예같은 문서 유지, [htmx:full boosted] 요청 1건

      
운영 콘솔다른 문서 (React SPA의 index.html)아니오 (hx-boost="false")부스트하면 #root 자식 0개, 제목 없음 (빈 화면). 부스트를 끄자 정상

    
  

  
부스트는 응답의 <body>만 가져오고 <head>는 버립니다(7편). 콘솔의 앱 스크립트는 Vite가 head에 넣은 모듈 스크립트라 실행되지 않고, 빈 <div id="root">만 남습니다. 규칙은 간단합니다. 같은 레이아웃(셸)을 쓰는 화면끼리만 부스트하고, 다른 앱으로 가는 링크는 전체 이동합니다. 셸 레이아웃을 공유하는 한, 다른 팀 서비스라도 게이트웨이 조합 덕분에 부스트할 수 있습니다.

공유 런타임: React를 한 벌만

  
14편 운영 콘솔 페이지에는 콘솔 번들과 아일랜드 번들이 각자 React를 하나씩 들고 와 React가 두 벌이었습니다. 표준 import map으로 이를 한 벌로 줄입니다.

  
apps/server/views/layout.eta (head, 콘솔 index.html도 동일)


<script type="importmap">
{ "imports": {
    "react": "/shared/react.js",
    "react/jsx-runtime": "/shared/react-jsx-runtime.js",
    "react-dom/client": "/shared/react-dom-client.js"
} }
</script>

  
아일랜드·콘솔 빌드는 react, react/jsx-runtime, react-dom/client를 external로 지정해 번들에 넣지 않고, 브라우저가 import map을 보고 /shared/의 파일을 불러옵니다. 공유 런타임은 새 워크스페이스 apps/shared-runtime이 만듭니다.

  

    
만들며 측정한 문제해결

    
      
npm의 react는 CommonJS라 export * from 'react'로 만든 진입점에 useState 같은 이름 있는 내보내기가 하나도 생기지 않음 (default만)gen-entries.mjs가 실제 내보내기 이름(react 46개, jsx-runtime 3개, react-dom/client 3개)을 읽어 export const { … } = M 진입점을 생성

      
Vite 라이브러리 모드의 es 출력이 공백을 압축하지 않음 (react-dom-client 287.74kB, 8,746줄)일반 빌드 + preserveEntrySignatures: 'strict' → 211.26kB

      
react와 react-dom이 각자 React를 품으면 인스턴스가 둘세 진입점을 한 빌드로 → React 본체가 공용 청크 하나 (chunks/react-*.js), react-dom-client가 그것을 import

증상원인해결

    
      
다른 팀 화면을 열면 포털 메뉴가 사라짐업스트림이 자기 전체 페이지를 돌려주고 그대로 전달업스트림은 조각만, 셸이 전체 요청일 때 레이아웃에 조합

      
업스트림 조각의 버튼이 엉뚱한 주소로 요청공개 경로 접두사 모름X-Forwarded-Prefix로 링크 생성

      
누구나 업스트림에 사용자 헤더를 위조업스트림이 게이트웨이 경유를 확인하지 않음공유 비밀·mTLS·서명 토큰, 네트워크 격리

      
업스트림이 죽으면 포털 전체가 오류예외를 셸까지 전파타임아웃 + 해당 영역만 오류 조각

      
다른 SPA로 가는 메뉴가 빈 화면다른 문서를 부스트hx-boost="false"

      
토큰을 바꿔도 아일랜드 색이 안 바뀜호스트에 걸린 페이지 CSS가 :host보다 우선호스트 규칙도 토큰으로, 섀도 안은 변수 직접 사용

      
공유 React에서 useState is not a functionCommonJS를 export *로 재내보냄이름 있는 내보내기를 생성해 진입점 작성

      
import map이 무시됨모듈 스크립트보다 뒤에 둠head에서 모든 모듈 스크립트보다 먼저
