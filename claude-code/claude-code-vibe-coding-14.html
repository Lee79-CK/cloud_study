병렬 작업여러 Claude를 동시에

13편의 서브에이전트는 한 세션 안의 일꾼이었습니다. 이번에는 세션 자체를 여러 개 돌립니다. 버그 수정·PR 리뷰·불안정한 테스트 조사를 세 줄로 맡겨 두고, 필요한 순간에만 끼어드는 방식입니다. 손은 늘어나지만 사용량도 그만큼 늘어난다는 사실과 함께 배웁니다.

병렬의 다섯 가지 길

공식 문서는 여러 일을 동시에 하는 방법을 다섯 가지로 나눕니다. 모두 일꾼은 Claude 세션이고, 차이는 여러분이 얼마나 관여하느냐와 어디서 도느냐입니다.

방식무엇이럴 때상태
서브에이전트 (13편)한 세션 안에서 곁가지 일을 하고 요약을 돌려주는 일꾼곁가지 출력이 메인 대화를 채울 때정식
agent viewclaude agents 한 화면에서 백그라운드 세션을 보내고 지켜봄독립적인 일 여러 개를 맡기고, 필요할 때만 들여다볼 때리서치 프리뷰
agent teams리더가 공유 작업 목록과 메시지로 팀원 세션들을 조율Claude가 일을 나눠 맡기고 팀원끼리 의견을 주고받게 할 때실험적, 기본 꺼짐
dynamic workflows스크립트가 많은 서브에이전트를 돌리고 결과를 서로 검증몇 개 서브에이전트로는 부족한 대규모 감사·마이그레이션정식
projectsclaude.ai/code·데스크톱의 한 대화가 클라우드에서 병렬 스레드를 돌림며칠·몇 주에 걸친 일, 내 컴퓨터가 꺼져도 계속Pro·Max 공개 베타
🌿 worktree (7편)

세션마다 별도 체크아웃을 줘서 같은 파일을 동시에 고치지 않게 하는 보조 도구.

✉️ 세션 간 메시지

내가 직접 돌리는 세션끼리 발견·상태를 주고받게 하는 보조 도구 (7장).

📦 /batch

큰 변경 하나를 worktree로 격리된 서브에이전트 5~30개로 쪼개는 번들 Skill (9장).

병렬 = 사용량 곱하기 세션이나 서브에이전트를 여럿 동시에 돌리면 토큰 사용량도 곱해집니다. agent view 문서는 열 개를 병렬로 돌리면 하나일 때보다 할당량이 대략 열 배 빨리 준다고 명시합니다. 10장에서 계산해 봅니다.

직접 여는 병렬 세션

가장 단순한 병렬은 터미널을 여러 개 열고 각자 worktree에서 Claude를 띄우는 것입니다(7편). 서로 파일이 섞이지 않습니다.

# 터미널 1 claude -w feat-cert-check # 터미널 2 claude -w fix-timeout

Writer · Reviewer 패턴

공식 모범 사례 문서의 패턴입니다. 새 컨텍스트는 방금 쓴 코드에 편향되지 않으므로 리뷰가 더 날카롭습니다. 테스트를 한 세션이 쓰고 다른 세션이 통과시키는 변형도 있습니다.

세션 A (Writer)세션 B (Reviewer)
servers.txt의 서버들에 대한 인증서 만료 점검 기능을 구현해줘
@scripts/check_cert.sh 의 구현을 리뷰해줘. 예외 상황, 타임아웃, 기존 스크립트 패턴과의 일관성을 봐줘.
리뷰 의견이야: [B의 출력]. 반영해줘.

13편의 code-reviewer 서브에이전트도 같은 효과를 냅니다. 차이는 세션 B를 사람이 직접 운전하느냐, Claude가 위임하느냐입니다. 세션 B의 결과를 A로 옮겨 적는 일은 7장의 세션 간 메시지로 줄일 수 있습니다.

4 / 16

agent view

claude agents는 백그라운드 세션 전부를 한 화면에 보여 줍니다. 각 백그라운드 세션은 터미널이 붙어 있지 않아도 계속 도는 완전한 Claude Code 대화입니다. 리서치 프리뷰라 화면과 단축키는 바뀔 수 있습니다.

1
보내기 (dispatch)

아래 입력칸에 할 일을 쓰고 Enter. 입력할 때마다 새 세션이 생깁니다(후속 메시지가 아님). 셸에서는 claude --bg "할 일", 이름은 --name, 특정 서브에이전트는 --agent.

2
엿보고 답하기 (peek)

행에서 Space. 최근 출력이나 기다리는 질문이 보이고, 그 자리에서 답을 보낼 수 있습니다. 권한 요청 같은 대화창은 붙어야 답할 수 있습니다.

3
붙기·떼기 (attach)

Enter나 →로 전체 대화에 들어가고, 빈 프롬프트에서 ←로 표로 돌아옵니다. 떼어도 세션은 계속 돕니다. 끝내려면 세션 안에서 /stop.

4
지금 세션을 들여보내기

열려 있는 세션에서 /bg, 또는 빈 프롬프트에서 ←. /fork는 복사본을 백그라운드로 보내고 원래 대화는 계속합니다.

표시뜻
Working (움직임)도구 실행·응답 생성 중
Needs input (노랑)여러분만 줄 수 있는 것을 기다림: 질문 답, 권한 결정, 샌드박스 네트워크 허용 등
Idle (흐림) · Completed (초록) · Failed (빨강) · Stopped (회색)할 일 없음 · 성공 · 오류 · 중지됨
#1234 라벨세션이 연 PR. 노랑(검사·리뷰 대기) → 초록(통과, 리뷰·머지할 때) → 보라(머지됨)
🌿 편집 전 worktree로 이동

agent view나 --bg로 보낸 세션은 파일을 고치기 전에 .claude/worktrees/ 아래 자기 worktree로 들어갑니다. 그래서 여러 세션이 같은 체크아웃을 읽되 각자 따로 씁니다. /bg로 들여보낸 기존 세션은 원래 자리에서 계속 편집합니다.

💾 일을 지키는 규칙

자기 worktree에서 코드를 바꾼 세션은 끝내기 전에 커밋하고(원격이 있으면 push), 필요하면 초안 PR을 엽니다. main·master로 push, force push, 머지는 하지 않습니다. CLAUDE.md에 “커밋은 내가 한다”가 있으면 그 지시가 우선.

🗑️ 지우면 worktree도

agent view에서 세션을 지우면(Ctrl+X 두 번) Claude가 만든 worktree와 커밋 안 한 변경도 지워집니다. push 안 된 커밋이 있으면 한 번 거절하고 알려 줍니다. 대화 기록은 claude --resume으로 남습니다.

🛠️ 감독 프로세스

별도 감독 프로세스가 세션을 돌리므로 터미널을 닫아도 계속됩니다. 끝났거나 대기 중인 채 한 시간쯤 아무도 안 붙으면 프로세스를 멈추고, 다시 붙으면 이어집니다(Ctrl+T로 고정하면 유지). 잠자기는 버티지만 컴퓨터를 끄면 멈춥니다.

셸 명령하는 일
claude --bg "할 일"바로 백그라운드 세션 시작, 짧은 ID와 관리 명령 출력
claude attach <id> · claude logs <id>붙기 · 최근 출력 보기
claude stop <id> · claude respawn <id> · claude rm <id>중지 · 대화를 가진 채 재시작 · 목록에서 제거
claude agents --json --all스크립트용 상태 목록 (working, blocked, done, failed, stopped)
claude agents --cwd ~/vibe-lab한 프로젝트의 세션만 보기
권한 모드는 어디서 오나 /bg나 ←로 들여보낸 세션은 원래 권한 모드를 유지합니다. 셸의 claude agents나 claude --bg로 보낸 세션은 그 폴더에서 새로 연 claude처럼 시작합니다. 한꺼번에 정하려면 claude agents --permission-mode plan --model sonnet처럼 기본값을 주고 엽니다. 보는 사람 없이 도는 세션이므로 9편의 deny 규칙·샌드박스·11편 Hook이 더 중요해집니다.

세션끼리 메시지

세션 간 메시지를 쓰면 Claude가 여러분의 다른 Claude Code 세션 목록을 보고 메시지를 보낼 수 있습니다. 같은 컴퓨터는 물론 다른 컴퓨터나 클라우드 세션까지 가능합니다. 직접 돌리는 세션들, agent view로 보낸 세션들끼리 발견과 상태를 주고받을 때 씁니다. 서브에이전트는 자기를 띄운 대화에만, agent view 세션은 여러분에게만 결과를 보고하는 것과 대비됩니다.

(세션 A에서) fix-timeout 세션에 “check_cert.sh 도 같은 타임아웃 상수를 쓰니까 맞춰줘”라고 전해줘
들어오는 메시지도 승인 대상 다른 세션의 메시지를 받아들이기 전에 승인을 요구하도록 설정할 수 있고, 그 경우 agent view에서 해당 행이 Needs input으로 바뀌어 보낸 쪽 주소를 보여 줍니다. 13편의 원칙과 같습니다: 다른 에이전트의 메시지는 여러분의 권한 승인이 아닙니다. 이 기능의 세부 설정은 사용 중인 버전의 Cross-session messaging 문서를 확인하세요.

agent teams (실험적)

한 세션이 팀 리더가 되어 일을 나누고, 팀원 세션들을 띄우고, 공유 작업 목록과 메시지로 조율하고, 결과를 종합합니다. 서브에이전트가 메인에게만 보고하는 반면, 팀원은 서로 직접 메시지를 주고받고 여러분이 특정 팀원과 직접 대화할 수도 있습니다. 실험적 기능이라 기본으로 꺼져 있고, 세션 재개·작업 조율·종료에 알려진 한계가 있습니다.

{ "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1" } }
시작

켠 뒤 자연어로: “운영·보안·비용 관점의 팀원 셋으로 팀을 만들어 이 설계를 검토해줘”. 리더가 작업 목록을 만들고 팀원을 띄웁니다.

보기 방식

in-process(기본, 한 터미널 아래 패널에서 팀원 선택)와 split-pane(tmux나 iTerm2에서 팀원마다 창). teammateMode 설정이나 --teammate-mode.

계획 승인

위험한 일은 팀원이 읽기 전용 plan 모드에서 계획하고, 리더가 승인해야 구현하게 할 수 있습니다.

파일 충돌 주의

agent teams는 팀원을 worktree로 격리하지 않습니다. 팀원마다 서로 다른 파일 묶음을 맡기도록 일을 나누세요.

11편의 TaskCreated·TaskCompleted·TeammateIdle Hook으로 팀 작업에 규칙을 걸 수 있습니다. 13편 서브에이전트 정의를 팀원으로 재사용하면 도구 목록과 모델은 적용되지만 mcpServers와 skills는 적용되지 않는다는 보고가 있으니 확인하고 쓰세요.

/batch와 dynamic workflows

📦 /batch

큰 변경 하나를 Claude가 5~30개의 서브에이전트로 나누고, 각자 worktree에서 작업해 PR을 엽니다. 서브에이전트와 worktree를 묶은 번들 Skill입니다.

/batch scripts/ 아래 모든 .sh 파일에 set -euo pipefail 을 넣고 변수를 큰따옴표로 감싸줘

PR이 여러 개 생기니 처음엔 작은 범위로. 기계적으로 반복되는 변경에 잘 맞습니다.

🧭 dynamic workflows

Claude의 턴 단위 판단 대신 스크립트가 계획을 쥐고 많은 서브에이전트를 돌리고 결과를 서로 검증합니다. 저장소 전체 감사, 수백 파일 마이그레이션, 교차 검증 조사에 맞습니다. 실행 상황은 /workflows.

공식 문서의 “Orchestrate dynamic workflows”에서 번들 워크플로를 쓰거나 Claude에게 워크플로를 쓰게 하는 방법을 볼 수 있습니다.

스크립트로 직접 펼치기 (fan-out) 모범 사례 문서에는 claude -p를 반복문으로 돌리는 방법도 있습니다. 파일 목록을 만들고, 2~3개로 프롬프트를 다듬은 뒤 전체에 돌립니다. --allowedTools로 필요한 도구만 미리 허용하고 --permission-mode dontAsk로 나머지는 거부합니다. 비대화형 실행은 19편에서 자세히 다룹니다.
