1장

설정 파일 지도

서버 동작을 정하는 파일은 모두 데이터 디렉터리 안에 있습니다(RHEL 계열 기준 /var/lib/edb/as18/data). Debian·Ubuntu는 설정 파일이 /etc/edb-as/18/main/에 따로 있다는 점만 기억하세요.

파일내용누가 고치나
postgresql.conf서버 파라미터 전반. 주석으로 된 기본값 목록이 들어 있음관리자가 편집기로
postgresql.auto.confALTER SYSTEM으로 바꾼 파라미터. postgresql.conf 다음에 읽혀 우선함ALTER SYSTEM만 (직접 편집 금지)
pg_hba.conf클라이언트 인증 규칙관리자가 편집기로 (7편)
pg_ident.confOS 사용자와 DB 사용자 매핑관리자가 편집기로 (7편)

설정 파일 위치 자체도 파라미터로 확인할 수 있습니다.

SHOW config_file;     -- /var/lib/edb/as18/data/postgresql.conf
SHOW hba_file;
SHOW data_directory;

설정 파일 나누기: include

운영 환경에서는 공통 설정과 서버별 설정을 파일로 나누면 관리가 쉬워집니다. postgresql.conf 안에서 다른 파일을 불러올 수 있습니다.

include 'tuning.conf'              # 파일이 없으면 오류로 서버가 시작되지 않음
include_if_exists 'local.conf'     # 없으면 조용히 건너뜀
include_dir 'conf.d'               # 디렉터리의 *.conf 파일을 이름순으로 모두 읽음
현장 팁: MSP 표준 설정을 conf.d로

고객사가 여러 곳이라면 회사 표준 설정(로그 형식, 타임아웃, 감시용 확장)을 conf.d/00-msp-standard.conf로, 고객별 튜닝을 conf.d/50-customer.conf로 나눠 두세요. 파일 이름순으로 읽고 같은 파라미터는 나중에 읽힌 값이 이기므로, 숫자 접두사로 적용 순서를 통제할 수 있습니다. 구성 관리 도구(Ansible 등)로 배포하기에도 좋습니다.

2장

postgresql.conf 문법과 단위

# 주석은 # 로 시작
shared_buffers = 4GB             # 메모리 단위
checkpoint_timeout = 15min       # 시간 단위
log_line_prefix = '%m [%p] '     # 문자열은 작은따옴표
autovacuum = on                  # 불리언: on/off, true/false, yes/no, 1/0
search_path = '"$user", public'
  • 한 줄에 파라미터 하나. =는 생략할 수 있습니다.
  • 파라미터 이름은 대소문자를 구분하지 않습니다.
  • 같은 파라미터가 여러 번 나오면 마지막 값이 적용됩니다.
  • 줄을 주석 처리하거나 지우고 reload하면 그 파라미터는 기본값으로 돌아갑니다(재시작 필요 파라미터는 재시작 후).

단위

종류쓸 수 있는 단위주의
메모리B, kB, MB, GB, TB대소문자 구분. mb, Gb는 오류. 1kB = 1024B
시간us, ms, s, min, h, d분은 m이 아니라 min
시험 포인트: 단위를 안 쓰면 "기본 단위"로 해석된다

파라미터마다 기본 단위가 다릅니다. shared_buffers = 1000은 1000MB가 아니라 1000 × 8kB(블록) ≈ 8MB이고, work_mem = 4096은 4096kB = 4MB, statement_timeout = 30은 30초가 아니라 30ms입니다. 기본 단위는 pg_settings.unit 컬럼에서 확인할 수 있습니다. 실무에서는 항상 단위를 붙여 쓰세요.

SELECT name, setting, unit FROM pg_settings
WHERE name IN ('shared_buffers','work_mem','statement_timeout','checkpoint_timeout');

        name        | setting | unit
--------------------+---------+------
 checkpoint_timeout | 300     | s
 shared_buffers     | 16384   | 8kB      -- 16384 × 8kB = 128MB
 statement_timeout  | 0       | ms
 work_mem           | 4096    | kB

3장

파라미터 context 7단계

모든 파라미터에는 context라는 속성이 있습니다. "이 파라미터를 언제, 누가, 어떻게 바꿀 수 있는가"를 정하는 값으로, 히어로의 사다리가 바로 이것입니다. pg_settings.context 컬럼으로 확인합니다.

context바꾸는 방법적용 시점예
internal바꿀 수 없음(빌드나 initdb 때 결정)—block_size, wal_segment_size, server_version, data_checksums
postmaster설정 파일 또는 ALTER SYSTEM서버 재시작 후shared_buffers, max_connections, port, listen_addresses, wal_level, shared_preload_libraries, io_method
sighup설정 파일 또는 ALTER SYSTEMreload 후 (재시작 불필요). 세션 SET 불가checkpoint_timeout, max_wal_size, archive_command, log_line_prefix, autovacuum
superuser-backend설정 파일, 또는 슈퍼유저가 연결 시작 옵션으로reload 후 새 연결부터. 세션 중 변경 불가log_connections, log_disconnections
backend설정 파일, 또는 누구나 연결 시작 옵션으로reload 후 새 연결부터ignore_system_indexes (거의 쓰지 않음)
superuser설정 파일, 또는 슈퍼유저가 SETreload 또는 SET 즉시log_min_duration_statement, log_statement, lc_messages
user설정 파일, 또는 누구나 SETreload 또는 SET 즉시work_mem, search_path, statement_timeout, TimeZone, random_page_cost
시험 포인트: 재시작이 필요한 대표 파라미터

shared_buffers, max_connections, port, listen_addresses, wal_level, archive_mode, max_wal_senders, shared_preload_libraries. 대부분 "서버가 시작할 때 메모리나 소켓, 프로세스 구조를 잡는 데 쓰이는 값"이라고 이해하면 외우기 쉽습니다. 반면 archive_command는 reload로 충분하고, archive_mode는 재시작이 필요합니다. 이 짝이 자주 나옵니다.

용어: GRANT SET / ALTER SYSTEM 권한

PostgreSQL 15부터는 슈퍼유저가 아닌 역할에게 특정 파라미터의 변경 권한을 줄 수 있습니다. 예: GRANT SET ON PARAMETER log_min_duration_statement TO dba_team;, GRANT ALTER SYSTEM ON PARAMETER work_mem TO dba_team;. 운영 계정에 슈퍼유저를 주지 않고 필요한 설정만 허용할 때 씁니다.

4장

ALTER SYSTEM과 postgresql.auto.conf

ALTER SYSTEM은 SQL로 서버 설정을 바꾸는 명령입니다. 서버에 SSH로 들어가 파일을 편집하지 않아도 되므로 관리형 환경이나 원격 관리에 편리합니다. 핵심은 세 가지입니다.

  • 값은 postgresql.auto.conf에 기록됩니다. postgresql.conf는 건드리지 않습니다.
  • ALTER SYSTEM은 파일에 적기만 합니다. 적용은 context에 따라 reload나 재시작을 따로 해야 합니다.
  • 트랜잭션 블록 안에서는 실행할 수 없고, 기본적으로 슈퍼유저 권한이 필요합니다.

적용과 확인 방법

  
reload 하는 네 가지 방법


SELECT pg_reload_conf();                     -- SQL (슈퍼유저)
pg_ctl reload -D /var/lib/edb/as18/data      -- enterprisedb 사용자
sudo systemctl reload edb-as-18              -- 유닛에 reload가 정의된 경우
kill -HUP $(head -1 /var/lib/edb/as18/data/postmaster.pid)   -- postmaster에 SIGHUP


  
현재 값 확인


SHOW work_mem;                          -- 현재 세션에서의 값
SELECT current_setting('work_mem');     -- SQL 함수로

-- 값이 어디서 왔는지, 재시작이 필요한지까지
SELECT name, setting, unit, context, source, sourcefile, sourceline, pending_restart
FROM   pg_settings
WHERE  name = 'shared_buffers';

-- 재시작을 기다리는 파라미터 모두 찾기
SELECT name, setting FROM pg_settings WHERE pending_restart;


  
설정 파일 자체를 점검: pg_file_settings

  
pg_settings가 "지금 적용된 값"이라면, pg_file_settings는 "설정 파일에 적혀 있는 내용"입니다. reload 전에 오타나 잘못된 값이 없는지 미리 점검할 수 있습니다.


SELECT sourcefile, sourceline, name, setting, applied, error
FROM   pg_file_settings
WHERE  error IS NOT NULL OR NOT applied;

  

    시험 포인트
    
재시작이 필요한 파라미터를 바꾸고 reload만 하면 값은 바뀌지 않고 pending_restart가 true가 되며, 서버 로그에 "cannot be changed without restarting the server" 메시지가 남습니다. 설정 파일에 문법 오류가 있으면 로그에 오류가 기록되니, reload 후에는 로그를 확인하는 습관을 들이세요.

  







  
6장

  
설정 우선순위

  
같은 파라미터를 여러 곳에서 설정할 수 있고, 좁은 범위의 설정이 넓은 범위의 설정을 이깁니다. work_mem으로 직접 확인해 보세요. 체크하면 그 층의 설정을 켭니다. 아래에서 위로 갈수록 우선순위가 높습니다.

  

    

    

  


-- 각 층을 설정하는 명령
ALTER DATABASE sales SET work_mem = '32MB';                    -- 데이터베이스 단위
ALTER ROLE report_user SET work_mem = '128MB';                 -- 역할 단위
ALTER ROLE report_user IN DATABASE sales SET work_mem = '256MB';  -- 역할+DB 조합
PGOPTIONS="-c work_mem=64MB" psql sales                        -- 연결 시작 옵션
SET work_mem = '512MB';                                        -- 이 세션 동안
SET LOCAL work_mem = '1GB';                                    -- 이 트랜잭션 동안만

-- 되돌리기
RESET work_mem;                        -- 세션 설정 해제
ALTER ROLE report_user RESET work_mem; -- 역할 설정 해제
\drds                                  -- psql: 역할·DB별 설정 목록

  

    현장 사례: 리포트 계정만 메모리를 더 주기
    
"야간 정산 배치가 느리다"는 요청에 서버 전체 work_mem을 올리면, 수백 개의 OLTP 연결도 같이 영향을 받아 메모리가 위험해집니다(2편 계산기 참고). 대신 배치 전용 역할에만 ALTER ROLE batch_user SET work_mem = '256MB'를 주는 것이 정석입니다. 역할·DB 단위 설정은 새 연결부터 적용된다는 점도 함께 안내하세요.

핵심 파라미터 그룹

  
메모리와 WAL·체크포인트 파라미터는 2편에서 봤으니, 여기서는 나머지 그룹을 정리합니다. 전체 목록은 히어로의 판정기에서 검색할 수 있습니다.

  
연결

  

    
파라미터기본값context설명

    
      
listen_addresseslocalhostpostmaster연결을 받을 주소. '*'는 모든 인터페이스

      
port5432 (EPAS 5444)postmaster서버 포트

      
max_connections100postmaster최대 동시 연결 수

      
superuser_reserved_connections3postmaster연결이 가득 차도 슈퍼유저가 들어올 수 있게 남겨 두는 수

      
reserved_connections0postmasterpg_use_reserved_connections 역할에 남겨 두는 수 (PG16+)

    

  
타임아웃

  

    
파라미터기본값설명

    
      
statement_timeout0 (무제한)문장 하나가 이 시간을 넘으면 취소

      
lock_timeout0잠금을 이 시간 이상 기다리면 취소

      
idle_in_transaction_session_timeout0트랜잭션을 연 채 놀고 있는 세션을 끊음. 잠금을 쥔 채 방치된 세션 방지

      
idle_session_timeout0트랜잭션 밖에서 놀고 있는 세션을 끊음 (커넥션 풀 환경에서는 주의)

      
transaction_timeout0트랜잭션 전체 시간 제한 (PG17+)

    

  

    statement_timeout은 서버 전체보다 역할 단위로
    
서버 전체에 짧은 statement_timeout을 걸면 백업, 인덱스 생성, VACUUM 같은 긴 관리 작업까지 취소될 수 있습니다. 보통 애플리케이션 역할에만 ALTER ROLE app_user SET statement_timeout = '30s'처럼 겁니다.

  

  
옵티마이저 비용

  

    
파라미터기본값설명

    
      
random_page_cost4.0무작위 페이지 읽기의 상대 비용. SSD 환경에서는 1.1~2 정도로 낮추는 경우가 많음

      
seq_page_cost1.0순차 페이지 읽기 비용(기준값)

      
effective_cache_size4GB옵티마이저 힌트. 메모리를 할당하지 않음 (2편)

      
default_statistics_target100ANALYZE가 수집하는 통계의 상세도 (8편)

로그 설정 실전

  

    
파라미터기본값설명

    
      
logging_collectoroff (PG 기본)on이면 logger 프로세스가 로그를 파일로 모음. 변경 시 재시작

      
log_destinationstderrstderr, csvlog, jsonlog, syslog 등. 여러 개 동시 지정 가능

      
log_directory / log_filenamelog / postgresql-%Y-%m-%d_%H%M%S.log로그 위치와 파일 이름 패턴

      
log_rotation_age / log_rotation_size1d / 10MB로그 파일 교체 주기와 크기

      
log_line_prefix'%m [%p] '로그 한 줄 앞에 붙는 정보 (아래 빌더)

      
log_min_duration_statement-1 (끔)이 시간보다 오래 걸린 문장을 기록. 느린 쿼리 찾기의 기본

      
log_statementnonenone, ddl, mod(DDL+데이터 변경), all

      
log_checkpointson (PG15+)체크포인트 수행 기록

      
log_lock_waitsoffdeadlock_timeout(1초)보다 오래 잠금을 기다린 경우 기록

      
log_temp_files-1이 크기 이상의 임시 파일 생성을 기록. work_mem 부족 진단에 유용

      
log_autovacuum_min_duration10min이 시간보다 오래 걸린 autovacuum 기록

    

  
EPAS 패키지 설치는 기본 설정 파일에서 logging_collector를 켜 두는 경우가 많습니다. 설치 직후 SHOW logging_collector;와 SHOW log_directory;로 확인하세요.


  
log_line_prefix 빌더

  
넣고 싶은 정보를 고르면 설정값과 로그 예시를 만들어 줍니다. 로그 분석 도구(pgBadger 등)는 특정 형식을 요구하기도 하니 도구 문서도 함께 확인하세요.

  

    

    

    

  

  

    시험 포인트
    
log_statement = 'mod'는 DDL과 INSERT·UPDATE·DELETE·TRUNCATE 등 데이터를 바꾸는 문장을 기록하고, 'ddl'은 DDL만 기록합니다. log_min_duration_statement = 0은 모든 문장을 실행 시간과 함께 기록하므로 운영에서는 부하에 주의해야 합니다. 누가 무엇을 했는지 감사 목적으로 기록하는 것은 EPAS의 EDB Audit(7편)이 더 적합합니다.

EPAS 전용 파라미터

  
EPAS의 postgresql.conf에는 커뮤니티 PostgreSQL에 없는 파라미터가 추가되어 있습니다. 시험에서는 이름과 역할을 구분하는 수준으로 나옵니다.

  
동적 튜닝: edb_dynatune

  
EPAS는 서버의 자원을 보고 여러 메모리 관련 설정을 자동으로 정하는 Dynatune 기능을 제공합니다. 두 파라미터로 조절하며, 바꾸려면 서버를 재시작해야 합니다.

  

    
파라미터값의미

    
      
edb_dynatune0동적 튜닝 끔. 모든 자원 사용이 postgresql.conf의 다른 파라미터를 따름

      
34 ~ 66DB에 중간 정도의 자원 할당. 다른 애플리케이션과 함께 쓰는 서버

      
67 ~ 100대부분의 자원을 DB에 할당. EPAS 전용 서버

      
edb_dynatune_profileoltp / mixed / reporting예상 작업 유형에 맞춰 튜닝 방향을 정함

    

  
Dynatune을 켠 상태에서도 postgresql.conf에 직접 지정한 파라미터는 Dynatune이 정한 값보다 우선합니다. 즉 Dynatune으로 큰 틀을 잡고, 필요한 파라미터만 직접 조정하는 방식입니다.


  
Oracle 호환 동작 파라미터

  

    
파라미터켜면(Oracle 호환)

    
      
edb_redwood_dateDATE 컬럼에 시·분·초까지 저장 (Oracle DATE와 같은 동작)

      
edb_redwood_strings문자열 연결에서 NULL을 빈 문자열처럼 취급 ('a' || NULL → 'a')

      
edb_redwood_raw_namesOracle 호환 딕셔너리 뷰에 객체 이름을 저장된 그대로(소문자) 표시

      
edb_stmt_level_tx오류가 난 문장만 롤백하고 트랜잭션은 계속 (Oracle 동작). 4편의 aborted 트랜잭션과 대비

      
db_dialectpostgres 또는 redwood. 시스템 카탈로그 동작의 방언 지정

      
oracle_homeOracle 데이터베이스 연결(DB 링크 등)에 쓰는 Oracle 클라이언트 경로

    

  

    시험 포인트: edb_stmt_level_tx
    
PostgreSQL 기본 동작은 "문장 하나가 실패하면 트랜잭션 전체가 중단"이고, edb_stmt_level_tx = on은 "실패한 문장만 롤백"입니다. EDB는 성능 부담이 있으므로 꼭 필요할 때만 쓰라고 안내합니다. 12편 Oracle 호환에서 다시 다룹니다.

  

  

    shared_preload_libraries는 덮어쓰지 말고 덧붙이기
    
EPAS는 Oracle 호환 패키지 등을 위해 shared_preload_libraries에 여러 라이브러리가 기본으로 들어 있습니다. pg_stat_statements 같은 확장을 추가할 때 기존 값을 지우고 새 값만 적으면 EPAS 기능이 깨질 수 있습니다. 먼저 SHOW shared_preload_libraries;로 현재 값을 확인하고 그 목록에 덧붙이세요. 이 파라미터는 재시작이 필요합니다.
