리뷰할 수 있는 PR

Claude가 코드를 빠르게 쓸수록 사람의 리뷰가 병목이 됩니다. 리뷰어가 30분 안에 이해하고 판단할 수 없는 PR은, 아무리 테스트가 초록이어도 “통과 도장”만 받거나 방치됩니다.

📦 작게, 의미 단위로

한 PR은 하나의 목적. 한 커밋은 하나의 변경 이유. 리팩터링과 기능 변경을 섞지 않습니다.

🧭 왜를 먼저

무엇을 바꿨는지는 diff가 말합니다. 설명에는 왜, 어떤 위험을, 어떻게 확인했는지를.

🧪 증거와 함께

테스트 결과, 재현 방법, 실패하던 것이 통과하게 된 근거(17편).

↩️ 되돌릴 길

운영 스크립트는 머지가 곧 반영입니다. 롤백 방법과 반영 후 확인 방법을 적습니다. 고객사 변경관리(CAB) 문서에 그대로 옮길 수 있게.

커밋을 의미 단위로

테스트 커밋을 맨 앞에 두고, 위험 하나씩 고치는 커밋을 쌓으면 커밋마다 실패가 줄어들기만 합니다. 어느 커밋에서 무엇이 고쳐졌는지 테스트가 증명하고, 문제가 생기면 그 커밋만 되돌릴 수 있습니다. 아래는 이 강의를 만들며 실제로 커밋을 쌓고 매번 테스트를 돌린 결과입니다.

한 파일에 두 이유가 섞였다면

config.env는 #3(설정 주입)과 #4(비밀번호 제거)가 함께 바뀝니다. git add -p로 덩어리(hunk)별로 나누거나, 이 예처럼 한 커밋에 두 번호를 함께 적습니다.

이미 한 덩어리로 커밋했다면

git reset --soft <테스트 커밋>로 되돌린 뒤 다시 나눕니다. 이미 push했다면 남의 작업과 겹치지 않는지 확인하고 force push 대신 새 브랜치로(7편).

fix/risks 의 구현 커밋들을 위험 번호별 커밋으로 다시 나눠줘. - 첫 커밋은 테스트 커밋 그대로 두기 - 커밋마다 python3 -m unittest discover -s tests -t tests 결과를 기록하고, 실패 수가 늘어나는 커밋이 있으면 순서를 바꿔 - 메시지는 “fix(영역): 무엇을 (#번호)” 형식 - push 는 하지 마

    /code-review 해부

    /code-review(별칭 /review)는 현재 브랜치의 변경에서 정확성 버그를 찾는 번들 Skill입니다. 모델과 effort에 따라 재사용·단순화·효율 개선도 봅니다. 요금제와 상관없이 쓸 수 있고, 여러분 세션의 사용량으로 계산됩니다. 명령을 조립해 보세요.

    백그라운드 서브에이전트로

    터미널에서는 자기 컨텍스트를 가진 백그라운드 서브에이전트로 돌고, 끝나면 결과가 대화에 도착합니다. 그동안 계속 일할 수 있습니다.

    --fix와 /rewind

    백그라운드 리뷰가 --fix로 고친 파일은 체크포인트 밖입니다. /rewind로는 대화에서 이미 고친 파일만 돌아오니, 나머지는 Git으로 되돌리세요(6·13편). 앞쪽(foreground)으로 돌리면 평소처럼 되감깁니다.

    무엇을 기준으로

    CLAUDE.md를 따릅니다(-p에서도). REVIEW.md는 읽지 않습니다. 그 파일은 GitHub의 관리형 Code Review 서비스용입니다.

    effort

    low는 가장 확신하는 것만 보고해 거짓 양성이 적고, medium~max는 범위를 넓힙니다. 레벨을 안 쓰면 마지막에 직접 쓴 레벨을 다시 씁니다.

    Claude가 알아서 부를 때

    “리뷰해줘”라고 하면 Claude가 부를 수 있습니다. 직접 칠 때만 돌게 하려면 "skillOverrides": {"code-review": "user-invocable-only"}(10편).

    바꾸고 싶다면

    번들이라 SKILL.md 파일이 없습니다. 규칙은 CLAUDE.md에, 완전히 바꾸려면 같은 이름의 프로젝트 Skill(단 /review 별칭은 계속 번들을 부름). 정리만 원하면 /simplify.

    동료 PR 리뷰 연습

    동료 choi가 feat/cert-check 브랜치로 인증서 만료 점검을 올렸습니다. 테스트 결과는 OK입니다. 먼저 코드를 직접 읽고, 다음으로 /code-review fix/risks...feat/cert-check를 돌려 본 뒤, 찾은 것에 표시하세요. 표시한 항목을 누르면 이 강의를 만들며 확인한 내용이 열립니다.

    #!/bin/bash source $(dirname $0)/../lib/common.sh WARN_DAYS=30 for host in $(cat $(dirname $0)/../certs.txt); do end=$(echo | openssl s_client -connect $host:443 -servername $host 2>/dev/null | openssl x509 -noout -enddate | cut -d= -f2) left=$(( ($(date -d "$end" +%s) - $(date +%s)) / 86400 )) echo "$host $left" >> /tmp/cert_report.txt if [ $left -lt $WARN_DAYS ]; then send_alert "cert $host $left days" fi done

    그 밖의 변경: certs.txt 추가(주석 한 줄 + 호스트 2개), run_all.sh에 ./checks/check_cert.sh 한 줄, tests/test_disk.py에 한 줄.

    리뷰 결과 다루기

    근거 확인

    지적마다 “재현 방법이나 실행 근거를 보여줘”. 6장의 1·2번은 가짜 openssl로 재현되지만, 3번(시간 제한)은 코드 근거입니다. 둘의 확신도는 다릅니다.

    거짓 양성 가려내기

    “date -d는 macOS에서 안 된다”는 사실이지만 이 서버는 Linux입니다. 틀린 건 아니어도 우선순위가 낮습니다. 판단은 여러분 몫.

    --fix를 맹신하지 않기

    지적이 맞아도 고치는 방식은 여러 가지입니다. 큰 변경은 --fix 대신 계획을 먼저 받고(4편), 커밋을 따로 만드세요.

    남의 PR은 제안으로

    동료 브랜치를 직접 고치지 말고 --comment로 남기거나 제안 코드를 코멘트로. 고치는 사람은 작성자입니다.

    GitHub Actions로 자동 리뷰

    anthropics/claude-code-action은 GitHub 워크플로 안에서 Claude Code를 돌립니다. PR·이슈 코멘트의 @claude에 응답하거나, 정해진 이벤트에 프롬프트를 실행합니다. 가장 쉬운 설정은 터미널의 Claude Code에서 /install-github-app입니다. 저장소 관리자 권한이 필요하고, GitHub 앱 설치와 인증 비밀(API 키면 ANTHROPIC_API_KEY, 구독 토큰이면 CLAUDE_CODE_OAUTH_TOKEN) 저장, 워크플로 파일 추가를 안내합니다.

    비밀은 secrets에만

    API 키·토큰을 워크플로 파일에 쓰지 마세요. ${{ secrets.… }}로만 참조합니다.

    외부인의 PR·코멘트

    PR 본문·코드·코멘트는 Claude에게 들어가는 입력입니다(1편 프롬프트 인젝션). 공개 저장소라면 누가 @claude를 부를 수 있는지 제한하고, 포크 PR에 비밀을 넘기는 pull_request_target은 그 위험을 이해하기 전에는 쓰지 마세요.

    권한은 최소로

    리뷰만 한다면 contents는 읽기로. 코드를 고쳐 커밋하게 할 때만 쓰기를 줍니다.

    비용 상한

    최대 턴 수, 작업 timeout, 같은 PR에 새 push가 오면 이전 실행 취소(concurrency), 경로 필터로 문서만 바뀐 PR 건너뛰기.

    액션의 입력 이름(예: prompt, claude_args)과 예시는 버전에 따라 바뀌어 왔습니다. 위 생성기는 출발점이며, 실제 적용 전에 액션 저장소의 examples/와 공식 GitHub Actions 문서를 기준으로 맞추세요. 클라우드 쪽 Bedrock·Vertex 사용, 셀프 호스팅 러너 설정도 그 문서에 있습니다.

    실습: 두 PR 끝내기

    17편까지 마친 ~/acme-ops-legacy(fix/risks 브랜치, 테스트 16개 통과)에서 진행합니다. 아래 블록은 fix/risks 위에 동료 choi의 feat/cert-check 브랜치를 만듭니다. 이 블록을 실행한 저장소에서 6장의 문제를 모두 재현했습니다.

    cd ~/acme-ops-legacy git switch fix/risks python3 -m unittest discover -s tests -t tests 2>&1 | tail -1 # 17편 완료 확인: OK git switch -c feat/cert-check cat > checks/check_cert.sh <<'PREOF' #!/bin/bash source $(dirname $0)/../lib/common.sh WARN_DAYS=30 for host in $(cat $(dirname $0)/../certs.txt); do end=$(echo | openssl s_client -connect $host:443 -servername $host 2>/dev/null | openssl x509 -noout -enddate | cut -d= -f2) left=$(( ($(date -d "$end" +%s) - $(date +%s)) / 86400 )) echo "$host $left" >> /tmp/cert_report.txt if [ $left -lt $WARN_DAYS ]; then send_alert "cert $host $left days" fi done PREOF chmod +x checks/check_cert.sh cat > certs.txt <<'PREOF' # 인증서 점검 대상 (호스트명) www.acme.example api.acme.example PREOF python3 - <<'PREOF' s = open("run_all.sh").read() open("run_all.sh", "w").write(s.replace("./checks/check_disk.sh\n", "./checks/check_disk.sh\n./checks/check_cert.sh\n")) s = open("tests/test_disk.py").read() open("tests/test_disk.py", "w").write(s.replace(" def test_alerts", ' @unittest.skip("내 PC에서 가끔 실패함")\n def test_alerts')) PREOF git add -A GIT_AUTHOR_NAME=choi GIT_AUTHOR_EMAIL=choi@example.com git commit -qm "feat: 인증서 만료 점검 추가" git switch fix/risks git log --oneline --graph --all | head -12
