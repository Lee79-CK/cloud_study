Terraform & Ansible 강의 · Level 3 Ansible 기초 · 15편 / 26편 · 시리즈 목차

같은 플레이북, 다른 서버, 알맞은 결과 변수·팩트·템플릿·흐름 제어 — 우선순위 22단계, facts, Jinja2와 필터, when·loop·register, block/rescue/always, 오류 처리와 재시도

14편의 플레이북은 값이 플레이에 박혀 있고, 배포판 차이는 태스크 하나의 조건으로 버텼습니다. 서버가 늘고 배포판이 섞이면 이 방식은 금방 한계에 부딪힙니다. 이번 편은 값을 어디에 둘지(변수와 우선순위), 서버의 사실을 어떻게 알지(팩트), 설정 파일을 어떻게 찍어낼지(Jinja2 템플릿), 그리고 실패했을 때 어떻게 되돌릴지(block/rescue)를 다룹니다. 마지막에 14편 플레이북을 Ubuntu·Rocky 모두에서 동작하고, 잘못된 설정이면 스스로 이전 설정으로 돌아가는 2판으로 다시 씁니다.

값

-e가 언제나 이긴다. 그 아래 21단계는 “넓은 것에서 좁은 것으로”.

판단

팩트로 서버를 알고, when·loop로 다르게 처리한다.

복구

nginx -t 실패 → rescue가 백업으로 되돌림 → 서비스는 200 유지 (실측).

  • 변수 우선순위 22단계 중 실무에 필요한 핵심 층을 알고, 같은 이름의 변수가 여러 곳에 있을 때 무엇이 이기는지 예측할 수 있습니다.

  • block/rescue/always, assert, failed_when, until/retries로 실패를 다룹니다.

1변수 우선순위 22단계

아래로 갈수록 강하다 — 층을 눌러 설명을 보세요 (굵은 층이 실무 핵심)

층을 선택하세요

공식 문서의 22단계입니다. 전부 외울 필요는 없고, “역할 기본값은 가장 약하다, -e는 언제나 이긴다, 인벤토리는 넓은 것(all)에서 좁은 것(호스트) 순, 플레이 안에서는 태스크에 가까울수록 강하다”를 기억하면 대부분 맞힙니다.

어디에 둘까두는 값예
역할 defaults (16편)“바꿔도 되는” 기본값. 가장 약해서 어디서든 덮어쓸 수 있다nginx_port: 80
인벤토리 group_vars / host_vars (13편)환경·서버 그룹·서버별로 다른 값dev/prd의 도메인, node3만 다른 포트
플레이 vars / vars_files이 플레이북에서만 쓰는 값사이트 이름, 위치 목록
include_vars조건에 따라 불러오는 값 (배포판별 경로 등). 플레이 vars보다 강하다vars/{{ os_family }}.yml
set_fact / register실행 중에 계산·수집한 값명령 결과, 조합한 값
-e (extra vars)실행 시 강제로. 무엇보다 강함긴급 실행, CI 파이프라인 매개변수
include_vars·set_fact가 생각보다 강하다

18단계 include_vars와 19단계 set_fact는 플레이 vars(12)는 물론 인벤토리 host_vars(9·10)보다 강합니다. 실습 2판에서 배포판별 값을 include_vars로 불러오므로, 같은 이름(nginx_user 등)을 인벤토리에 두어 서버별로 바꾸려 해도 바뀌지 않습니다. 서버별로 바꿀 여지가 있는 값은 include_vars 파일에 두지 말고, 이름을 나눠(예: _nginx_user_default) default 필터로 합치는 식으로 설계합니다. -e만은 언제나 이 모두를 이깁니다.

3팩트와 매직 변수

서버가 스스로 알려 주는 사실, 그리고 Ansible이 알고 있는 인벤토리 정보

playbooks/facts.yml
---
- name: 팩트 살펴보기
  hosts: lab
  gather_facts: true
  tasks:
    - name: 자주 쓰는 팩트 (ansible_facts 사전에서)
      ansible.builtin.debug:
        msg:
          - "배포판: {{ ansible_facts['distribution'] }} {{ ansible_facts['distribution_version'] }}"
          - "계열: {{ ansible_facts['os_family'] }} / 패키지 관리자: {{ ansible_facts['pkg_mgr'] }}"
          - "CPU {{ ansible_facts['processor_vcpus'] }}개, 메모리 {{ ansible_facts['memtotal_mb'] }}MB"
          - "기본 IPv4: {{ ansible_facts['default_ipv4']['address'] | default('없음') }}"
          - "Python: {{ ansible_facts['python_version'] }}"
      when: inventory_hostname == 'node1'

    - name: 매직 변수 — 인벤토리에 대한 정보
      ansible.builtin.debug:
        msg:
          - "나: {{ inventory_hostname }}, 내 그룹: {{ group_names }}"
          - "ubuntu 그룹: {{ groups['ubuntu'] }}"
          - "이번 실행 대상: {{ ansible_play_hosts }}"
          - "node3의 pkg_manager 변수: {{ hostvars['node3']['pkg_manager'] }}"
      run_once: true

- name: 사용자 정의 팩트 (facts.d)
  hosts: node1
  become: true
  gather_facts: false
  tasks:
    - name: 팩트 디렉터리
      ansible.builtin.file:
        path: /etc/ansible/facts.d
        state: directory
        mode: "0755"

    - name: 고객·역할 정보를 로컬 팩트로 기록
      ansible.builtin.copy:
        dest: /etc/ansible/facts.d/msp.fact
        content: |
          [owner]
          customer=custa
          role=web
          sla=gold
        mode: "0644"

    - name: 팩트 다시 수집 (local 만)
      ansible.builtin.setup:
        gather_subset: ['!all', 'local']

    - name: 사용자 정의 팩트 읽기
      ansible.builtin.debug:
        var: ansible_facts['ansible_local']['msp']['owner']

4Jinja2와 template 모듈

설정 파일을 “값만 바꿔 찍어내는 틀”로

문법뜻예
{{ … }}값 출력listen {{ web_port }};
{% … %}제어문 (for, if, set){% for loc in locations %}
{# … #}템플릿 주석 (결과에 남지 않음)—

렌더링 결과 — 값을 바꾸면 결과가 어떻게 달라지는지 (node1에서 실제 렌더링한 파일)

template 모듈 인자쓰임
src / dest플레이북 옆 templates/에서 찾는다 (역할이면 역할의 templates/, 16편)
owner·group·mode권한 (mode는 항상 따옴표, 14편)
backup: true내용이 바뀔 때만 이전 파일을 이름.PID.날짜@시각~으로 보존하고, 결과의 backup_file에 경로를 돌려준다 (실측: iac-lab.conf.4680.2026-10-22@08:32:08~)
validate: '명령 %s'임시 파일을 검사 명령이 통과해야만 실제 위치에 쓴다. 파일 하나로 완결되는 설정에 (sudoers visudo -cf %s, sshd sshd -t -f %s, 전체 nginx.conf)
백업 파일 이름이 ~로 끝나는 이유

nginx는 conf.d/*.conf만 읽으므로, 백업 파일(….conf.4680.…~)은 설정으로 읽히지 않습니다. 반대로 백업을 iac-lab.conf.bak.conf처럼 만들면 nginx가 두 파일을 모두 읽어 중복 오류가 납니다. 디렉터리 전체를 include하는 서비스에서는 백업 위치와 이름에 주의하고, 오래된 백업은 정기적으로 정리합니다(과제 4).

5필터와 테스트

값을 가공하는 |(필터)와 값을 판정하는 is(테스트)

playbooks/filters.yml
---
- name: Jinja2 필터 연습 (컨트롤 노드에서만)
  hosts: localhost
  connection: local
  gather_facts: false
  vars:
    servers:
      - { name: web1, role: web, port: 8080, enabled: true }
      - { name: web2, role: web, port: 8081, enabled: false }
      - { name: db1, role: db, port: 5432, enabled: true }
    base_tags: { Project: custa, ManagedBy: ansible }
    extra_tags: { Env: dev, ManagedBy: someone-else }
    version: "1.24.0"
  tasks:
    - name: 결과 보기
      ansible.builtin.debug:
        msg:
          - "default:      {{ undefined_var | default('기본값') }}"
          - "map+join:     {{ servers | map(attribute='name') | join(', ') }}"
          - "selectattr:   {{ servers | selectattr('enabled') | map(attribute='name') | list }}"
          - "조건 필터:     {{ servers | selectattr('role', 'equalto', 'web') | map(attribute='port') | max }}"
          - "combine:      {{ base_tags | combine(extra_tags) }}"
          - "dict2items:   {{ base_tags | dict2items | map(attribute='key') | sort }}"
          - "ternary:      {{ (servers | length > 2) | ternary('대규모', '소규모') }}"
          - "regex:        {{ 'custa-prd-web-01' | regex_replace('-\\d+$', '') }}"
          - "버전 비교:     {{ version is version('1.20', '>=') }}"
          - "형 변환:       {{ '8080' | int + 1 }} / {{ 'yes' | bool }}"

- name: when · loop · register 연습
  hosts: node1
  gather_facts: true
  vars:
    sysctl_wanted:
      net.core.somaxconn: 1024
      vm.swappiness: 10
  tasks:
    - name: Nginx 버전 확인
      ansible.builtin.command: nginx -v
      register: nginx_ver

      failed_when: false

    - name: 등록된 결과의 구조 보기
      ansible.builtin.debug:
        msg:
          - "rc={{ nginx_ver.rc }}"
          - "stderr={{ nginx_ver.stderr }}"
          - "버전={{ nginx_ver.stderr | regex_search('[0-9]+\\.[0-9]+\\.[0-9]+') }}"

    - name: 1.24 이상일 때만 (버전 테스트)
      ansible.builtin.debug:
        msg: "최신 설정 문법 사용 가능"
      when:
        - nginx_ver.rc == 0
        - nginx_ver.stderr | regex_search('[0-9]+\.[0-9]+\.[0-9]+') is version('1.24', '>=')

    - name: Rocky 계열에서만 (이 랩에서는 건너뜀)
      ansible.builtin.debug:
        msg: "firewalld 설정 필요"
      when: ansible_facts['os_family'] == "RedHat"

    - name: 딕셔너리를 돌기 (dict2items)
      ansible.builtin.debug:
        msg: "{{ item.key }} = {{ item.value }}"
      loop: "{{ sysctl_wanted | dict2items }}"
      loop_control:
        label: "{{ item.key }}"

    - name: 반복 + register 결과는 results 목록
      ansible.builtin.command: "test -d {{ item }}"
      loop: [/etc/nginx, /etc/notexist]
      register: dir_check
      changed_when: false
      failed_when: false

    - name: 없는 디렉터리만 골라내기
      ansible.builtin.debug:
        msg: "{{ dir_check.results | selectattr('rc', 'ne', 0) | map(attribute='item') | list }}"

when표현식(따옴표 안에 {{ }} 없이). 목록으로 쓰면 모두 참(AND). 결과는 반드시 불리언(2.19+). loop와 함께면 항목마다 평가

7block · rescue · always

프로그래밍 언어의 try · catch · finally

- name: 사이트 설정 안전하게 배포
  block:                                   # try
    - name: 새 설정 쓰기 (바뀔 때만 이전 파일을 자동 백업)
      ansible.builtin.template: { …, backup: true }
      register: site_conf
      notify: nginx 설정 변경
    - name: 문법 검사
      ansible.builtin.command: nginx -t
      changed_when: false
  rescue:                                  # catch — block 안에서 실패하면
    - name: 백업으로 되돌리기
      ansible.builtin.copy: { src: "{{ site_conf.backup_file }}", dest: …, remote_src: true }
      when: site_conf.backup_file is defined
    - name: 실패로 끝내기
      ansible.builtin.fail: { msg: "…이전 설정으로 되돌렸습니다…" }
  always:                                  # finally — 성공·실패와 무관하게
    - name: 배포 기록 남기기
      ansible.builtin.lineinfile: { line: "… result={{ 'failed' if ansible_failed_task is defined else 'ok' }}", … }

규칙설명
rescue가 실행되면block의 실패가 “구조됨(rescued)”으로 바뀐다. rescue를 끝까지 통과하면 플레이는 계속된다. 실패로 끝내려면 rescue 마지막에 fail (실습처럼)

block에 공통 키워드become, when, tags를 block에 한 번 쓰면 안의 모든 태스크에 적용
14편의 “검사 핸들러”와 무엇이 다른가

14편은 잘못된 설정이 디스크에 남은 채 다시 읽기만 막았습니다. 2판은 디스크의 파일까지 이전 상태로 되돌리고, 실패를 기록합니다. 다음 정상 실행은 바뀐 것이 없으므로 changed=0으로 끝납니다(실측). Terraform이라면 잘못된 변경이 apply 단계에서 실패하면 어중간한 상태가 남지만, 서버 설정은 이렇게 “쓰기 → 검사 → 실패 시 복구”를 한 덩어리로 묶을 수 있습니다.

8오류 처리와 재시도

실패를 미리 막고(assert), 실패를 정확히 판정하고(failed_when), 일시적 실패는 기다린다(until)

# 실측: 입력 검증 (pre_tasks의 assert) — web_port=80
fatal: [node1]: FAILED! =>

FAILED - RETRYING: [node1]: 응답이 올 때까지 재시도 (4 retries left).
FAILED - RETRYING: [node1]: 응답이 올 때까지 재시도 (3 retries left).

도구쓰임
assert (that, fail_msg, quiet)시작 전에 가정 확인 — 11편 Terraform precondition과 같은 역할. 잘못된 값이면 아무것도 바꾸기 전에 멈춘다
fail (msg)조건부로 의도적 실패 (rescue 마지막 등)
failed_when반환 코드 대신 출력 내용으로 실패 판정. failed_when: false는 “절대 실패하지 않음”(조회·탐지용)
ignore_errors: true실패해도 계속 (RECAP의 ignored). 남용하면 문제를 숨긴다
ignore_unreachable: true접속 실패를 무시 (점검용 플레이)
until + retries + delay조건이 참이 될 때까지 재시도 (서비스 기동 대기, API 준비, 잠금 해제 대기). 기본 retries 3, delay 5
any_errors_fatal: true한 호스트라도 실패하면 플레이 전체 중단 (클러스터처럼 반쪽 상태가 위험할 때)
max_fail_percentage, serial롤링 배포에서 허용 실패 비율 (20편)
validate: 쓰기 전에 검사

실습 2판은 deploy 계정에 “nginx 다시 읽기”만 허용하는 sudoers 파일을 validate: /usr/sbin/visudo -cf %s로 씁니다. sudoers에 문법 오류가 있으면 sudo 자체가 막혀 Ansible도 접속 후 권한 상승을 못 하게 되므로(스스로 잠기는 사고), 쓰기 전 검사가 필수인 대표 사례입니다. sshd_config도 같은 이유로 sshd -t -f %s로 검사합니다(17편).

# 15편: 14편 web.yml을 변수·팩트·템플릿·흐름 제어로 다시 쓴 버전
- name: 웹 서버 구성 (Ubuntu·Rocky 공통)
  hosts: lab
  become: true

  vars:
    web_port: 8080
    site_title: "iac-lab"
    site_root: /var/www/iac-lab
    server_names: ["_"]
    web_packages: [nginx, curl]
    locations:
      - path: /
        comment: 정적 파일
        headers:
          X-Frame-Options: DENY
          X-Content-Type-Options: nosniff
      - path: /health
        comment: 상태 확인 (로드밸런서용)
    ops_users:
      - { name: deploy, comment: "배포 자동화", shell: /bin/bash }
      - { name: auditor, comment: "점검 전용", shell: /usr/sbin/nologin }

  pre_tasks:
    - name: 입력 값 검증
      ansible.builtin.assert:
        that:
          - web_port | int >= 1024
          - web_port | int <= 65535
          - locations | length > 0
        fail_msg: "web_port는 1024~65535, locations는 1개 이상이어야 합니다 (현재 web_port={{ web_port }})"
        quiet: true

    - name: 배포판 계열별 변수 불러오기
      ansible.builtin.include_vars:
        file: "vars/{{ ansible_facts['os_family'] }}.yml"

  tasks:
    - name: 패키지 설치
      ansible.builtin.package:
        name: "{{ web_packages }}"
        state: present

    - name: 운영 계정
      ansible.builtin.user:
        name: "{{ item.name }}"
        comment: "{{ item.comment }}"
        shell: "{{ item.shell }}"
        state: present
      loop: "{{ ops_users }}"
      loop_control:
        label: "{{ item.name }}"

    - name: Deploy 계정에 nginx 다시 읽기 권한만 위임 (문법 검사 후 반영)
      ansible.builtin.copy:
        dest: /etc/sudoers.d/deploy-nginx
        content: "deploy ALL=(root) NOPASSWD: /usr/sbin/nginx -s reload\n"
        owner: root
        group: root
        mode: "0440"
        validate: /usr/sbin/visudo -cf %s

    - name: 배포판 기본 사이트 끄기 (해당하는 계열만)
      ansible.builtin.file:
        path: "{{ nginx_default_site }}"
        state: absent
      when: nginx_default_site | length > 0
      notify: nginx 설정 변경

    - name: 사이트 디렉터리
      ansible.builtin.file:
        path: "{{ site_root }}"
        state: directory
        owner: root
        group: root
        mode: "0755"

    - name: 첫 페이지와 상태 확인 파일
      ansible.builtin.template:
        src: index.html.j2
        dest: "{{ site_root }}/{{ item }}"
        owner: root
        group: root
        mode: "0644"
      loop: [index.html, health]

    - name: 사이트 설정 안전하게 배포
      block:
        - name: 새 설정 쓰기 (바뀔 때만 이전 파일을 자동 백업)
          ansible.builtin.template:
            src: iac-lab.conf.j2
            dest: /etc/nginx/conf.d/iac-lab.conf
            owner: root
            group: root
            mode: "0644"
            backup: true
          register: site_conf
          notify: nginx 설정 변경

        - name: 문법 검사
          ansible.builtin.command: nginx -t
          changed_when: false

      rescue:
        - name: 백업으로 되돌리기
          ansible.builtin.copy:
            src: "{{ site_conf.backup_file }}"
            dest: /etc/nginx/conf.d/iac-lab.conf
            remote_src: true
            mode: "0644"
          when: site_conf.backup_file is defined

        - name: 실패로 끝내기
          ansible.builtin.fail:
            msg: "새 설정이 nginx -t를 통과하지 못해 이전 설정으로 되돌렸습니다. 템플릿 값을 확인하세요."

      always:
        - name: 배포 기록 남기기
          ansible.builtin.lineinfile:
            path: /var/log/iac-lab-deploy.log
            line: >-
              {{ now(utc=true).isoformat() }} {{ inventory_hostname }} port={{ web_port }}
              result={{ 'failed' if ansible_failed_task is defined else 'ok' }}
            create: true
            mode: "0644"
          changed_when: false

    - name: Nginx 실행 및 부팅 시 자동 시작
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true

    - name: 대기 중인 핸들러를 지금 실행
      ansible.builtin.meta: flush_handlers

    - name: 응답이 올 때까지 재시도
      ansible.builtin.uri:
        url: "http://127.0.0.1:{{ web_port }}/health"
        return_content: true
      register: health
      until: health.status == 200 and site_title in health.content
      retries: 5
      delay: 2
      changed_when: false

  handlers:
    - name: Nginx 다시 읽기
      ansible.builtin.service:
        name: nginx
        state: reloaded
      listen: nginx 설정 변경

11MSP 현장 팁

고객사마다 다른 값을 하나의 플레이북으로

값의 자리를 정해 두기

“코드에 기본값(역할 defaults) → 고객·환경 값은 인벤토리 group_vars → 서버 예외는 host_vars → 긴급 조치만 -e”. 이 규칙 하나로 대부분의 “이 값이 왜 이렇게 됐지?”가 사라집니다. include_vars·set_fact는 계산·배포판 분기 전용으로 제한합니다.

사용자 정의 팩트로 서버 메타데이터

고객명·역할·SLA 등급·담당자를 /etc/ansible/facts.d/msp.fact로 서버에 심어 두면, 어떤 플레이북에서든 ansible_facts['ansible_local']['msp']로 읽을 수 있고 동적 인벤토리(18편)의 그룹 기준으로도 쓸 수 있습니다.

템플릿 = 고객 설정 표준

nginx·chrony·sshd·logrotate 설정을 템플릿으로 표준화하고 고객별 차이는 변수로만 둡니다. 서버에서 손으로 고친 흔적은 다음 실행의 diff로 드러납니다. 템플릿 첫 줄의 ansible_managed에 담당 팀 연락처를 넣는 조직도 있습니다.

변경은 “쓰기·검사·복구” 한 덩어리로

운영 설정을 바꾸는 모든 태스크에 실습 2판의 block/rescue 패턴(또는 validate)을 적용하는 것을 팀 규칙으로 두면, 설정 오류로 인한 장애의 대부분을 막을 수 있습니다. 복구 결과는 always에서 로그·메신저로 남깁니다.

팩트는 보고서 재료

13편 과제 5의 서버 현황표를 팩트 + 템플릿으로 자동 생성할 수 있습니다(과제 3). OS 버전 분포, 메모리·디스크, 커널 버전을 고객 월간 보고서에 넣으면 EOL 계획(예: 구형 OS 교체)의 근거가 됩니다.

비밀은 변수 파일에 평문으로 두지 않는다

mandatory 필터로 “반드시 외부에서 주입”을 강제하고, 실제 값은 Ansible Vault나 외부 비밀 저장소에서(19편). loop에 비밀이 섞이면 loop_control.label과 no_log로 출력에서 숨깁니다.

과제 1. 우선순위 예측

http_port가 인벤토리 group_vars/all(80), 인벤토리 host_vars/node3(9090), 플레이 vars(8080), include_vars(7070)에 있습니다. node1과 node3에서 각각 무엇이 나올까요? -e http_port=6060을 주면? 2장의 스크립트를 고쳐 확인하세요.

해설

include_vars(18)가 플레이 vars(12)와 host_vars(9)보다 강하므로 node1·node3 모두 7070. -e를 주면 둘 다 6060. 서버별로 다르게 하려던 node3의 9090이 무시되는 것이 1장 경고의 실제 모습입니다.

과제 2. 로드밸런서 설정 템플릿

lab의 node1을 “로드밸런서”로 정하고, groups['ubuntu']의 다른 호스트들과 각자의 hostvars[h]['ansible_host']·web_port로 nginx upstream 블록을 만드는 템플릿을 작성하세요. 자기 자신은 제외합니다.

힌트

{% for h in groups['ubuntu'] if h != inventory_hostname %}server {{ hostvars[h]['ansible_host'] }}:{{ hostvars[h]['web_port'] | default(8080) }};{% endfor %}. 다른 호스트의 팩트를 쓰려면 그 호스트가 이번 실행에서 팩트를 수집했어야 하므로, --limit node1로 실행하면 팩트가 비어 있을 수 있습니다(팩트 캐시 또는 delegate_facts로 해결).

과제 3. 서버 현황 보고서

팩트로 lab 전체의 “호스트, 배포판, 커널, vCPU, 메모리, 루트 디스크 사용률”을 모아 컨트롤 노드에 Markdown 표(report.md)로 만드세요. 13편 과제 5를 자동화하는 것입니다.

힌트

템플릿을 delegate_to: localhost와 run_once: true로 한 번만 렌더링하고, 템플릿 안에서 {% for h in ansible_play_hosts %}로 hostvars[h]['ansible_facts']를 읽습니다. 루트 디스크는 ansible_facts['mounts'] | selectattr('mount','equalto','/') | first.

과제 4. 오래된 백업 정리

template의 backup이 만든 iac-lab.conf.*~ 파일 중 최근 5개만 남기고 지우는 태스크를 작성하세요. find 모듈과 필터(sort, 슬라이스)를 씁니다.

힌트

ansible.builtin.find: paths=/etc/nginx/conf.d patterns='iac-lab.conf.*~' → register → (result.files | sort(attribute='mtime'))[:-5]를 loop로 file state=absent.

과제 5. chrony를 2판 방식으로

{{ }}·{% %}·{# #}, ansible_managed, for·if. template의 backup(바뀔 때만)·validate(쓰기 전 검사).
