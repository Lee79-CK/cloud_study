시작 전 체크리스트

💻 시스템 요구사항 (터미널 CLI)

  • OS: macOS 13.0 이상, Windows 10 1809 이상 또는 Windows Server 2019 이상, Ubuntu 20.04 이상, Debian 10 이상, Alpine Linux 3.19 이상
  • 하드웨어: RAM 4GB 이상, x64 또는 ARM64 CPU
  • 네트워크: 인터넷 연결 필수
  • 셸: Bash, Zsh, PowerShell, CMD
  • 지역: Anthropic 지원 국가

🔑 계정

  • Pro·Max·Team·Enterprise 구독, 또는 Claude Console(API) 계정
  • 무료 claude.ai 요금제로는 Claude Code를 쓸 수 없습니다
  • 회사가 Amazon Bedrock·Google Cloud Agent Platform·Microsoft Foundry를 쓴다면 그 경로도 가능
  • 회사 계정이라면 관리자가 Claude Code를 켜 두었는지 확인
검색 도구 ripgrep Claude Code에는 ripgrep이 함께 들어 있어서 따로 설치할 필요가 없습니다. Alpine 같은 musl 기반 배포판에서는 함께 들어 있는 ripgrep이 동작하지 않을 수 있으므로 시스템에 ripgrep을 설치하고 USE_BUILTIN_RIPGREP=0을 설정합니다.

설치하기

공식 권장은 네이티브 설치입니다. 백그라운드에서 자동 업데이트되기 때문입니다. Homebrew·WinGet·Linux 패키지 관리자로 설치하면 업데이트를 직접 해 줘야 합니다. 아래에서 내 환경을 고르면 설치 명령과 주의점을 보여 줍니다.

관리자 권한이 필요 없습니다 네이티브 설치는 사용자 홈 디렉토리에 설치되므로 sudo나 관리자 권한 PowerShell이 필요 없습니다. 특히 npm으로 설치할 때 sudo npm install -g는 권한 문제와 보안 위험이 있어 공식 문서가 하지 말라고 경고합니다.
인터넷에서 받은 스크립트를 파이프로 실행하는 것이 찜찜하다면 curl ... | bash 방식이 불편한 보안 정책 환경이라면 서명된 apt·dnf·apk 저장소를 쓰세요. 패키지 관리자가 저장소 서명을 자동으로 검증합니다. 공식 문서는 릴리스마다 서명된 manifest.json(SHA256 체크섬)도 제공하며, macOS와 Windows 바이너리에는 각각 Anthropic의 코드 서명이 들어 있습니다.

claude --version # 버전 번호와 (Claude Code)가 출력되면 성공 claude doctor # 설치 상태·설정 파일 오류·경고를 세션 없이 점검

설치 명령은 내려받는 동안 진행 표시가 없습니다. 멈춘 것처럼 보여도 잠시 기다리세요. 세션 안에서는 /doctor로 같은 점검을 하고, 일부 문제는 바로 고칠 수도 있습니다.

로그인과 인증

처음 claude를 실행하면 브라우저가 열리고 로그인 화면이 나옵니다. 로그인을 마치면 터미널에 Login successful이 표시되고 Enter를 누르면 계속됩니다. 이후에는 자격 증명이 저장되어 다시 로그인할 필요가 없습니다. 로그인 만료 3일 전부터는 시작할 때 /login으로 갱신하라는 안내가 나옵니다.

Pro·Max 구독

claude.ai 계정으로 로그인. 개인 학습에 가장 일반적인 경로입니다.

Team·Enterprise

관리자가 초대한 claude.ai 계정으로 로그인. SSO는 자동으로 처리됩니다.

Claude Console

관리자 초대 후 Console 자격 증명으로 로그인. API 키를 만들지 않는 OAuth 로그인이 권장(recommended)으로 표시됩니다.

클라우드 제공자

Bedrock·Agent Platform·Foundry는 환경 변수를 설정하거나 로그인 화면에서 “3rd-party platform”을 고릅니다. 브라우저 로그인이 없습니다.

브라우저가 다른 컴퓨터에 있을 때

SSH로 접속한 서버, WSL2, 컨테이너에서는 브라우저가 열리지 않거나 로그인 후 터미널로 돌아오지 못할 수 있습니다. 이럴 때는 로그인 화면에서 c를 눌러 로그인 URL을 복사하고, 내 PC의 브라우저에서 열어 로그인한 뒤, 브라우저에 표시된 코드를 터미널의 “Paste code here if prompted”에 붙여 넣습니다.

인증 우선순위 판정기

여러 자격 증명이 동시에 있으면 Claude Code는 정해진 순서로 하나를 고릅니다. 가장 흔한 사고는 구독으로 로그인해 놓고 셸 프로필에 예전 ANTHROPIC_API_KEY가 남아 있는 경우입니다. 처음 물어볼 때 이 키를 승인하면 구독 대신 API 키가 쓰여 요금이 API로 청구되거나, 키의 조직이 비활성화되어 400 “organization disabled” 오류가 납니다. 내 상황을 체크해 보세요.

내 환경에 있는 것
    Claude Code가 고르는 순서
      지금 무엇으로 로그인했는지 확인: /status 세션 안에서 /status를 실행하면 현재 모델, 로그인 방식, 조직, 이메일이 나옵니다. 로그인과 API 키가 함께 있으면 쓰지 않는 쪽이 표시됩니다. 구독으로 돌아가려면 unset ANTHROPIC_API_KEY를 하고 셸 프로필에서도 지웁니다. 계정을 바꾸려면 /logout 후 다시 로그인합니다.

      회사 계정과 개인 계정을 함께 쓰려면

      계정마다 설정 디렉토리를 따로 두면 됩니다. 각 디렉토리는 자기만의 설정, 세션 기록, 로그인 정보를 가집니다.

      # ~/.bashrc 또는 ~/.zshrc 에 추가 alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'

      새 터미널에서 claude-work를 처음 실행하면 회사 계정용 로그인과 설정을 새로 진행합니다. 고객사 코드를 다루는 MSP라면 업무와 개인 학습 환경을 이렇게 분리하는 습관을 권합니다.

      첫 세션 열기

      Claude Code는 실행한 폴더를 작업 디렉토리로 삼습니다(2편). 그래서 아무 데서나 실행하지 말고, 이 과정 전용 실습 폴더를 만들어 그 안에서 시작합니다. 홈 디렉토리 전체에서 실행하면 Claude가 다룰 수 있는 범위가 불필요하게 넓어집니다.

      mkdir -p ~/vibe-lab && cd ~/vibe-lab claude
      1. 로그인: 처음이면 브라우저 로그인. 이미 했다면 건너뜁니다.
      2. 폴더 신뢰 확인: 처음 여는 폴더에서는 이 폴더의 파일을 신뢰하는지 묻습니다. Claude가 이 폴더의 파일을 읽고, 쓰고, 실행할 수 있기 때문입니다. 내가 만든 실습 폴더라면 신뢰해도 되지만, 출처를 모르는 저장소라면 먼저 내용을 살펴보세요. 저장소 안의 설정 파일이나 지시 파일이 Claude의 행동에 영향을 줄 수 있습니다.
      3. 첫 실행 안내: 최신 버전에서는 Auto 모드로 시작했다는 안내가 한 번 표시될 수 있습니다.
      4. 프롬프트 대기: 입력창에 질문을 입력하면 됩니다.
      처음 질문은 “읽기”로 공식 FAQ는 첫 시도로, 미뤄 둔 지루하지만 어렵지 않은 버그를 맡겨 보라고 권합니다. 코드를 직접 설명하지 말고 Claude가 읽게 하라는 것이죠. 이 강의에서는 그보다 한 단계 안전하게, 파일을 바꾸지 않는 “이 프로젝트 설명해줘”로 시작합니다(10장 실습).

      권한 모드 실전

      2편에서 네 가지 모드를 개념으로 배웠습니다. 실제로는 여섯 가지가 있고, 그중 대화형 세션에서 주로 쓰는 것은 네 가지입니다. 매번 확인하는 모드는 화면에 Manual, 설정 파일에는 default로 표시됩니다(manual도 별칭으로 인정).

      모드묻지 않고 하는 일적합한 상황
      default (Manual)읽기만모든 행동을 직접 검토. 민감한 작업, 처음 보는 코드
      acceptEdits읽기, 파일 편집, mkdir·touch·rm·mv·cp·sed 같은 파일 명령 (작업 폴더 안)편집은 나중에 git diff로 몰아서 검토할 때
      plan읽기, Auto를 쓸 수 있으면 분류기가 승인한 탐색 명령바꾸기 전에 조사와 계획부터
      auto모든 것, 단 분류기가 백그라운드에서 위험한 행동을 차단긴 작업, 승인 피로 줄이기
      dontAsk읽기와 미리 허용한 도구만. 물어볼 일은 모두 거부CI, 스크립트 (19편)
      bypassPermissions모든 것, 검사 없음격리된 컨테이너·VM에서만

      어떤 모드에서도 deny 규칙은 적용되고, .git·.claude·셸 설정 파일 같은 보호 경로에 대한 쓰기는 bypassPermissions가 아니면 자동 승인되지 않습니다.

      Shift+Tab 순환 시뮬레이터

      세션이 Auto 모드로 시작했다고 가정합니다. 버튼을 눌러 상태 줄이 어떻게 바뀌는지 보세요.

      세션은 어떤 모드로 시작하나

      터미널·VS Code 대화형 세션

      v2.1.283 이상에서는 아무 설정이 없으면 Auto로 시작합니다. Auto를 쓸 수 없는 상황(지원하지 않는 모델, 조직이 끈 경우 등)이면 Manual로 시작합니다.

      claude -p·Agent SDK

      사람이 없는 실행은 Manual로 시작하고, 승인이 필요한 호출은 허용 규칙이 없으면 거부됩니다.

      바꾸는 방법

      한 세션: claude --permission-mode default. 내 컴퓨터 전체: ~/.claude/settings.json의 permissions.defaultMode. 조직 전체: 관리형 설정.

      저장소는 나를 자율 모드로 만들 수 없다

      프로젝트의 .claude/settings.json에 auto나 bypassPermissions를 적어도 적용되지 않습니다. 남이 만든 저장소를 열었다고 자동으로 위험한 모드가 켜지지 않게 하는 안전장치입니다.

      # ~/.claude/settings.json — 내 모든 터미널 세션을 Manual로 시작 { "permissions": { "defaultMode": "default" } }

      Auto 모드가 기본으로 막는 것 (인프라 엔지니어가 알아야 할 것 위주)

      실습: “이 프로젝트 설명해줘”

      빈 폴더에서는 설명할 것이 없으니, 먼저 작은 실습용 프로젝트를 만듭니다. 고객사 서버 점검 스크립트 모음이라는 설정입니다. 아래 블록을 복사해 터미널(macOS·Linux·WSL)에 붙여 넣으면 ~/vibe-lab 안에 파일 네 개가 생기고 첫 커밋까지 됩니다. 이 프로젝트는 5편 이후 실습에서도 계속 키워 갑니다.

      mkdir -p ~/vibe-lab/scripts && cd ~/vibe-lab cat > README.md <<'LAB' # vibe-lab 고객사 서버 상태 점검용 스크립트 모음 (실습용) LAB cat > servers.txt <<'LAB' web-01 10.0.1.11 22 web-02 10.0.1.12 22 db-01 10.0.2.21 22 LAB cat > scripts/check_disk.sh <<'LAB' #!/usr/bin/env bash # 사용법: ./check_disk.sh 80 (경고 임계값 %) THRESHOLD=${1:-80} df -hP | awk -v t="$THRESHOLD" 'NR>1 {gsub("%","",$5); if ($5+0 >= t) print "WARN", $6, $5"%"}' LAB cat > scripts/ping_all.sh <<'LAB' #!/usr/bin/env bash while read -r name ip port; do if ping -c1 -W1 "$ip" >/dev/null 2>&1; then echo "UP $name"; else echo "DOWN $name"; fi done < servers.txt LAB chmod +x scripts/*.sh git init -q && git add . && git commit -qm "initial lab" && echo "준비 완료"

      Windows 네이티브(PowerShell)라면 이 블록 대신, Claude Code를 연 뒤 “README.md, servers.txt, scripts/check_disk.sh, scripts/ping_all.sh를 PowerShell 환경에 맞게 만들어줘”라고 요청해도 됩니다. Git이 아직 없다면 마지막 줄의 git 부분은 빼세요(7편에서 다룹니다).

      원격 서버·사내망에서 쓰기

      MSP·인프라 업무에서는 내 노트북이 아니라 점프 서버나 작업용 리눅스 VM에서 Claude Code를 쓰고 싶을 때가 있습니다. 가능하지만 몇 가지를 지켜야 합니다.

      🔐 SSH에서 로그인

      로그인 화면에서 c로 URL 복사 → 내 PC 브라우저에서 로그인 → 표시된 코드를 터미널에 붙여 넣기.

      📦 서버에는 패키지 저장소로

      서명된 apt·dnf·apk 저장소를 쓰면 기존 서버 패치 절차로 업데이트를 관리할 수 있습니다. 안내된 기본 설정은 약 1주 늦은 stable 채널입니다.

      🌐 프록시와 사내 인증서

      회사 프록시, 사내 CA, mTLS 환경은 별도 네트워크 설정이 필요합니다. 로그인 후 403이 나면 관리자 활성화 여부와 프록시를 먼저 의심하세요(24편).

      🖱️ tmux·SSH에서 복사가 안 될 때

      화면이 마우스 이벤트를 가져갑니다. Shift를 누른 채 선택하거나, /copy(마지막 응답 복사), /export(대화 저장)를 쓰세요.

      🐢 WSL이 느릴 때

      /mnt/c/...의 Windows 파일을 읽는 것은 느립니다. 저장소를 WSL 파일 시스템(~/)으로 옮기면 체감 속도가 크게 달라집니다.

      🧾 공유 홈(NFS)

      여러 서버가 홈 디렉토리를 공유하면 업데이트가 다른 서버의 실행 중 세션을 깨뜨릴 수 있습니다. 로컬 디스크에 설치하고 자체 업데이트를 끄는 방식이 권장됩니다.

      고객사 운영 서버에는 설치하지 마세요 2편에서 봤듯 도구는 실행한 사용자의 권한으로 돕니다. 운영 자격 증명이 있는 서버에 Claude Code를 두면 실수 한 번의 피해 범위가 그 서버 전체가 됩니다. 실습과 개발은 별도 작업 VM에서 하고, 운영 접근이 필요한 자동화는 9편(권한 규칙)과 21편(IaC 안전장치)을 배운 뒤 Manual 모드와 deny 규칙을 갖춰 진행하세요. 회사의 AI 사용 정책과 고객 계약도 먼저 확인합니다.

      업데이트와 제거

      🔄 업데이트

      • 네이티브 설치: 시작할 때와 실행 중에 확인해 백그라운드로 내려받고, 다음 실행 때 적용됩니다. 세션 중간에 바뀌지 않습니다.
      • 지금 바로: claude update
      • Homebrew: brew upgrade claude-code (latest 캐스크라면 claude-code@latest)
      • WinGet: winget upgrade Anthropic.ClaudeCode
      • npm: npm install -g @anthropic-ai/claude-code@latest (npm update -g는 최신으로 안 갈 수 있음)

      📡 릴리스 채널

      • latest (기본): 새 기능을 바로 받음
      • stable: 약 1주 늦은 버전, 큰 문제가 있던 릴리스는 건너뜀
      • 설정: /config → Auto-update channel, 또는 settings.json의 "autoUpdatesChannel": "stable"
      • 새로 나온 모델은 stable보다 새 버전을 요구할 수 있습니다
      • 자동 업데이트 끄기: settings.json의 env에 "DISABLE_AUTOUPDATER": "1"
      업데이트 직후 첫 응답이 느린 이유 2편에서 배웠듯 새 버전은 보통 시스템 프롬프트나 도구 정의를 바꾸기 때문에, 업데이트 후 첫 대화는 캐시를 처음부터 만듭니다.

      제거 (네이티브 설치 기준)

      # macOS · Linux · WSL rm -f ~/.local/bin/claude rm -rf ~/.local/share/claude # 설정·세션 기록까지 모두 지우려면 (되돌릴 수 없음) rm -rf ~/.claude && rm -f ~/.claude.json

      Windows는 %USERPROFILE%\.local\bin\claude.exe와 %USERPROFILE%\.local\share\claude를 지웁니다. Homebrew·WinGet·패키지 관리자로 설치했다면 각각의 uninstall 명령을 씁니다. VS Code 확장·JetBrains 플러그인·데스크톱 앱도 ~/.claude/를 쓰므로 완전히 지우려면 그것들을 먼저 제거하세요.
