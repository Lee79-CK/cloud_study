쓰는 사람에서 만드는 사람으로

Claude Agent SDK는 Claude Code를 만드는 데 쓰인 것과 같은 에이전트 루프·내장 도구·컨텍스트 관리를 Python과 TypeScript에서 쓰게 해 줍니다. 19편의 claude -p는 사실 “CLI로 쓰는 Agent SDK”였습니다. SDK는 같은 일을 코드 안에서 하고, 거기에 여러분이 만든 함수를 도구로, 여러분이 만든 함수를 Hook과 권한 판단으로 끼워 넣을 수 있게 합니다.

하고 싶은 일알맞은 것
내가 터미널에서 대화하며 일한다Claude Code (1~22편)
정해진 프롬프트를 스크립트·cron으로 돌린다claude -p (19편)
내 프로그램 안에서 Claude가 내 함수를 도구로 쓰게 하고, 결과를 내 코드로 받는다Agent SDK (이번 편)
도구 없이 한 번 묻고 답만 받는다Claude API 직접 호출 (에이전트 루프 불필요)

✅ 이 강의에서 실제로 확인한 것

  • claude-agent-sdk 0.2.177 (번들 Claude Code CLI 2.1.317), Python 3.12, 가상환경 설치
  • 오프라인 테스트 26개 통과 (22편 콘솔 17개 + 에이전트 9개). SDK가 없으면 에이전트 9개는 건너뜀
  • 번들 CLI를 실제로 띄워 초기화 메시지 확인: ops MCP 서버 connected (source: sdk), 보이는 도구, 권한 모드 dontAsk, 모델 별칭 sonnet → claude-sonnet-5-5
  • 가짜 API 키로 실행해 실패 경로 확인: authentication_failed, HTTP 401, SDK 예외 → 종료 코드 1
  • 진짜 키로 모델이 조사하는 장면은 이 환경에서 실행하지 않았습니다. 실습 4단계에서 직접 돌립니다

도구 만들기

@tool로 비동기 함수를 도구로 만들고, create_sdk_mcp_server로 묶어 프로세스 안 MCP 서버로 붙입니다. 12편처럼 별도 프로세스가 필요 없고, Claude에게는 mcp__서버__도구 이름으로 보입니다. 이번 도구 네 개는 22편 콘솔의 수집기를 감싼 것이라, 콘솔과 에이전트가 같은 검증된 코드를 씁니다.

@tool("problem_pods", "네임스페이스의 문제 파드(Running 아님, 재시작 많음)와 관련 런북 이름", {"namespace": str}, annotations=ToolAnnotations(readOnlyHint=True, openWorldHint=False)) async def problem_pods(args): r = C.k8s_problems(cmd, env, args["namespace"]) # 22편 수집기 → 12편 k8s-ro return {"content": [{"type": "text", "text": json.dumps(r, ensure_ascii=False)}], **({"is_error": True} if not r["ok"] else {})} SERVER = create_sdk_mcp_server(name="ops", version="1.0.0", tools=[server_status, problem_pods, read_runbook, latest_report])
입력 모양

간단하면 {"namespace": str}, 범위·필수 검사가 필요하면 JSON Schema. 그래도 함수 안에서 한 번 더 검증합니다(콘솔의 이름 규칙).

오류는 예외 대신 is_error

예외를 던지지 말고 "is_error": True로 돌려주면 Claude가 오류를 읽고 다르게 시도합니다. 잘못된 네임스페이스, 없는 런북 모두 이 길로(테스트로 확인).

annotations는 힌트일 뿐

readOnlyHint는 클라이언트에게 주는 힌트이고 보안 장치가 아닙니다. 공식 문서도 그렇게 말합니다. 진짜 읽기 전용은 함수가 아무것도 바꾸지 않는 것.

작은 함정

문서 표기는 readOnlyHint지만, 이번 설치본(mcp 2.3.0)에서 객체 속성 이름은 read_only_hint였습니다. 테스트는 model_dump(by_alias=True)로 읽었습니다.

무엇이 보이는가

권한보다 먼저 정할 것은 Claude에게 어떤 도구가 보이는가입니다. 처음엔 disallowed_tools로 Bash·Write·Edit 등을 빼면 충분하다고 생각했습니다. 번들 CLI의 초기화 메시지를 보니 아니었습니다. 아래 버튼으로 실제로 찍힌 두 목록을 비교하세요.

tools=[] 로 내장 도구를 모두 빼고 시작 tools=[]를 주면 내장 도구가 하나도 없고, 우리 ops 도구 넷과 구조화 출력용 StructuredOutput만 남았습니다(확인함). 필요한 내장 도구가 있으면 tools=["Read"]처럼 그것만 넣습니다. 12편의 “도구가 없으면 할 방법 자체가 없다”를 SDK에서 가장 확실하게 적용하는 방법입니다.

권한: 다섯 개의 문

옵션하는 일주의
tools어떤 내장 도구가 존재하는가4장. 가장 앞의 문
allowed_tools묻지 않고 자동 승인할 도구공식 문서: 다른 도구를 막지 않음. 제한은 tools·disallowed_tools로
disallowed_tools이름만 쓰면 도구를 컨텍스트에서 제거, Bash(rm *) 같은 규칙은 모든 모드에서 거부bypassPermissions에서도 적용
permission_modedontAsk: 미리 허용하지 않은 것은 묻지 않고 거부19편과 같은 이유로 무인 실행에 권장
can_use_tool사람에게 물을 차례가 왔을 때 대신 판단하는 함수allowed_tools·허용 규칙·권한 모드가 이미 승인한 호출에는 불리지 않음. dontAsk에서는 대부분 불리지 않음. 모든 호출을 보려면 PreToolUse Hook

이 호출은 어떻게 될까

setting_sources=[] 도 권한의 일부 생략하면 SDK는 CLI처럼 사용자·프로젝트·로컬 설정을 모두 읽습니다. 그러면 작업 폴더의 .claude/settings.json Hook과 허용 규칙이 에이전트에 섞입니다. 19편 --bare와 같은 이유로 빈 목록을 주어 에이전트의 동작을 코드에 적힌 것으로만 고정했습니다. 관리형 정책 설정은 이 값과 상관없이 적용됩니다(24편).

Hook과 감사

11편 Hook을 Python 함수로 씁니다. 모델이 아니라 SDK가 반드시 부릅니다. 이번 에이전트에는 두 개를 겁니다.

🚧 only_ops_tools

ops 도구가 아니면 무엇이든 거부. tools=[]가 이미 막지만, 나중에 누가 tools를 넓혀도 이 한 겹이 남습니다.

📝 audit_tool_use

모든 도구 호출을 reports/incidents/audit.jsonl에 한 줄씩. 12편 MCP 감사 Hook과 같은 생각.

Hook 이 실패하면? on_failure="block" (CLI v2.1.317+) 기본값에서는 Hook 함수가 예외를 내거나 아무것도 돌려주지 않으면 “판단 없음”으로 치고 동작이 진행됩니다. 가드 Hook이라면 위험한 기본값입니다. HookMatcher(hooks=[...], on_failure="block")로 두면 실패가 곧 차단이 됩니다(SDK 문서 주석: 의견이 없을 때는 반드시 {}를 돌려줄 것). 그래서 가드에는 block을, 감사 기록에는 기본값을 줬습니다. 일부러 예외를 내는 Hook에 block을 걸어 CLI 2.1.317과 정상 연결되는 것을 확인했습니다(오래된 CLI면 연결 오류).
StructuredOutput 을 막지 마세요 output_format을 쓰면 Claude는 StructuredOutput이라는 도구로 결과를 냅니다(초기화 목록에 보임). “ops 도구만 허용” Hook을 그대로 쓰면 결과 자체를 막을 수 있어, 이 이름을 예외로 넣었습니다. 테스트가 이 예외와 Read·Grep·SendMessage 거부를 함께 지킵니다. 모델과의 실제 실행에서 결과가 나오는지는 실습 4단계에서 확인하세요.

한도와 실패

max_turns · max_budget_usd

12턴, $0.50. 추정 비용 기준이라 여유 있게. 넘으면 결과의 subtype이 error_max_turns·error_max_budget_usd.

model · effort

조사는 sonnet + medium(20편). 별칭은 CLI가 실제 모델로 풀어 줍니다(초기화에서 claude-sonnet-5-5 확인).

예외로 오는 실패

가짜 키로 실행하자 어시스턴트 메시지에 authentication_failed, 결과에 401이 실리고, 이 SDK 버전에서는 query()가 ClaudeSDKError 계열 예외를 던졌습니다. 그래서 try/except ClaudeSDKError로 감싸 종료 코드 1로 바꿉니다(확인함).

종료 코드 설계 (19편)

0 정상·경미, 3 major·critical, 1 실행 실패, 2 구조화 출력 없음. cron·CI가 0이 아닌 코드에 알림.

운영 콘솔과 잇기

22편 SPEC의 비목표는 “콘솔은 아무것도 바꾸지 않는다”였습니다. 에이전트를 콘솔의 버튼으로 붙이면 콘솔이 모델 호출(비용)을 일으키는 도구가 됩니다. 그래서 에이전트는 사람이나 cron이 실행하고, 콘솔은 결과 파일을 읽기만 합니다.

① 실행당번이 python -m agent.investigate payments, 또는 19편처럼 cron
② 조사ops 도구 넷만으로. 모든 호출은 audit.jsonl
③ 결과reports/incidents/시각.json + .md
④ 알림종료 코드 3이면 major 이상 → 모니터링
⑤ 보기콘솔에 “최근 조사” 카드(새 수집기, 22편 9장 프롬프트)
사람이 하는 일은 그대로 에이전트의 next_actions는 제안입니다. 실행·롤백·고객 소통은 21·22편처럼 사람이 합니다. 에이전트가 할 수 있는 일은 도구 네 개가 정하고, 그 도구는 모두 읽기 전용입니다.

TypeScript 대응표

같은 설계를 TypeScript(@anthropic-ai/claude-agent-sdk)로 옮길 때의 이름입니다. 이 강의에서 실행 확인은 Python만 했으니, 정확한 형태는 TypeScript SDK 참조 문서로 맞추세요.

PythonTypeScript
query(prompt=…, options=ClaudeAgentOptions(…))query({ prompt, options: { … } })
@tool(name, desc, {"x": str})tool(name, desc, zod 스키마, handler)
create_sdk_mcp_server(...)createSdkMcpServer(...)
allowed_tools · disallowed_toolsallowedTools · disallowedTools
permission_mode · can_use_toolpermissionMode · canUseTool
setting_sources · mcp_serverssettingSources · mcpServers
max_turns · max_budget_usd · output_formatmaxTurns · maxBudgetUsd · outputFormat
AgentDefinition(maxTurns=…) (이것만 camelCase)agents: { 이름: { … } }

Python의 AgentDefinition 필드는 TypeScript와 같은 camelCase라서 snake_case로 쓰면 TypeError가 납니다. 반대로 ClaudeAgentOptions는 snake_case. 공식 참조 문서가 짚는 함정입니다. Python에는 아직 없는 Hook 이벤트(SessionStart 등)가 TypeScript에는 있다는 점도 다릅니다.
