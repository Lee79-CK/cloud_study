Skill이란, 언제 만드나

Skill은 SKILL.md 파일에 담긴 지시서입니다. Claude는 관련 있을 때 스스로 꺼내 쓰고, 여러분은 /이름으로 바로 부를 수 있습니다. 공식 문서가 꼽는 만들 때: 같은 지시·체크리스트·여러 단계 절차를 계속 붙여넣고 있을 때, 또는 CLAUDE.md의 한 부분이 “사실”이 아니라 “절차”로 자랐을 때.

핵심 차이는 로딩입니다. CLAUDE.md는 매 세션 통째로 들어가지만, Skill은 평소엔 이름과 설명만 목록에 있다가 쓰일 때 본문이 로드됩니다. 긴 참고 자료를 넣어도 필요할 때까지 거의 비용이 들지 않습니다.

내용어디에성격
모든 작업에 필요한 짧은 사실·규칙CLAUDE.md (8편)항상 로드되는 맥락
특정 파일에만 해당하는 규칙.claude/rules + paths (8편)그 파일을 읽을 때
여러 단계 절차, 가끔 쓰는 지식Skill (이번 편)부르거나 관련 있을 때
절대 하면 안 되는 것권한 규칙·샌드박스 (9편)강제 차단
예외 없이 매번 실행돼야 하는 것Hook (11편)강제 실행
커스텀 커맨드는 Skill로 합쳐졌습니다 .claude/commands/deploy.md와 .claude/skills/deploy/SKILL.md는 둘 다 /deploy를 만들고 똑같이 동작합니다. 기존 commands 파일은 계속 쓸 수 있지만, Skill은 보조 파일을 둘 폴더, 누가 부를지 정하는 설정, 자동 로드가 더해져 새로 만든다면 Skill이 권장됩니다. Skill은 여러 AI 도구에서 쓰이는 Agent Skills 공개 표준을 따르고, Claude Code가 기능을 더 얹은 형태입니다.

번들 Skill 둘러보기

Claude Code에는 프롬프트 기반 Skill이 기본으로 들어 있습니다. 고정된 로직을 실행하는 대부분의 내장 명령과 달리, 번들 Skill은 Claude에게 자세한 지침을 주고 도구로 일을 조율하게 합니다. 일부는 Claude가 알아서 부르고, /verify처럼 오래 걸리는 것은 직접 불러야만 실행됩니다.

/doctor

설치·확장·CLAUDE.md·권한·사용량 점검. 바꾸기 전에 확인을 요청합니다. /doctor prompt-audit은 지시 파일의 오래되거나 충돌하는 지시를 찾습니다.

/code-review

현재 diff를 새 컨텍스트의 서브에이전트에서 버그 관점으로 리뷰 (18편).

/run · /verify

앱을 띄워 변경이 실제로 동작하는지 확인. /run-skill-generator는 실행 방법을 프로젝트 Skill로 기록합니다 (17편).

/debug

세션이나 Claude Code 자체 문제를 조사하는 플레이북.

/batch

큰 변경을 5~30개의 서브에이전트로 나눠 각자의 worktree에서 처리 (14편).

/loop

프롬프트를 일정 간격으로 반복 실행 (19편).

/claude-api

Claude API·Managed Agents 참고 자료. 코드가 anthropic SDK를 쓰면 자동 활성 (23편).

커밋 전 자동 실행

세션 시작 때 verify나 simplify라는 이름의 Skill이 프로젝트에 있으면, Claude는 커밋 직전에 그것을 실행하라는 지시를 받습니다(문서·테스트만 바뀐 경우 제외).

번들 Skill은 disableBundledSkills 설정으로 끌 수 있고, 같은 이름의 내 Skill을 만들면 그 명령을 대체합니다(별칭은 제외). 전체 목록은 /help나 공식 명령 레퍼런스에서 “Skill” 표시를 보세요.

어디에 두고 이름은 어떻게

위치경로로드되는 곳
조직관리형 설정 폴더의 .claude/skills/<이름>/SKILL.md조직이 배포한 모든 사용자
개인~/.claude/skills/<이름>/SKILL.md이 컴퓨터의 모든 프로젝트 (Cowork·클라우드 세션 제외)
프로젝트.claude/skills/<이름>/SKILL.md이 저장소. 커밋하면 팀도 받음
하위 폴더<sub>/.claude/skills/…그 폴더에서 시작했거나, Claude가 그 폴더 파일을 다룰 때부터
플러그인<plugin>/skills/<이름>/SKILL.md플러그인이 켜진 곳, /플러그인:이름 (15편)
claude.ai 계정계정에서 켠 SkillCowork·클라우드 세션, 그 계정으로 로그인한 터미널
명령 이름

폴더 이름 또는 frontmatter의 name. .claude/commands/frontend/component.md는 /frontend:component.

같은 이름이면

조직 > 개인 > 프로젝트. Skill과 commands 파일이 같으면 Skill. 내 Skill이 번들 Skill·내장 명령과 같으면 내 것이 대체(별칭은 그대로).

세션 중 수정

Skill 폴더의 변경을 감시해 재시작 없이 반영합니다. 세션 시작 때 없던 최상위 skills 폴더를 새로 만들었다면 /reload-skills.

모노레포

시작 폴더부터 저장소 루트까지 위쪽 .claude/skills/를 모두 읽습니다. 그래서 하위 패키지에서 시작해도 루트 Skill이 보입니다.

누가 부르게 할까

기본값

나도, Claude도 부름.
설명은 항상 목록에, 본문은 부를 때 로드.

예: 코드 설명, 변경 요약, 참고 지식

disable-model-invocation: true

나만 부름.
설명도 목록에 없음. 부를 때 로드.

예: 배포, 커밋, 슬랙 전송, 런북 파일 쓰기처럼 부작용이 있거나 타이밍을 내가 정해야 하는 일

user-invocable: false

Claude만 부름.
/ 메뉴에서 숨김.

예: “레거시 시스템 배경 지식”처럼 명령으로 부를 일은 없지만 알고 있어야 하는 것

배포처럼 위험한 일은 반드시 수동으로 공식 문서의 표현대로, 코드가 준비돼 보인다는 이유로 Claude가 스스로 배포를 결정하게 두면 안 됩니다. disable-model-invocation: true인 Skill을 Claude가 부르려 하면 Claude Code가 막고, 같은 단계를 다른 방법으로 재현하지 말라고 지시합니다. 그래서 Claude는 여러분에게 /deploy를 직접 실행하라고 제안하게 됩니다.

이름을 어디에 쓰나: 메시지 맨 앞의 /deploy staging은 바로 실행합니다. 문장 중간의 “좋아, /deploy 해도 돼”는 바로 실행하지 않고, 그 메시지 동안 Claude가 그 Skill을 써도 된다는 허락이 됩니다.

frontmatter 핵심 필드

모든 필드는 선택이고, description만 권장됩니다. 필드 이름은 하이픈까지 정확해야 하며, 모르는 필드는 오류 없이 무시됩니다. 여는 ---가 파일 첫 줄이 아니면 frontmatter로 읽지 않습니다.

필드뜻
description무엇을 하고 언제 쓰는지. Claude가 자동으로 부를지 판단하는 근거. 핵심 용도를 앞에 (when_to_use와 합쳐 1,536자에서 잘림)
name명령 이름. 없으면 폴더 이름
argument-hint · arguments자동 완성 힌트 · 이름 붙은 인자 ($kind처럼 쓰기)
disable-model-invocation · user-invocable5장의 호출 제어
allowed-tools이 Skill을 부른 턴 동안 묻지 않고 쓸 도구. 다음 메시지를 보내면 해제. 다른 도구를 막지는 않음
disallowed-toolsSkill이 활성인 동안 도구 목록에서 제거
model · effort이 Skill에서만 쓸 모델·effort (2편)
context: fork · agent · background서브에이전트에서 따로 실행 (9장)
paths이 패턴의 파일을 다룰 때만 자동 활성 (8편의 rules와 같은 glob)
hooksSkill을 부르면 등록되는 Hook (11편)
shell동적 주입 명령을 bash(기본) 또는 powershell로
남의 저장소 Skill의 allowed-tools를 먼저 읽으세요 폴더 신뢰(9편)는 이 필드를 막지 않습니다. 신뢰하지 않은 폴더의 -p 실행에서도 프로젝트 Skill의 allowed-tools는 적용됩니다. Skill이 스스로에게 넓은 도구 권한을 줄 수 있으니, 저장소에 들어 있는 Skill은 Claude Code를 돌리기 전에 검토하세요. 조직 차원에서는 관리형 설정의 allowManagedPermissionRulesOnly로 이 필드를 무시하게 할 수 있습니다.

    동적 컨텍스트 주입

    줄 맨 앞(또는 공백 뒤)에 !`명령`을 쓰면, Claude Code가 Skill 내용을 Claude에게 보내기 전에 그 명령을 실행해 출력으로 바꿔 넣습니다. Claude는 명령이 아니라 실제 데이터를 받습니다. 여러 줄은 ```!로 여는 코드 블록을 씁니다.

    ## 지금 상태 !`git status --short` ```! python3 --version git log --oneline -3 ```
    한 번만 치환

    명령 출력은 일반 텍스트로 들어가고, 그 안에 또 !`…`가 있어도 다시 실행되지 않습니다.

    실패하면 Skill 전체가 취소

    bash에서는 0이 아닌 종료 코드면 실패입니다(검색·비교 명령의 종료 코드 1은 예외). 문제를 찾으면 1로 끝나는 점검 스크립트라면 || true를 붙이세요.

    권한 검사

    주입 명령은 렌더링 중에 묻지 않습니다. deny에 걸리면 취소되고, Auto 모드가 아니면 allow가 아닌 명령도 취소됩니다. 그래서 필요한 명령은 allowed-tools에 미리 넣습니다.

    타임아웃과 위치

    Bash 도구처럼 기본 2분, 세션의 현재 폴더에서 실행. 항상 같은 경로가 필요하면 ${CLAUDE_SKILL_DIR}나 ${CLAUDE_PROJECT_DIR}.

    MSP: 주입 명령은 여러분의 컴퓨터에서 돈다 !`kubectl get pods -A` 같은 줄은 Skill을 부르는 순간 지금 로드된 kubeconfig로 실행됩니다. 읽기 명령이라도 어느 클러스터를 향하는지 늘 의식하세요. 조직 차원에서 막으려면 "disableSkillShellExecution": true를 설정합니다(관리형 설정에서 가장 유용). claude.ai에서 동기화된 Skill의 주입 명령은 내 컴퓨터에서 실행되지 않습니다.

    보조 파일과 context: fork

    runbook/ ├── SKILL.md # 필수: 개요와 안내 (500줄 이하 권장) ├── template.md # 필요할 때 읽음 ├── examples/ │ └── disk-full.md # 필요할 때 읽음 └── scripts/ └── check.sh # 실행만 하고 내용은 로드 안 함

    SKILL.md에서 각 파일이 무엇이고 언제 읽을지 링크로 알려 주면, 긴 참고 자료가 매번 컨텍스트에 들어가지 않습니다. 스크립트는 ${CLAUDE_SKILL_DIR}/scripts/check.sh로 부르고, allowed-tools: Bash(${CLAUDE_SKILL_DIR}/scripts/check.sh *)처럼 같은 변수를 쓰면 묻지 않고 실행됩니다.

    서브에이전트에서 실행: context: fork

    무엇이 다른가

    새 서브에이전트가 Skill 본문을 프롬프트로 받아 따로 일합니다. 대화 기록을 보지 못하므로 본문만으로 일을 끝낼 수 있게 써야 합니다.

    agent

    어떤 서브에이전트로 돌릴지. Explore·Plan·general-purpose(기본) 또는 내가 만든 것(13편). Explore와 Plan은 CLAUDE.md 없이 시작합니다.

    기본은 백그라운드

    작업하는 동안 결과를 기다리지 않고, 끝나면 대화에 도착합니다. 기다리려면 background: false.

    체크포인트 밖

    백그라운드로 돈 fork Skill의 편집은 세션 체크포인트 밖이라 /rewind로 안 돌아옵니다(6편). Git으로 되돌리세요.

    지침만 있는 Skill에 fork를 쓰지 마세요 “이런 API 규칙을 써라” 같은 참고 지식만 있고 할 일이 없으면, 서브에이전트는 지침만 받고 아무 결과 없이 돌아옵니다. fork는 명확한 작업이 있는 Skill에만.
    10 / 16

    수명주기: 언제 잊히나

    Skill을 부르면 렌더링된 내용이 메시지 하나로 대화에 들어가 이후 턴에도 남습니다. Claude Code는 그 파일을 다시 읽지 않으므로, 작업 내내 지켜야 할 지침은 “테스트 실행”이 아니라 “편집할 때마다 테스트 실행”처럼 상시 지침으로 쓰세요. 반면 allowed-tools 허용은 다음 메시지를 보내면 해제됩니다.

    압축 후 남는 양

    압축(2·6편)이 일어나면 각 Skill의 가장 최근 호출을 요약 뒤에 다시 붙이되, Skill마다 앞 5,000토큰, 전체 25,000토큰까지입니다. 가장 최근에 부른 Skill부터 채우므로 오래된 Skill은 통째로 빠질 수 있습니다. 슬라이더로 Skill 크기를 바꿔 보세요.

    그래서: 중요한 지시는 SKILL.md 맨 위에 압축 후에는 앞부분만 남을 수 있습니다. 절대 빼먹으면 안 되는 규칙은 맨 위에 두고, 정말 매번 지켜야 한다면 Hook으로 만드세요. Claude가 Skill을 따르다 말면 Skill을 다시 부르면 전체 내용이 복구됩니다.

    잘 동작하는지 재는 법

    Skill이 불렸다는 것은 Claude가 찾았다는 뜻일 뿐, 의도대로 했다는 뜻은 아닙니다. 공식 문서의 방법은 기준선 비교입니다: 현실적인 프롬프트 몇 개를 새 세션에서 Skill을 켠 채 한 번, skillOverrides로 끈 채 한 번 돌려 비교합니다. 새 세션이어야 Skill을 만들며 쌓인 맥락이 빈틈을 가리지 않습니다. 반복 개선은 공식 skill-creator 플러그인이 자동화해 줍니다(테스트 케이스, 격리 실행, 채점, 설명 튜닝). 플러그인으로 배포할 Skill은 15편의 claude plugin eval로 잽니다.

    실습: /runbook 만들기

    세 가지 Skill을 만듭니다. 이 강의를 만들며 YAML이 올바르게 해석되는지 확인한 파일들입니다.

    • /runbook — 나만 부르는 작업 Skill. 이름 인자, 템플릿·예시 보조 파일
    • /lab-status — 동적 주입으로 저장소 상태를 요약. Claude도 부를 수 있음
    • servers-file — Claude만 쓰는 참고 지식. servers.txt를 다룰 때만 활성
