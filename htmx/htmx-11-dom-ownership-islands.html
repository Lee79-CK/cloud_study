DOM 소유권, 측정으로 다시 보기

랩의 React CPU 차트(5초마다 데이터를 다시 읽어 그림)가 마운트된 컨테이너에 htmx로 일부러 HTML을 넣어 보았습니다. 결과는 "곧바로 터진다"가 아니었습니다. 그래서 더 위험합니다.

htmx가 한 일직후React가 다음에 다시 그릴 때 (실측)
컨테이너 안쪽을 innerHTML로 교체화면에 htmx 내용만 보임오류 없음. React는 문서에서 떨어진 자기 옛 노드를 계속 갱신하고, 데이터 API 요청도 5초마다 계속 나감(11초 동안 2회). 화면과 React 상태가 조용히 어긋남
위와 같은 상태에서 React의 출력 구조가 바뀜 (차트 → 오류 문구)-오류: Failed to execute 'removeChild' on 'Node': The node to be removed is not a child of this node. 화면은 htmx 내용 그대로
컨테이너에 beforeend·afterbegin으로 덧붙임React 출력 앞뒤에 htmx 요소글자·속성만 바뀌는 동안은 오류 없이 공존. 구조가 바뀌는 순간 같은 위험
컨테이너의 바깥 영역을 교체 (컨테이너가 통째로 사라짐)React 화면 사라짐누수: 언마운트를 부르지 않으면 React 루트가 살아남아 타이머와 API 요청이 계속됨 (4절에서 측정)

아래 실험 상자에는 이 파일에 내장한 실제 React 19.3.1로 만든 작은 카운터가 들어 있습니다. 0.5초마다 다시 그리고, 3틱마다 최상위 요소 종류를 바꿉니다(구조 변경). 1편의 철칙을 어기는 버튼을 눌러 보세요.

  03
  
경계를 표시하는 법

  

    
htmx 쪽 규칙아일랜드 컨테이너의 안쪽을 hx-target으로 삼지 않는다. 바꿔야 하면 컨테이너를 포함한 바깥 영역을 통째로 바꾼다(그리고 정리는 등록부가).

    
React·Vue 쪽 규칙자기 루트 밖의 DOM을 직접 건드리지 않는다. htmx 영역에 알릴 것이 있으면 이벤트로(13편).

    
표시컨테이너에 data-island="이름"으로 누구 것인지, hx-ignore로 htmx가 안쪽을 처리하지 말라고 적는다.

  

  
views/partials/vm-detail.eta (발췌)


<h3>CPU 사용률</h3>
<!-- 11편: React 아일랜드. 이 div의 안쪽은 React 소유. hx-ignore로 htmx가 안쪽을 처리하지 않게 경계를 표시한다 -->
<div class="island" data-island="metric-chart" data-vm="<%= vm.name %>" hx-ignore></div>

  
hx-ignore는 htmx 4.0.1 소스에서 elt.closest('[hx-ignore]')로 판정되어, 그 요소와 모든 자손이 htmx 처리에서 빠집니다(2.x의 hx-disable 역할, 4편). 랩에서 아일랜드 컨테이너 안에 hx-get 버튼을 넣고 htmx.process()를 불러도 초기화되지 않았고, 컨테이너 밖에 같은 버튼을 넣으면 초기화됐습니다. React가 그린 마크업에 우연히 hx-로 시작하는 속성이 섞여도 htmx가 끼어들지 않게 하는 안전장치입니다. 반대로 React 안에서 일부러 htmx를 쓰고 싶은 경우(패턴 B)는 14편에서 이 경계를 의도적으로 다르게 긋습니다.

  

    
hx-ignore가 막지 못하는 것

    
hx-ignore는 "htmx가 안쪽 요소를 초기화하지 않는다"는 뜻이지, "누구도 안쪽을 스왑하지 못한다"는 뜻이 아닙니다. 바깥의 버튼이 hx-target="#어떤-아일랜드-안쪽"을 가리키거나, 서버가 그 안쪽 id를 대상으로 OOB·partial을 보내면 그대로 스왑됩니다. 2절 ①의 실험도 컨테이너에 hx-ignore가 있는 상태에서 일어났습니다. 대상 선택은 결국 사람이 지켜야 하는 규칙이고, 코드 리뷰 체크리스트에 넣어 두는 편이 좋습니다.

마운트 시점: 아일랜드 등록부

  
2편의 아일랜드는 페이지가 로드될 때 한 번 마운트하고 끝이었습니다. 7편에서 부스트 재방문 때 아일랜드가 비는 문제를, 5편에서 패널을 새로 그리면 Vue 상자가 비는 문제를 봤습니다. 원인은 같습니다. htmx가 새 내용을 넣는 시점을 아일랜드 코드가 모른다.

  

    
필요한 순간쓸 수 있는 신호측정·근거

    
      
새 내용이 들어왔다 (마운트)htmx.onLoad(fn) = htmx:after:process페이지 로드, 스왑, 부스트, SSE partial 모두 이 이벤트를 거침 (8편)

      
내용이 사라졌다 (언마운트)htmx:before:cleanup? → 쓸 수 없음htmx가 초기화한 요소에만 발생. 아일랜드 컨테이너는 hx-ignore라 더더욱 해당 없음 (8편 측정)

      
내용이 사라졌다 (대안)MutationObserver로 "문서에서 떨어진 컨테이너" 찾기이번 편 등록부

    
  

  
apps/server/public/js/portal.js (등록부 부분)


(() => {
  const defs = new Map();          // 이름 → { mount(el) => 정리 함수 }
  const live = new Set();          // 마운트된 컨테이너
  function scan(root) { /* root 안의 [data-island] 중 아직 안 된 것을 defs로 마운트, el.__island 표시 */ }
  function sweep() { /* live 중 isConnected가 false인 것의 정리 함수 호출 */ }
  window.PortalIslands = {
    autoCleanup: true,
    register(name, def) { defs.set(name, def); scan(document); },   // 번들이 늦게 와도 등록 시점에 다시 찾기
    stats: () => ({ ...stats, live: live.size }),
  };
  htmx.onLoad(scan);
  new MutationObserver(sweep).observe(document.documentElement, { childList: true, subtree: true });
})();

  
React·Vue 번들은 이제 "이 이름은 이렇게 마운트하고, 정리는 이 함수로"만 등록합니다(7절 코드). 번들은 레이아웃 <head>의 모듈 스크립트로 한 번만 불러오므로, 7편에서 확인한 "body 안 모듈은 첫 방문만 실행" 문제가 생기지 않습니다. 등록부가 부스트로 바뀐 body에서도 after:process를 받아 새 컨테이너를 찾기 때문입니다.

app.get('/api/vms/:name/metrics', (req, res) => {

6편의 302 나쁜 예를 기억하면 왜 리다이렉트하면 안 되는지 알 수 있습니다. fetch()는 리다이렉트를 따라가 로그인 페이지 HTML을 200으로 받고, 아일랜드의 res.json()이 깨집니다. 랩에서 세션을 만료시키자 다음 갱신 때 차트 자리에 "세션이 만료되었습니다. 새로고침 후 다시 로그인하세요."가 표시됐고, 세션 없이 curl로 부르면 401 application/json이 왔습니다. 지표 데이터는 실제로는 Prometheus 같은 모니터링 시스템에서 읽어 올 자리이며, 랩은 VM 이름과 시각으로 정해지는 의사 난수로 10초 간격 30개 값을 만듭니다(두 서버가 같은 시각에 같은 값을 내도록 같은 해시 함수 사용).

  
아일랜드 쪽에서는 언마운트 때 반드시 정리합니다. React의 useEffect가 돌려주는 정리 함수에서 타이머를 멈추고 진행 중인 요청을 AbortController로 취소합니다. 4절의 누수 측정은 "정리 함수는 있었지만 아무도 언마운트를 부르지 않았을 때" 생긴 것입니다. 정리 코드를 쓰는 책임(아일랜드)과 정리를 부르는 책임(등록부)이 둘 다 있어야 합니다.

등록부로 7편·5편의 문제는 풀었지만, 측정해 보면 구멍이 남습니다. 이것이 12편에서 웹 컴포넌트로 넘어가는 이유입니다.

  

    
한계근거웹 컴포넌트(12편)에서는

    
      
컨테이너가 문서에 남아 있으면 침범을 감지 못함2절 ①: 안쪽이 덮어써져도 컨테이너는 연결 상태라 정리 대상이 아님. React는 보이지 않는 노드를 계속 갱신하고 요청도 계속섀도 DOM 등으로 안쪽을 바깥 선택자로부터 숨길 수 있음

      
모핑 앞에서 무력함측정: web-01 상세를 web-02 상세 HTML로 innerMorph하자 컨테이너는 같은 노드로 남고 data-vm만 web-02로 바뀌었으며, React가 그린 안쪽은 서버 HTML(빈 div)에 맞춰 비워졌습니다. 등록부는 마운트 상태라 다시 그리지 않았고, React는 보이지 않는 채 web-01 데이터를 계속 요청했습니다. 모핑은 hx-ignore와 무관하게 자식을 맞춥니다attributeChangedCallback으로 속성 변화를 받고, 모핑 제외(hx-morph-skip-children, 5편)와 함께 씀

      
정리 시점이 늦고 전역 감시 비용MutationObserver는 문서 전체 변경마다 비동기로 깨어나 살아 있는 아일랜드를 모두 확인브라우저가 요소별로 disconnectedCallback 호출

      
이름표 방식의 약속data-island 철자 하나 틀리면 조용히 아무 일도 없음정의되지 않은 태그는 :not(:defined)로 드러남

    
  

  
그럼에도 이번 편의 등록부를 먼저 만든 이유가 있습니다. 웹 컴포넌트도 결국 "마운트·언마운트 시점을 브라우저가 알려 준다"는 것뿐이고, 그 시점에 무엇을 해야 하는지(데이터 API를 읽고, 정리 함수로 타이머와 요청을 끊고, 경계 밖을 건드리지 않는 것)는 이번 편에서 정한 그대로입니다.
