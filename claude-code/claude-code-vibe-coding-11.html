Hooks로자동화 규칙 걸기

CLAUDE.md와 Skill은 Claude가 따르려 노력하는 지침이었습니다. Hook은 다릅니다. 정해진 순간이 오면 Claude의 판단과 상관없이 반드시 실행되는 내 스크립트입니다. 편집 후 문법 검사, 비밀 커밋 차단, 테스트 통과 전 종료 금지를 시스템이 보장하게 만듭니다.

Hook 이벤트와 matcher·if 필터의 관계를 설명한다
종료 코드와 JSON 출력으로 차단·허용·맥락 추가를 구분해 쓴다
“exit 1은 막지 않는다” 같은 함정을 피해 정책 Hook을 만든다
vibe-lab에 검증된 MSP Hook 6개를 설치하고 직접 확인한다

Hook은 “반드시”다

Hook은 Claude Code 생명주기의 특정 시점에 자동으로 실행되는 사용자 정의 핸들러입니다. 셸 명령, HTTP 엔드포인트, MCP 도구, LLM 프롬프트, 서브에이전트가 될 수 있습니다. 공식 모범 사례 문서의 표현대로, CLAUDE.md의 지시는 권고이지만 Hook은 결정적이어서 그 동작이 일어나는 것을 보장합니다. “예외 없이 매번 일어나야 하는 일”이 Hook의 자리입니다.

장치성격예편
CLAUDE.md항상 읽는 맥락 (권고)“테스트는 make test로”8편
Skill필요할 때 따르는 레시피 (권고)/runbook 절차10편
권한 규칙·샌드박스Claude Code·OS가 강제 차단deny Bash(pip install *)9편
Hook정해진 시점에 내 스크립트를 반드시 실행편집할 때마다 문법 검사, 테스트 실패면 종료 금지이번 편
Hook을 직접 쓰지 않아도 됩니다 공식 문서도 “편집할 때마다 eslint를 돌리는 Hook을 써줘”, “migrations 폴더 쓰기를 막는 Hook을 써줘”처럼 Claude에게 만들게 하라고 권합니다. 이번 편에서는 동작 원리를 알고, Claude가 만든 Hook을 검토할 수 있는 눈을 기르는 것이 목표입니다.
2 / 15

이벤트 지도

이벤트는 세 가지 박자로 일어납니다. 세션당 한 번(SessionStart·SessionEnd), 턴당 한 번(UserPromptSubmit·Stop), 도구 호출마다(PreToolUse·PostToolUse). 공식 문서에는 30개가 넘는 이벤트가 있지만, 실무에서 자주 쓰는 것을 골랐습니다. 눌러서 자세히 보세요.

3 / 15

설정의 세 단계

Hook은 settings JSON에 이벤트 → matcher 그룹 → 핸들러의 세 단계로 씁니다. 아래는 공식 문서의 예를 옮긴 것으로, Bash 호출 중 rm으로 시작하는 하위 명령이 있을 때만 스크립트를 띄웁니다.

{ "hooks": { "PreToolUse": [ // ① 이벤트 { "matcher": "Bash", // ② matcher: 도구 이름으로 거르기 "hooks": [ { "type": "command", // ③ 핸들러 "if": "Bash(rm *)", // 더 좁히기 (권한 규칙 문법) "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-rm.sh", "args": [] } ] } ] } }
matcher 값해석예
"*", "", 생략모두이벤트마다 항상
글자·숫자·_·-·공백·,·|만정확한 이름 (목록 가능)Edit|Write, Edit, Write
그 밖의 문자 포함JavaScript 정규식, 부분 일치mcp__memory__.*, ^Notebook
if: 프로세스를 아끼는 2차 필터

도구 이벤트에서만 동작하며 규칙 하나만 쓸 수 있습니다(&& 없음). 맞지 않으면 스크립트를 아예 띄우지 않습니다. 단 최선 노력 필터라서, 명령을 해석할 수 없으면 그냥 실행합니다. 반드시 막아야 하는 것은 권한 시스템으로.

정규식 함정

Edit.*는 NotebookEdit에도 맞습니다. 전체 일치가 필요하면 ^Edit$. MCP 서버 전체는 mcp__서버__.*처럼 .*까지 써야 합니다.

모두 병렬로

맞는 핸들러는 동시에 실행됩니다. 같은 핸들러가 여러 설정 파일에 있으면 한 번만 실행됩니다.

/hooks

설정된 Hook을 이벤트별로 보고 출처 파일을 확인하는 읽기 전용 화면. 고치려면 settings JSON을 직접 편집하거나 Claude에게 시킵니다. 파일 변경은 보통 자동으로 반영됩니다.

정의 위치범위
~/.claude/settings.json내 모든 프로젝트
.claude/settings.json이 프로젝트, 팀과 공유
.claude/settings.local.json이 프로젝트, 나만
관리형 설정조직 전체 (개인이 끌 수 없음)
플러그인 hooks/hooks.json플러그인이 켜진 동안 (15편)
Skill·서브에이전트 frontmatterSkill을 부른 뒤 세션 끝까지 · 서브에이전트가 도는 동안

Hook은 범위끼리 덮어쓰지 않고 합쳐집니다. 설정 파일·관리형·플러그인 Hook은 서브에이전트 안의 도구 호출에도 똑같이 걸립니다.

4 / 15

입력과 출력

명령 Hook은 이벤트 정보를 stdin의 JSON으로 받습니다. Bash PreToolUse라면 이런 모양입니다.

{ "session_id": "abc123", "cwd": "/home/me/vibe-lab", "permission_mode": "default", "hook_event_name": "PreToolUse", "tool_name": "Bash", "tool_input": { "command": "kubectl -n prod delete pod api", "description": "…" }, "tool_use_id": "toolu_01…" }

종료 코드

종료 코드뜻
0성공. 출력이 JSON이면 그 필드를 읽음. 대부분 이벤트에서 그냥 텍스트 stdout은 디버그 로그로만 감 (UserPromptSubmit·SessionStart 등은 Claude의 맥락으로 추가)
2차단 오류. 막을 수 있는 이벤트에서 그 동작을 막고, stderr를 이유로 전달. JSON의 allow로도 뒤집지 못함
그 밖 (1 등)막지 않는 오류. 동작은 진행되고 화면에 오류 알림만
함정 1: exit 1은 막지 않습니다 유닉스에서 실패는 보통 1이지만, Claude Code에서 정책을 강제하려면 반드시 exit 2(또는 JSON 결정)를 쓰세요. 스크립트 경로를 잘못 써서 127로 끝나는 경우도 “막지 않는 오류”라 문지기가 조용히 꺼진 상태가 됩니다. 정책 Hook은 처음 실행에서 오류 알림이 없는지 꼭 확인하세요.
함정 2: 시간 초과된 PreToolUse는 막지 않습니다 command·http·mcp_tool Hook이 timeout(기본 600초)에 걸려 취소되면 결정이 없는 것으로 보고 도구 호출이 평소 권한 흐름으로 계속됩니다. 멈춘 Hook을 관문으로 믿지 마세요.

JSON 출력

필드쓰는 곳효과
hookSpecificOutput.permissionDecisionPreToolUseallow · deny · ask · defer와 permissionDecisionReason
decision: "block" + reasonStop, PostToolUse, UserPromptSubmit 등Stop이면 Claude가 멈추지 않고 이유를 받아 계속 일함
hookSpecificOutput.additionalContextSessionStart, UserPromptSubmit, Pre/PostToolUse, Stop 등Claude의 맥락에 시스템 리마인더로 추가. 명령이 아니라 사실 문장으로 쓰기
systemMessage대부분사용자에게 보이는 경고
continue: false + stopReason대부분Claude를 완전히 멈춤
terminalSequence대부분 (Notification 포함)데스크톱 알림·창 제목·벨. Hook은 /dev/tty를 쓸 수 없어 이 필드로

stdout에는 JSON 객체만 있어야 합니다. 셸 프로필이 시작할 때 글자를 찍으면 JSON 해석이 깨질 수 있습니다. 출력 문자열은 10,000자로 제한되고, 넘으면 파일로 저장되어 경로와 미리보기만 전달됩니다.

Hook 시뮬레이터

이벤트와 Hook의 행동을 고르면 Claude Code가 어떻게 반응하는지 보여 줍니다. 공식 문서의 종료 코드·결정 규칙을 바탕으로 한 학습용 요약입니다.

6 / 15

핸들러 다섯 가지

command

셸 명령. stdin으로 JSON을 받고 종료 코드와 stdout으로 답합니다. 가장 많이 씀. 기본 timeout 600초.

http

JSON을 POST 본문으로 보냄. 상태 코드만으로는 막을 수 없고 2xx + JSON 결정이 필요. 헤더의 환경 변수는 allowedEnvVars에 적은 것만 치환.

mcp_tool

이미 연결된 MCP 서버의 도구를 호출. 연결이 안 돼 있으면 막지 않는 오류 (12편).

prompt

모델에게 한 번 물어 JSON 결정을 받음. $ARGUMENTS에 Hook 입력이 들어감. 기본 timeout 30초.

agent (실험적)

Read·Grep 같은 도구를 쓰는 서브에이전트가 조건을 확인한 뒤 결정. 바뀔 수 있음.

exec 형식과 shell 형식

exec 형식 (args 있음)

command를 실행 파일로 직접 띄우고 args를 그대로 전달합니다. 셸이 없어 따옴표 문제가 없습니다. ${CLAUDE_PROJECT_DIR} 같은 경로를 쓸 때 권장.

"command": "python3", "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/guard_bash.py"]

shell 형식 (args 없음)

셸이 해석하므로 파이프·&&·리다이렉트를 쓸 수 있습니다. 경로 자리표시자는 큰따옴표로 감싸세요.

"command": "jq -r '.tool_input.command' >> ~/claude-bash.log"

MSP 레시피 6종

모두 Python 표준 라이브러리만 쓰고(jq 불필요), 이 강의를 만들며 예시 입력으로 실행해 동작을 확인했습니다. 탭을 눌러 스크립트와 확인 방법을 보세요. 설치는 11장에서 한 번에 합니다.

전체 settings.json

{ "hooks": { "SessionStart": [ { "hooks": [ { "type": "command", "command": "python3", "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/session_context.py"] } ] } ], "PreToolUse": [ { "matcher": "Bash", "hooks": [ { "type": "command", "command": "python3", "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/guard_bash.py"] } ] }, { "matcher": "Edit|Write", "hooks": [ { "type": "command", "command": "python3", "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/no_secrets.py"] } ] } ], "PostToolUse": [ { "matcher": "Edit|Write", "hooks": [ { "type": "command", "command": "python3", "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/check_shell.py"] } ] } ], "Stop": [ { "hooks": [ { "type": "command", "command": "python3", "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/tests_before_stop.py"] } ] } ], "Notification": [ { "matcher": "permission_prompt|idle_prompt", "hooks": [ { "type": "command", "command": "python3", "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/notify.py"] } ] } ] } }

Windows 네이티브에서 python3가 없다면 py나 python으로 바꾸세요. 하나의 설정 파일에 권한 규칙(9편)과 Hook이 함께 있어도 됩니다.

8 / 15

권한 규칙과 함께 쓰기

9편의 deny 규칙은 명령 글자를 봤고, 그래서 sh -c '…'나 /usr/bin/ssh 같은 모양을 놓칠 수 있었습니다. 레시피 ①의 guard_bash.py는 명령 전체를 정규식으로 검사해 그 틈을 메웁니다. 둘의 관계는 이렇습니다.

Hook이 권한 규칙을 우회하지 못함

PreToolUse Hook이 무엇을 반환하든 deny·ask 규칙은 평가됩니다. Hook이 allow를 줘도 deny 규칙에 맞으면 막히고, ask 규칙에 맞으면 묻습니다.

Hook은 allow 규칙보다 셈

exit 2로 막는 Hook은 권한 규칙 평가 전에 호출을 멈추므로, allow 규칙이 허용하는 명령도 막을 수 있습니다. 공식 문서 예: Bash 전체를 allow하고 몇 가지만 Hook으로 막기.

침묵은 허용이 아님

exit 0에 출력이 없으면 “결정 없음”입니다. 평소 권한 흐름이 그대로 적용됩니다.

Hook도 완벽하지 않음

정규식은 오탐(grep ssh도 막힘)과 미탐(변수·인코딩으로 숨긴 명령)이 있습니다. 샌드박스와 자격 증명 분리를 함께 쓰는 겹 방어가 정답입니다.

9 / 15

보안과 신뢰

Hook은 여러분의 권한으로 도는 코드입니다 저장소의 .claude/settings.json에 들어 있는 Hook은 그 저장소에서 Claude Code를 실행하면 여러분 컴퓨터에서 실행됩니다. 9편에서 봤듯 claude -p와 SDK는 폴더 신뢰 창을 띄우지 않고 설정 파일의 Hook을 사용하며, 프로젝트 Skill의 frontmatter Hook도 신뢰하지 않은 폴더의 -p 실행에서 등록됩니다. 남의 저장소를 돌리기 전에 .claude/settings.json의 hooks와 .claude/skills/*/SKILL.md의 hooks를 꼭 읽으세요.
하고 싶은 일방법
모든 Hook 잠시 끄기"disableAllHooks": true. 단 프로젝트 설정의 false가 사용자 설정의 true를 이김
이번 실행만 확실히 끄기claude --settings '{"disableAllHooks": true}' (프로젝트·로컬 설정보다 우선)
Hook 하나만 끄기방법 없음. 설정에서 지우기
조직이 허용한 Hook만관리형 설정의 allowManagedHooksOnly (24편)
HTTP Hook 주소 제한allowedHttpHookUrls, 헤더 변수는 httpHookAllowedEnvVars

관리형 Hook은 사용자·프로젝트의 disableAllHooks로 끌 수 없습니다. HTTP Hook으로 슬랙 등에 알림을 보낼 때는 토큰을 설정 파일에 쓰지 말고 환경 변수와 allowedEnvVars를 쓰세요.

디버깅

1
혼자 돌려 보기

Claude Code 없이 예시 JSON을 파이프로 넣어 종료 코드와 출력을 봅니다. 레시피마다 확인 명령을 넣어 두었습니다.

echo '{"tool_input":{"command":"sh -c \"pip install x\""}}' | python3 .claude/hooks/guard_bash.py; echo "exit $?"
2
등록됐는지 보기

/hooks에서 이벤트, matcher, 출처 파일을 확인합니다.

3
실행 기록 보기

claude --debug로 디버그 로그를 켜면 Hook의 stdout·stderr와 오류가 남습니다. 종료 코드 0일 때 stderr는 디버그 로그에만 갑니다.

4
“hook error” 알림 읽기

Failed with non-blocking status code: …는 막지 않는 오류입니다. 127이면 경로·실행 권한 문제. 정책 Hook이라면 그 순간 관문이 꺼져 있었던 것입니다.

실습: vibe-lab에 Hook 걸기

아래 블록이 스크립트 6개와 settings.json의 hooks 부분을 만듭니다. 이미 9편에서 만든 .claude/settings.json이 있다면 블록 대신 4단계의 프롬프트로 합치세요.
