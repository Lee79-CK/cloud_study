모델 포맷·양자화
레지스트리

2편에서 “가중치 메모리 = 파라미터 × 바이트”를 배웠고, 3편에서는 FP8·FP4가 토큰당 비용을 바꾸는 것을, 5편에서는 “같은 정밀도로 맞췄나”가 공정한 비교의 첫 조건이라는 것을 봤습니다. 이번 편은 그 “바이트”를 정면으로 다룹니다. 모델이 어떤 파일로 오는지, 숫자를 몇 비트로 어떻게 줄이는지, 그 대가로 무엇을 잃는지, 같은 양자화가 왜 GPU마다 다르게 동작하는지, 그리고 그 모델 파일을 회사 안에서 어떻게 들여오고 관리하고 라이선스를 지키는지까지.

선행 2·3·5편 읽는 시간 약 110분 실습 약 120분 기준 2026년 10월
같은 모델, 네 가지 정밀도

가중치만 계산(스케일 등 부가 데이터 근사 포함). 세로선은 GPU 한 장의 메모리. 품질 위험은 일반적 경향이며 모델·작업마다 반드시 평가해야 합니다.

01시작하기 전에

양자화는 “공짜 성능”이 아니라 품질을 담보로 메모리·속도를 사는 거래입니다. 거래 조건을 아는 사람이 이깁니다.

학습 목표

  1. Hugging Face 모델 저장소의 파일 구성과 safetensors·GGUF·compressed-tensors 등 포맷의 차이, pickle 형식의 보안 위험을 설명할 수 있다.
  2. BF16·FP8·INT4·FP4의 비트 구조와 스케일 단위(텐서·채널·그룹·블록·마이크로스케일)를 설명하고, 이상치가 왜 문제인지 보여 줄 수 있다.
  3. 가중치 전용·가중치+활성값·KV 캐시 양자화와 GPTQ·AWQ·SmoothQuant·RTN의 차이, 보정 데이터의 역할을 설명할 수 있다.
  4. 같은 양자화가 A100·L4·H100·B200·GB10에서 다르게 동작하는 이유를 텐서 코어와 커널 경로로 설명할 수 있다.
  5. 사내 모델 레지스트리의 선택지(허브 미러·오브젝트 스토리지·OCI 레지스트리)와 반입·검증·버전 고정 절차를 설계할 수 있다.
  6. 라이선스와 게이트 모델의 운영 규칙을 세우고, 같은 모델의 BF16·FP8·AWQ 버전을 메모리·속도·품질로 비교할 수 있다.
이 편의 비유: 사진 압축

BF16 원본은 RAW 사진, FP8은 고화질 JPEG, 4비트 양자화는 메신저로 보낼 때 줄어든 사진입니다. 풍경 사진은 압축해도 거의 티가 안 나지만, 작은 글씨가 많은 문서 사진은 금방 뭉개집니다. LLM도 마찬가지로 일상 대화는 잘 버티지만, 수학·코드·긴 추론·드문 언어처럼 “작은 글씨”가 중요한 작업에서 압축 손실이 먼저 드러납니다. 그리고 압축을 잘하는 방법(어느 부분을 덜 깎을지 정하는 알고리즘)에 따라 같은 용량에서도 화질이 달라집니다.

03파일 포맷

같은 가중치도 어떤 그릇에 담느냐에 따라 안전성·로딩 속도·지원 엔진이 달라집니다.

포맷특징주 사용처운영 메모
PyTorch pickle (.bin, .pt)파이썬 객체 직렬화. 읽는 순간 임의 코드가 실행될 수 있음오래된 모델보안 위험. 출처가 불분명하면 반입 금지 또는 safetensors로 변환 후 반입. 스캐너로 검사

AWQ·GPTQ 패킹 포맷4비트 정수 가중치를 패킹해 저장(라이브러리별 규약)여러 엔진이 읽음최근 도구는 compressed-tensors로 변환·통합하는 추세
MXFP4 체크포인트MoE 전문가 가중치를 MXFP4로 배포gpt-oss 등원본 자체가 4비트. BF16 버전이 없을 수 있음
포맷과 정밀도는 다른 축이다

“safetensors 모델”이라는 말은 정밀도를 알려 주지 않습니다. 같은 safetensors 안에 BF16도, FP8도, 패킹된 INT4도 들어갈 수 있습니다. 정밀도는 config.json의 torch_dtype과 quantization_config로 판단합니다(실습 6-1).

04숫자 표현과 스케일

양자화를 이해하는 데 필요한 것은 두 가지뿐입니다: 숫자 하나를 몇 비트로 표현하나, 그리고 그 작은 숫자를 원래 크기로 되돌리는 “스케일”을 몇 개씩 묶어 공유하나.

비트 구조 한눈에

부동소수점은 부호, 수의 크기 범위를 정하는 지수, 정밀도를 정하는 가수로 나뉩니다. 지수 비트가 많을수록 넓은 범위, 가수 비트가 많을수록 촘촘한 값을 표현합니다.

부호지수가수정수
  • BF16 vs FP16: 둘 다 16비트지만 BF16은 FP32와 같은 지수(8비트)를 가져 범위가 넓고, FP16은 가수가 많아 촘촘하지만 최댓값이 65,504라 큰 값에서 넘칩니다. 대부분의 최신 모델이 BF16으로 학습·배포되는 이유입니다.
  • FP8 두 종류: E4M3(최대 448)은 정밀도를, E5M2(최대 57,344)는 범위를 택했습니다. 추론의 가중치·활성값에는 보통 E4M3를 씁니다.
  • FP4 (E2M1): 표현 가능한 양수가 0, 0.5, 1, 1.5, 2, 3, 4, 6 여덟 개뿐입니다. 그래서 스케일을 아주 잘게 공유해야 쓸 만해집니다.
  • INT8·INT4: 지수가 없는 균등 간격 정수. 스케일(과 필요하면 영점)을 곱해 원래 값으로 되돌립니다.

스케일을 몇 개씩 공유하나

단위스케일 하나가 담당하는 범위장점단점대표 사용
텐서 단위행렬 전체부가 데이터 최소, 커널 단순이상치 하나가 전체 정밀도를 망침FP8 per-tensor
채널 단위출력 채널(행) 하나채널 간 크기 차이를 흡수채널 안의 이상치에는 약함FP8·INT8 per-channel
그룹 단위연속된 값 g개(보통 32~128)4비트에서 품질을 크게 살림스케일 저장량 증가, 커널 복잡W4A16 (AWQ·GPTQ group 128)
블록 단위2차원 블록(예: 128×128)행렬 곱 타일과 맞아 효율적블록 안 이상치에 영향FP8 block (DeepSeek 계열에서 대중화)
마이크로스케일값 16개(NVFP4) 또는 32개(MXFP4·MXFP8)4비트 부동소수점을 실용적으로 만듦. 하드웨어가 스케일 처리를 직접 지원지원 GPU 필요(Blackwell 등)NVFP4: 16개마다 FP8 스케일 + 텐서 단위 FP32 스케일, MXFP4: 32개마다 지수형(E8M0) 스케일

양자화 실험실: 이상치와 스케일 단위의 영향

가중치처럼 생긴 값 1,024개(대부분 작은 값 + 드문 이상치)를 여러 방식으로 양자화했다가 되돌려, 원래 값과의 오차를 잽니다. 실제 커널 구현이 아니라 숫자 표현의 원리를 보여 주는 계산입니다. 실제 LLM에서 큰 이상치는 가중치보다 활성값에서 더 두드러지므로(5장 SmoothQuant), 이 실험의 오차 크기를 실제 모델 품질 손실로 그대로 읽지 마세요.

05양자화 방식 지도

“무엇을”(가중치·활성값·KV), “어떻게”(알고리즘), “언제”(미리·로딩 시) 줄이느냐의 세 축으로 정리합니다.

표기무엇을 줄이나대표 방법보정 데이터주된 이득품질 위험
W8A16가중치만 8비트(FP8·INT8)RTN불필요메모리 절반, 작은 배치 Decode매우 낮음
W4A16가중치만 4비트 정수GPTQ, AWQ, AutoRound필요(수백 샘플)메모리 1/4, 작은 배치 Decode낮음~중간. 작은 모델·수학·코드에서 민감
W8A8-FP8가중치+활성값 FP8동적(요청마다 활성 스케일 계산) 또는 정적동적은 불필요메모리 절반 + FP8 연산(Prefill·큰 배치)매우 낮음. 많은 모델의 새 기본값
W8A8-INT8가중치+활성값 INT8SmoothQuant + GPTQ필요FP8 없는 GPU(A100 등)에서 연산 가속낮음~중간
W4A8 / W4AFP8가중치 4비트 + 활성값 8비트혼합필요메모리와 연산 둘 다중간
NVFP4 (W4A4)가중치+활성값 FP4 마이크로스케일RTN·GPTQ·AWQ 계열 + 보정필요(활성 스케일)메모리 1/4 + FP4 연산(Blackwell)중간. 정수 4비트보다 나은 경우가 많지만 평가 필수
NVFP4A16·MXFP4A16가중치만 FP4RTN·GPTQ선택메모리 1/4중간
KV FP8 (·FP4)KV 캐시스케일 보정 또는 동적선택KV 공간 2배 → 동시성(2·3편)대체로 낮음. 긴 컨텍스트·추론에서 확인

알고리즘 네 가지를 한 문장씩

  • RTN (Round-To-Nearest): 그냥 가장 가까운 값으로 반올림. 보정 데이터가 필요 없고 빠릅니다. 8비트에서는 대부분 충분합니다.
  • GPTQ: 층 하나씩, 보정 데이터로 측정한 입력 통계를 이용해 한 가중치를 반올림하며 생긴 오차를 아직 반올림하지 않은 가중치들이 메워 주도록 조정합니다. 4비트 품질을 크게 끌어올린 대표 방법입니다.
  • AWQ (Activation-aware Weight Quantization): 활성값이 큰 소수의 “중요한 채널”이 결과를 좌우한다는 관찰에서 출발해, 그 채널의 가중치가 덜 깎이도록 스케일을 조정한 뒤 양자화합니다.
  • SmoothQuant: 활성값에 몰린 이상치를 수학적으로 등가인 변환으로 가중치 쪽에 옮겨, 활성값까지 8비트로 줄일 수 있게 만듭니다.

최근에는 회전(Hadamard) 변환으로 이상치를 고르게 퍼뜨린 뒤 양자화하는 방법들(QuIP·SpinQuant 계열)과 AutoRound 같은 최적화 기반 방법도 도구에 통합되어 있습니다. vLLM 생태계의 표준 도구인 LLM Compressor는 AWQ·GPTQ·AutoRound·RTN과 이런 변환들, FP8·INT8·INT4·NVFP4·MXFP4·혼합 정밀도, KV 캐시·어텐션 양자화까지 지원하고 결과를 vLLM이 바로 읽는 compressed-tensors로 저장합니다. NVIDIA 쪽에서는 ModelOpt가 같은 역할을 합니다.

보정 데이터는 “우리 데이터”여야 한다

한국어 서비스라면 한국어로 보정한다

GPTQ·AWQ·정적 활성 스케일은 보정 데이터에서 본 분포에 맞춰 “어디를 덜 깎을지”를 정합니다. 공개 양자화 모델은 대개 영어 위주 데이터로 보정되어 있어, 한국어·사내 용어·코드 비중이 높은 서비스에서는 품질 손실이 예상보다 클 수 있습니다. 4비트가 필요하다면 실제 서비스 프롬프트를 닮은 수백 개 샘플(개인정보 제거)로 직접 보정하고, 같은 데이터로 원본과 비교 평가하세요(실습 6-4).

미리 양자화 vs 로딩 시 양자화

vLLM은 BF16 체크포인트를 읽으면서 FP8로 바꾸는 온라인 양자화를 지원합니다(v0.31.0에서는 fp8_per_tensor 같은 단축 표기로 정리됨). 보정 없이 바로 쓸 수 있어 편하지만, 로딩 때마다 변환 비용이 들고 정적 스케일·4비트처럼 보정이 필요한 방식에는 쓸 수 없습니다. 운영에서는 미리 양자화해 레지스트리에 올린 체크포인트를 쓰는 것이 재현성·기동 시간 면에서 낫습니다.

06품질·속도·메모리 맞교환

메모리는 확실히 줄고, 속도는 상황에 따라 다르고, 품질은 반드시 재야 합니다.

속도가 “상황에 따라” 다른 이유

  • Decode, 작은 배치: 메모리 대역폭 병목(2편)이라 읽을 바이트가 줄면 그대로 빨라집니다. 가중치 전용 4비트(W4A16)가 가장 크게 이득을 봅니다.
  • Decode, 큰 배치·Prefill: 연산 병목으로 넘어갑니다. W4A16은 매번 4비트를 16비트로 풀어 BF16 연산을 하므로 연산 이득이 없고, 오히려 풀어내는 비용 때문에 FP8(W8A8)보다 느려질 수 있습니다. 여기서는 활성값까지 저정밀로 계산하는 방식(FP8·NVFP4)이 이깁니다.
  • KV 공간: 가중치가 줄면 같은 GPU에 KV 공간이 늘어 동시성이 늘어납니다(2편 11장). 많은 경우 이것이 속도보다 큰 이득입니다.

맞교환 탐색기

모델·GPU·배치를 고르면 방식별로 메모리, Decode 스텝 시간, Prefill 연산 경로, 품질 위험 경향을 보여 줍니다. 2편의 단순 모델을 쓴 교육용 추정입니다.

품질은 어떻게 무너지나

양자화 손실은 평균 점수에서는 잘 안 보이다가 특정 영역에서 먼저 드러나는 경향이 있습니다. 평가 세트를 만들 때 아래 영역을 꼭 포함하세요(22편에서 체계화).

  • 정확한 계산·코드: 숫자 하나, 괄호 하나가 틀리면 전체가 틀립니다.
  • 긴 추론·긴 컨텍스트: 작은 오차가 수천 토큰에 걸쳐 누적됩니다.
  • 형식 준수: JSON·툴 호출 형식이 미묘하게 깨지는 경우.
  • 비영어·전문 용어: 보정 데이터에 적게 나온 분포.
  • 작은 모델: 같은 비트 수에서 큰 모델보다 손실이 큽니다. 8B 모델의 4비트와 70B 모델의 4비트는 같은 이야기가 아닙니다.

07GPU 세대별 차이

“이 GPU가 FP8을 지원하나”는 사실 두 질문입니다: 하드웨어가 그 연산을 하는가, 그리고 엔진에 그 GPU용 커널이 있는가.

세대 (아키텍처 번호)대표 GPU하드웨어 저정밀 연산W4A16·W8A16 (가중치 전용)FP8 (W8A8)FP4 (NVFP4·MXFP4)
Ampere (SM80·86)A100, A10BF16·FP16·INT8가속 (Marlin 등 혼합 정밀도 커널)가중치만 FP8로 저장, 연산은 BF16하드웨어 미지원
Ada (SM89)L4, L40S+ FP8가속하드웨어 FP8하드웨어 미지원
Hopper (SM90)H100, H200+ FP8 (Transformer Engine)가속 (Hopper 전용 혼합 커널)하드웨어 FP8, 성숙한 커널가중치만 저장·변환 경로(지원 여부는 엔진 확인)
Blackwell 데이터센터 (SM100·103)B200, B300, GB200·GB300+ FP4·FP6, 마이크로스케일 지원가속하드웨어 FP8하드웨어 FP4, 가장 깊게 최적화
Blackwell 클라이언트·GB10 (SM120·121)RTX PRO 6000, GB10(DGX Spark·PGX)+ FP4가속하드웨어 FP8하드웨어 FP4. 단, 데이터센터 Blackwell과 커널 경로가 달라 엔진·모델별 지원이 다를 수 있음

왜 같은 체크포인트가 GPU마다 다르게 도나

  1. 하드웨어 연산 유무: FP8 텐서 코어가 없는 A100에서 FP8 체크포인트는 “메모리에는 8비트로, 계산은 16비트로” 돌아갑니다. 메모리 이득은 같고 연산 이득은 없습니다.
  2. 엔진이 고르는 커널: 같은 W4A16이라도 Ampere에서는 Marlin 계열, Hopper에서는 Hopper 전용 혼합 정밀도 커널, Blackwell에서는 또 다른 커널이 선택됩니다. 커널마다 배치 크기별 효율이 달라 “작은 배치에서는 A가, 큰 배치에서는 B가 빠른” 현상이 생깁니다.
  3. 세대 안에서도 다르다: Blackwell이라도 데이터센터용(SM100)과 GB10·RTX 계열(SM12x)은 커널이 별도로 만들어집니다. 새 장비에서 특정 양자화 모델이 안 뜨거나 느리다면 엔진 릴리스 노트에서 해당 SM 지원을 먼저 확인하세요.
  4. 형식 변형: AMD MI300 계열의 FP8은 NVIDIA의 E4M3와 미세하게 다른 변형을 쓰고, NVFP4와 MXFP4는 스케일 구조가 다릅니다. 체크포인트를 그대로 옮기면 엔진이 변환하거나 거부합니다.
확인하는 방법

엔진 기동 로그에는 “어떤 양자화 방식을, 어떤 커널로” 처리하는지가 찍힙니다(4편 실습에서 본 로그). 같은 체크포인트를 다른 GPU에 옮길 때는 이 줄을 비교하는 것이 첫 번째 점검입니다. 실습 6-2에서 GB10의 로그로 확인합니다.

09라이선스·게이트 모델 관리

“오픈 모델”이 “아무렇게나 써도 되는 모델”은 아닙니다. 아래는 운영 관점의 정리이며, 실제 계약·배포 판단은 법무 검토를 거쳐야 합니다.

유형예시운영에서 확인할 것
허용형 오픈소스 라이선스Apache 2.0(Qwen3 계열, gpt-oss 등), MIT(DeepSeek 계열 등)라이선스·고지문 보존. 모델에 별도 사용 정책이 붙어 있는지 확인
조건부 커뮤니티 라이선스Llama 계열 커뮤니티 라이선스, Gemma 이용 약관 등허용 사용 정책(금지 용도), 대규모 사용자 기준 같은 상업 조건, 표기 의무, 파생 모델에 조건이 따라가는지
비상업·연구용CC BY-NC 계열, 연구 전용 라이선스업무·상용 서비스 사용 불가. 사내 PoC라도 범위 확인
게이트 모델허브에서 약관 동의·승인 후 내려받는 모델누가 어떤 계정으로 동의했는지 기록. 개인 토큰을 공용 서버에 두지 않기. 조직 서비스 계정 사용

운영 규칙 다섯 가지

  1. 양자화·파인튜닝 모델도 파생물입니다. 원 모델의 라이선스 의무가 그대로 따라오므로 레지스트리에 원본 라이선스와 고지문을 함께 보관합니다.
  2. 모델 카드의 라이선스 항목만 믿지 말고 원문을 저장합니다. 약관이 버전마다 바뀌는 경우가 있어, 반입 시점의 원문을 남겨야 나중에 근거가 됩니다.
  3. 게이트 모델 토큰은 Secret으로, 읽기 전용·최소 권한으로 발급합니다. 사람 계정의 토큰을 클러스터에 두지 않습니다.
  4. 사용 용도 승인을 카탈로그에 기록합니다(8장 approved_uses). 허용 사용 정책이 있는 모델은 용도가 바뀔 때 다시 검토합니다.
  5. 배포 범위: 모델을 고객에게 넘기거나 외부에 서빙하는 것이 라이선스상 “재배포”에 해당하는지 확인합니다.
MSP 관점: 라이선스 당사자는 누구인가

MSP가 고객 환경에 모델을 대신 내려받아 운영할 때, 약관에 동의하는 주체가 MSP인지 고객인지가 모호해지기 쉽습니다. 원칙적으로 모델을 사용하는 고객이 라이선스 당사자가 되도록 하고, MSP는 고객이 승인한 모델 목록과 동의 기록을 근거로 운영한다는 점을 계약서·작업 지시서에 명시하세요. 공용 MSP 서비스(여러 고객이 같은 모델을 쓰는 경우)는 MSP가 당사자가 되므로 서비스 약관과 모델 라이선스가 충돌하지 않는지 사전에 검토합니다.

10시나리오별 선택

지금까지의 내용을 현장 질문에 적용해 봅니다.

"""허브 저장소의 파일 구성, 총 크기, 정밀도·양자화 설정, 라이선스, 게이트 여부, 파일 해시를 출력한다."""
import json, sys
from huggingface_hub import HfApi, hf_hub_download

REPOS = sys.argv[1:] or ["Qwen/Qwen3-8B", "Qwen/Qwen3-8B-FP8", "Qwen/Qwen3-8B-AWQ", "Qwen/Qwen3-8B-GGUF"]
api = HfApi()

for repo in REPOS:
    info = api.model_info(repo, files_metadata=True)
    files = info.siblings or []
    total = sum((f.size or 0) for f in files)
    kinds = {}
    for f in files:
        ext = f.rfilename.rsplit(".", 1)[-1] if "." in f.rfilename else "(없음)"
        kinds[ext] = kinds.get(ext, 0) + 1
    card = info.card_data.to_dict() if info.card_data else {}
    print(f"\n=== {repo} ===")
    print(f"  리비전(커밋): {info.sha}")
    print(f"  라이선스: {card.get('license')}   게이트: {info.gated}")
    print(f"  파일 수: {len(files)}  총 크기: {total/1e9:.2f} GB  확장자: {kinds}")
    risky = [f.rfilename for f in files if f.rfilename.endswith((".bin", ".pt", ".pkl", ".py"))]
    if risky: print("  주의 파일(pickle·코드):", risky)
    try:
        cfg = json.load(open(hf_hub_download(repo, "config.json", revision=info.sha)))
        print("  torch_dtype:", cfg.get("torch_dtype") or cfg.get("dtype"))
        qc = cfg.get("quantization_config")
        print("  quantization_config:", json.dumps(qc, ensure_ascii=False)[:300] if qc else "없음 (원본 정밀도)")
    except Exception as e:
        print("  config.json 없음 (GGUF 저장소 등):", type(e).__name__)
    for f in [f for f in files if f.rfilename.endswith((".safetensors", ".gguf"))][:3]:
        sha = f.lfs.sha256 if f.lfs else None
        print(f"  {f.rfilename}: {f.size/1e9:.2f} GB  sha256={str(sha)[:16]}…")

실습 6-3 · 속도와 품질 측정

속도는 5편의 engine_bench.py를 그대로 씁니다. 품질은 정답이 정해진 계산 문제, JSON 형식 준수, BF16 응답과의 일치도를 보는 간이 평가로 잽니다.

python · quick_eval.py
"""간이 품질 평가: (1) 다단계 계산 정확도 (2) JSON 형식 준수 (3) BF16 기준 응답과의 유사도.
사용: python quick_eval.py --base http://llm-engine:8000/v1 --label fp8 [--ref /tmp/eval_bf16.json]"""
import argparse, asyncio, difflib, json, random, re
from openai import AsyncOpenAI

ap = argparse.ArgumentParser()
ap.add_argument("--base", required=True); ap.add_argument("--label", required=True); ap.add_argument("--ref")
a = ap.parse_args()
cli = AsyncOpenAI(base_url=a.base, api_key="EMPTY", timeout=600)
M = "qwen3-8b"
SEM = asyncio.Semaphore(8)

def math_items(n=40, seed=11):
    r = random.Random(seed); items = []
    for i in range(n):
        x, y, z, w = r.randint(12, 97), r.randint(3, 19), r.randint(2, 9), r.randint(5, 60)
        q = (f"서버 랙 하나에 GPU 노드가 {x}대 있고, 노드마다 GPU가 {z}장 있다. "
             f"랙이 {y}개일 때 전체 GPU 수에서 고장 난 {w}장을 빼면 몇 장인가? 마지막 줄에 숫자만 써라.")
        items.append((q, x * z * y - w))
    return items

JSON_ITEMS = [f"다음 경보를 분류해 JSON으로만 답하라. 키는 severity(info|warning|critical), component, action. 경보: {t}"
              for t in ["GPU 온도 92도 지속", "KV 캐시 사용률 99% 선점 증가", "인증서 만료 30일 전",
                        "노드 디스크 사용률 71%", "vLLM Pod 재시작 5회", "게이트웨이 5xx 비율 4%",
                        "모델 다운로드 지연", "DCGM XID 79 발생", "프리픽스 캐시 적중률 하락", "TTFT p95 SLO 위반"]]
SIM_ITEMS = [f"{t}을(를) 세 문장으로 설명하라." for t in
             ["KV 캐시", "연속 배칭", "FP8 양자화", "텐서 병렬", "프리픽스 캐시", "선점",
              "TTFT", "Goodput", "AWQ", "모델 레지스트리"]]

async def ask(prompt, max_tokens=400):
    async with SEM:
        r = await cli.chat.completions.create(model=M, temperature=0, max_tokens=max_tokens,
            messages=[{"role": "user", "content": prompt + " /no_think"}])
        return r.choices[0].message.content or ""

def last_int(t):
    m = re.findall(r"-?\d[\d,]*", t)
    return int(m[-1].replace(",", "")) if m else None

def json_ok(t):
    t = t.strip().removeprefix("```json").removeprefix("```").removesuffix("```").strip()
    try:
        o = json.loads(t)
        return o.get("severity") in ("info", "warning", "critical") and "component" in o and "action" in o
    except Exception:
        return False

async def main():
    mi = math_items()
    math_out = await asyncio.gather(*[ask(q) for q, _ in mi])
    acc = sum(last_int(o) == ans for o, (_, ans) in zip(math_out, mi)) / len(mi)
    js = await asyncio.gather(*[ask(p, 200) for p in JSON_ITEMS])
    jok = sum(json_ok(o) for o in js) / len(js)
    sim = await asyncio.gather(*[ask(p, 300) for p in SIM_ITEMS])
    res = {"label": a.label, "math_acc": acc, "json_valid": jok, "sim_outputs": sim}
    if a.ref:
        ref = json.load(open(a.ref))["sim_outputs"]
        res["similarity_vs_ref"] = sum(difflib.SequenceMatcher(None, x, y).ratio() for x, y in zip(sim, ref)) / len(ref)
    print(f"{a.label}: 계산 정확도 {acc:.1%}  JSON 준수 {jok:.0%}" +
          (f"  기준 대비 유사도 {res['similarity_vs_ref']:.2f}" if a.ref else ""))
    json.dump(res, open(f"/tmp/eval_{a.label}.json", "w"), ensure_ascii=False, indent=1)

asyncio.run(main())

실습 6-4 · (선택) 한국어로 보정한 4비트 모델 직접 만들기

LLM Compressor로 GPTQ W4A16을 만들어 공개 AWQ 버전과 비교합니다. 보정 데이터는 한국어 지시문 데이터셋 또는 여러분이 준비한 서비스 프롬프트(개인정보 제거) JSONL을 씁니다. GPU 노드에서 Job으로 실행합니다.

python · quantize_w4a16.py
"""한국어 보정 데이터로 Qwen3-8B를 GPTQ W4A16(compressed-tensors)으로 양자화한다.
사용: python quantize_w4a16.py [보정용 JSONL 경로(각 줄 {"text": ...})]"""
import json, sys
from datasets import Dataset, load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer
from llmcompressor import oneshot
from llmcompressor.modifiers.quantization import GPTQModifier

SRC, OUT, N, MAXLEN = "Qwen/Qwen3-8B", "/out/Qwen3-8B-W4A16-ko", 256, 2048
tok = AutoTokenizer.from_pretrained(SRC)
model = AutoModelForCausalLM.from_pretrained(SRC, torch_dtype="auto")

if len(sys.argv) > 1:                               # 서비스 프롬프트 샘플
    texts = [json.loads(l)["text"] for l in open(sys.argv[1], encoding="utf-8")][:N]
else:                                               # 공개 한국어 지시문 데이터 (존재·라이선스 확인 후 사용)
    ds = load_dataset("beomi/KoAlpaca-v1.1a", split="train").shuffle(seed=0).select(range(N))
    texts = [tok.apply_chat_template([{"role": "user", "content": r["instruction"]},
                                      {"role": "assistant", "content": r["output"]}], tokenize=False)
             for r in ds]
calib = Dataset.from_dict(tok(texts, max_length=MAXLEN, truncation=True))

recipe = GPTQModifier(targets="Linear", scheme="W4A16", ignore=["lm_head"])
oneshot(model=model, dataset=calib, recipe=recipe, max_seq_length=MAXLEN, num_calibration_samples=len(texts))
model.save_pretrained(OUT, save_compressed=True)
tok.save_pretrained(OUT)
print("저장 완료:", OUT)

"""허브 모델의 커밋·라이선스·파일 해시를 읽어 사내 카탈로그 YAML 초안을 만든다. (pip install huggingface_hub pyyaml)"""
import sys, datetime, yaml
from huggingface_hub import HfApi
repo = sys.argv[1] if len(sys.argv) > 1 else "Qwen/Qwen3-8B-FP8"
info = HfApi().model_info(repo, files_metadata=True)
card = info.card_data.to_dict() if info.card_data else {}
weights = [f for f in info.siblings if f.rfilename.endswith(".safetensors")]
entry = {
  "id": f"{repo.split('/')[-1].lower()}@{datetime.date.today():%Y-%m}",
  "source": {"hub_repo": repo, "revision": info.sha, "retrieved_at": str(datetime.date.today())},
  "license": {"name": card.get("license"), "gated": bool(info.gated), "acceptance_record": None},
  "artifact": {"format": "safetensors", "total_bytes": sum(f.size or 0 for f in weights),
               "sha256": {f.rfilename: (f.lfs.sha256 if f.lfs else None) for f in weights}},
  "evaluation": {"baseline": None, "suite": "quick_eval", "results": {}},
  "approval": {"approved_uses": [], "owner": None, "approved_at": None},
}
print(yaml.safe_dump(entry, allow_unicode=True, sort_keys=False))

출력된 YAML에 실습 6-3의 결과와 승인 정보를 채워 보세요. 내려받은 파일의 해시(sha256sum)가 허브에 기록된 해시와 일치하는지 확인하는 단계를 반입 절차에 넣으면, 전송 중 손상이나 바꿔치기를 잡을 수 있습니다. 조직에 Harbor 같은 OCI 레지스트리가 있다면 ORAS로 같은 파일들을 아티팩트로 올려 보는 것도 좋은 연습입니다(13편에서 로딩 방식으로 다시 다룸).

15정리와 체크리스트

핵심 여섯 문장.

  1. 포맷과 정밀도는 다른 축이다. safetensors가 표준 그릇이고, 정밀도는 config의 dtype과 quantization_config로 판단한다. pickle은 반입하지 않는다.
  2. 양자화의 핵심은 비트 수와 스케일 단위다. 이상치가 정밀도를 망치므로 4비트에서는 그룹·마이크로스케일 같은 잘게 나눈 스케일이 필요하다.
  3. 가중치 전용(W4A16)은 작은 배치 Decode에, 연산 저정밀(FP8·NVFP4)은 Prefill·큰 배치에 유리하다. 메모리 절감은 KV 공간·동시성으로 이어진다.
  4. FP8은 대부분 손실이 거의 없는 새 기본값이고, 4비트는 모델 크기·작업·보정 데이터에 따라 손실이 달라 반드시 우리 데이터로 평가한다.
  5. 같은 체크포인트도 GPU 세대와 엔진 커널에 따라 다르게 돈다. 기동 로그의 양자화·커널 줄로 확인한다.
  6. 모델은 반입 심사 → 사내 레지스트리(커밋 해시·파일 해시·라이선스·평가·승인 기록) → 캐시 → 엔진의 경로로만 들어온다. 파생 모델에도 원 라이선스가 따라간다.
