테스트 먼저 (TDD)

모범 사례 문서의 TDD 흐름을 운영 스크립트에 맞췄습니다. 핵심은 테스트가 실패하는 것을 눈으로 확인한 뒤 테스트를 커밋하고, 그다음 테스트를 바꾸지 않고 구현하는 것입니다.

1
테스트를 쓴다 (구현 금지)

“기대 입출력을 바탕으로 테스트를 써. TDD로 하고 있으니 아직 구현은 하지 마.” 이번 실습은 테스트를 미리 드립니다.

2
빨강 확인

원본에서 10개 실패, 5개 통과(16편 특성화), 1개 안전상 건너뜀. 처음부터 통과하는 새 테스트는 아무것도 지켜 주지 않습니다.

3
테스트 커밋

테스트를 먼저 커밋하면, 구현 중 테스트가 바뀌었는지 git diff tests/ 한 줄로 확인할 수 있습니다.

4
테스트 잠그고 구현

“테스트는 고치지 말고 통과할 때까지 구현을 고쳐.” 말로만 하지 말고 아래처럼 잠급니다.

5
초록 확인과 독립 검토

16개 통과(확인함). 13편 code-reviewer나 다른 세션에게 구현이 테스트에만 맞춘 것은 아닌지 봐 달라고 합니다.

테스트 잠그기

권한 규칙으로 (9편)

// .claude/settings.local.json — 구현하는 동안만 { "permissions": { "deny": ["Edit(tests/**)", "Write(tests/**)"] } }

프로젝트 루트에서 시작한 세션 기준. 끝나면 지웁니다. 9편처럼 Bash 리다이렉트까지 막지는 못하니 3단계 커밋이 최후의 확인입니다.

Stop Hook으로 (11편)

11편 tests_before_stop.py의 테스트 명령을 python3 -m unittest discover -s tests -t tests로 바꾸면, 테스트가 실패하는 동안 Claude는 턴을 끝내지 못합니다.

테스트가 가짜로 고칠 수 없는 상태라면 Claude가 “못 고친다”고 보고하는 것이 올바른 결과입니다.

가짜 세상 만들기

운영 스크립트는 디스크를 지우고, DB에 접속하고, 웹훅을 부릅니다. 테스트에서 진짜로 그러면 안 됩니다. 16편의 가짜 find를 일반화한 tests/fakes.py입니다.

1. 위험한 명령은 PATH 앞의 가짜로

df, systemctl, mysqldump, curl, find는 호출 인자만 calls.log에 남기고, 정해 둔 출력·종료 코드를 냅니다.

2. 모든 경로는 임시 디렉토리로

로그(ACME_LOG), 백업 폴더, 보고서(REPORT_OUT)를 환경 변수로 돌립니다. 그래서 수정 과정에서 config.env가 환경 변수를 존중하도록 바꿨습니다.

3. 안전하지 않으면 건너뛰기

전체 흐름 테스트는 config.env가 환경 변수를 무시하거나 run_all.sh가 아직 /var/www에 쓰면 실행하지 않고 건너뜁니다. 원본에서 이 테스트를 돌려도 실제 경로를 건드리지 않습니다(확인함).

4. 호출 기록으로 단언

“curl이 msg=service down으로 불렸다”, “mysqldump 인자에 비밀번호가 없다”처럼, 실제 부작용 대신 호출 기록을 검사합니다.

📄 tests/fakes.py
"""테스트용 가짜 세상: 위험한 명령(df, systemctl, mysqldump, curl, find …)을 호출만 기록하는 가짜로 바꾸고, 모든 경로를 임시 디렉토리로 돌린다.""" import os, subprocess, tempfile from pathlib import Path ROOT = Path(__file__).resolve().parent.parent class FakeWorld: def __init__(self): self._tmp = tempfile.TemporaryDirectory() self.dir = Path(self._tmp.name) self.bin = self.dir / "bin"; self.bin.mkdir() self.calls = self.dir / "calls.log" self.log = self.dir / "acme.log" def fake(self, name, body="exit 0"): """name 을 부르면 'name 인자…' 를 calls.log 에 남기고 body 를 실행하는 가짜 명령.""" p = self.bin / name p.write_text(f'#!/bin/bash\necho "{name} $*" >> "{self.calls}"\n{body}\n') p.chmod(0o755) def called(self): return self.calls.read_text() if self.calls.exists() else "" def env(self, **kw): e = dict(os.environ, PATH=f"{self.bin}:{os.environ['PATH']}", ACME_LOG=str(self.log), ALERT_WEBHOOK="http://fake.invalid/hook") e.update({k: str(v) for k, v in kw.items()}) return e def run(self, rel, *args, **kw): cmd = ["bash", str(ROOT / rel), *args] if rel.endswith(".sh") else ["python3", str(ROOT / rel), *args] return subprocess.run(cmd, env=self.env(**kw), capture_output=True, text=True, cwd=ROOT) def close(self): self._tmp.cleanup()
📄 tests/test_run_all.py (안전 건너뛰기 포함)
"""전체 흐름을 가짜 세상에서 돌린다. 실제 경로를 건드리지 않도록, config.env 가 환경 변수를 존중하지 않으면 실행하지 않고 건너뛴다.""" import os, subprocess, time, unittest from fakes import FakeWorld, ROOT def config_respects_env(tmp): r = subprocess.run(["bash", "-c", "set -a; source ./config.env; echo $BACKUP_DIR"], cwd=ROOT, env=dict(os.environ, BACKUP_DIR=str(tmp)), capture_output=True, text=True) return r.stdout.strip() == str(tmp) class RunAllTest(unittest.TestCase): def test_service_and_backup_failures_alert_and_keep_old_backups(self): w = FakeWorld(); self.addCleanup(w.close) bdir = w.dir / "backup"; bdir.mkdir() if not config_respects_env(bdir): self.skipTest("config.env 가 BACKUP_DIR 를 덮어써서 실제 경로를 건드릴 수 있어 실행하지 않음") if "/var/www" in (ROOT / "run_all.sh").read_text(): self.skipTest("run_all.sh 가 보고서를 실제 웹 경로에 써서 실행하지 않음 (REPORT_OUT 사용 후 실행)") old = bdir / "db-old.sql.gz"; old.write_text("good backup") t = time.time() - 10 * 86400; os.utime(old, (t, t)) w.fake("df", 'printf "Filesystem 1024-blocks Used Available Capacity Mounted on\\n"') w.fake("systemctl", '[ "$2" = acme-agent ] && echo inactive || echo active') w.fake("mysqldump", "exit 2") w.fake("curl", "exit 0") report = w.dir / "ops.html" r = w.run("run_all.sh", BACKUP_DIR=bdir, REPORT_OUT=report, DB_PASS="x") calls = w.called() self.assertIn("msg=service down", calls, "위험 3: 서비스 장애 알림") self.assertIn("msg=backup failed", calls) self.assertTrue(old.exists(), "백업이 실패한 날에는 오래된 백업을 지우면 안 된다") self.assertTrue(report.exists()) if __name__ == "__main__": unittest.main()

/run · /verify · /debug

번들 Skill하는 일
/run앱을 띄움. 프로젝트 종류(CLI·서버·TUI·브라우저)와 README·package.json·Makefile에서 실행법을 추론
/verify앱을 빌드·실행해 변경이 실제로 의도대로 동작하는지 확인. 테스트나 타입 검사로 대신하지 않음. 직접 불러야만 실행
/run-skill-generator깨끗한 환경에서 실행에 성공한 방법을 .claude/skills/run-<이름>/에 기록. 이후 /run·/verify가 그 기록을 따름
/debugClaude Code 자체(세션, 설정) 문제를 조사하는 플레이북. 여러분 코드의 버그용이 아닙니다
프로젝트 verify Skill = 커밋 전 자동 검증 10편에서 본 규칙: 세션이 시작될 때 프로젝트에 verify라는 Skill이 있으면, Claude는 커밋 직전마다 그것을 실행하라는 지시를 받습니다(문서·테스트만 바뀐 경우 제외). 같은 이름의 프로젝트 Skill은 번들 /verify를 대체합니다. acme-ops-legacy는 “띄울 앱”이 아니라 cron 스크립트이므로, 테스트와 shellcheck를 돌리는 verify Skill을 직접 만듭니다(실습 3단계). 주입 명령이 실패해도 Skill이 취소되지 않도록 출력은 | tail로, shellcheck는 || true로 감쌌습니다(10편 8장).
📄 .claude/skills/verify/SKILL.md
--- name: verify description: acme-ops-legacy 의 테스트와 셸 정적 분석을 실행해 변경을 검증한다. 커밋 전 검증이나 “확인해줘” 요청에 사용. allowed-tools: Bash(python3 -m unittest *) Bash(shellcheck *) --- ## 테스트 !`python3 -m unittest discover -s tests -t tests 2>&1 | tail -5` ## shellcheck (warning 이상) !`shellcheck -x -S warning run_all.sh lib/common.sh checks/*.sh backup/*.sh 2>&1 | tail -20 || true` ## 할 일 위 결과로 통과·실패를 한 줄로 요약하고, 실패가 있으면 원인 파일:줄을 짚어라. 테스트 파일은 고치지 않는다. 테스트를 통과시키려고 assert 를 바꾸거나 skip 을 추가하지 않는다.

가끔만 실패할 때

반복해서 확률 재기

“이 테스트를 30번 돌려 실패 횟수와 실패 때의 출력만 모아줘.” 14편 hero의 check_disk 간헐 실패처럼, 한 번 통과는 증거가 아닙니다.

흔한 원인

시각·날짜(자정, 타임존), 실행 순서 의존, 공유 임시 파일, 네트워크, 로케일(16편 df), 병렬 실행.

고정하기

시간은 주입하고, 임시 디렉토리는 테스트마다 새로, 외부 호출은 가짜로. FakeWorld가 테스트마다 새 디렉토리를 만드는 이유입니다.

sleep과 재시도로 덮지 않기

for i in $(seq 30); do python3 -m unittest discover -s tests -t tests -q 2>&1 | tail -1; done | sort | uniq -c
