    KServe 강의와의 관계
    
KServe의 구조, 서빙 런타임, 오토스케일링, LLM 서빙은 이 시리즈의 KServe 강의에서 자세히 다뤘습니다. 이 편은 Kubeflow 안에서 레지스트리와 KServe가 이어지는 지점에 집중합니다.

  






  
1왜 모델 레지스트리인가

  
모델 파일은 결국 어딘가의 파일입니다. 파일만 있으면 이런 질문에 답할 수 없습니다.

  

    
질문파일만 있을 때레지스트리가 있을 때

    
      
지금 운영 중인 모델은 어느 것인가final_v3_진짜최종.pt 중 하나라는 소문배포된 버전이 이름과 번호로 기록됨

      
그 모델은 무엇으로 만들었나만든 사람의 기억데이터, 코드, 실행 ID, 하이퍼파라미터가 버전에 붙어 있음

      
이전 버전으로 되돌리려면예전 파일을 찾아 다시 배포 절차를 밟음이전 버전 번호를 골라 다시 배포

      
감사 기관이 근거를 요구하면흩어진 기록을 모아 재구성버전의 메타데이터와 계보를 그대로 제출

    
  

  

    레지스트리는 파일이 아니라 장부입니다
    
모델 레지스트리는 모델 파일 자체를 저장하지 않습니다. 파일은 오브젝트 스토리지나 PVC에 있고, 레지스트리에는 그 위치(URI)와 메타데이터만 있습니다. 도서관의 소장 목록과 같습니다. 그래서 파일을 지우면 장부에는 있는데 책은 없는 상태가 됩니다. 등록된 모델 파일의 보존 정책을 레지스트리와 함께 정해야 합니다.

  






  
2Kubeflow Hub와 논리 모델

  
Kubeflow Hub는 예전 이름이 Kubeflow Model Registry인 구성요소로, 26.03.1 패치에서 이름이 바뀌었습니다. 공식 문서도 Kubeflow Hub의 Model Registry 구성요소라고 부릅니다. 설치하면 kubeflow 네임스페이스에 레지스트리 서버(REST API)와 메타데이터 DB가 뜨고, 대시보드에 Model Registry 화면이 생깁니다.

  

    
개념뜻예

    
      
RegisteredModel모델 하나의 이름. 여러 버전을 묶는 상위 개념digits-classifier

      
ModelVersion그 모델의 특정 버전. 작성자, 설명, 메타데이터, 상태(LIVE, ARCHIVED)를 가짐v3

      
ModelArtifact버전에 딸린 실제 파일의 위치와 형식pvc://.../digits-rf, 형식 sklearn

      
메타데이터버전과 아티팩트에 붙이는 이름=값 정보accuracy=0.9806, pipeline_run=rf-300

    
  

  
ModelArtifact의 형식 이름(model_format_name)은 KServe가 어떤 서빙 런타임으로 띄울지 고르는 데 쓰입니다. sklearn, xgboost, onnx, pytorch, huggingface 같은 값입니다.






  
3실습: 모델 등록하기

  
4편에서 노트북의 작업 공간 PVC에 저장한 손글씨 숫자 모델(/home/jovyan/models/digits-rf/model.joblib)을 등록합니다. 4편의 노트북에서 실행합니다.

  
!pip install model-registry

from model_registry import ModelRegistry

registry = ModelRegistry(
    server_address="http://model-registry-service.kubeflow.svc.cluster.local",
    port=8080,
    author="jieun@example.com",
    is_secure=False,                     # 클러스터 내부 HTTP. 운영은 13편
)

rm = registry.register_model(
    "digits-classifier",
    "pvc://my-first-notebook-workspace/models/digits-rf",   # 파일 위치 (PVC 이름/경로)
    model_format_name="sklearn",            # KServe 런타임 선택에 쓰임
    model_format_version="1",
    version="v1",
    description="RandomForest 200 trees, 4편 실습",
    metadata={"accuracy": 0.9722, "n_estimators": 200,
              "data": "sklearn digits, test_size=0.2, seed=42",
              "code": "digits-first-model.ipynb"},
)

print(registry.get_registered_model("digits-classifier"))
print(registry.get_model_version("digits-classifier", "v1"))
print(registry.get_model_artifact("digits-classifier", "v1").uri)

  
통합 Kubeflow SDK를 쓴다면 pip install "kubeflow[hub]"로 설치한 뒤 from kubeflow.hub import ModelRegistryClient로 같은 일을 할 수 있습니다. 생성자 인자 이름 등이 조금 다르므로 사용하는 버전의 문서를 확인하세요.

  
대시보드의 Model Registry 화면에서도 방금 등록한 모델과 버전, 메타데이터를 볼 수 있습니다. 같은 이름으로 v2, v3를 계속 등록하면 버전 목록이 쌓입니다.

  

    이번 실습의 pvc:// 위치는 학습용입니다
    
노트북 작업 공간 PVC를 서빙에서도 읽게 하면, 3편의 kind처럼 노드가 하나일 때는 동작하지만 실제 클러스터에서는 ReadWriteOnce 때문에 서로 다른 노드의 Pod가 함께 붙일 수 없습니다. 운영에서는 파이프라인이나 학습 작업이 모델을 오브젝트 스토리지(s3://)에 올리고, 그 위치를 등록합니다.

5레지스트리와 서빙을 잇는 세 길

  

    
방법어떻게장점주의

    
      
1. 위치를 읽어 직접 쓰기레지스트리에서 버전의 아티팩트 URI와 형식을 읽어, InferenceService의 storageUri와 modelFormat에 그대로 넣음. 4장 실습의 방식기본 설치로 바로 동작레지스트리와 서빙의 연결이 사람이나 스크립트의 몫. 버전 정보를 InferenceService 라벨이나 주석에 남겨 두기

      
2. model-registry:// 주소storageUri에 model-registry://모델이름/버전을 쓰면, 전용 storage initializer가 레지스트리에 물어 실제 위치에서 내려받음InferenceService가 레지스트리의 버전을 직접 가리킴. 맨 위 여권 실험의 방식관리자가 Model Registry용 storage initializer를 ClusterStorageContainer로 등록해 두어야 함

      
3. 파이프라인이 자동으로6편의 조건 분기 뒤에서, 기준을 넘은 모델을 등록하고 배포까지 하는 단계를 둠사람 없이 끝까지 이어짐자동 배포 전에 카나리나 승인 단계를 두는 것이 안전. 12편 종합 실습

    
  






  
6버전 교체와 카나리

  
새 버전을 한 번에 100% 바꾸면, 문제가 있을 때 모든 사용자가 영향을 받습니다. KServe의 카나리는 InferenceService의 모델 위치를 새 버전으로 바꾸면서 canaryTrafficPercent를 함께 주면, 새 버전에는 그 비율만, 나머지는 이전 버전으로 보냅니다. 맨 위 여권에서 v3를 고르고 카나리 10%를 눌러 보세요.

  
    
    
  1. 카나리 시작
    storageUri를 새 버전으로 바꾸고 canaryTrafficPercent: 10을 적용합니다. 이전 버전이 90%를 계속 처리합니다.
    2. 
    
  2. 지켜보기
    새 버전의 오류율, 응답 시간, 예측 분포를 이전 버전과 비교합니다. 15편의 관측 도구로 대시보드를 만들어 둡니다.
    3. 
    
  3. 승격 또는 되돌리기
    괜찮으면 canaryTrafficPercent를 지워 100%로 승격합니다. 문제가 있으면 canaryTrafficPercent를 0으로 두거나 이전 버전 위치로 되돌립니다. 레지스트리에도 어떤 버전이 운영 중인지 기록을 갱신합니다.
    4. 
  

  

    카나리는 배포 모드에 달려 있습니다
    
canaryTrafficPercent를 이용한 비율 분배는 Knative 기반의 서버리스 모드에서 동작합니다. 설치에 따라 KServe가 Deployment 기반의 표준(raw) 모드로 동작한다면, 이 방식 대신 InferenceService를 둘 두고 게이트웨이에서 비율을 나누는 등 다른 방법을 씁니다. 자세한 내용은 KServe 강의와 Knative 강의의 트래픽 관리 편을 참고하세요.

8Kubeflow 안의 KServe

  
KServe를 단독으로 쓸 때와 Kubeflow 안에서 쓸 때 달라지는 점입니다.

  

    
주제Kubeflow 안에서

    
      
어디에 만드나InferenceService는 각 사용자의 프로필 네임스페이스에 만듭니다. KServe의 제어부는 26.03에서는 kubeflow 네임스페이스에 있고, 다음 릴리스부터 kserve 네임스페이스로 옮겨 갑니다

      
배포 모드Knative가 함께 설치되어 서버리스 모드(요청이 없으면 0까지 줄이기, 카나리)를 쓸 수 있습니다. 설치 설정에 따라 표준 모드일 수 있으니 확인합니다

      
인증과 권한프로필 네임스페이스에는 Istio가 있어, 외부에서 호출하려면 3편의 로그인 흐름을 통과하거나 토큰이 필요하고, 다른 네임스페이스에서 호출하려면 권한 정책이 필요합니다(13편)

      
저장소 자격 증명S3에서 모델을 받으려면 자격 증명 Secret을 서비스 계정에 연결하고 InferenceService가 그 서비스 계정을 쓰게 합니다

      
화면대시보드의 Endpoints 화면(KServe UI)에서 상태와 로그를 봅니다

      
LLM 서빙Hugging Face 런타임(vLLM 기반 등)으로 LLM을 띄울 수 있습니다. 런타임과 GPU 설정은 KServe 강의를 참고하세요

    
  






  
9운영자가 볼 것

  

    
항목이유와 방법

    
      
레지스트리 DB 백업레지스트리의 장부가 사라지면 어떤 파일이 어떤 버전인지 알 수 없게 됩니다. 메타데이터 DB를 정기적으로 백업합니다. 3편 1장의 표에서 Hub가 PVC 20GB를 쓰는 이유입니다

      
모델 파일 보존등록된 버전의 파일은 레지스트리에서 보관(ARCHIVED) 처리하기 전까지 지우지 않는 규칙을 둡니다. 오브젝트 스토리지의 수명 주기 규칙과 맞춥니다

      
접근 범위설치 구성에 따라 레지스트리 하나를 여러 팀이 함께 쓸 수 있습니다. 누가 등록하고 고칠 수 있는지 확인하고, 팀 이름을 모델 이름 앞에 붙이는 규칙을 둡니다

      
이름과 버전 규칙모델 이름은 업무 기준(digits-classifier), 버전은 단조 증가 번호나 날짜로 통일합니다

      
서빙 자원InferenceService마다 requests와 limits, 최소와 최대 복제본 수를 정합니다. 0까지 줄이는 설정은 첫 요청이 느려지는 대가가 있습니다

13정리와 다음 편

  
    
    
  1. 모델 레지스트리는 파일이 아니라 장부입니다. 파일 위치와 메타데이터를 버전별로 기록하고, 파일 보존 정책을 함께 정합니다.
    2. 
    
  2. Kubeflow Hub(예전 Model Registry)의 기본 단위는 RegisteredModel, ModelVersion, ModelArtifact입니다. 형식 이름은 KServe 런타임 선택에 쓰입니다.
    3. 
    
  3. 등록한 버전은 위치를 읽어 직접, model-registry:// 주소로, 또는 파이프라인이 자동으로 KServe에 배포합니다.
    4. 
    
  4. 새 버전은 카나리로 일부 트래픽부터 보내고, 지켜본 뒤 승격하거나 되돌립니다. 비율 분배는 서버리스 모드에서 동작합니다.
    5. 
    
  5. Kubeflow 안의 KServe는 프로필 네임스페이스, Istio 권한, 저장소 자격 증명을 함께 생각해야 합니다.
    6. 
  

    
현장에서 쓰이는 장면

  
  • 금융. 운영 중인 이상거래 탐지 모델의 버전, 학습 데이터 날짜, 승인자를 레지스트리에서 즉시 꺼내 감사에 답합니다.
  • 제조. 새 버전을 카나리 10%로 라인 한 곳에만 먼저 적용해 보고 나머지 라인으로 넓힙니다.
  • MSP. 고객사마다 모델 이름 규칙(팀 접두사)과 메타데이터 필수 항목을 표준으로 정해 운영 혼선을 막습니다.
