1장

클라이언트 도구 지도

EPAS에 접속하는 도구는 크게 명령줄 도구, 그래픽 도구, 애플리케이션 드라이버로 나뉩니다. 시험에서는 앞의 두 종류를 구분해 두면 됩니다.

psql

PostgreSQL 표준 명령줄 클라이언트. EPAS 설치 시 함께 설치됩니다. 관리 작업의 기본 도구입니다.

EDB*Plus

Oracle SQL*Plus와 비슷한 명령 체계의 EPAS용 명령줄 클라이언트. 별도 패키지이며 Java가 필요합니다.

pgAdmin 4

웹 기반 그래픽 관리 도구. 서버를 등록해 객체 탐색, 쿼리 실행, 백업 등을 화면으로 합니다.

드라이버

JDBC, ODBC, .NET, OCI 호환 드라이버 등. EDB는 Oracle 애플리케이션용 커넥터를 따로 제공합니다.

현장 팁: 운영 서버에는 psql 하나면 충분하다

장애 대응 중에는 그래픽 도구가 붙지 않는 경우가 많습니다. 방화벽 너머 점프 서버에서 SSH로 들어가 psql로 문제를 확인하는 것이 MSP 운영의 기본 동작입니다. 이 편의 메타명령은 손에 익을 때까지 반복하세요.

2장

psql 접속 옵션과 기본값

psql -h db01 -p 5444 -U app_user -d sales
옵션의미생략했을 때
-h 호스트서버 주소 또는 유닉스 소켓 디렉터리로컬 유닉스 소켓으로 접속
-p 포트서버 포트PGPORT 환경변수, 없으면 클라이언트 빌드 기본 포트
-U 사용자데이터베이스 사용자(역할)현재 운영체제 사용자 이름
-d 데이터베이스접속할 데이터베이스사용자 이름과 같은 이름의 데이터베이스
-c "SQL"명령 하나를 실행하고 종료—
-f 파일파일의 SQL을 실행하고 종료—
-X~/.psqlrc를 읽지 않음 (스크립트 실행 시 권장)—
-v ON_ERROR_STOP=1스크립트에서 오류가 나면 즉시 중단오류가 나도 다음 문장을 계속 실행
-A -t정렬·헤더 없는 출력 (쉘 스크립트에서 값만 받을 때)—
시험 포인트: 왜 psql edb라고 치나

enterprisedb OS 사용자로 그냥 psql만 치면, 데이터베이스 이름도 사용자 이름을 따라 enterprisedb로 접속을 시도합니다. 그런 데이터베이스는 없으므로 database "enterprisedb" does not exist 오류가 납니다. 그래서 기본 데이터베이스 이름 edb를 붙여 psql edb로 접속합니다. 첫 번째 인자는 데이터베이스 이름, 두 번째 인자는 사용자 이름입니다(psql edb app_user).

포트는 항상 명시하는 습관

EPAS 패키지에 들어 있는 psql로 로컬 소켓에 붙으면 EDB 문서 예시처럼 포트 없이도 접속되지만, 다른 서버의 커뮤니티 psql이나 드라이버는 기본값 5432로 붙으려 합니다. 원격 접속, 스크립트, 운영 문서에서는 -p 5444를 항상 적으세요.

3장

접속 정보 전달 4가지 방법

같은 접속을 네 가지 방식으로 표현할 수 있습니다. 여러 곳에 값이 있으면 명령줄 옵션 > 환경변수 > 기본값 순으로 적용됩니다.

  • 명령줄 옵션 — -h -p -U -d
  • 연결 URI — postgresql://app_user@db01:5444/sales?sslmode=require
  • 키워드=값 문자열 — "host=db01 port=5444 dbname=sales user=app_user"
  • 환경변수 — PGHOST, PGPORT, PGUSER, PGDATABASE, PGSSLMODE 등

접속 문자열 생성기

값을 바꾸면 도구별 접속 표현을 모두 만들어 줍니다. 비밀번호는 넣지 않습니다. 비밀번호는 아래의 비밀번호 파일로 관리하세요.

비밀번호 파일 ~/.pgpass

비밀번호를 명령줄이나 스크립트에 적으면 프로세스 목록과 쉘 이력에 남습니다. 대신 홈 디렉터리의 .pgpass 파일에 적어 두면 psql과 libpq 기반 도구가 자동으로 읽습니다. EDB*Plus도 이 파일을 참고합니다.

# 형식: 호스트:포트:데이터베이스:사용자:비밀번호  (* 는 모든 값)
db01.example.com:5444:sales:app_user:S3cure!pass
localhost:5444:*:enterprisedb:Adm1n!pass

chmod 600 ~/.pgpass    # 권한이 넓으면 파일을 무시함
시험 포인트

.pgpass는 권한이 0600이어야 사용됩니다. Windows에서는 %APPDATA%\postgresql\pgpass.conf입니다. PGPASSWORD 환경변수도 동작하지만 다른 사용자에게 노출될 수 있어 권장되지 않습니다.

\?는 메타명령 도움말, \h는 SQL 문법 도움말입니다. \d는 모든 관계 목록이고 \dt는 테이블만입니다. \du는 사용자(역할), \dn은 스키마(namespace)입니다. \copy는 9편에서 서버 쪽 COPY와 비교합니다.

용어: ~/.psqlrc

psql이 시작할 때 자동으로 실행하는 개인 설정 파일입니다. 자주 쓰는 설정을 넣어 둡니다. 예: \set ON_ERROR_ROLLBACK interactive, \pset null '(null)', \timing on. 스크립트를 실행할 때는 개인 설정이 영향을 주지 않도록 psql -X로 이 파일을 건너뜁니다.

5장

EDB*Plus — SQL*Plus 사용자를 위한 클라이언트

EDB*Plus는 Oracle SQL*Plus와 비슷한 명령 체계를 가진 EPAS 전용 명령줄 클라이언트입니다. Oracle에서 넘어온 DBA와 개발자가 쓰던 스크립트와 습관을 크게 바꾸지 않고 쓸 수 있게 해 줍니다.

설치와 실행

# 별도 패키지이며 Java 1.8 이상이 필요
sudo dnf -y install edb-edbplus
export JAVA_HOME=/usr/lib/jvm/jre      # 설치한 Java 경로에 맞게
export PATH=$JAVA_HOME/bin:$PATH

# 사용자/비밀번호@호스트:포트/데이터베이스
/usr/edb/edbplus/edbplus.sh enterprisedb/비밀번호@localhost:5444/edb

# 호스트·포트·DB를 생략하면 localhost:5444/edb가 기본
/usr/edb/edbplus/edbplus.sh enterprisedb

비밀번호를 생략하면 .pgpass를 찾아보고, 없으면 입력을 요청합니다. /NOLOG로 접속 없이 시작한 뒤 CONNECT로 나중에 접속할 수도 있습니다.

분류 연습

각 문장이 어느 분류인지 골라 보세요.

시험 포인트: DDL도 롤백된다

PostgreSQL 계열은 CREATE TABLE, DROP TABLE, ALTER TABLE 같은 대부분의 DDL을 트랜잭션 안에서 실행하고 롤백할 수 있습니다. Oracle은 DDL을 실행하면 그 전 작업까지 암묵적으로 커밋하므로 동작이 다릅니다. 예외도 있습니다. CREATE DATABASE, CREATE TABLESPACE, VACUUM처럼 트랜잭션 블록 안에서 실행할 수 없는 명령이 있습니다. Oracle 애플리케이션을 이관할 때는 이 차이를 실제로 테스트해 확인하세요.

BEGIN;
CREATE TABLE t_test (id int);
INSERT INTO t_test VALUES (1);
ROLLBACK;
SELECT * FROM t_test;     -- ERROR: relation "t_test" does not exist  (테이블 생성까지 취소됨)

자동 증가 키: serial보다 IDENTITY

CREATE TABLE orders (
  order_id   bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  customer   text        NOT NULL,
  amount     numeric(12,2) NOT NULL CHECK (amount >= 0),
  created_at timestamptz NOT NULL DEFAULT now()
);

serial은 오래된 방식으로, 내부적으로 시퀀스를 따로 만들어 연결합니다. SQL 표준인 GENERATED ... AS IDENTITY가 권한 관리와 테이블 복사에서 더 깔끔해 새 설계에 권장됩니다. ALWAYS는 사용자가 값을 직접 넣지 못하게 하고, BY DEFAULT는 직접 넣는 것을 허용합니다.

용어: timestamp와 timestamptz

timestamptz(timestamp with time zone)는 입력 시각을 UTC로 바꿔 저장하고, 조회할 때 세션의 TimeZone 설정에 맞춰 보여 줍니다. 여러 지역에서 쓰는 시스템이나 클라우드 서버(대개 UTC)에서는 timestamptz를 쓰는 것이 안전합니다. 한국 시간으로 보려면 SET TimeZone = 'Asia/Seoul';.

8장

트랜잭션과 격리 수준

psql의 자동 커밋

psql은 기본적으로 자동 커밋(autocommit)입니다. BEGIN 없이 실행한 문장은 하나하나가 곧바로 커밋됩니다. 여러 문장을 하나로 묶으려면 BEGIN … COMMIT으로 감쌉니다. Oracle SQL*Plus에 익숙하면 이 차이에 주의하세요. SQL*Plus는 명시적으로 COMMIT할 때까지 변경을 확정하지 않는 것이 기본입니다.

\set AUTOCOMMIT off     -- psql에서 자동 커밋을 끄기 (이후 COMMIT 필요)

오류가 나면 트랜잭션 전체가 멈춘다

PostgreSQL 계열에서는 트랜잭션 안의 문장 하나가 실패하면, 그 트랜잭션은 중단(aborted) 상태가 되어 이후 문장을 모두 거부합니다. ROLLBACK으로 끝내야 다시 쓸 수 있습니다.

BEGIN;
INSERT INTO orders (customer, amount) VALUES ('A', 100);
INSERT INTO orders (customer, amount) VALUES ('B', -5);   -- CHECK 위반 오류
INSERT INTO orders (customer, amount) VALUES ('C', 30);
ERROR:  current transaction is aborted, commands ignored until end of transaction block
ROLLBACK;                                                  -- A도 함께 취소됨

일부만 취소하고 계속하려면 SAVEPOINT를 쓰거나, psql에서 \set ON_ERROR_ROLLBACK interactive를 켜면 psql이 문장마다 자동으로 세이브포인트를 걸어 줍니다.

BEGIN;
INSERT INTO orders (customer, amount) VALUES ('A', 100);
SAVEPOINT sp1;
INSERT INTO orders (customer, amount) VALUES ('B', -5);   -- 오류
ROLLBACK TO SAVEPOINT sp1;                                 -- B만 취소
INSERT INTO orders (customer, amount) VALUES ('C', 30);
COMMIT;                                                    -- A와 C가 저장됨

EPAS 18은 PostgreSQL 18의 SQL 기능을 그대로 물려받습니다. 실습 서버에서 직접 실행해 보세요.

시간 순으로 정렬되는 UUID

기존 gen_random_uuid()(버전 4)는 완전히 무작위라서, 기본 키로 쓰면 새 행이 인덱스의 아무 위치에나 들어가 B-tree 인덱스가 빨리 커지고 캐시 효율이 떨어집니다. PostgreSQL 18의 uuidv7()은 앞부분에 생성 시각이 들어가 생성 순서대로 정렬되므로, 분산 환경에서 전역 고유 키가 필요하면서도 인덱스 효율을 챙길 수 있습니다. 버전 4는 uuidv4()라는 이름으로도 부를 수 있게 됐습니다.

CREATE TABLE events (
  id      uuid PRIMARY KEY DEFAULT uuidv7(),
  payload jsonb
);
SELECT uuidv7(), uuidv7();   -- 앞자리가 거의 같고 뒤로 갈수록 증가
SELECT uuid_extract_timestamp(uuidv7());   -- 들어 있는 생성 시각 추출

저장하지 않고 조회 시 계산하는 생성 컬럼이 기본

생성 컬럼(generated column)은 다른 컬럼 값으로 자동 계산되는 컬럼입니다. 예전에는 값을 디스크에 저장하는 STORED만 있었는데, PostgreSQL 18부터 조회할 때 계산하는 VIRTUAL이 추가되고 기본값이 되었습니다. 디스크 공간을 쓰지 않고, 계산식이 바뀌어도 테이블을 다시 쓸 필요가 없습니다.

CREATE TABLE order_items (
  qty        int           NOT NULL,
  unit_price numeric(10,2) NOT NULL,
  total      numeric(12,2) GENERATED ALWAYS AS (qty * unit_price),          -- VIRTUAL (기본)
  total_s    numeric(12,2) GENERATED ALWAYS AS (qty * unit_price) STORED    -- 디스크에 저장
);

자주 조회되고 계산이 무거우면 STORED, 그렇지 않으면 VIRTUAL이 유리합니다. 인덱스가 필요한 경우처럼 VIRTUAL에 제약이 있는 상황도 있으니 설계 시 확인하세요.

변경 전 값과 변경 후 값을 한 번에 받기

RETURNING은 INSERT·UPDATE·DELETE가 바꾼 행을 결과로 돌려주는 PostgreSQL 기능입니다. PostgreSQL 18부터 old와 new로 변경 전과 후의 값을 함께 받을 수 있습니다. 변경 이력 기록이나 "얼마나 바뀌었는지" 확인하는 로직을 쿼리 하나로 끝낼 수 있습니다.

UPDATE accounts
   SET balance = balance - 5000
 WHERE id = 7
RETURNING old.balance AS before, new.balance AS after;

 before | after
--------+-------
  50000 | 45000
