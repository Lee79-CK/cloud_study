1장

이 시험은 무엇을 검증하나

EDB Postgres AI Database Essentials 시험은 Oracle 호환 기능을 가진 엔터프라이즈 Postgres, 즉 EDB Postgres Advanced Server(EPAS)를 프로덕션 환경에서 설치·설정·운영·유지보수할 수 있는가를 묻는 기초(Foundational) 등급 자격증입니다. 이름에 "AI"가 들어 있지만, 벡터 검색이나 모델 서빙을 깊게 묻는 시험이 아닙니다. 중심은 어디까지나 데이터베이스 관리자(DBA)의 기본기입니다.

앞 버전(v17) 배지에 공개된 스킬 목록을 기준으로 보면, 출제 범위는 크게 다음 묶음으로 정리됩니다.

  • 아키텍처 — Postgres 시스템 아키텍처, 데이터베이스 클러스터 개념
  • 구축과 설정 — 설치, 설정 파라미터 관리, 데이터베이스와 테이블스페이스 생성·관리
  • 객체와 SQL — 데이터베이스 객체 계층, 기초 SQL, 데이터베이스 개발
  • 보안 — 사용자·권한·접근 제어, 데이터베이스 보안
  • 유지보수와 이동 — 정기 유지보수, 데이터 이동(로드·언로드)
  • 데이터 보호 — 백업·복구 전략과 도구, 시점 복구(PITR), 재해 복구
  • 도구 개요 — 고가용성 도구 개요, 모니터링 개요, 엔터프라이즈 관리 도구
  • Oracle 호환 — Oracle과 호환되는 문법·타입·도구
시험 포인트

이 시험을 "PostgreSQL 자격증"과 가르는 것은 마지막 묶음입니다. 문항 상당수가 PostgreSQL 공통 지식이지만, 선택지 속에 EPAS에만 있는 기능·도구·기본값이 섞여 나옵니다. 공부하면서 늘 "이건 PostgreSQL 공통인가, EPAS 전용인가"를 표시해 두세요. 이 강의 시리즈는 EPAS 전용 내용을 청록색으로 일관되게 표시합니다.

시험 형식은 반드시 공식 페이지에서 확인

v18 시험의 문항 수·제한 시간·합격선은 공식적으로 확인하지 못했습니다. 참고로 커뮤니티 PostgreSQL Essentials v16 응시 후기에서는 50문항·50분·합격선 80%였고, 과거 EDB 자격증 중에는 합격선 70%인 것도 있었습니다. 버전마다 다를 수 있으니 시험 구매 전에 EDB 교육 포털의 시험 상세 페이지를 꼭 확인하세요.

이 시험을 따 두면 좋은 사람

MSP나 SI 현장에서 Oracle을 쓰던 고객이 비용 문제로 Postgres 전환을 검토하는 경우가 늘고 있습니다. 이때 EPAS는 "Oracle 애플리케이션을 최소한으로 고쳐서 옮길 수 있는" 선택지로 자주 거론됩니다. 고객사 인프라를 운영하는 엔지니어가 EPAS의 구조와 운영 방식을 알고 있으면, 전환 검토 단계에서부터 대화에 참여할 수 있습니다.

현장 사례: 이런 요청이 들어옵니다
  • "Oracle 라이선스 갱신 전에 일부 업무 DB를 EPAS로 옮기고 싶은데, 기존 PL/SQL 프로시저가 얼마나 그대로 돌아갈지 알고 싶다." → 5장의 Oracle 호환 개념과 12편에서 다룹니다.
  • "금융 감사 대응 때문에 누가 언제 어떤 SQL을 실행했는지 남겨야 한다." → EPAS의 EDB Audit 기능, 7편에서 다룹니다.
  • "개발팀은 커뮤니티 PostgreSQL을 쓰는데 운영은 EPAS다. 뭐가 달라지나?" → 4장의 배포판 비교가 답의 출발점입니다.

2장

EDB와 PostgreSQL의 관계

PostgreSQL은 특정 회사가 소유하지 않는 오픈소스 관계형 데이터베이스입니다. 전 세계 개발자와 여러 기업이 참여하는 PostgreSQL Global Development Group이 개발하고, PostgreSQL License라는 매우 관대한 라이선스로 배포됩니다. 누구나 가져다 쓰고, 고치고, 상용 제품으로 만들 수 있습니다.

EDB(EnterpriseDB)는 이 PostgreSQL을 기반으로 소프트웨어와 서비스를 제공하는 미국 기업입니다. 두 가지 방식으로 PostgreSQL과 관계를 맺습니다. 하나는 커뮤니티 PostgreSQL 개발에 기여하는 것이고, 다른 하나는 PostgreSQL 위에 성능·보안·관리 기능과 Oracle 호환 기능을 더한 자체 배포판을 만드는 것입니다.

용어: 배포판(Distribution)

같은 원본 소스 코드를 바탕으로 기능을 추가하거나 패키징을 달리해서 내놓은 제품을 말합니다. 리눅스 커널 위에 RHEL, Ubuntu가 있는 것과 비슷합니다. EPAS는 PostgreSQL 소스 위에 EDB가 기능을 추가한 배포판이라서, PostgreSQL에서 되는 것은 대부분 EPAS에서도 그대로 됩니다.

EPAS 이름의 변천

시험에 연도가 나오지는 않지만, 오래된 문서나 고객사 시스템에서 옛 이름을 만날 수 있어서 알아두면 편합니다.

2006EnterpriseDB Advanced Server

EDB의 첫 상용 배포판 이름입니다.

2008Postgres Plus Advanced Server

"PPAS"라는 약어로 오래된 문서에 자주 등장합니다.

2016EDB Postgres Advanced Server

EDB Postgres Platform 출시와 함께 지금의 이름, 약어 EPAS가 됐습니다.

현재EDB Postgres AI의 일부

EDB는 제품 전체를 EDB Postgres AI라는 플랫폼 브랜드로 묶었고, EPAS는 그 안의 데이터베이스 구성요소로 자리합니다. 시험 이름이 "EDB Postgres AI Database Essentials"인 이유입니다.

시험 포인트

문제 지문에서 "EDB Postgres Advanced Server", "EPAS", "Advanced Server", "Enterprise Postgres (Oracle Compatible)"은 모두 같은 제품을 가리킨다고 보면 됩니다.

3장

EDB Postgres AI 플랫폼 4요소

EDB Postgres AI는 단일 데이터베이스 제품이 아니라, 트랜잭션 처리·분석·AI·통합 관리를 하나로 묶은 플랫폼 이름입니다. EDB 공식 소개 과정은 이 플랫폼의 주요 구성요소로 Postgres 클러스터 데이터베이스, Analytics Accelerator, AI Factory, Hybrid Management를 꼽습니다. 탭을 눌러 각 요소의 역할과 이번 시험에서의 비중을 확인하세요.

시험 비중: 핵심 — 시험의 대부분

EDB Postgres AI Database

운영계 트랜잭션(OLTP) 워크로드를 처리하는 데이터베이스 엔진 묶음입니다. 커뮤니티 PostgreSQL, EDB Postgres Extended, EDB Postgres Advanced Server가 여기에 속하고, 여기에 고가용성 구성 선택지(EDB Failover Manager를 쓰는 스트리밍 복제 구성, EDB Postgres Distributed를 쓰는 분산 구성)가 더해집니다.

이번 시험은 사실상 이 중 EPAS 단일 서버의 설치·설정·보안·유지보수·백업에 집중합니다. 고가용성은 "어떤 도구가 어떤 역할을 하는가" 정도의 개요 수준으로 나옵니다.

시험 비중: 개요 수준 또는 범위 밖

Analytics Accelerator

운영 데이터베이스에 부담을 주지 않고 대용량 분석을 하기 위한 구성요소입니다. 오브젝트 스토리지에 저장된 레이크하우스 형식 데이터(예: Apache Iceberg, Delta Lake 테이블)를 Postgres에서 SQL로 조회하고, 분석에 유리한 컬럼형·벡터화 방식으로 처리하는 것이 핵심 아이디어입니다.

비유: 매장(운영 DB)에서 재고 조사까지 하면 손님 응대가 느려집니다. 재고 데이터를 창고(오브젝트 스토리지)로 옮기고, 창고 전용 계산 담당(분석 엔진)이 따로 셈을 하는 구조입니다.

시험 비중: 개요 수준 또는 범위 밖

AI Factory

Postgres를 중심으로 생성형 AI 애플리케이션을 만들기 위한 구성요소입니다. 데이터에서 임베딩(텍스트·이미지를 숫자 벡터로 바꾼 것)을 만들고, pgvector 같은 확장으로 벡터 유사도 검색을 하고, 지식 베이스를 구성해 RAG(검색 증강 생성)나 에이전트에 연결하는 작업을 지원합니다. 모델 서빙 기능도 이 영역에 포함됩니다.

AI 엔지니어라면 관심이 가는 부분이지만, Database Essentials 시험에서 깊게 묻지는 않습니다. 플랫폼 구성요소의 이름과 역할을 구분하는 정도면 충분합니다.

시험 비중: 개요 수준

Hybrid Manager

온프레미스와 여러 퍼블릭 클라우드에 흩어진 Postgres를 하나의 제어 화면(컨트롤 플레인)에서 배포·관리·관측하기 위한 구성요소입니다. 쿠버네티스 위에서 동작하며, 데이터베이스 생성, 백업, 모니터링을 한곳에서 다루는 것이 목표입니다.

MSP 관점에서는 "고객사마다 다른 환경에 있는 DB를 한 곳에서 본다"는 요구와 맞닿아 있습니다. 시험에서는 11편의 모니터링·관리 도구 개요(예: Postgres Enterprise Manager)와 함께 이름과 역할 정도를 구분해 두면 됩니다.

시험 포인트

플랫폼 4요소는 "이 중 트랜잭션 데이터베이스 엔진은 무엇인가", "레이크하우스 분석을 담당하는 것은 무엇인가"처럼 역할 구분형으로 나올 수 있습니다. 세부 기능보다 역할 한 문장을 정확히 외우세요.

4장

세 배포판 비교: PostgreSQL · PGE · EPAS

히어로의 동심원 그림처럼, 세 배포판은 같은 PostgreSQL 코어를 공유하고 바깥으로 갈수록 기능이 더해지는 관계로 이해하면 편합니다. 다만 이것은 학습용 단순화입니다. 세부 기능 지원 여부는 버전마다 달라질 수 있으니 실무에서는 EDB 공식 문서의 기능 비교표를 확인하세요.

한 줄 정의

  • PostgreSQL — 커뮤니티가 만드는 원본. 무료이고 누구나 쓸 수 있습니다.
  • EDB Postgres Extended Server (PGE) — PostgreSQL과 높은 호환성을 유지하면서 엔터프라이즈 기능(투명 데이터 암호화 등)과 EDB Postgres Distributed용 최적화를 더한 배포판입니다. Oracle 호환 기능은 없습니다.
  • EDB Postgres Advanced Server (EPAS) — 엔터프라이즈 기능에 더해 Oracle 호환 기능과 EPAS 전용 보안·관리 도구를 제공하는 배포판입니다. 이 시험의 주인공입니다.

5장

Oracle 호환이란 무엇인가

"Oracle 호환"은 Oracle Database용으로 작성된 SQL, 절차 코드, 운영 도구 사용 습관을 가능한 한 고치지 않고 EPAS에서 쓸 수 있게 해 준다는 뜻입니다. 100% 동일하다는 뜻은 아닙니다. 마이그레이션 비용을 크게 줄여 주는 것이지, 없애 주는 것은 아닙니다.

호환이 적용되는 다섯 영역

  • SQL 문법 — DUAL 테이블, ROWNUM, CONNECT BY 계층 쿼리, 시너님(SYNONYM), NVL·DECODE 같은 함수
  • 데이터 타입 — VARCHAR2, NUMBER, 시간까지 담는 Oracle식 DATE 등
  • 절차 언어 — PL/SQL과 호환되는 SPL(Stored Procedure Language)로 작성하는 프로시저, 함수, 트리거, 패키지
  • 내장 패키지와 딕셔너리 — DBMS_OUTPUT 같은 패키지, USER_TABLES 같은 딕셔너리 뷰
  • 도구와 마이그레이션 — EDB*Plus, EDB*Loader, 그리고 Oracle에서 옮겨 오는 작업을 돕는 Migration Portal·Migration Toolkit
용어: Oracle 호환 모드 (Redwood 모드)

EPAS는 데이터베이스 클러스터를 만들 때(initdb) Oracle 호환 모드로 만들지, PostgreSQL 방식으로 만들지 고를 수 있습니다. EDB 문서와 파라미터 이름에서는 Oracle 호환을 "Redwood"라는 말로 부르는 경우가 많습니다(Oracle 본사가 있는 지명에서 따온 이름). 기본값과 구체적인 옵션은 3편에서 실습으로 확인합니다. 아래 판별기의 EPAS 결과는 Oracle 호환 모드 기준입니다.

호환성 판별기

왼쪽에서 SQL을 고르면 Oracle, EPAS, 커뮤니티 PostgreSQL에서 그대로 실행되는지와 그 이유를 보여 줍니다.

시험 포인트: EPAS는 "양쪽 다" 된다

EPAS는 PostgreSQL 기반이라서 Oracle식 문법과 PostgreSQL식 문법을 둘 다 받아들입니다. NVL도 되고 COALESCE도 되며, ROWNUM도 되고 LIMIT도 됩니다. "EPAS에서는 PostgreSQL 문법을 쓸 수 없다"는 선택지는 함정입니다.

6장

버전 체계와 PostgreSQL 18 미리보기

PostgreSQL은 1년에 한 번 메이저 버전(16, 17, 18…)을 내고, 그 사이에 버그·보안 수정만 담은 마이너 버전(18.1, 18.2…)을 정기적으로 냅니다. 메이저 버전 사이에는 디스크 저장 형식이 바뀔 수 있어서 업그레이드에 pg_upgrade나 덤프·복원 같은 별도 절차가 필요하고, 마이너 버전은 바이너리 교체와 재시작만으로 올릴 수 있습니다. 커뮤니티는 각 메이저 버전을 출시 후 약 5년간 지원합니다.

EPAS는 같은 번호의 PostgreSQL 메이저 버전을 기반으로 만들어집니다. EPAS 18은 PostgreSQL 18 기반이고, 시험 이름의 v18도 이 버전을 뜻합니다.

시험 포인트

"마이너 업그레이드에 pg_upgrade가 필요하다"는 틀린 문장입니다. 메이저 업그레이드와 마이너 업그레이드의 절차 차이는 기초 시험의 단골 소재입니다.

PostgreSQL 18에서 달라진 것 중 이 시리즈에 나올 것들

EPAS 18은 PostgreSQL 18의 변경 사항을 그대로 물려받습니다. 각 항목은 해당 편에서 자세히 다룹니다.

변경 사항한 줄 설명다루는 편
비동기 I/O디스크 읽기를 한 번에 여러 개 요청해 대기 시간을 줄이는 구조. io_method 파라미터로 방식을 고릅니다.2편, 5편
initdb 데이터 체크섬 기본 활성화새 클러스터는 기본적으로 페이지 손상 감지용 체크섬을 켠 상태로 만들어집니다.3편
uuidv7(), 가상 생성 컬럼시간 순 정렬되는 UUID 생성 함수, 저장하지 않고 조회 시 계산하는 생성 컬럼이 기본이 됨.4편
OAuth 인증, MD5 비밀번호 폐지 예고외부 ID 공급자를 통한 인증 방식이 추가되고, MD5 비밀번호는 향후 제거 대상으로 경고가 나옵니다.7편
B-tree 스킵 스캔다중 컬럼 인덱스의 앞 컬럼 조건이 없어도 인덱스를 활용할 수 있는 경우가 늘었습니다.8편
pg_upgrade 통계 보존메이저 업그레이드 후에도 옵티마이저 통계가 유지되어 업그레이드 직후 성능 저하가 줄어듭니다.10편

학습 계획 만들기

남은 기간을 고르면 이 시리즈 기준 주차별 계획을 만들어 줍니다.

공부 방법 다섯 가지

  1. 공식 무료 과정을 한 번은 끝까지 본다. EDB는 교육 과정 자체는 무료로 공개하고 시험만 유료로 판매합니다. EDB Postgres AI Database Essentials 온디맨드 과정은 약 8.5시간 분량이며, 시험 문제의 용어와 표현이 이 과정에서 나옵니다. 이 강의 시리즈는 그 과정을 이해하기 쉽게 풀고 보충하는 역할입니다.
  2. 모든 명령어를 직접 쳐 본다. "이 파라미터를 바꾸면 재시작이 필요한가"는 외우는 것보다 한 번 바꿔 보는 쪽이 훨씬 오래 남습니다. 8장의 실습 환경을 꼭 준비하세요.
  3. EPAS 전용 노트를 따로 만든다. 공통 지식과 EPAS 전용 지식을 섞어서 외우면 선택지에서 헷갈립니다. 청록색 표시가 나올 때마다 따로 적어 두세요.
  4. 기본값과 숫자를 표로 모은다. 포트, 기본 사용자, 파라미터 기본값, 디렉터리 이름처럼 정답이 하나로 정해지는 항목은 표 한 장으로 모아 반복합니다.
  5. 마지막 주는 모의고사와 오답 정리에 쓴다. 시리즈 마지막 편의 모의고사를 풀고, 틀린 문항의 해당 편으로 돌아가 다시 읽습니다.

8장

실습 환경 준비

실습 환경은 두 가지를 권합니다. EPAS 전용 기능을 연습하려면 첫 번째가 필요하고, PostgreSQL 공통 내용만 빠르게 연습할 때는 두 번째로도 충분합니다. 설치 옵션과 초기화 과정의 의미는 3편에서 한 줄씩 해설하니, 여기서는 "무엇을 준비해 두면 되는가"만 확인합니다.

방법 1. 리눅스 VM에 EPAS 18 설치 (권장)

RHEL 호환 배포판(Rocky Linux 9 등) VM 한 대를 준비합니다. 사양은 vCPU 2개, 메모리 4GB, 디스크 30GB 정도면 충분합니다. EPAS 패키지는 EDB 리포지터리에서 받는데, 리포지터리 접근에는 EDB 계정의 구독 토큰이 필요합니다. EDB 웹사이트에 로그인해 리포지터리 접근 정보를 확인하세요.

# 1) EDB 리포지터리 등록 (토큰은 EDB 계정에서 확인)
export EDB_SUBSCRIPTION_TOKEN='발급받은_토큰'
curl -1sSLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/enterprise/setup.rpm.sh" | sudo -E bash

# 2) EPAS 18 서버 패키지 설치
sudo dnf -y install edb-as18-server

# 3) 데이터베이스 클러스터 초기화 후 서비스 시작 (3편에서 상세 해설)
sudo /usr/edb/as18/bin/edb-as-18-setup initdb
sudo systemctl enable --now edb-as-18

# 4) 접속 확인: EPAS 기본 포트 5444, 기본 슈퍼유저 enterprisedb
sudo -iu enterprisedb psql -p 5444 -d edb -c "SELECT version();"
명령어가 다르게 동작한다면

패키지 이름, 설치 경로, 초기화 스크립트 이름은 EDB가 리포지터리 구성을 바꾸면서 달라질 수 있습니다. 명령이 실패하면 EDB 공식 문서의 EPAS 18 설치 안내(사용 중인 OS 버전 항목)를 기준으로 맞추세요. 이 편에서는 흐름만 익히면 됩니다.

방법 2. 컨테이너로 커뮤니티 PostgreSQL 18 (보조)

아키텍처, 설정 파라미터, VACUUM, 백업처럼 PostgreSQL 공통 내용은 공식 컨테이너 이미지로도 충분히 연습할 수 있습니다. 노트북에서 몇 초 만에 띄우고 지울 수 있다는 것이 장점입니다.

docker run -d --name pg18 \
  -e POSTGRES_PASSWORD='Lab!2345' \
  -p 5432:5432 \
  postgres:18

docker exec -it pg18 psql -U postgres -c "SELECT version();"

이 환경에서는 DUAL, SPL, EDB*Plus 같은 EPAS 전용 기능은 동작하지 않습니다. 5장 판별기에서 "PostgreSQL ✗"로 나온 예제를 직접 실행해 오류 메시지를 확인해 보는 것도 좋은 공부가 됩니다.

현장 팁: 실습 VM도 운영처럼

실습용이라도 VM 스냅샷을 "설치 직후", "초기화 직후" 두 단계로 찍어 두세요. 7편의 pg_hba.conf 실습이나 10편의 PITR 실습에서 설정을 망가뜨렸을 때 몇 초 만에 되돌릴 수 있습니다.
